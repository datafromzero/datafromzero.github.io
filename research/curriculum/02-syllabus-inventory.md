# 02 — Syllabus Inventory: What Data From Zero Teaches

**Purpose.** The single topic inventory the website build teaches from. It follows the decided linear path — Excel → SQL (one complete block) → Python → advanced core → specialized tracks (Data Analyst, Data Engineer, Data Scientist, Analytics Engineer, ML/AI Engineer) — and lists, in dependency order, every topic the learner is expected to meet, in the order they meet it.

**Source rule.** Topic lists in this file come only from the five Wave 1 syllabus inventories: `syllabus-excel-bi.md`, `syllabus-sql.md`, `syllabus-python.md`, `syllabus-stats-analytics-ds.md`, and `syllabus-de-ml-ai.md`. Where this file notes those layers, it points to them; it does not duplicate their lists.

**How to read the labels.** Unmarked items are sourced from the syllabus inventories. Items marked **[Recommendation]** are curriculum design choices carried from the source files, not findings. Items marked *(awareness)* are know-it-exists level, not drill level. Items marked *(working level)* are expected of independent practitioners in that tool. Counts are preserved only as stated in the source files and in STATE.md: SQL 260+ items, Excel/BI about 190 items, Python 16 sections (0–15), Statistics about 120 items, DE/ML/AI sections A0–A12 plus B0–B12.

**Confidence.** High for the Excel, SQL, Python, and statistics cores, where the source inventories report agreement across multiple independent syllabi and vendor references, all accessed 2026-11-15. Medium for dialect edge cases in SQL and for the analytics-craft material, which the source files note is scattered across courses rather than canonical in one syllabus.

Source detail: per-claim URLs and access dates (all 2026-11-15) are recorded in the underlying wave research files in the curriculum-distillation research folder, mapped in 00-README.md §6; this file is the synthesis.

## 1. Stage 1 — Spreadsheets and the BI Layer

Source: `syllabus-excel-bi.md` — Microsoft Excel (Part A), Google Sheets (Part B), BI concepts (Part C), Tableau (Part D), Power BI (Part E). Three tiers run through the stage in dependency order: Beginner (first job tasks), Working (independent analyst), Advanced (power user / BI developer).

### 1.1 Excel — interface, hygiene, and formula foundations

- Workbook navigation and editing: ribbon, name box, formula bar, copy/paste and Paste Special, Fill Series and Flash Fill, multiple sheets and workbooks, number formats, freeze panes and print setup.
- Data-hygiene rules that every later stage assumes: one header row, one fact per cell, no merged cells in data, no blank rows or columns inside a dataset, raw data kept separate from calculations and outputs.
- Sheet and workbook protection and workbook properties.
- Formula writing: operators and order of operations; relative, absolute, and mixed references and what happens when a formula is copied; named ranges and the Name Manager; structured references inside Excel Tables.
- Error literacy and auditing: the common error values, tracing precedents and dependents, Evaluate Formula, Watch Window, Show Formulas.

### 1.2 Excel — function families

- Math and statistics: SUM, AVERAGE, MIN, MAX, and the COUNT family; conditional aggregation with SUMIF(S), COUNTIF(S), AVERAGEIF(S); ROUND family, INT, MOD; SUBTOTAL and AGGREGATE on filtered data; SUMPRODUCT; MEDIAN, MODE, standard deviation and variance (sample vs. population), PERCENTILE, QUARTILE, RANK; LARGE, SMALL, MAXIFS, MINIFS; CORREL and first-pass regression functions (SLOPE, INTERCEPT, RSQ; LINEST at awareness level); database functions and RAND/RANDBETWEEN at awareness level.
- Logic: IF, nested IF and IFS, AND/OR/NOT, IFERROR and IFNA, SWITCH and CHOOSE; the flag-then-aggregate pattern (build a label column, then count or sum by it).
- Lookup and reference: XLOOKUP as the current default; VLOOKUP and HLOOKUP for reading legacy workbooks; INDEX + MATCH including two-way lookups; MATCH match types and approximate-match behavior; CHOOSE, OFFSET, INDIRECT at awareness level with caution; ROW/COLUMN family; joining datasets on a unique key as the spreadsheet rehearsal for SQL joins.
- Text: LEFT, RIGHT, MID, LEN; TEXTBEFORE, TEXTAFTER, TEXTSPLIT; CONCAT and TEXTJOIN; TRIM, CLEAN, UPPER, LOWER, PROPER; FIND, SEARCH, SUBSTITUTE, REPLACE; TEXT for formatting and VALUE/DATEVALUE/TIMEVALUE for conversion back; regular-expression functions at awareness level; EXACT at awareness level.
- Date and time: dates as serial numbers; TODAY, NOW, DATE and date-part functions including WEEKDAY and week numbers; EDATE and EOMONTH; DATEDIF and subtraction for ages and lead times; NETWORKDAYS and WORKDAY families; YEARFRAC at awareness level; fixing text-dates imported from CSV files.

### 1.3 Excel — working with data

- Tables, sorting, and filtering: converting a range to an Excel Table; single- and multi-level sorting and custom sort lists; AutoFilter; Advanced Filter at awareness level; Remove Duplicates and Consolidate at awareness level; Text to Columns.
- Conditional formatting: highlight-cell rules, top/bottom and above/below-average rules, data bars, color scales and icon sets, formula-based rules that format a whole row, and rule management.
- Data validation: whole-number, decimal, date, and text-length validation with messages and alerts; dropdown lists; dependent dropdowns; formula-based custom validation; circling invalid data in an inherited sheet.
- PivotTables and PivotCharts: building from a clean Table; changing aggregation and number format; grouping dates, numbers, and text; sorting, filtering, top-10 and value filters; Show Values As (share, difference, running total, rank); slicers and timelines; calculated fields and items at working level; refresh discipline and GETPIVOTDATA at awareness level; linked PivotCharts; drill-down to detail.
- Charts and presentation: column/bar, line, and pie/doughnut charts and when each is honest; combo charts with a secondary axis; scatter and bubble charts at working level; titles that state the takeaway, axis formatting, legends and gridline restraint; sparklines; dynamic chart ranges from Tables and named ranges; in-cell alternatives at awareness level.

### 1.4 Excel — cleaning, modern functions, and automation-adjacent tools

- End-to-end cleaning workflow: profile before cleaning (blanks, duplicates, distinct values, type mismatches); standardize keys; handle missing values deliberately and document the choice; split and merge columns; convert types safely and check after conversion; resolve duplicates by full row and by key; replace inconsistent labels via a mapping table; keep raw data, cleaned data, and a change log.
- Dynamic arrays (Microsoft 365): spill ranges and the #SPILL! error; FILTER; SORT, SORTBY, UNIQUE; SEQUENCE and RANDARRAY at working level; TAKE, DROP, CHOOSECOLS, CHOOSEROWS, HSTACK, VSTACK, TOCOL/TOROW; LET for readable long formulas; LAMBDA with BYROW/BYCLO/MAP/SCAN/REDUCE at advanced awareness level; combined XLOOKUP + FILTER + UNIQUE reporting patterns.
- Power Query in Excel: Get Data from files, folders, the web, and other sheets; core editor transformations (remove/rename/reorder, types, filter, sort); split/merge columns, replace values, fill down, trim/clean; unpivot and pivot; merge queries with explicit join types; append queries; Group By; parameters and folder refresh at advanced level; reading and lightly editing M code at advanced awareness level; loading to a Table or the Data Model and refreshing on open.
- What-if, Solver, and forecasting: Goal Seek; one- and two-variable Data Tables; Scenario Manager; Solver at working level; Forecast Sheet and FORECAST.ETS / FORECAST.LINEAR at working level; regression through the Analysis ToolPak; financial functions (NPV, IRR, PMT, PV, FV, RATE) at working level for finance-adjacent roles.
- Dashboards and workbook craft: raw / calculations / dashboard sheet structure; one-screen dashboards with KPI cells, linked charts, and slicers; linking every figure to a formula or pivot, never a typed constant; documenting assumptions, sources, and refresh date on the sheet; control totals against source systems; recording simple macros at working level and reading basic VBA at awareness level.

### 1.5 Google Sheets — what transfers, what is Sheets-only

- Direct transfer: core formula families, PivotTables, charts, conditional formatting, data validation, named ranges, and protected ranges work in Sheets with different menus; Explore, filter views, and slicers.
- Sheets-only power features: QUERY (SQL-like selection over a range, and a gentle on-ramp to Stage 2); ARRAYFORMULA with MAP/LAMBDA; IMPORTRANGE; IMPORTDATA, IMPORTHTML, IMPORTXML; GOOGLEFINANCE; SPARKLINE; REGEXMATCH, REGEXEXTRACT, REGEXREPLACE; UNIQUE, FILTER, SORT, SORTN, FLATTEN, TRANSPOSE; DETECTLANGUAGE and GOOGLETRANSLATE at awareness level; sharing, comments, version history and restore; Connected Sheets and BigQuery-linked tables at awareness level; the in-cell AI function at awareness level, with its output verified like any unverified draft (see Section 7).

### 1.6 BI concepts that precede any tool

- Operational reports vs. dashboards vs. self-service BI; the pipeline connect → clean/transform → model → calculate → visualize → publish/refresh.
- Facts vs. dimensions and the star schema; grain stated for every table before joining; keys and relationships, one-to-many and many-to-many hazards, cross-filter direction; measures (aggregated on the fly) vs. stored columns; refresh, scheduling, and visible data-freshness labels.

### 1.7 Tableau

- Foundations: dimensions vs. measures, discrete vs. continuous; connecting to files, databases, and cloud sources; live connection vs. extract; the Data pane (rename, alias, default formats, geographic roles, hierarchies, folders); first views for comparison, trend, composition, and correlation; sorting, grouping, sets, and bins; filter types and the order of operations.
- Calculations and analysis: row-level and aggregate calculated fields; quick table calculations (running total, percent of total, difference, percent difference, rank, moving average); addressing and partitioning; LOD expressions (FIXED, INCLUDE, EXCLUDE); parameters and parameter actions; reference lines, bands, distributions, trend lines, and simple forecasting; blending, relationships, joins, and unions; Tableau Prep Builder flows at working level.
- Dashboards, stories, and publishing: layout containers and device layouts; dashboard actions (filter, highlight, URL, parameter); stories as sequenced arguments; publishing to Tableau Server / Cloud with permissions and extract refresh schedules; Tableau Public as portfolio proof; performance hygiene at advanced level; Tableau Certified Data Analyst blueprint at awareness level.

### 1.8 Power BI

- Get and prepare: connecting Power BI Desktop to files, folders, databases, and web sources; Power Query transformations (the same engine and M language as Section 1.4); Import vs. DirectQuery vs. composite models at working level.
- Modeling: star schema design; relationships, cardinality, and cross-filter direction; active vs. inactive relationships; hiding keys and technical columns, display folders, formats and types; hierarchies and drill-down paths.
- DAX: measures vs. calculated columns vs. calculated tables; core aggregation and iterator functions including DISTINCTCOUNT; filter context and row context; CALCULATE with ALL / ALLEXCEPT / REMOVEFILTERS; time intelligence (TOTALYTD, SAMEPERIODLASTYEAR, DATEADD, DATESINPERIOD) with a marked date table; variables (VAR … RETURN); visual calculations at awareness level; USERELATIONSHIP and role-playing dimensions at advanced level; row-level security roles at advanced level.
- Visuals, reports, and publishing: core visuals and formatting discipline; cross-highlighting, drill-through, tooltips, bookmarks, and buttons; conditional formatting in tables and matrices; publishing to the Power BI service (workspaces, apps, sharing, permissions); scheduled refresh and gateways; the PL-300 domain list at awareness level (cross-reference in Section 9).

## 2. Stage 2 — SQL, One Complete Block

Source: `syllabus-sql.md`, sections 0–17 plus its completion standard (260+ items). Teach in the order shown; a later block assumes the earlier blocks. Three depth labels run through the block in the source: Core (analysts and data scientists), Working (data/analytics engineers and advanced analysts), Awareness (recognize and know when to look it up).

### 2.1 Foundations and retrieval (source sections 0–3)

- Relational model: database, schema, table, row, column, value; primary keys and foreign keys; one-to-one, one-to-many, and many-to-many relationships; result grain stated before writing a metric.
- Query anatomy and logical order of execution (SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT); schema discovery through catalogs and information_schema; safe previewing with a row limit; readable formatting, comments, and statement boundaries.
- Retrieval: named columns vs. SELECT * and its risks; column and table aliases; qualified names; literals; arithmetic expressions and operator precedence; DISTINCT on one and on multiple columns; stable output column order.
- Filtering: equality and inequality, range comparisons, AND/OR/NOT with parentheses, BETWEEN and half-open date ranges, IN and NOT IN lists, LIKE with % and _, IS NULL / IS NOT NULL, case sensitivity and collation, filtering on calculated conditions, sargable filter shapes, WHERE vs. HAVING.
- Sorting and limiting: ORDER BY on one column, several columns, and expressions; ASC/DESC; NULLS FIRST/LAST where supported; LIMIT and OFFSET; deterministic tie-breakers; FETCH FIRST; dialect sampling syntax; pagination cost awareness.

### 2.2 Aggregation and joining (source sections 4–5)

- Aggregates: COUNT(*) vs. COUNT(column) vs. COUNT(DISTINCT …); SUM, AVG, MIN, MAX; GROUP BY on one key, several keys, and expressions; HAVING; aggregate behavior with NULL; conditional aggregation and FILTER (WHERE …) where supported; percentages and ratios with the correct denominator; percent of total; median and percentile functions per dialect; string, array, and boolean aggregation; ROLLUP, CUBE, and GROUPING SETS; grouping-key validation.
- Joins: join keys and cardinality prediction; INNER, LEFT, RIGHT, FULL OUTER, and CROSS joins; multiple joins in one query; composite keys; non-equi (band) joins; temporal and as-of joins; self-joins; anti-joins (LEFT JOIN … IS NULL and NOT EXISTS); semi-joins (EXISTS and IN); join fanout and pre-aggregating the many side before joining; USING shorthand; why NATURAL JOIN is risky; join-condition placement in ON vs. WHERE.

### 2.3 Composition (source sections 6–8)

- Subqueries and CTEs: scalar subqueries; subqueries in WHERE with IN, ANY/SOME, and ALL; EXISTS; derived tables; subqueries in SELECT; correlated and nested subqueries; single and multiple dependent CTEs; CTE reuse; recursive CTEs (hierarchies, category trees, date spines); CTE vs. subquery choice; CTE materialization awareness; LATERAL joins where supported; debugging a CTE pipeline stage by stage.
- Set operations: UNION vs. UNION ALL; column count, order, and type compatibility; INTERSECT; EXCEPT (MINUS in Oracle-oriented material); precedence and parentheses; sorting a combined result; set operations vs. joins and vs. OR.
- Conditional logic: searched and simple CASE; ordered and nested branches; CASE inside aggregation, for numeric bucketing, for standardization, in ORDER BY, and for pivot-style columns; ELSE defaults; unmatched branches returning NULL; CASE with aggregate conditions; short-circuit caveats.

### 2.4 Functions, windows, and missing data (source sections 9–11)

- String functions: length, case conversion, trimming, concatenation, substring and left/right extraction, position-finding, REPLACE, SPLIT_PART, splitting and unnesting, pattern matching and regular expressions, padding, and parsing emails, URLs, and UTM parameters.
- Date and time functions: current date/time anchors; EXTRACT / DATE_PART; DATE_TRUNC; interval addition and subtraction; date differences and age; date construction; parsing text to dates with an explicit format; formatting for export; time-zone conversion; month-boundary logic; incomplete-period awareness.
- Math and general scalar functions: arithmetic and modulo; ABS; CEIL and FLOOR; ROUND and truncation; POWER, SQRT, EXP, LOG; GREATEST and LEAST; safe division with NULLIF; COALESCE for display defaults and for sentinel cleanup; random functions; JSON extraction; array membership and unnesting where supported.
- Window functions: OVER, PARTITION BY, and window ORDER BY; ROW_NUMBER, RANK, DENSE_RANK, NTILE, PERCENT_RANK, CUME_DIST; LAG and LEAD with offsets and defaults; FIRST_VALUE, LAST_VALUE (including its default-frame trap), NTH_VALUE; running totals, counts, averages, minima, and maxima; moving averages with ROWS BETWEEN; RANGE and GROUPS frames; default frame semantics; named WINDOW definitions; filtering on a window result through an outer query or CTE; share of partition total; window functions after grouping; cumulative distinct-count limitations.
- NULL and three-valued logic: NULL as unknown; comparisons with NULL returning unknown; IS DISTINCT FROM / IS NOT DISTINCT FROM; the NOT IN with NULL trap; aggregates and NULL; join keys containing NULL; outer-join-generated NULLs; NULL ordering defaults; unique constraints and NULL; empty string vs. NULL; COALESCE chains; missingness profiling; explicit business rules for what missing means.

### 2.5 Types, writing data, and performance (source sections 12–14)

- Data types and casting: integer, DECIMAL/NUMERIC for money, floating point and approximation, text types, booleans and engine substitutes, DATE, TIME, timestamp with and without time zone, INTERVAL; UUID, binary, JSON, array, and spatial types at awareness level; CAST and the PostgreSQL :: shorthand; implicit-conversion risks; integer-division differences; date-parsing ambiguity; collation; SQLite type affinity and strict-typing differences; read-time generated values vs. stored generated columns.
- Defining and changing data: CREATE SCHEMA and CREATE TABLE; single and composite primary keys; foreign keys and referential actions (RESTRICT, CASCADE, SET NULL); NOT NULL, UNIQUE, CHECK, and DEFAULT constraints; identity/serial/autoincrement keys; generated columns; ALTER TABLE; DROP TABLE; TRUNCATE vs. DELETE; INSERT (one row, many rows, INSERT INTO … SELECT); UPDATE with a restrictive WHERE and UPDATE from another table; DELETE with a restrictive WHERE; upserts (ON CONFLICT, ON DUPLICATE KEY UPDATE, MERGE); RETURNING where supported; views and materialized views; temporary tables; CREATE TABLE AS SELECT; transactions (BEGIN, COMMIT, ROLLBACK) and savepoints; ACID at awareness level; normalization to 1NF–3NF and deliberate denormalization into star schemas.
- Indexes and performance: what an index does and the B-tree mental model; single-column, composite (with column order), unique, partial, expression, and covering indexes; indexes on foreign and join keys; index costs; EXPLAIN and EXPLAIN ANALYZE, and SQLite EXPLAIN QUERY PLAN; recognizing a full scan; join algorithms (nested loop, hash, merge) at awareness level; selectivity and cardinality; planner statistics; sargable predicates; removing unnecessary DISTINCT and sorting; pre-filtering and pre-aggregation; keyset pagination; partition pruning; BigQuery bytes-scanned awareness; before-and-after verification that an optimization preserved the result.

### 2.6 Dialects, analytic patterns, and production checks (source sections 15–17)

- Dialect differences that change real work: identifier quoting and case folding; fully qualified warehouse names; row limiting; string concatenation; case-insensitive matching; boolean representation; date/time, string, division, cast, upsert, changed-row output, recursive CTE spelling, window-function availability by version, FULL OUTER JOIN and set-operation availability, identity generation, JSON and nested data, native pivot support, QUALIFY, temporary and materialized objects, regular-expression syntax, date-spine generation, and error/warning behavior — across PostgreSQL, MySQL, SQLite, and BigQuery, with SQL Server forms recognized in inherited code.
- Analytic patterns: a metric contract before SQL (numerator, denominator, grain, date field, time zone, inclusion rules); source profiling; reconciliation totals; complete time series on a date spine; period-over-period, year-over-year, and rolling metrics; funnel definition, ordered funnels, conversion and drop-off, session-constrained funnels; cohort assignment by first event, retention matrices, and retention denominator control; churn, reactivation, and resurrection flags; exact-duplicate and key-based deduplication with stated survivorship rules; latest record per entity; top-N per group with an explicit tie policy; pivoting and unpivoting; Pareto and cumulative-share analysis; RFM segmentation; basket and attach-rate analysis; distribution and percentile analysis; benchmark comparison; A/B test aggregation; data-quality checks for orphans, duplicate keys, and impossible values; slowly changing status reconstruction; gaps-and-islands; sessionization by inactivity timeout; dashboard-ready output shaping.
- Interview and production-pattern checks (topic list from the source; the hiring-task overlay itself is owned by Wave 2A — see Section 9): nth-highest value, duplicate-key reports, deleting duplicates while keeping one survivor, consecutive-day patterns, adjacent-row comparison, first purchase and latest login, hierarchy aggregation at one level, category leaders, bought-A-but-not-B anti-joins, monthly transaction summaries, conversion rate by cohort, and explaining a query's grain, join logic, filter timing, and edge cases out loud.
- Completion standard (from the source): on an unfamiliar schema, the learner states grain and relationships first; builds a filtered, grouped, joined, and ranked report without fanout or NULL surprises; decomposes a complex question into CTE stages and verifies each stage's row count; produces a complete time series, a funnel, a cohort-retention table, a deduplicated latest-record table, and a top-N-per-group report; creates and safely modifies a constrained table with an idempotent load and rollback; reads an execution plan and proves an optimization preserved the result; and ports a query between PostgreSQL, MySQL, SQLite, and BigQuery while naming every dialect assumption changed.

## 3. Stage 3 — Python for Data Work

Source: `syllabus-python.md`, sections 0–15 plus its cut list. Learners arrive able to think in tables, filters, joins, and aggregations; this stage re-teaches those instincts in code. The source flags explicit bridges from Excel and SQL, and a cut list of widely taught beginner material demoted because working data roles rarely use it at this level.

### 3.1 Foundations (source sections 0–9)

- Setup and notebooks: running Python in the browser with zero install; notebook anatomy (code vs. Markdown cells, top-to-bottom execution, kernel restart); cell state and execution order; saving, sharing, and exporting notebooks; print and last-expression display; local setup (Python, VS Code, Jupyter) as a later optional step.
- Core syntax: variables and assignment; int, float, str, bool, and None; dynamic typing and type(); arithmetic, comparison, and boolean operators; input() and conversion with int(), float(), str(); comments.
- Strings: literals, quotes, and escapes; indexing and slicing; the working method set (strip, lower/upper, replace, split, join, startswith, find, membership); f-strings for formatted reporting; string immutability.
- Conditionals: if/elif/else; nested conditions and when to flatten them; truthiness; ternary expressions.
- Loops and comprehensions: for loops, range(), while loops with an infinite-loop warning, break and continue, enumerate() and zip(), list comprehensions as the stage's central idiom, and dict/set comprehensions in one line each.
- Data structures: lists (indexing, slicing, append, sort, membership); tuples and immutability; dictionaries (get with a default, keys/values/items, building from data) as the structure of JSON and of DataFrame construction; sets (uniqueness, intersection/union/difference); choosing list vs. dict vs. set; sorting with key= and lambda.
- Functions, modules, and packages: def, parameters, return vs. print; default and keyword arguments; scope at recognition level; docstrings and naming; import forms; a standard-library tour for data work (math, statistics, datetime, collections/Counter, random); lambda functions.
- Errors and debugging: reading a traceback bottom-up; the five errors beginners actually meet (SyntaxError, NameError, TypeError, ValueError, KeyError/IndexError); try/except for expected failures; debugging by printing intermediates and isolating cells; explaining an error to an AI assistant with the traceback and failing cell (verification strand in Section 7).
- Files, CSV, and JSON: paths and the working directory; reading and writing text files with open() and with; the csv module at recognition level (pandas does the real work); JSON loading and navigating nested dicts/lists; encoding awareness including mojibake; downloading a file from a URL.
- OOP, the minimum for data work: class and object in one lesson, taught through objects learners already touch (a DataFrame, its methods and attributes); calling methods vs. functions; creating one tiny class with __init__ and one method.

### 3.2 NumPy and pandas (source sections 10–11)

- NumPy: why arrays exist under pandas; creating arrays (array, arange, linspace, zeros/ones, reshape); shape, dtype, ndim; indexing, slicing, and boolean masking; vectorized arithmetic and universal functions including np.where; broadcasting; aggregation axes; random numbers with a seed for reproducible sampling, shuffling, and simulation.
- pandas structures and first contact: Series and DataFrame; building a DataFrame from a dict and from a list of dicts; reading CSV, Excel, JSON, and SQL; the first-look toolkit (head, tail, info, describe, shape, columns, dtypes); writing CSV and Excel.
- Selection and filtering: column selection; loc (labels) vs. iloc (positions); boolean filtering with &, |, ~ and parentheses; isin, between, and query; sort_values; adding, renaming, and dropping columns.
- Grouping and aggregation: groupby as split-apply-combine; agg with several statistics and named aggregations; multiple grouping columns; pivot_table as the reproducible form of the Stage 1 pivot; value_counts; cumulative, rolling, and shifted calculations.
- Combining tables: merge with how= inner/left/right/outer, validate= for relationship checks, and indicator= for diagnosing row changes; concat for stacking files; index join at recognition level.
- Reshaping and tidiness: melt (wide to long) and pivot/pivot_table (long to wide); stack/unstack at recognition level; explode; get_dummies for one-hot encoding; MultiIndex at recognize-and-flatten level only (reset_index), per the source cut list.
- Missing data and types: NaN and pd.NA and why they poison sums and comparisons; isna counts per column; dropna and fillna (value, median, forward-fill) with a decision framework; duplicated and drop_duplicates; astype, to_numeric with coercion, and to_datetime.
- Datetime: parsing on read and with to_datetime; the dt accessor for date parts; date arithmetic and Timedelta; filtering by date range and resample for period rollups.
- Text in columns: the str accessor (contains, lower, replace, split, extract with a simple regex); a working subset of regular expressions only (character classes, quantifiers, groups, anchors).
- Applying functions: apply with a named function and with lambda; map for dictionary-based recoding; the performance rule preferring vectorized methods and np.where/np.select over apply and row loops.

### 3.3 Visualization, workflow, APIs, and automation (source sections 12–15)

- Visualization: figure vs. axes as the one mental model; pandas plotting for a first chart; matplotlib essentials (line/bar/scatter, titles, labels, saving a figure); chart choice by question; seaborn one-liners on tidy data with hue= for grouped comparison; reading a chart critically (truncated axes, chartjunk, misleading bins).
- Workflow skills: virtual environments and pip (taught after the browser phase); requirements.txt; Git and GitHub basics (clone, add, commit, push, pull, reading a diff); reading documentation and help; asking AI tools well and verifying the answer by running it; project organization (data / notebooks / outputs, dated file names); notebook fluency including restart-and-run-all before sharing.
- APIs and web data: what an API is; HTTP request/response and status codes at concept level; requests.get and reading JSON into dicts/lists; query parameters and API keys kept out of shared notebooks; pagination at concept level; json_normalize from response to DataFrame; scraping awareness through read_html for public tables, with terms and ethics, in one lesson.
- Automation and reporting: turning a notebook into a runnable .py script; parameterizing a script at the top; the batch pattern (loop over a folder, clean each file, concat, write one output); scheduled refresh at concept level; automated reporting (Excel/CSV output, a chart image, and a short Markdown/HTML summary in one run); a capstone on one messy real dataset — cleaned with pandas, three charts, one written conclusion, published as a notebook.

### 3.4 Python cut list (from the source, kept as scope decisions)

## 4. Advanced Core, Part 1 — Statistics, Analytics, and Data-Science Foundations

Source: `syllabus-stats-analytics-ds.md`, sections 1–14 (about 120 items). This inventory is the advanced core for every track and the foundation of the Data Scientist track. Items are in dependency order. The source marks with an opening flag the topics where competitors are weakest — typically formula-first, intuition-light, or skipped — including observational-vs-experimental design, base-rate reasoning, correct confidence-interval interpretation, p-value misreadings, survivorship and missing-not-at-random traps, and Simpson's paradox. Those flags are preserved in substance below because they set teaching priority, not extra topics.

### 4.1 Design, description, and visualization judgment (source sections 1–3)

- Data types and study design: categorical vs. numerical, discrete vs. continuous; levels of measurement; observational study vs. experiment; confounders and lurking variables; random assignment vs. random sampling as two different jobs; association is not causation at the design stage; units, rows, and grain; data provenance.
- Descriptive statistics and distributions: frequency and relative-frequency tables; mean vs. median vs. mode and when each misleads; range, IQR, variance, standard deviation; percentiles, quartiles, and box plots; shape (skewness, modality, symmetry); outlier detection plus the keep/remove judgment; z-scores and standardization; the normal distribution and the empirical rule; binomial, Poisson, uniform, and exponential distributions at recognition level; comparing distributions across groups on center, spread, and shape together.
- Visualization judgment: chart choice by question type; what bar, line, scatter, histogram, and box plots are each for; truncated axes, dual axes, and cherry-picked windows; aggregation hiding the story; displaying uncertainty (error bars, bands, sample-size annotation); sorting, labeling, and direct annotation; color discipline including colorblind safety; dashboard vs. exploratory plot.

### 4.2 Probability, sampling, and inference (source sections 4–7)

- Probability foundations: sample spaces, events, addition and complement rules; independent vs. dependent events and the multiplication rule; conditional probability read in both directions; Bayes' theorem as belief updating with base rates first; discrete vs. continuous random variables; expected value; variance of a random variable; law of large numbers at intuition level; permutations and combinations at recognition level.
- Sampling and bias: population vs. sample, parameter vs. statistic; simple random, stratified, cluster, and systematic sampling; convenience and voluntary-response samples; the bias taxonomy (selection, nonresponse, survivorship, measurement); sampling variability and sampling distributions; the Central Limit Theorem, intuition first; standard error vs. standard deviation; sample size and margin-of-error trade-offs.
- Confidence intervals: point vs. interval estimates; correct interpretation of a 95% interval as long-run coverage; intervals for a proportion and for a mean (t-interval); margin of error and what shrinks it; bootstrap intervals for statistics with no neat formula; confidence interval vs. prediction interval.
- Hypothesis testing, taught honestly: null and alternative as competing claims; what a p-value is and the three things it is not; significance level and the Type I / Type II trade-off; power and what raises it; one- and two-sample t-tests, paired vs. independent; proportion tests and chi-square tests; ANOVA at recognition level; multiple comparisons and false discovery; p-hacking, HARKing, and optional stopping; effect size and practical significance alongside the p-value; assumptions, robustness, and non-parametric fallbacks.

### 4.3 Experimentation, causation, and regression (source sections 8–10)

- A/B testing end to end: from business question to one primary metric; primary, guardrail, and vanity metrics; randomization unit and assignment; sample-size and power analysis before launch; minimum detectable effect as a business choice; running discipline (fixed horizon, no peeking, no mid-test changes); sanity checks (sample-ratio mismatch, instrumentation, seasonality, weekday effects); analyzing means and proportions; ratio metrics and the delta method at recognition level; novelty and primacy effects and long-term holdouts; the ship / no-ship decision memo; Bayesian A/B testing at recognition level.
- Correlation vs. causation: the correlation coefficient and its limits; the three rival explanations (reverse causation, confounder, coincidence) as a checklist; spurious correlation and data dredging; Simpson's paradox; the ecological fallacy; regression to the mean; what earns causal language (randomization, natural experiments, difference-in-differences at recognition level, mechanism and dose-response).
- Regression as a thinking tool: slope and intercept as a story; least squares and residuals; R² and its limits; reading coefficients with units and baselines; multiple regression as controlling for other variables; categorical predictors and dummy variables; logistic regression (log-odds, odds ratios, predicted probabilities); assumptions and diagnostics; multicollinearity at recognition level; extrapolation danger; prediction vs. explanation as two goals; overfitting preview and adjusted R².

### 4.4 Analytics craft and communication (source sections 11–14)

- Metrics, funnels, cohorts, and retention: metric design and gaming resistance; north-star vs. input vs. health metrics; rates vs. counts vs. ratios and denominator choice; funnel analysis (step conversion, drop-off, time between steps); cohort analysis separating age effects from calendar effects; retention curves and churn definitions (logo vs. revenue, voluntary vs. involuntary); segmentation including RFM; customer lifetime value, CAC, and the LTV:CAC ratio; seasonality and year-over-year comparison; anomaly triage (data, real, or us — in that order); instrumentation and event taxonomy basics; data-quality checks inside analysis.
- Storytelling and stakeholder communication: starting from the decision, not the dataset; one headline takeaway per chart; narrative structure (context, tension, evidence, recommendation); translating statistical output into business language without losing uncertainty; anticipating hostile questions; documenting method and caveats without burying the answer; agreeing the question and success criteria before analyzing.
- Spreadsheet-to-code workflow: the spreadsheet mental model as the bridge to SQL and pandas; cleaning as a first-class step; reproducibility through scripts and notebooks over manual edits; the analyst's loop (question → extract → wrangle → summarize → visualize → communicate); versioning and documenting an analysis; when to stay in a spreadsheet vs. move to code.
- Fallacies and data-quality capstone checklist: base-rate neglect; survivorship bias; Simpson's paradox in the wild; cherry-picked windows and endpoints; false precision; averaging averages and weighting errors; missing data that is not missing at random; leakage preview; broken tracking and silent schema changes; descriptive summary vs. decision as separate acts.

## 6. Specialized Tracks — Data Engineering, Machine Learning / Deep Learning, Applied AI

Source: `syllabus-de-ml-ai.md` — Part A (Data Engineering, A0–A12, serving the Data Engineer and Analytics Engineer tracks) and Part B (Machine Learning, Deep Learning, Applied AI, B0–B12, serving the Data Scientist and ML/AI Engineer tracks), plus the source's capstone shapes and its hype-vs-fundamentals flags, preserved in substance at the end of this section.

### 6.1 Data Engineering (source Part A)

- A0 Ground rules: what a data engineer owns vs. analysts and data scientists; the data lifecycle (generate → ingest → store → transform → serve); batch vs. streaming as a business decision with a price attached.
- A1 Ingestion: extracting from REST APIs (auth, pagination, rate limits); reading CSV, JSON, Parquet, and Excel defensively; incremental extraction (updated_at watermarks, change data capture at concept level); failure modes (retries, idempotent loads, dead-letter handling).
- A2 Data modeling: entities, keys, and relationships in plain language; normalization (1NF–3NF) and when to break it; dimensional modeling (fact vs. dimension); star and snowflake schemas; slowly changing dimensions (Type 1 vs. Type 2); naming and grain discipline.
- A3 Storage: OLTP vs. OLAP and row vs. columnar stores; data warehouse concepts; data lake concepts (object storage, schema-on-read); lakehouse and open table formats (Delta Lake, Apache Iceberg; ACID, time travel, schema enforcement); file-format trade-offs (CSV vs. Parquet vs. JSON); partitioning and clustering basics.
- A4 ETL/ELT and pipeline design: ETL vs. ELT and why ELT won in cloud warehouses; pipeline anatomy (extract → stage → transform → load → serve); staging layers and the medallion pattern (bronze/silver/gold); full vs. incremental loads, upserts, and merges; backfills and safe reprocessing; idempotency as a design rule.
- A5 Batch pipelines in Python: pandas for pipeline work; connecting Python to databases; structuring a pipeline as small testable functions; logging, configuration, and secrets handling; shell scripting for glue work.
- A6 Orchestration with Apache Airflow: DAG, task, operator, scheduler, executor; writing a first DAG end to end; scheduling semantics (cron, intervals, catchup, backfill); dependencies and sensors; XComs, variables, and connections; TaskFlow API and dynamic task mapping; asset-aware scheduling; retries, SLAs, alerting, and debugging failed runs; DAG versioning and keeping business logic out of DAG files.
- A7 Distributed processing with Apache Spark: why Spark exists; SparkSession, DataFrames, and the Catalyst mental model; transformations vs. actions and lazy evaluation; reading and writing with explicit schemas; joins, aggregations, and window functions in PySpark; shuffle, partitioning, and the classic bottlenecks (skew, spill, shuffle, storage, serialization); Spark SQL; Structured Streaming basics.
- A8 dbt and analytics engineering: the analytics-engineering role and transformation-as-code; dbt project structure (models, sources, seeds, snapshots, macros, profiles); models as SELECT statements with ref() and source(); materializations (view, table, incremental, ephemeral) and their cost trade-offs; layered modeling (staging → intermediate → marts); dbt tests (unique, not_null, accepted_values, relationships, custom tests); documentation and lineage; Jinja and macros; snapshots for slowly changing dimensions; dbt in CI (slim CI, state selection) and deployment jobs.
- A9 Data quality and testing: the quality dimensions (completeness, uniqueness, validity, timeliness, consistency); schema and contract testing at ingestion; freshness and volume anomaly checks; reconciliation checks; quarantine patterns for bad records. The source notes this material is taught scattered across tools almost everywhere, which is why it stands as its own section here.
- A10 Streaming concepts, awareness level: events, producers/consumers, and topics (the Kafka mental model); windowing, watermarks, and late data; exactly-once vs. at-least-once in honest terms; managed streaming services; when streaming is not worth it.
- A11 Cloud platform basics, one cloud done properly: object storage, IAM, and networking vocabulary; the managed warehouse + Spark + orchestration stack on one provider; cost literacy (storage vs. compute, scan-based pricing); infrastructure awareness (reading a simple Terraform configuration).
- A12 Git, CI, and engineering practice: Git workflow for data code; dev/staging/prod environments; CI for data; secrets, per-environment configuration, and reproducible runs; the end-to-end pipeline capstone (API → landing → warehouse → dbt marts → Airflow schedule → quality checks → README).

### 6.2 Machine Learning, Deep Learning, and Applied AI (source Part B)

- B0 Framing: what ML is for (prediction under uncertainty) and what it is not; problem framing (target, unit of analysis, the decision the model feeds); classification vs. regression vs. ranking vs. forecasting; the baseline-first rule; data availability and label-quality audit.
- B1 Workflow and honest evaluation: train/validation/test splits; data leakage (target leakage and train/test contamination), promoted ahead of algorithms in the source; cross-validation (k-fold, stratified, time-based); bias–variance and over/underfitting diagnosis; error analysis before model shopping. Framing and metrics material here is cross-referenced from Section 4 in the build, not retaught as a separate statistics block.
- B2 Metrics per problem type: regression metrics (MAE, RMSE, R²) and when each misleads; accuracy and its failure on imbalanced data; precision, recall, F1, and the threshold trade-off; ROC/AUC and precision–recall curves; the confusion matrix as a communication tool; business-cost framing of errors.
- B3 Supervised learning, core algorithms: linear regression; feature scaling; logistic regression; regularization (L1/L2 in plain terms); decision trees; random forests; gradient boosting (XGBoost/LightGBM class); k-NN and SVM at awareness level; Naive Bayes at awareness level; time-series forecasting basics (trend/seasonality, lag features, honest backtesting by time).
- B4 Feature engineering: missing-value imputation and missingness as signal; categorical encoding (one-hot, ordinal, target encoding and its leakage risk); numeric transforms (log, binning, interactions, ratios); datetime features; mutual information for feature screening; text features at basics level (counts, TF-IDF).
- B5 Unsupervised learning: clustering with k-means (how it works, choosing k, scaling sensitivity); hierarchical and density-based clustering at awareness level (DBSCAN); PCA; dimensionality reduction for visualization (t-SNE/UMAP at awareness level); anomaly detection; recommender systems at user level (collaborative vs. content-based, cold start).
- B6 scikit-learn production patterns: the estimator API (fit/predict/transform) as one grammar; Pipelines and ColumnTransformer; grid/random search with cross-validation without leaking; saving, loading, and versioning model artifacts; class-imbalance handling (class weights, resampling, threshold choice).
- B7 Model interpretation: permutation importance; partial dependence and effect plots; SHAP values at user level; fairness and error-slice checks.
- B8 Intro deep learning: the neuron and the network; forward pass, loss, and backpropagation at intuition level; the training loop (epochs, batches, learning rate); overfitting controls (dropout, batch normalization, early stopping, data augmentation); transfer learning; CNNs at awareness level; RNN/LSTM at awareness level as the history attention replaced; structuring an ML project (single-number metric, human-level benchmark, error analysis by category).
- B9 NLP and transformers at user level: tokenization (subwords; tokens, not words); embeddings and cosine similarity; the transformer idea (attention in plain language; encoder vs. decoder vs. encoder-decoder); using pretrained models through pipelines (classification, NER, QA, summarization); fine-tuning a small pretrained model; the classical baseline that still matters (TF-IDF + logistic regression). Where this overlaps the AI-era layer, Section 7 owns the assistant-and-verification treatment and this section owns the modeling treatment.
- B10 LLM application skills: calling LLM APIs (messages, temperature, structured/JSON output); prompt engineering treated as code (instructions, few-shot, delimiters, guardrails; versioned and tested); embeddings and vector databases (chunking, indexing, similarity search); RAG end to end (retrieve → ground → cite → abstain); LLM evaluation (golden datasets, rubric and LLM-as-judge, regression-testing prompts); the fine-tuning vs. RAG vs. prompting decision order (prompt first, RAG second, fine-tune last); agents and tool use at user level (function calling, human-in-the-loop); cost, latency, and safety basics (token budgets, caching, PII redaction, prompt-injection awareness); LLMOps at awareness level. The concept-level treatment of RAG and agents for all learners sits earlier, in Section 7; this section is the build-level treatment for the ML/AI track.
- B11 MLOps basics: experiment tracking; reproducibility (seeds, data versions, environment pinning); model packaging and serving concepts (batch scoring vs. REST endpoint); monitoring and drift (data drift vs. concept drift); retraining triggers and rollback; CI/CD for models at concept level (data and model quality gates).
- B12 Capstone shapes (from the source): an ML exit artifact (one tabular model taken from framing through a leakage-safe pipeline, tuning, explanation, and packaging with a model card — or one RAG application with an evaluation set and a written cost/latency budget); an Analytics Engineering exit artifact (a dbt project, staging to marts with tests, docs, and CI, on warehouse data, orchestrated by Airflow); a DE exit artifact (the A12 end-to-end pipeline with a design note defending its batch/streaming, ETL/ELT, and modeling choices).

This is the thinnest inventory in the package, and this section says so plainly rather than implying coverage that the sources do not contain. ### 8.1 What the syllabus files actually contain

These are taught as models to frame, evaluate, and explain — not as algorithms to implement from scratch.
- **Sorting and searching as used operations** (`syllabus-python.md`, sections 4–5; `syllabus-sql.md`, sections 3 and 14): sorting with key= and lambda; sorting and ranking in SQL (ORDER BY, ranking window functions); predicting sort and join costs at the level of the SQL performance topics (join algorithms — nested loop, hash, merge — at awareness level; index and B-tree mental models). The operation is taught; implementing a sort is not.
- **Data-structure choice as judgment** (`syllabus-python.md`, section 5): lists, tuples, dictionaries, and sets, choosing the right structure for a task, and set operations for membership questions. Structures are consumed through Python and SQL, not implemented.

- **Explicitly cut from the core path** (`syllabus-python.md`, cut list and sections 4–5): hand-implementing linked lists, stacks/queues, and binary trees; hand-implementing sorting algorithms (the source names merge sort by hand); and nested-loop algorithm drills and pattern printing. The source classifies all of these as computer-science-track material with near-zero use in analyst and scientist day work, valuable for software-engineering interviews rather than for this path.
- **Interview algorithm patterns in pandas form** (cross-reference only): Wave 2A owns the interview layer, including the finding that data-role Python rounds are largely SQL patterns translated into pandas, judged on vectorized code. Those patterns attach to Sections 2 and 3 of this file as an assessment overlay; they are not a separate algorithm topic list.

### 8.2 Scope decision for Data From Zero

**[Recommendation — explicit scope decision, stated here because the sources leave the gap open]**

1. The core path (Stages 1–3, advanced core) teaches algorithmic thinking in context only: choosing a data structure, stating grain before computing, preferring vectorized and set-based operations over row loops, reading a join or sort cost at awareness level, and recognizing when a problem's size changes the right tool (spreadsheet → SQL → pandas → Spark, in the order the path itself teaches them). No Big-O formalism beyond that size intuition, and no from-scratch implementation of sorting, searching, or classic data structures, is required in the core path.
2. The ML/AI track teaches algorithm families as models (Section 6.2), with evaluation and leakage discipline as the graded core — not algorithm implementation.
3. A standalone algorithms and complexity module — formal complexity notation, sorting and searching implementations, classic data-structure implementations, and software-engineering interview patterns — is **out of scope for this inventory and for the current build**. If it is ever added, it belongs as a separate optional computer-science track, consistent with the Python source's cut list, and it must be commissioned as its own inventory rather than inferred from this file.
4. Builders must not present Data From Zero as covering a general algorithms curriculum. Any page, roadmap node, or marketing line implying one exists would be inventing coverage the research does not support.
