## How Competitors Teach Python for Data — Research Report

**Purpose.** The Python stage's structure is locked (27 lessons, issue #61); what is not decided is how each lesson teaches — its hook, explanation, visuals, internal order and exercises. This report studies how the best competitors teach the same material, lesson by lesson, so the team's own lessons can copy what works, avoid what fails, and be clearly better where everyone is weak. Our fixed lesson shape (same as the live SQL stage): The question → Warm-up (recall) → The big idea → Learn by doing (Idea, Try it, Predict, Result, Why) → Finish it → On your own → Check yourself. Lessons are static pages; code runs in a linked Colab notebook. Learners are Vietnamese career switchers who read English, many on phones and slow networks.

**Method.** Five research lines, all sources opened 2026-11-19: (A) Kaggle Learn + official pandas docs; (B) DataCamp + Dataquest; (C) Codecademy + freeCodeCamp + Google + W3Schools; (D) Real Python + McKinney's *Python for Data Analysis* 3rd ed. (open edition) + CS50P as the developer-style contrast; (E) Vietnamese sources, Excel/SQL bridging, and learner-voice evidence from named review sources. Working files: `cluster-a-kaggle-pandas.md` … `cluster-e-vietnamese-bridging-voice.md` in this folder. Paywalls are noted per source in §5; where a platform's lessons could not be opened, findings are labelled outline-level.

**How to read the labels.** Unmarked statements are findings from the named sources. Statements marked **[Recommendation]** are design choices for Data From Zero, not findings. Claims about learner behaviour appear only with a named source; no platform in this study publishes trustworthy completion rates, so none are reported anywhere in this report.

**Confidence.** High for platform mechanics, lesson structures and explanation devices (primary pages opened). Medium for learner-voice generalisations (review sources are self-selected samples; figures quoted are the sources' own, named inline).

## 1. The 10 most useful findings

**1. Predict-first is the strongest opening move in the field — but its best user assumes you can already code.** Kaggle's Python Lesson 1, "Hello, Python," shows a complete, silly program (ordering Monty Python Spam), hides its output, and makes the learner predict what it does before any syntax is taught; the same program is then unpacked line by line. The move is perfect for our Predict step. The catch: the lesson's own intro redirects true beginners elsewhere, and that one lesson carries roughly a dozen concepts. [Recommendation] Take the move, drop the assumption: our first lesson predicts the output of a tiny café program, then unpacks only 3–4 concepts.

**2. The boolean mask is the hardest idea in early pandas, and every good teacher prints it alone before using it.** The pandas intro tutorials run the condition by itself, show the True/False Series at full length, and only then put it inside the brackets to filter; Real Python's DataFrame tutorial does the same in prose, stating exactly which row labels come out True before filtering. Micro-lessons that jump straight to `df[df.x > 5]` skip the one step that makes the mechanism visible. Our SQL bridge makes this step doubly valuable: SQL's WHERE hides the mask; pandas shows it.

**3. groupby clicks when it is entered through an object the learner already owns — and three different doors work.** Kaggle enters through `value_counts()` ("value_counts is just a shortcut" for a groupby). DataLemur's GROUP BY lesson enters through the spreadsheet: build the real PivotTable first, map its "rows" box to the grouping, then show the matching output. McKinney enters through a named way of thinking — split-apply-combine — and proves the split is real by showing the GroupBy object computes nothing until a method is called. [Recommendation] Use all three doors in sequence in one lesson: PivotTable recall in the Warm-up, split-apply-combine as the big idea, `value_counts()` revealed as a groupby in the first exercise.

**4. Value-based checking with specific feedback is the gold standard — and it still fails in two documented ways.** Kaggle's open-source learntools binds per-question checkers into the exercise notebook; learners fill `____` blanks and run `qN.check()`, which inspects the actual values of their variables and replies with expected-vs-actual messages, not a bare wrong. But Kaggle's own forums document (a) progress-not-registering failures whose recurring cause is out-of-order cell execution and stale notebook state, and (b) at least one checker false-pass (Pandas "Summary Functions and Maps" Q7 passes even when a required condition is ignored, because the checker samples cases the wrong logic happens to satisfy). [Recommendation] Our Colab self-checks need three defences: a run-everything-from-the-top ritual, printed expected outputs on the static page (checking that works even if the notebook state is lost), and at least one adversarial case per trap — duplicate keys, a missing group key — so wrong code cannot pass by luck.

**5. Hints must be free, layered and boring to use.** DataCamp charges for help: hints and solutions deduct from the exercise's XP (its own FAQ/support pages document the mechanic), and review sources name it among the most resented features. Kaggle's pattern costs nothing and ports directly to Colab: each question ships with commented-out `qN.hint()` and `qN.solution()` lines the learner uncomments when stuck. Dataquest offers per-screen hints plus an AI tutor with no documented cost. [Recommendation] Adopt Kaggle's pattern verbatim in spirit: every notebook exercise carries a collapsed hint and a collapsed solution, free, with the lesson page's Check yourself section as the no-notebook fallback.

**6. The environment jump is where platforms either design an exit or build a trap.** Dataquest designs the exit early: course 3 of its analyst path contains a "Learn and Install Jupyter Notebook" project, guided projects run in-platform or locally, and datasets are downloadable for portfolios. DataCamp never lets go — courses, projects and its own notebook product stay in-platform, and course datasets generally cannot be downloaded, so learners report building separate projects outside for job applications (Dataquest's comparison, reporting learner accounts). Google's Colab welcome notebook has the best single onboarding move — a text cell that names the medium ("the document you are viewing is not a static webpage but an interactive environment") followed by one tiny pre-written arithmetic cell — but the notebook itself is advanced-skewed, sits behind a first-sign-in popup, and is unsaved by default (cluster C, via a screen-reader course reproducing it cell by cell). [Recommendation] Ship our own three-cell starter notebook in the project Drive folder (per issue #61's storage rule) instead of linking to Google's welcome notebook.

**7. Bridging from Excel/SQL is the field's open lane — and the honest bridge pattern is "match, then diverge."** The pandas docs bridge deliberately (a full Comparison with SQL page laid out SQL-first; a Comparison with Spreadsheets page that rebuilds a PivotTable in `pivot_table`; Tutorial 01's annotated table redrawn as a spreadsheet screenshot). Kaggle, in the materials opened, never bridges to spreadsheets or SQL at all — its anchors are its own earlier lessons. The bridge device that survives scrutiny is DataLemur's: perform the familiar action first, show the new output matching it, then immediately demo the one place the outputs diverge. The most misleading popular analogy is VLOOKUP → merge: VLOOKUP returns the first match, one column, case-insensitively, and errors on a missing key; merge returns every match (duplicate keys silently multiply rows), all columns, case-sensitively, with NaN for missing keys. The honest VLOOKUP twin is `Series.map()`. [Recommendation] Every Python lesson bridges to a named earlier Excel or SQL lesson — a move no competitor can copy, because none of them owns the learner's previous stage — and every bridge ends with its divergence demo.

**8. The most repeated learner complaint in every review source is over-guidance.** Across G2, Trustpilot, Reddit accounts quoted in comparisons, and Codecademy/Kaggle review pages, the same sentence recurs in different words: fill-in-the-blank exercises are so guided that learners finish courses without ever writing code from a blank cell, and hit a wall when the scaffolding stops. DataCamp's version is the sharpest (blanks that name the function to use exercise syntax recall, not problem-solving). [Recommendation] Our Finish it and On your own sections must include blank-cell tasks from the first pandas lesson onward — same result, empty cell — not only at the capstone. This is the cheapest differentiation available: it costs nothing but nerve.

**9. Winners publish minutes and keep one theme per sitting; density is the beginner-killer.** DataCamp's model is 4 chapters × ~1 hour, one concept per video with 3–4 exercises after it (its pandas course: 15 videos, 56 exercises, 4 hours). Dataquest publishes per-lesson minute estimates but lets a "lesson" run to 81 minutes — the anti-pattern for phone learners. Kaggle's stated totals (~5 h Python, ~4 h Pandas) hide ~12 concepts in lesson 1. [Recommendation] Enforce a budget of 3–4 new concepts per lesson, print a minutes estimate on every lesson page, and state the stage's honest total time on the stage page rather than implying Kaggle pace.

**10. The Vietnamese lane is empty, and our dataset holds a lesson nobody else can teach.** Free Vietnamese Python teaching (HowKTeam) is developer Python with no pandas; every Vietnamese pandas course found (MindX, 200Lab, Datapot, MCI, FUNiX, BAC, ZendVN) is paid, and MindX gives away only the roadmap — Excel → SQL → Power BI → Python, the same order as ours — while the pandas lessons sit inside the paid program. Meanwhile no competitor at any price teaches Vietnamese text traps: café product names stored in different Unicode normalisations (NFC vs NFD) that look identical and do not match in a filter, groupby or merge until normalised (issue #61, trap list). [Recommendation] The text-cleaning lesson built on that trap is a signature lesson: it is only teachable on Vietnamese data, and we are the only ones holding it.

## 3. Visual and exercise ideas — described in words, ours to draw

All visuals below are original designs for the café dataset, specified in words only. They follow the visual-teaching rules already adopted in issue #58: stepped statics as the default (learner-paced frames, every step stays on the page, predict-before-reveal), learner-controlled stepper animation only for window functions and recursive CTEs, no autoplay loops, no Venn diagrams for joins.

### Visuals

1. **The annotated café table.** A small café orders table drawn as a grid; the column-name band shaded one colour, the row-label band a second, the data cells a third — the same three-region idea the field's best diagrams converge on, drawn on our data with our labels. Used in `dataframe-first-look`, reused silently in every later lesson's tables so the regions stay familiar.
2. **The mask, in three frames.** Frame 1: the café table. Frame 2: the same table with one extra column beside it holding True/False for a stated condition, the True rows tinted. Frame 3: only the tinted rows remain. The learner predicts frame 3's row count before revealing it. Used in `pandas-select-and-filter` and echoed in `conditionals`.
3. **Split, apply, combine — three panels.** Panel 1: the café orders table. Panel 2: the table separated into per-store piles, one pile shown with its sum being computed inside it. Panel 3: the piles' results stacked into a small summary table. A fourth, trap panel shows the pile whose key is missing, set aside with a question mark — its fate is the lesson's Predict question. Used in `pandas-groupby-aggregate`.
4. **The merge flow.** Two café tables side by side (orders, prices), the shared key column banded in the same colour on both, arrows showing price columns flowing into matching order rows, and beneath, the shape arithmetic as a caption: rows before → rows after, with the expected count stated before the code runs. A variant frame shows one duplicated price row and the doubled order rows it creates. Used in `pandas-merge-and-validate`.
5. **The wide–long round-trip strip.** One café monthly-sales table in three states on a single horizontal strip: wide (months as columns), long (one row per store-month), wide again — with the middle state annotated "this is the shape databases and pandas prefer, and here is why." Used in `pandas-reshape-wide-long`.
6. **The sliding paper strip.** A column of daily café sales drawn as a vertical strip; a translucent window band covering three days slides down one row per frame, the window's average recomputed in each frame. Stepped static by default; this is one of the two concepts issue #58 reserves for a learner-controlled stepper. Used in `pandas-transform-rank-rolling` (with `shift` drawn as the same strip offset by one row, beside its SQL LAG twin).
7. **Figure anatomy.** One finished café bar chart with its parts labelled by leader lines: figure, axes, title, axis labels, ticks — drawn once, referred to by name in both chart lessons. Used in `charts-matplotlib`.
8. **Honest vs misleading.** The same café weekly sales drawn twice: once with a zero-based axis, once with a truncated axis and a cherry-picked week range, the visual lie circled. Used in `charts-seaborn` as the closing judgement exercise.
9. **The traceback, dissected.** A real (planted) error output from the café notebook, drawn with the last line boxed and labelled "start here," the file/line references labelled "where," and the learner's own code line labelled "the line that was running." Used in `errors-and-debugging`.
10. **The environment map.** Three boxes — Colab (where lessons run), Drive (where notebooks live), your computer (visited in `environments-and-pip`) — with arrows showing which direction files travel at each stage of the roadmap. Used in `first-notebook` and `environments-and-pip`.

### Exercise ideas

1. **Predict the output (before any Run).** Borrowed from Kaggle's opening move and generalised: every Learn-by-doing unit shows code and its *hidden* result; the learner commits to a prediction (in the notebook, a multiple-choice or typed guess) before the result is revealed. Our lesson shape already has the Predict slot — the finding is that it should carry marks, not just attention.
2. **Inspect the mask.** Before filtering, the learner states in plain words which rows will be True (or counts them). Checked against the printed mask. The exercise that makes finding 2 stick.
3. **Predict the row count.** Before every merge and concat, the learner writes the expected output row count and one reason. Checked against `.shape` after running. Converts the merge traps from surprises into tests.
4. **Adversarial trap cases.** Each trap in issue #61's list gets one exercise case designed so the naive answer is wrong: duplicate keys in a merge, a missing group key in a groupby, NFD-normalised names in a filter, `!=` keeping NaN rows. Directly answers the documented learntools false-pass failure.
5. **Escalation pairs.** Kaggle's pattern of a question and its harder twin (its 3a/3b expression-editing pair, with a 🌶 marker for the spicy variant): a base exercise, then the same task with one constraint added. Cheap to author, honest about difficulty.
6. **Blank-cell rewrite.** The anti-over-guidance exercise (finding 8): "produce this exact result again — the cell below is empty." Appears from the first pandas lesson onward, growing in length.
7. **Known-answer self-checks on the page.** CS50P's copyable core is private, instant, repeatable checking before any official moment. Our static equivalent: every exercise prints its expected output on the lesson page (in the Check yourself section), so a learner can verify with no notebook state at all — the direct defence against the out-of-order-execution failure Kaggle's forums document.
8. **Meet the error on purpose.** Exercises that *assign* the error: load this file and produce a UnicodeDecodeError, then fix it; run these cells out of order, watch the NameError, then establish the from-the-top ritual. Named after Kaggle's error-named lesson titles.

## 4. Weak spots the field leaves open (summary for the brainstorm)

For the owner's brainstorm, the gaps most worth exploiting, in order of leverage: (1) blank-cell production vs fill-in guidance (finding 8 — every competitor is weak here); (2) the Excel/SQL bridge owned end-to-end, with divergence demos (finding 7 — only the pandas docs bridge at all, and not to a curriculum the learner actually took); (3) merge validation and adversarial checking from lesson one, not as an advanced topic (findings 4–5, lesson table); (4) the Vietnamese text trap as a signature lesson (finding 10 — uncopyable); (5) a designed environment exit (finding 6 — only Dataquest bothers); (6) honest pacing — minutes printed, concept budget enforced (finding 9).
