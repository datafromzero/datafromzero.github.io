# cafe-sales

A fictional chain of three cafes in the San Francisco Bay Area, with six months of orders
(January 1 to June 30, 2026). The same data is used in Excel, SQL and Python, so you can answer
one question in every tool and compare the results.

The data is **synthetic**: it was generated by a script, and no row describes a real person or a
real business. Prices are in US dollars and cents.

## Files (version 1)

| File | Rows | One row is |
|---|---:|---|
| `v1/stores.csv` | 3 | a store |
| `v1/customers.csv` | 150 | a loyalty-program customer |
| `v1/products.csv` | 16 | a menu item |
| `v1/orders.csv` | 1,800 | an order (one visit to the till) |
| `v1/order_items.csv` | 3,287 | one product line inside an order |
| `v1/cafe-sales.xlsx` | | all five tables, one sheet each (Excel and Google Sheets) |
| `v1/cafe-sales.sql` | | a DuckDB script that creates and fills the five tables |

Row counts do not include the header row. The CSV files are UTF-8, comma-separated, with a header
row. An empty field means the value is missing (NULL).

## Columns

### stores

| Column | Type | Meaning |
|---|---|---|
| `store_id` | integer | Key of the store |
| `store_name` | text | Short name used by staff |
| `city` | text | City of the store |
| `opened_on` | date | Day the store opened |

### customers

| Column | Type | Meaning |
|---|---|---|
| `customer_id` | integer | Key of the customer |
| `signup_date` | date | Day the customer joined the loyalty program |
| `city` | text | Home city |
| `loyalty_tier` | text | `bronze`, `silver` or `gold` |
| `referred_by` | integer | `customer_id` of the customer who referred them; empty if nobody did |

### products

| Column | Type | Meaning |
|---|---|---|
| `product_id` | integer | Key of the product |
| `product_name` | text | Name on the menu |
| `category` | text | `coffee`, `tea`, `bakery` or `food` |
| `unit_price_usd` | decimal | Price of one unit, in US dollars |

### orders

| Column | Type | Meaning |
|---|---|---|
| `order_id` | integer | Key of the order; rises with time across all stores |
| `customer_id` | integer | Who ordered; empty for a walk-in customer without a loyalty card |
| `store_id` | integer | Where the order was taken |
| `ordered_at` | timestamp | Date and time, `YYYY-MM-DD HH:MM:SS`, local time |
| `status` | text | `completed` or `canceled` |
| `payment_method` | text | `card`, `mobile` or `cash` |

### order_items

| Column | Type | Meaning |
|---|---|---|
| `order_item_id` | integer | Key of the line |
| `order_id` | integer | The order this line belongs to |
| `product_id` | integer | The product sold |
| `quantity` | integer | Units sold |
| `discount_usd` | decimal | Discount on the whole line, in US dollars |

The amount of a line is `quantity × unit_price_usd − discount_usd`.

## Built-in surprises

Real data is never clean, so a few rows are odd on purpose. Lessons point to them when they matter.

- One walk-in order has no `customer_id`.
- One order is `canceled`; it is the only order of its customer.
- One line has a quantity of 20 where 2 was meant (an extra zero), which makes one day look huge.
- The Harbor store opened on April 1, 2026, so it has no orders before April.
- One product (Pumpkin Spice Latte) was never sold in this period.
- Some products share a price, so rankings by price have ties.
- Five customers signed up but never ordered.
- About one customer in five was referred by another customer.

## How it was made

`scripts/build-cafe-sales.py` generates every file from a fixed random seed, so running it again
gives the same rows. `python3 scripts/build-cafe-sales.py --check` confirms that the CSV files match
the script. It needs Python 3.10 or later, and openpyxl 3.1 for the `.xlsx` file.

A released version never changes. A change to columns or values creates a new folder (`v2/`), and
`v1/` stays as it is, so old notebooks and spreadsheets keep working.
