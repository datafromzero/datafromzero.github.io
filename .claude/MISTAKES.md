# Mistakes log

Every mistake the team has made once, and the rule that stops it happening again. **Read the sections for your
work before you start. Whoever finds a new mistake (a review finding, a red CI run, an owner correction) adds it here
in the same PR**: one line for what happened, one line for the rule. If the same mistake shows up twice, the rule
was not strong enough: make it a check in a script, the standard or the agent brief. Already automated in
`npm run check:lessons` (part of `npm run check`): British spellings, first-person notes outside `TODO(owner)`, a bare
`$` in SVG, and `datasets` naming a missing folder. Add a rule there whenever a mistake can be caught mechanically.

Lesson-writing rules also live in `.claude/agents/LESSON-STANDARD.md` (the standard says *what to do*; this log says
*what went wrong*). Format: `date — what happened` → **rule**.

## Git and process (lead)

- 2026-11-17 — A new cloud environment had git user "Claude"; the first commit was authored by it.
  → **Before the first commit in a session, run `git config user.name`; it must be `johnha912`
  (`johnha912@users.noreply.github.com`).** Fix with `git config` and amend only your own unpushed or own-branch commits.
- 2026-11-17 — The GitHub tool appended a "Generated by" footer to a new PR body. → **Update the PR body right after
  creating it.**
- 2026-11-17 — Wrote "he" for the owner in CLAUDE.md. → **Refer to the owner as "the owner"; never assume pronouns.**
- 2026-11-17 — Screenshots landed in the repo root because the shell's working directory had reset, and `git add -A`
  staged them. → **Write scratch files to the scratchpad with absolute paths; read `git status --short` before every
  `git add -A`.**
- 2026-11-17 — A check left the shell inside an agent's worktree; the stop hook then asked to commit that agent's
  half-finished work. → **Never `cd` into `.claude/worktrees/`; inspect them with `git -C <path>` or absolute paths, and
  never commit an agent's work in progress.**
- 2026-11-17 — An agent's worktree started from an older commit than the brief assumed (missing a refactor). →
  **Commit everything an agent needs before spawning it, and put the expected base commit in the brief; the agent
  fast-forwards to it first.**
- 2026-11-17 — The owner pasted a raw Google Analytics `<script>` snippet. → **Never paste third-party scripts; use the
  existing mechanism (SPEC §11: `GA_ID` and `GA_RETENTION` in `src/site.ts`).**
- 2026-11-17 — Reported "done" without a link; the owner did not know where to look, and expected unpublished drafts
  to be on the site. → **Every "done" ends with a link the owner can open: the live URL once deployed (merge when
  allowed, wait for the deploy, open the page), or a preview (a PDF or screenshot sent as a file) for anything not on
  the site yet. Say plainly when something is not live and why.**
- 2026-11-17 — Asked to stop the "Learn" button duplicating Start here on the start page, the lead changed the button
  on every page; the owner wanted the homepage to keep pointing at Start here. → **Change only the page or element
  the owner named; when a fix would change other pages, say so and ask first.**
- 2026-11-17 — A single PR mixed a mergeable change with one waiting for the owner. → **Split them: what the lead may
  merge goes in its own PR first; lesson content and SPEC decisions wait in theirs.**

- 2026-11-17 — The homepage had no `og:image`; after the author avatar was added, chat apps used the avatar as the
  link preview. → **Every page declares `og:image` (`OG_IMAGE` in `src/site.ts`); after adding an image to a page, check
  the link preview.**

## Repo tooling and checks

- 2026-11-18 — A commit and push ran after `npm run check` failed (a description over 160 characters), because the
  commands were joined with `;`. → **Join check, commit and push with `&&`, so nothing is committed after a failed check.**

- 2026-11-17 — Editing `.claude/HANDOFF.md` made CI fail on a stale knowledge graph. → **After changing any `.md`, SPEC,
  CLAUDE.md, `src/`, `scripts/` or config, run `npm run kb`, then `npm run check`, before committing.**
- 2026-11-17 — Sorting `project-words.txt` rewrote 85 lines. → **Append new words at the end; never re-sort.**
- 2026-11-17 — Rewriting `package.json` with a JSON serializer reformatted the whole file (99 lines). → **Edit
  config files with a one-line text edit; check `git diff --stat` shows only the lines you meant.**
- 2026-11-17 — A changelog entry quoted the literal owner-placeholder marker; `/changelog/` is a deployed page, so the
  placeholder gate failed. → **Never write the placeholder marker in CHANGELOG.md or any published page; describe it.**
- 2026-11-17 — A merge left two `### Changed` headings under `[Unreleased]` (markdownlint MD024). → **Add a changelog
  entry under the existing heading of its kind; never create a second one.**
- 2026-11-17 — A measurement ID failed cspell. → **For an identifier in code, use `// cspell:disable-line`; for a real
  word, append it to `project-words.txt`.**
- 2026-11-17 — The knowledge graph and cspell indexed the agents' worktrees (graph doubled to 1,565 nodes). → Fixed in
  `scripts/kb.mjs` and `cspell.json`. **Any new scanner must skip `.claude/worktrees/`.**
- 2026-11-17 — A symlinked `node_modules` in a worktree made every fixture test fail. → **In a worktree, run `npm ci`;
  do not symlink `node_modules`.**
- 2026-11-17 — A PDF preview showed the header, the table of contents, the consent banner and the taskbar over the
  text. → **For previews, remove fixed and sticky elements and open only the `<details>` inside `.sl-markdown-content`.**

- 2026-11-17 — The taskbar script assumed an element that one page variant never rendered (project pages with the
  table of contents off), so it would throw there. → **Every element a script queries must exist on every kind of
  page (homepage, lesson, project page with `tableOfContents: false`); take section lists from `headings`, not `toc`;
  load each variant once with the console open before merging.**

- 2026-11-17 — A copied Starlight rule `#starlight__search input:focus { outline: none }` (an ID selector) silently beat
  our class-level `:focus-visible` ring, so keyboard users lost the focus ring. → **Match the specificity of the rule you
  override, and Tab to every new focus style in a browser before merging.**

- 2026-11-17 — The consent card used plain class names (`.card`, `.head`); the homepage's own `.card` rule gave it a
  340px minimum height. → **A component that renders on the homepage and on docs pages prefixes its classes (for
  example `dfz-c-`), and is checked on both before merging.**
- 2026-11-17 — The floating consent card had no height limit; with Customize open on a landscape phone its top went
  off screen. → **Every fixed or floating overlay gets a `max-height` inside the viewport and its own scrolling; check
  it at 320×256 (400% zoom) with every panel open.**
- 2026-11-17 — The consent banner sits inside Starlight's `<main>`, so search indexed its text on every page. → **Anything placed in Starlight's `<main>` (Banner, PageTitle, Footer overrides) that is site chrome
  carries `data-pagefind-ignore`; after the build, read one file in `dist/pagefind/fragment/`.**

- 2026-11-18 — Long formulas in a table cell did not wrap, so on phones the other columns shrank to one letter per line
  (E4, E5, E7, E13, E21; reported by the owner). Fixed in `tokens.css`. → **Load every page with a table at 390 px
  before publishing; nothing in a cell may be narrower than a word.**

## Datasets and generated files

- 2026-11-17 — Order ids did not rise with time across stores. → **Generate events in time order, then assign ids.**
- 2026-11-17 — The "outlier day" was not visible (273 vs 272). → **After rigging a surprise, query it and confirm it
  stands out the way the README says.**
- 2026-11-17 — A placeholder loop was left in the generator. → **Reread your own generator before committing; no
  dead code.**
- 2026-11-17 — `.xlsx` files changed on every rebuild (openpyxl stamps the save time). → **Every generated binary must
  rebuild byte-identical (`scripts/stable_xlsx.py`); check with two builds and `md5sum`.**
- 2026-11-17 — `strftime("%-d")` works only on glibc. → **Use portable formatting (`f"{day.day}"`).**
- 2026-11-17 — Two batches reported different "total sales" (\$22,749.25 vs \$22,754.25). → **Every total names its
  rows: completed orders only, or all 1,800 including the canceled \$5.00 order.**

## Lessons (details in LESSON-STANDARD.md)

- 2026-11-17 — Text said "on the left / on the right" but the content stacks. → **Never describe layout by position;
  say "first / below".**
- 2026-11-17 — A wide side-by-side SVG was unreadable on phones. → **At most two stacked 360-wide SVGs.**
- 2026-11-17 — Windows shortcuts without the Mac version. → **Every shortcut names both.**
- 2026-11-17 — `reviewed` was set before the owner reviewed. → **The owner sets `reviewed` when publishing; drafts keep

- 2026-11-17 — Exercises overwrote the worked example's cells or output, in every batch. → **One pre-built sheet per
  exercise (`calc_ex1..3`).**
- 2026-11-17 — Solutions edited `raw_*` sheets. → **Raw data is never edited, also in solutions.**
- 2026-11-17 — Filters hid summary cells placed beside the table. → **Summaries go above the data or on another sheet.**
- 2026-11-17 — First-person research notes ("I could not find…", "checked as SQL") in learner text. → **Those go in
  `TODO(owner)` only.**
- 2026-11-17 — Unsourced app behavior stated as fact (Sheets `#SPILL!`, Excel showing 181 day rows, Sheets filter
  "between"). → **Open the official page or move the claim to `TODO(owner)`.**
- 2026-11-17 — A ranking used the wrong payment method; an answer depended on the extra-zero typo; a relative
  conditional-format rule was explained wrongly. → **Recompute every answer by script, including rankings, and say
  whether figures include order 2075.**
- 2026-11-17 — SVGs showed codes and results that are not in the data. → **Draw pictures from the real rows.**
- 2026-11-17 — A quote was not the source's wording. → **Exact quotes or no quote marks.**
- 2026-11-17 — A frontmatter `datasets` value named a dataset that does not exist (the build does not catch it). →
  **`datasets` lists only folders in `datasets/`.**
- 2026-11-17 — A lesson used functions taught later without the prerequisite. → **Add the prerequisite when a lesson
  relies on another lesson's skill.**
- 2026-11-17 — "greyed" in a lesson. → **American English; grep for -our, -ise, grey, cancelled.**
- 2026-11-17 — MDX read `$…$` as math and `*` in SVG text as emphasis. → **`\$` in prose, `&#36;` and `&#42;` in SVG.**

- 2026-11-18 — The SQL model lesson draft had 3,372 body words for a 20-minute lesson (about twice the Excel model).
  → **Count body words before reporting; a 20-minute lesson is at most about 2,200 words including exercises, and the

- 2026-11-18 — After the SQL stage was reordered, S18 still listed only its old prerequisites and missed the S4 and S7

- 2026-11-18 — SQL drafts cited SQLite's documentation for how DuckDB ranks `AND` over `OR` and `*` over `+`, and for
  integer division. → **Cite only the engine the lesson runs (DuckDB). A standard-SQL rule is shown by the results in the
  steps and called "standard SQL"; the missing DuckDB page goes in `TODO(owner)`.**

- 2026-11-18 — A Check yourself answer was cut off and followed by a line `XX`; every check passed because tests only ran
  the SQL. → Automated in `check:lessons` (placeholder lines and bare TODO).
- 2026-11-18 — SVG row highlights drifted two rows, and an Expected line gave away the count the learner was asked to
  predict. → **Check each highlight's y against the row grid; after "Before you run it: how many…", Expected gives
  only the columns.**
- 2026-11-18 — Results like `-nan` and `inf` depend on the DuckDB version Colab installs. → **SQL notebooks pin
  `duckdb==2.0.0` (`scripts/pin-notebook-duckdb.py`).**
- 2026-11-18 — A planned objective said a SELECT alias "cannot be used in WHERE", but DuckDB 2.0.0 accepts it for plain
  expressions (its Friendly SQL page lists it). → **Run every behavior claim in a stub's objectives on the engine the
  lesson uses before teaching it; teach the running order, name what other databases do from their docs, and report the
  objective wording.**

- 2026-11-18 — One quantity was counted two ways in sibling lessons (Harbor open 90 vs 91 days). → **Keep one counting
  convention per quantity across lessons, or name both.**

- 2026-11-18 — Notebook cells that error on purpose (fix-the-query exercises, error demos) would stop Colab's Run all.
  → **Run `scripts/wrap-notebook-error-cells.py`; it wraps every erroring cell in try/except.**
- 2026-11-18 — Parallel writers used the same file names in the shared scratchpad and overwrote each other's test
  scripts. → **Each agent works only in its own scratchpad subfolder (`scratchpad/batchX/`, `scratchpad/revX/`).**
- 2026-11-18 — A predict-first exercise named the surprise in its own question ("why is January so large?"). → **The

- 2026-11-18 — The normalization lesson called a split "2NF" while naming a one-column key, which cannot have a 2NF
  violation. → **Label each normalization step by the dependency it removes, checked against the key the lesson names
  (2NF: a column depends on part of the key; 3NF: a column depends on another non-key column).**
- 2026-11-18 — An index lesson explained a plan with a docs figure (0.1%) as if it were a hard rule; the engine's
  threshold has a 2,048-row floor, and a 355-row filter on a single-column index did use the index. → **Run the
  counter-case before explaining why an engine did or did not use a feature; quote a guideline as guidance.**

  (about 25) and says "then report".**
