## The question

The help box of the site sends each learner question to the lesson that answers it. In lesson MLE8 a prompt did that, and named the right lesson for 8 of 16 questions. To do better you can say more to the model, show it text, or change the model. *Which one pays for this job, and what does each cost?* Three of the 32 test questions, with the lesson that answers each:

## The big idea

A prompt changes what you say to the model, retrieval changes what it can read, and fine-tuning changes the model itself: each costs something else, and each fails in its own way.

Where each approach acts: the words of the request, the text it carries, or the model.

### 1. Prompt it

**Idea.** A prompt changes the words of the request. The instruction and the eight lesson names travel with every question, so every request counts and pays for them (the prompt tokens of lesson MLE8). A prompt needs no labeled data, and nothing guarantees that the reply follows it.

**Try it:** ask the 32 test questions with a system prompt that lists the eight names, and print the numbers of the approach: replies that pass the `Route` schema, right lessons, mean tokens, dollars for 1,000 requests at the assumed prices of lesson MLE8, and median seconds.

```python
SYSTEM = ("You route learner questions to lessons. Reply with JSON only, like {\"lesson\": \"ctes\"}. "
          "The value of lesson must be exactly one of: " + ", ".join(LESSONS) + ".")


def ask_prompt(question):
    """Prompting: the instructions and the eight names travel with every question."""
    return checked(chat([{"role": "system", "content": SYSTEM}, {"role": "user", "content": question}], max_new_tokens=30))


runs = {"prompt": [ask_prompt(question) for question, _ in TEST]}
print(report(runs["prompt"], TEST))
print(sorted({r["error"] for r in runs["prompt"] if r["error"]}))
```

**Predict:** How many of the 32 replies will pass the check, how many will name the right lesson, and how many tokens will a request count on average?

### 2. Retrieve for it

**Idea.** Retrieval changes what the model can read. The three most similar chunks of the lessons go in with the question (the search of lesson MLE9), each starting with the name of its lesson. The model can use text it was never trained on, and text you changed today is read today. The request grows by the chunks, and a wrong search brings the wrong text.

**Try it:** the same instruction with three chunks added to each question, and the count of questions whose best chunk comes from the right lesson, with no model.

```python
SYSTEM_R = SYSTEM + " Sources follow the question: each one starts with the name of the lesson it comes from."


def ask_retrieval(question, k=3):
    """Retrieval: the three most similar chunks of the lessons go in with the question."""
    sources = "\n".join(f"[{CHUNKS[i][0]}] {CHUNKS[i][2]}" for _, i in search(question, k))
    return checked(chat([{"role": "system", "content": SYSTEM_R}, {"role": "user", "content": f"Question: {question}\n\nSources:\n{sources}"}], max_new_tokens=30))


runs["retrieval"] = [ask_retrieval(question) for question, _ in TEST]
print(report(runs["retrieval"], TEST))
top_chunk = [CHUNKS[search(question, 1)[0][1]][0] for question, _ in TEST]                 # no model: the lesson of the best chunk
print(sum(lesson == expected for lesson, (_, expected) in zip(top_chunk, TEST)))
```

**Predict:** Will the replies name more right lessons than in unit 1, and how many tokens will a request count now? How many questions would the best chunk alone get right?

### 3. Tune it with LoRA

**Idea.** Fine-tuning changes the model. LoRA (low-rank adaptation) freezes the model's numbers and adds two small matrices beside each layer you choose; only those are trained, and the PEFT documentation says the original and the adapted weights are combined to give the output. The rank `r` sets how small the matrices are: a layer with `n_in` inputs and `n_out` outputs gets `r x (n_in + n_out)` new numbers. `lora_alpha` scales the update, `lora_dropout` drops values while training (the dropout of lesson MLE6), and `target_modules` names the layers, typically the attention layers only, says the documentation. Training needs labeled examples: here a question with its reply, 96 of them.

**Try it:** wrap the four attention layers of all 28 layers of the model, with rank 8, and count the numbers that will be trained.

```python
SHAPES = {}                                                                   # the shape of each layer the adapter will wrap, read before wrapping
layer = llm.model.layers[0]
for name, module in [("q_proj", layer.self_attn.q_proj), ("k_proj", layer.self_attn.k_proj), ("v_proj", layer.self_attn.v_proj), ("o_proj", layer.self_attn.o_proj)]:
    SHAPES[name] = (module.in_features, module.out_features)
N_LAYERS = len(llm.model.layers)
print(SHAPES, N_LAYERS)

config = LoraConfig(r=8, lora_alpha=16, lora_dropout=0.05, target_modules=list(SHAPES), task_type="CAUSAL_LM")
torch.manual_seed(SEED)                                                       # the first of the two small matrices starts random
llm = get_peft_model(llm, config)
trainable = sum(p.numel() for p in llm.parameters() if p.requires_grad)
total = sum(p.numel() for p in llm.parameters())
print(config.r, config.lora_alpha, config.lora_dropout, sorted(config.target_modules))
print(trainable, total, round(100 * trainable / total, 3))
```

The OpenAI guide on accuracy, a vendor page, recommends starting with the prompt, adding retrieval when the model lacks facts or has outdated ones, and tuning for consistent behavior such as format and tone; it adds that the quality of the training data matters more than the amount. The deep dive *Fine-tuning a small model with LoRA, for real* (a draft) goes further.

<Aside type="tip" title="Remember">

- A prompt changes the words; every request carries them, and nothing guarantees that the reply follows them.
- Retrieval changes what the model can read: new text works once it is embedded, and every request carries the chunks.
- LoRA trains small matrices beside frozen layers; the adapter is a small file, and the model comes back with it switched off.
- Read a run in three places: the configuration, the validation loss beside the training loss, and a score on questions kept out of training.
- Start with the prompt, add retrieval for facts the model lacks, and tune for behavior you have many labeled examples of.

**Common trap:** a tuned model that scores best on one test has learned the task. This one named 28 of 32 lessons on one run, from 96 questions written by one author, and it answered a question outside its task with broken JSON.

</Aside>
