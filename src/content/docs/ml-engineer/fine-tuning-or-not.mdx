## The question

The help box of the site sends each learner question to the lesson that answers it. To get a model to do that you can say more to it, show it text, or change the model. *Which one pays for this job, and what does each cost?* Three of the 32 test questions, with the lesson that answers each:

| question | lesson |
|---|---|
| Why does a NOT IN list that holds a NULL return no rows? | null-handling |
| How do I add a running count of orders for each customer? | window-functions |
| Which test should come first in a CASE when two tests overlap? | case-expressions |

## The big idea

A prompt changes what you say to the model, retrieval changes what it can read, and fine-tuning changes the model itself: each costs something else, and each fails in its own way.

Where each approach acts: the words of the request, the text it carries, or the model.

### 1. Prompt it

**Idea.** A prompt changes the words of the request. The instruction and the eight lesson names travel with every question, so every request counts and pays for them (the prompt tokens of lesson MLE8). A prompt needs no labeled data, and nothing guarantees that the reply follows it.

**Try it:** ask the 32 test questions with a system prompt that lists the eight names, and print the numbers of the approach: replies that pass the `Route` schema, right lessons, mean tokens, dollars for 1,000 requests at the assumed prices of lesson MLE8, and median seconds.

```python
SYSTEM = ("You route learner questions to lessons. Reply with JSON only, like {\"lesson\": \"ctes\"}. "
          "The value of lesson must be exactly one of: " + ", ".join(LESSONS) + ".")


def ask_prompt(question):
    """Prompting: the instructions and the eight names travel with every question."""
    return checked(chat([{"role": "system", "content": SYSTEM}, {"role": "user", "content": question}], max_new_tokens=30))


runs = {"prompt": [ask_prompt(question) for question, _ in TEST]}
print(report(runs["prompt"], TEST))
print(sorted({r["error"] for r in runs["prompt"] if r["error"]}))
```

**Predict:** How many of the 32 replies will pass the check, how many will name the right lesson, and how many tokens will a request count on average?

### 2. Retrieve for it

**Idea.** Retrieval changes what the model can read. The three most similar chunks of the lessons go in with the question (the search of lesson MLE9), each starting with the name of its lesson. The model can use text it was never trained on, and text you changed today is read today. The request grows by the chunks, and a wrong search brings the wrong text.

**Try it:** the same instruction with three chunks added to each question, and the count of questions whose best chunk comes from the right lesson, with no model.

```python
SYSTEM_R = SYSTEM + " Sources follow the question: each one starts with the name of the lesson it comes from."


def ask_retrieval(question, k=3):
    """Retrieval: the three most similar chunks of the lessons go in with the question."""
    sources = "\n".join(f"[{CHUNKS[i][0]}] {CHUNKS[i][2]}" for _, i in search(question, k))
    return checked(chat([{"role": "system", "content": SYSTEM_R}, {"role": "user", "content": f"Question: {question}\n\nSources:\n{sources}"}], max_new_tokens=30))


runs["retrieval"] = [ask_retrieval(question) for question, _ in TEST]
print(report(runs["retrieval"], TEST))
print(sorted({r["error"] for r in runs["retrieval"] if r["error"]}), [r["text"] for r in runs["retrieval"] if r["error"]][:3])
top_chunk = [CHUNKS[search(question, 1)[0][1]][0] for question, _ in TEST]                 # no model: the lesson of the best chunk
print(sum(lesson == expected for lesson, (_, expected) in zip(top_chunk, TEST)))
```

**Predict:** Will the replies name more right lessons than in unit 1, and how many tokens will a request count now? How many questions would the best chunk alone get right?

### 3. Tune it with LoRA

**Idea.** Fine-tuning changes the model. LoRA (low-rank adaptation) freezes the model's numbers and adds two small matrices beside each layer you choose; only those are trained, and the PEFT documentation says the original and the adapted weights are combined to give the output. The rank `r` sets how small the matrices are: a layer with `n_in` inputs and `n_out` outputs gets `r x (n_in + n_out)` new numbers. `lora_alpha` scales the update, and `target_modules` names the layers: the documentation says LoRA is typically applied to the attention blocks only. `lora_dropout` drops a share of the adapter's values while training, as the dropout of lesson [MLE6](/ml-engineer/deep-learning-training-practice/) does. Training needs labeled examples: here a question with its reply, 96 of them.

**Try it:** wrap the four attention layers of all 40 layers of the model, with rank 8, and count the numbers that will be trained.

```python
SHAPES = {}                                                                   # the shape of each layer the adapter will wrap, read before wrapping
layer = llm.model.layers[0]
for name, module in [("q_proj", layer.self_attn.q_proj), ("k_proj", layer.self_attn.k_proj), ("v_proj", layer.self_attn.v_proj), ("o_proj", layer.self_attn.o_proj)]:
    SHAPES[name] = (module.in_features, module.out_features)
N_LAYERS = len(llm.model.layers)
print(SHAPES, N_LAYERS)

config = LoraConfig(r=8, lora_alpha=16, lora_dropout=0.05, target_modules=list(SHAPES), task_type="CAUSAL_LM")
torch.manual_seed(SEED)                                                       # the first of the two small matrices starts random
llm = get_peft_model(llm, config)
trainable = sum(p.numel() for p in llm.parameters() if p.requires_grad)
total = sum(p.numel() for p in llm.parameters())
print(config.r, config.lora_alpha, config.lora_dropout, sorted(config.target_modules))
print(trainable, total, round(100 * trainable / total, 3))
```

**Idea.** A training example is the request followed by the reply, and the loss counts the reply only. An epoch is one pass over the 96 questions, in batches of 8. After each epoch the loss on `DEV`, which the model never trains on, says whether what it learns carries over (the validation loss of lesson MLE6). The rate 5e-4 and the 4 epochs were chosen on `DEV`: a first run at 2e-4 for 3 epochs left 12 of 16 `DEV` questions right, and 5e-4 for 4 epochs got all 16. `TEST` chose nothing.

### 5. The bill

**Idea.** The bill has three parts. A request costs its tokens, at the assumed prices of lesson MLE8 ($1.00 per million prompt tokens, $5.00 per million completion tokens). Tuning adds a price paid once: labeled data and a training run. Every change in the facts has a price too: an edit, new text to embed, or new labeled examples and a new run. Two scores can differ by chance. If two approaches were equally good, each question on which they differ would fall to either side like a coin flip, and the exact sign test adds up the chances of a split at least as uneven as the one seen, in either direction.

**Try it:** put the three runs side by side, compute how many requests the shorter prompt of the tuned model needs to repay the labeling of the 112 questions (an invented $200), count the questions on which two approaches differ, and run the sign test on those counts.

```python
reports = {name: report(rows, TEST) for name, rows in runs.items()}
for name, row in reports.items():
    print(name, row)
LABELING = 200.00                                                             # dollars to write and check 112 labeled questions: invented for this lesson
saved = (reports["prompt"]["cost"] - reports["tuned"]["cost"]) / 1000       # dollars saved on one request by the shorter prompt
print(round(saved, 6), round(LABELING / saved))                              # requests until the shorter prompt has repaid the labeling
print(round(LABELING / saved / 400_000, 1))                                  # months at 400,000 requests a month, the invented volume of lesson MLE8
right = {name: [r["lesson"] == lesson for r, (_, lesson) in zip(rows, TEST)] for name, rows in runs.items()}


def differ(a, b):
    """The questions that a gets right and b gets wrong, and the questions that b gets right and a gets wrong."""
    return sum(x and not y for x, y in zip(right[a], right[b])), sum(y and not x for x, y in zip(right[a], right[b]))


print(differ("tuned", "retrieval"), differ("tuned", "prompt"), differ("retrieval", "prompt"))


def sign_test(a, b):
    """The exact two-sided sign test: if the two approaches were equally good, how often would the questions where they differ split at least this unevenly?"""
    n, k = a + b, min(a, b)
    return round(min(1.0, 2 * sum(math.comb(n, i) for i in range(k + 1)) / 2 ** n), 3)


print(sign_test(*differ("tuned", "retrieval")), sign_test(*differ("tuned", "prompt")))
```

<Aside type="tip" title="Remember">

- A prompt changes the words; every request carries them, and nothing guarantees that the reply follows them.
- Retrieval changes what the model can read: new text works once it is embedded, and every request carries the chunks.
- LoRA trains small matrices beside frozen layers; the adapter is a small file, and the model comes back with it switched off.
- Read a run in three places: the configuration, the validation loss beside the training loss, and a score on questions kept out of training, with the questions where two approaches differ counted.
- Start with the prompt, add retrieval for facts the model lacks, and tune for behavior you have many labeled examples of.

**Common trap:** a tuned model that scores best on one test has learned the task. This one named 29 of 32 lessons on one run, from 96 questions written by one author; its lead over retrieval (29 against 22) is clear on a sign test, its lead over the prompt (29 against 28) is one question, and it put JSON around an answer to a question outside its task.

</Aside>
