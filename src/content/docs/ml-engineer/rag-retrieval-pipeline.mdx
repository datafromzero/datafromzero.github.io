## The question

A learner types a question into the help box of the site, and the answer is somewhere in eight lessons. A model that has never read them will guess; a model that is given the right paragraphs can answer from them and say where it read them. *How do you cut the lessons into pieces, find the right pieces, answer with citations, and refuse when the lessons do not say?* Four of the 16 questions the notebook uses, and two it must refuse:

| question | answered by |
|---|---|
| What is a CTE? | ctes |
| Why does BETWEEN miss orders placed on the last day of a month? | dates-and-time |
| What does CASE return when no WHEN is true and there is no ELSE? | case-expressions |
| How do I find customers who never placed an order? | left-join-anti-join |
| What is the capital of Australia? | no lesson |
| What is a self join? | no lesson |

By the end you can say how chunk size changes what a search finds and what it costs, run a similarity search, check an answer's citations, and stop a question that nothing in the corpus matches.

## The big idea

Retrieval-augmented generation finds the few paragraphs that match a question, gives them to a model as numbered sources, and checks that the answer and its citations stay inside them.

## Learn by doing

### 1. Chunk size

**Idea.** A *chunk* is the piece of a document that is embedded and retrieved whole. The retrieval-augmented generation of Lewis et al. pairs a language model with a store of documents that it can look up, which the abstract calls non-parametric memory. How big the pieces are is your choice. The encoder reads at most 256 tokens of a text; the model card says that longer input is truncated.

**Try it:** cut the eight lessons into chunks of about 40, 120 and 400 words and print, for each size, the number of chunks, the mean tokens of a chunk, how many chunks are longer than 256 tokens, how many of the 16 questions find the phrase of their answer in the top 3 chunks, and the mean tokens of those 3 chunks together.

```python
for target in [40, 120, 400]:
    chunks = make_chunks(target)
    vectors = emb.encode([chunk[2] for chunk in chunks])
    sizes = [len(emb.tokenizer.tokenize(chunk[2])) for chunk in chunks]
    top3 = np.argsort(-(emb.encode(QUESTIONS) @ vectors.T), axis=1)[:, :3]
    context = statistics.mean(sum(sizes[i] for i in row) for row in top3)
    print(target, len(chunks), round(statistics.mean(sizes)), sum(size > emb.max_seq_length for size in sizes), hits(chunks, vectors), round(context))
```

**Predict:** Which size finds the most answers, and what does it cost?

*Why:* The columns are the target words, the chunks, the mean tokens of a chunk, the chunks over 256 tokens, the questions found, and the tokens of the top 3. Chunks of 40 words find 8 of the 16, because the answer is often split across two small pieces. Chunks of 120 words find 12 and cost 375 tokens of context. The middle size wins here; the numbers are for these 16 questions and these lessons, not a rule.

### 2. Embed and search

**Idea.** Embed every chunk once and keep the matrix of vectors. To search, embed the question and take the cosine with every chunk, which for vectors of length 1 is one matrix product, and keep the `k` largest. The cosine is the score that unit 4 will use.

**Try it:** with chunks of 120 words, print the 3 best chunks for one question with their cosines, then count over all 16 questions how often the best chunk comes from the lesson that answers and how often the top 3 hold the phrase.

```python
CHUNKS = make_chunks(120)
VECTORS = emb.encode([chunk[2] for chunk in CHUNKS])                          # one row of 384 numbers for each chunk, computed once


def search(question, k=3):
    """The k chunks most similar to the question, as (cosine, number of the chunk)."""
    scores = VECTORS @ emb.encode([question])[0]
    return [(round(float(scores[i]), 3), int(i)) for i in np.argsort(-scores)[:k]]


for score, i in search("How do I find customers who never placed an order?"):
    print(score, CHUNKS[i][0], "|", CHUNKS[i][1], "|", CHUNKS[i][2][:60])
first_right = sum(CHUNKS[search(question, 1)[0][1]][0] == lesson for question, lesson, _, _ in DEV)
print(first_right, hits(CHUNKS, VECTORS))
```

**Predict:** What is the cosine of the best chunk, and from which lesson is it? Over the 16 questions, how often is the best chunk from the right lesson, and how often does the top 3 hold the phrase of the answer?

### 3. Answer from the chunks, with citations

**Idea.** Give the model the best chunks as numbered sources, tell it to answer only from them, and ask for JSON with the answer and the numbers of the sources it used, so that code can check the reply as in lesson MLE8. The retrieved text comes from outside the prompt: OWASP's page on prompt injection says that indirect injections occur when a model accepts input from external sources, such as websites or files, that RAG does not fully mitigate prompt injection, and that expected output formats should be defined and validated. So the prompt names the sources as the only material, and the code checks the JSON and the cited numbers.

**Try it:** run the pipeline on one question for each lesson, 8 in all, and print for each answer whether the JSON is valid with cited numbers among the sources shown, the cited numbers, and whether the answer matches the patterns; then print the answers that do not.

```python
class Cited(BaseModel):
    answer: str | None                                                        # null when the sources do not hold the answer
    sources: list[int]


SYSTEM = ("Answer the question using only the numbered sources. Reply with JSON only, like {\"answer\": \"one or two sentences\", \"sources\": [1]}, "
          "where sources lists the numbers of the sources you used. If the sources do not contain the answer, reply {\"answer\": null, \"sources\": []}.")


def answer(question, k=3):
    """Search, build the prompt from the k best chunks, ask the model, and check what comes back."""
    found = search(question, k)
    sources = "\n".join(f"[{n}] {CHUNKS[i][2]}" for n, (score, i) in enumerate(found, start=1))
    reply = chat([{"role": "system", "content": SYSTEM}, {"role": "user", "content": f"Sources:\n{sources}\n\nQuestion: {question}"}], max_new_tokens=100)
    try:
        parsed = Cited.model_validate_json(reply["text"])
        ok = all(1 <= n <= k for n in parsed.sources)                         # every cited number is one of the numbers shown
        return {**reply, "found": found, "answer": parsed.answer, "sources": parsed.sources, "valid": ok}
    except ValidationError:
        return {**reply, "found": found, "answer": None, "sources": [], "valid": False}


chosen = list(range(0, 16, 2))                                                # the first question of each lesson
results = [answer(DEV[i][0]) for i in chosen]


def matches(i, result):
    """True when the answer holds the words that a correct answer must match."""
    return result["answer"] is not None and all(re.search(pattern, result["answer"], re.I) for pattern in DEV[i][3])


for i, r in zip(chosen, results):
    print(r["valid"], r["sources"], matches(i, r))
print(sum(r["valid"] for r in results), sum(matches(i, r) for i, r in zip(chosen, results)))
for i, r in zip(chosen, results):
    if not matches(i, r):
        print(DEV[i][0], "->", r["answer"])
```

**Predict:** How many of the 8 replies will be valid JSON whose cited numbers are among the sources shown, and how many will contain the words that a correct answer must match?

### 4. Abstain when nothing is relevant

**Idea.** A system that answers every question will answer the ones it should not. The search already holds a signal: the cosine of the best chunk. When even the best chunk scores below a threshold, the system refuses without calling the model. The threshold is chosen on the 16 real questions and the rule is stated first: the lowest best-chunk cosine among them, rounded down to 0.05, so that no real question is refused.

**Try it:** print the threshold, the lowest and highest best-chunk cosines of the 16 questions, and the best-chunk cosine of each of the 8 trap questions, from the lowest, with whether the threshold stops it.

```python
best_dev = [search(question, 1)[0][0] for question in QUESTIONS]
best_trap = [(search(question, 1)[0][0], question, kind) for question, kind in TRAPS]
THRESHOLD = math.floor(min(best_dev) * 20) / 20                               # the lowest cosine of a real question, rounded down to 0.05
print(THRESHOLD, round(min(best_dev), 3), round(max(best_dev), 3))
for score, question, kind in sorted(best_trap):
    print(score, kind, score < THRESHOLD, question)


def answer_or_abstain(question, k=3):
    """Refuse without calling the model when even the best chunk is a poor match."""
    if search(question, 1)[0][0] < THRESHOLD:
        return {"answer": None, "sources": [], "abstained": True}
    return {**answer(question, k), "abstained": False}


print(sum(score < THRESHOLD for score, _, _ in best_trap), "of", len(best_trap), "traps refused")
```

The one that gets through is *What is a self join?* at 0.437: it uses the words of the join lessons, and no lesson of the eight is about self joins. A cosine cannot tell a question about a missing topic from a question about a present one when they share words. Whether the model then refuses by itself is what lesson MLE10 measures.

<Aside type="tip" title="Remember">

- Chunk size is a trade: small chunks split answers, large chunks are cut by the encoder and cost many tokens; measure it on questions with known answers.
- A search is the cosine of the question with every chunk, keeping the `k` largest; the right lesson is easier to find than the right paragraph.
- The retrieved text is outside input: tell the model to use only the sources, and validate the JSON and the citations in code.
- A refusal threshold is chosen on real questions first, and a trap that uses the corpus's words can still pass it.

**Common trap:** the biggest chunks hold the most text, so they find the most answers. Here they found fewer than the middle size, at 3.6 times the tokens.

</Aside>
