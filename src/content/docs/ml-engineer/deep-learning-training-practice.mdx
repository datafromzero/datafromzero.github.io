<OpenInColab />

```python
def fit_network(Xa, ya, hidden, lr, epochs, batch=256, seed=SEED, dropout=0.0, weight_decay=0.0, patience=None):
    """Train a network with one hidden layer; return it and the loss on the fitting and validation people after each epoch."""
    torch.manual_seed(seed)
    model = nn.Sequential(nn.Linear(Xa.shape[1], hidden), nn.ReLU(),
                          nn.Dropout(dropout),                             # NEW: switches off a random share of the hidden outputs
                          nn.Linear(hidden, 1), nn.Sigmoid())
    optimizer = torch.optim.SGD(model.parameters(), lr=lr, weight_decay=weight_decay)    # NEW: weight_decay is used in Exercise 1
    history, best, best_state, waited = [], float("inf"), None, 0
    for epoch in range(epochs):
        model.train()                                                      # NEW: training mode
        order = torch.randperm(len(Xa))
        for start in range(0, len(Xa), batch):
            rows = order[start:start + batch]
            optimizer.zero_grad()
            loss_fn(model(Xa[rows]), ya[rows]).backward()
            optimizer.step()
        model.eval()                                                       # NEW: evaluation mode, to measure the loss
        with torch.no_grad():
            history.append((float(loss_fn(model(Xa), ya)), float(loss_fn(model(Xv), yv))))
        if history[-1][1] < best:                                          # NEW: remember the numbers of the lowest validation loss so far
            best, best_state, waited = history[-1][1], copy.deepcopy(model.state_dict()), 0
        else:
            waited += 1
            if patience is not None and waited >= patience:                # NEW: stop after `patience` epochs without a new lowest
                break
    if patience is not None:
        model.load_state_dict(best_state)                                  # NEW: give back the numbers of the lowest point
    return model, history
```

### 1. Dropout

**Idea.** *Regularization* is any change that makes memorizing harder. *Dropout* is one: at every training step it switches off a random share `p` of a layer's outputs, chosen again each time. The first `NEW` line puts `nn.Dropout(dropout)` after the hidden layer.

**Try it:** train the 64-neuron network on the 500 people for 300 epochs with no dropout and with half of the hidden outputs switched off, and print the lowest validation loss, then the loss on the 500 people and on the validation people at epoch 300.

```python
for p in [0.0, 0.5]:
    model, history = fit_network(Xp, yp, 64, 0.1, 300, batch=50, dropout=p)
    validation = [pair[1] for pair in history]
    print(p, round(min(validation), 3), round(history[-1][0], 3), round(history[-1][1], 3))
```

**Predict:** Will dropout lower the lowest validation loss of the 300 epochs, the validation loss at epoch 300, or both?

<summary>Reveal the result</summary>

```text
0.0 0.638 0.33 0.874
0.5 0.639 0.456 0.717
```

</details>

*Why:* The columns are the dropout, the lowest validation loss, and the two losses at epoch 300. Dropout left the lowest point where it was, 0.638 and 0.639, and lowered the end: the validation loss at epoch 300 went from 0.874 to 0.717, while the loss on the 500 people rose from 0.330 to 0.456. Dropout did not make the best network better. It made the network memorize more slowly, so the end of training is less bad. The optional cell with 20 other pilots of 500 people agrees: dropout gave the lower loss at epoch 300 in all 20 (median 0.689 against 0.842) and the same lowest point (0.638 for both medians).

### 2. Early stopping

**Idea.** *Early stopping* watches the validation loss after each epoch. When it has not reached a new lowest for `patience` epochs, training stops and the network gets back the numbers of the lowest point. These are the last three `NEW` lines of `fit_network`.

**Try it:** train with `patience=10` and, as in unit 1, for all 300 epochs; score both on the validation people with the ROC AUC, next to a logistic regression fitted on the same 500 people.

```python
model, history = fit_network(Xp, yp, 64, 0.1, 300, batch=50, patience=10)
best_epoch = int(np.argmin([pair[1] for pair in history])) + 1
long_model, _ = fit_network(Xp, yp, 64, 0.1, 300, batch=50)                    # the same network for all 300 epochs
print(len(history), best_epoch, val_auc(model), val_auc(long_model))
print(round(float(roc_auc_score(y_val, logit_pilot.predict_proba(prep.transform(X_val))[:, 1])), 3))
```

### 3. Batch size and learning rate

**Idea.** A *batch* is the people used for one update (lesson MLE5), and the learning rate sets the size of the step. Smaller batches give more updates in an epoch, each from fewer people. Both decide how far the network gets in a fixed number of epochs, so they are chosen together.

**Try it:** train the 8-neuron network on all 10,021 fitting people for 10 epochs at six combinations, and print the batch, the learning rate, the number of updates and the validation loss.

```python
for batch in [32, 256, 1024]:
    for lr in [0.1, 1.0]:
        model, history = fit_network(Xf, yf, 8, lr, 10, batch=batch)
        updates = -(-len(Xf) // batch) * 10                                    # steps taken: batches per epoch times 10 epochs
        print(batch, lr, updates, round(history[-1][1], 3))
```

**Predict:** Which run ends with the lowest validation loss, and does one learning rate win at every batch size?

<details>
<summary>Reveal the result</summary>

```text
32 1.0 3140 0.64
256 0.1 400 0.638
256 1.0 400 0.627
1024 0.1 100 0.663
1024 1.0 100 0.629
```

</details>

*Why:* Two runs tie for the lowest, 0.627: batch 32 with 0.1 and batch 256 with 1.0. No rate wins everywhere: 0.1 is better at 32 (0.627 against 0.640) and 1.0 is better at 256 and at 1,024 (0.627 against 0.638, and 0.629 against 0.663). Ten epochs are 3,140 updates at batch 32, 400 at 256 and 100 at 1,024. Our reading is that a larger batch gives a steadier slope, which a larger step can use; a smaller batch gives more steps, which a smaller step can use. The table says only that in this run the better rate moved with the batch size.

### 4. A pretrained start

**Idea.** A network trained on a very large dataset has already learned numbers that read pictures. The PyTorch transfer-learning tutorial names ImageNet, 1.2 million images in 1,000 categories, and two ways to reuse it. Fine-tuning starts every number from the pretrained ones and trains the whole network. As a fixed feature extractor the network is *frozen* (its numbers do not change), its last layer is replaced by a new one with random numbers, and only that layer is trained. Here we use the second.

**Try it:** train `Scratch`, a small network that starts from random numbers and reads pixels, and ResNet-18 with its ImageNet numbers frozen and a new last layer, for 200 epochs on the 60 photos. A given cell of the notebook loaded the photos (the six breeds, 10 to learn from and 30 to test for each) and defined `Scratch`, `fit_classifier` and `accuracy`; the flat guess for six equal breeds is 1 in 6, 0.167.

```python
backbone = models.resnet18(weights=WEIGHTS)                                # ResNet-18 with the numbers learned on ImageNet
for parameter in backbone.parameters():
    parameter.requires_grad = False                                        # freeze: these numbers stay as they are
backbone.fc = nn.Identity()                                                # take off its last layer: 512 numbers come out for each photo
backbone.eval()
with torch.no_grad():
    features_fit, features_test = backbone(images_fit), backbone(images_test)      # computed once, because nothing in the backbone learns
torch.manual_seed(SEED)
head = nn.Linear(512, 6)                                                   # the new last layer: the only numbers that learn
print(sum(p.numel() for p in backbone.parameters()), sum(p.numel() for p in head.parameters()))
fit_classifier(head, features_fit, labels_fit, 200, 0.01)
torch.manual_seed(SEED)
scratch = Scratch()
fit_classifier(scratch, images_fit, labels_fit, 200, 0.003, batch=20)
print("pretrained, new last layer", accuracy(head, features_test, labels_test), accuracy(head, features_fit, labels_fit))
print("from nothing", accuracy(scratch, images_test, labels_test), accuracy(scratch, images_fit, labels_fit))
```

<Aside type="tip" title="Remember">

- Dropout switches off a random share of a layer's outputs during training; here it lowered the end of the validation curve and left its lowest point where it was.
- Early stopping gives back the numbers of the lowest validation point after `patience` epochs without a new one.
- Batch size and learning rate are chosen together: in the six runs the better rate changed with the batch size.
- A frozen pretrained network with a new last layer learns from 60 photos what a network from nothing cannot.
- Report one number on people the choices never saw, next to a baseline fitted on the same people (Rules of Machine Learning, rule 4).

**Common trap:** a score above the flat guess means the network works. The early-stopped network scored 0.681 and a logistic regression on the same 500 people 0.677.

</Aside>
