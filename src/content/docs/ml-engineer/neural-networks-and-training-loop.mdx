### 1. A neuron, a layer, and their numbers

**Idea.** A *neuron* multiplies each input by a *weight*, adds the results and a *bias*, and bends the sum. A *layer* is several neurons that read the same inputs. A *ReLU* is a bend that keeps a positive number and turns a negative one into 0, and a *sigmoid* bends any number into 0 to 1. The numbers a network learns are its weights and biases. The PyTorch build-the-network page stacks `nn.Linear` layers with `nn.ReLU` between them in an `nn.Sequential`.

**Try it:** build one neuron and a small network, count their learnable numbers, and give the neuron the weights of the logistic regression.

```python
neuron = nn.Sequential(nn.Linear(19, 1), nn.Sigmoid())                     # one neuron: 19 weights, one bias, a bend into 0 to 1
small = nn.Sequential(nn.Linear(19, 8), nn.ReLU(), nn.Linear(8, 1))        # a layer of 8 neurons, a bend (ReLU), one output neuron


def count(model):
    """How many numbers the model learns."""
    return sum(parameter.numel() for parameter in model.parameters())


print(count(neuron), count(small))
with torch.no_grad():                                                      # give the neuron the logistic regression's own numbers
    neuron[0].weight.copy_(torch.tensor(logit.coef_, dtype=torch.float32))
    neuron[0].bias.copy_(torch.tensor(logit.intercept_, dtype=torch.float32))
    print(round(float((neuron(Xv).squeeze(1) - torch.tensor(logit_chances, dtype=torch.float32)).abs().max()), 6))
```

**Predict:** A single neuron reads the 19 columns and gives one chance; a small network has a layer of 8 neurons, then one output neuron. How many learnable numbers does each have?

```text
0.0
```

*Why:* The neuron has 20 numbers, 19 weights and a bias. The small network has 169: the 8 neurons of the layer have 19 weights and a bias each, 160 in all, and the output neuron has 8 weights and a bias. The second line printed 0.0: with the logistic regression's own weights, the neuron gives its chances (the largest difference is below a millionth). A neuron with a sigmoid is a logistic regression, and a network is made of them.

### 2. A loss says how wrong the chances are

**Idea.** Training needs one number that is small when the chances are good. *Binary cross-entropy* gives a person who churned the loss −ln(chance) and a person who stayed −ln(1 − chance), averaged over the people. The chance is the one the model gave to what happened.

**Try it:** compute the loss of a flat chance of 0.5, of the share of churners, and of a new network that has not learned anything.

```python
loss_fn = nn.BCELoss()                                                     # binary cross-entropy
torch.manual_seed(SEED)
untrained = nn.Sequential(nn.Linear(19, 8), nn.ReLU(), nn.Linear(8, 1), nn.Sigmoid())
share = float(yf.mean())
with torch.no_grad():
    print(round(float(loss_fn(torch.full_like(yf, 0.5), yf)), 3), round(float(loss_fn(torch.full_like(yf, share), yf)), 3), round(float(loss_fn(untrained(Xf), yf)), 3))
```

**Predict:** What loss will a chance of 0.5 for everyone give on the fitting people, what will the share of churners (about 0.54) give, and what will a new, untrained network give?

<details>
<summary>Reveal the result</summary>

```text
0.693 0.689 0.706
```

</details>

*Why:* A chance of 0.5 costs −ln 0.5 = 0.693 for everyone, whatever happened. The share of churners costs a little less, 0.689, because it is the best flat chance. The untrained network costs 0.706, a little more than the flat guess: its random numbers give chances near 0.5 that point nowhere. These three numbers are the starting line of every loss curve in this lesson: a trained network is worth something only below 0.689.

### 3. The training loop, and the size of its step

**Idea.** The loop repeats four things. The *forward pass* gives the chances for a batch, and the loss scores them. The *backward pass*, `loss.backward()`, finds the slope of the loss for every number. The *update*, `optimizer.step()`, moves each number by the *learning rate* times its slope, against it. A *batch* is the people used for one update, and an *epoch* is one pass over all of them. PyTorch's tutorial says gradients by default add up, so each step starts with `optimizer.zero_grad()`.

**Try it:** run the loop for 20 epochs at four learning rates and print the loss on the fitting and validation people and the validation AUC at the end.

```python
def fit_network(Xa, ya, hidden, lr, epochs, batch=256, seed=SEED):
    """Train a network with one hidden layer; return it and the loss on the fitting and validation people after each epoch."""
    torch.manual_seed(seed)
    model = nn.Sequential(nn.Linear(Xa.shape[1], hidden), nn.ReLU(), nn.Linear(hidden, 1), nn.Sigmoid())
    optimizer = torch.optim.SGD(model.parameters(), lr=lr)                 # the update: every number moves by lr times its slope
    history = []
    for epoch in range(epochs):
        order = torch.randperm(len(Xa))                                    # a new shuffle of the people every epoch
        for start in range(0, len(Xa), batch):
            rows = order[start:start + batch]
            optimizer.zero_grad()                                          # forget the slopes of the last batch
            loss = loss_fn(model(Xa[rows]), ya[rows])                      # forward pass, then the loss of this batch
            loss.backward()                                                # backward pass: the slope of the loss for every number
            optimizer.step()                                               # update
        with torch.no_grad():
            history.append((float(loss_fn(model(Xa), ya)), float(loss_fn(model(Xv), yv))))
    return model, history


for lr in [0.01, 0.1, 1.0, 10.0]:
    model, history = fit_network(Xf, yf, 8, lr, 20)
    with torch.no_grad():
        auc = roc_auc_score(y_val, model(Xv).squeeze(1).numpy())
    print(lr, round(history[-1][0], 3), round(history[-1][1], 3), round(float(auc), 3))
```

### 4. Two curves, and where they part

**Idea.** The loss is measured on two groups after every epoch: the people the network learns from, and validation people it never updates on. While the network learns a pattern both fall. When it starts to memorize its people, the loss on them keeps falling while the loss on the validation people rises. The epoch where the validation curve is lowest is where the network does best on people it does not learn from.

**Try it:** train a bigger network, 64 neurons in the hidden layer, on only 500 people for 300 epochs, and find where the validation loss is lowest.

```python
pilot = X_fit.sample(500, random_state=SEED)                               # 500 of the fitting people
```

<Aside type="tip" title="Remember">

- A neuron is a weighted sum plus a bias, bent; a layer is several neurons; a network learns their weights and biases.
- A loss is one number that is small when the chances are good; the flat guess sets the line to beat.
- The loop: forward pass, loss, backward pass, update, with `zero_grad` before each backward pass.
- The learning rate sets the step: too small learns slowly, too large overshoots.
- Read the validation curve beside the training curve; the lowest validation point marks where memorizing starts.

**Common trap:** a training loss that keeps falling. Look at the validation loss before you believe it.

</Aside>

```python
    torch.manual_seed(seed)
    model = nn.Sequential(nn.Linear(Xa.shape[1], hidden), nn.ReLU(), nn.Linear(hidden, 1), nn.Sigmoid())

        for start in range(0, len(Xa), batch):
            rows = order[start:start + batch]
            optimizer.zero_grad()
            loss = loss_fn(model(Xa[rows]), ya[rows])
```
