## The question

The retrieval system of lesson MLE9 answers questions about eight SQL lessons. Someone changes its prompt to save money. *How do you know that the system is good, that it refuses what it should, and that the change did not break something?* A golden question is a question with the answer written down before the run, and a trap is a question that has no answer. Four of the 22 used here:

| kind | question | the right result |
|---|---|---|
| golden | Why does a NOT IN list that holds a NULL return no rows? | an answer that says so, from the null-handling lesson |
| golden | What does a RIGHT JOIN keep that an inner join drops? | an answer from the left-join lesson |
| trap | How do I delete rows from a table? | a refusal |
| trap | What is the tallest mountain in Europe? | a refusal |

By the end you can score an answer on three checks, measure refusals, test how far a language-model judge can be trusted, rerun the evaluation after a change, and report cost beside quality.

## The big idea

An evaluation is a fixed set of questions with the right result written first, a few checks that each say yes or no, and the same run before and after every change.

### 1. A golden set and three checks

**Idea.** A *golden set* is questions whose right answer was written down before the run, here as a lesson, phrases of the paragraph that holds the answer, and patterns that a correct answer must match. Each answer gets three yes-or-no checks: *retrieved* (a chunk with the phrase was among the three given to the model), *matches* (the answer fits the patterns) and *cites* (a source the answer cites holds the phrase). Three checks say where a failure sits: in the search, in the answer or in the citation. A pattern check is crude: it misses a right answer in other words and passes a wrong one that uses the words.

**Try it:** run the system on the 16 golden questions and count each check and the answers that pass all three.

```python
def check_one(item, result):
    """The three checks of one golden question."""
    _, _, phrases, patterns = item
    retrieved = any(phrase in CHUNKS[i][2] for _, i in result["found"] for phrase in phrases)       # a chunk with the answer was found
    matches = result["answer"] is not None and all(re.search(pattern, result["answer"], re.I) for pattern in patterns)
    cites = result["valid"] and any(phrase in CHUNKS[result["found"][n - 1][1]][2] for n in result["sources"] for phrase in phrases)   # a cited source holds it
    return retrieved, matches, cites


runs = {"v1": {"gold": [answer(item[0], "v1") for item in GOLD]}}
checks = [check_one(item, result) for item, result in zip(GOLD, runs["v1"]["gold"])]
print([sum(row[k] for row in checks) for k in range(3)], sum(all(row) for row in checks))
```

**Predict:** Which check fails most often, and how many of the 16 answers pass all three?

The search found the answer more often than the answer or the citation used it. Seven of 16 pass all three, a number for this set and this model.

### 2. Traps and refusals

**Idea.** A *trap* is a question with no answer in the corpus, and the right result is a refusal. A refusal can come from two places: the threshold, before the model is called, or the model, which may reply with a null answer. A system is scored on both sides: refusing what it should, and not refusing what it should answer.

**Try it:** run the system on the 6 traps, print what happened to each, and count the refusals, the ones made by the threshold, and the golden questions that were refused.

```python
runs["v1"]["traps"] = [answer(question, "v1") for question, _ in TRAPS]
for (question, kind), result in zip(TRAPS, runs["v1"]["traps"]):
    print(kind, result["found"][0][0], "refused" if result["answer"] is None else "answered", "by the threshold" if result["abstained"] else "", "|", question)
refused_traps = sum(result["answer"] is None for result in runs["v1"]["traps"])
refused_gold = sum(result["answer"] is None for result in runs["v1"]["gold"])
print(refused_traps, sum(result["abstained"] for result in runs["v1"]["traps"]), refused_gold)
for item, result in zip(GOLD, runs["v1"]["gold"]):
    if result["answer"] is None:
        print(result["found"][0][0], item[0])
```

**Predict:** How many of the 6 traps will be refused, how many by the threshold, and how many of the 16 golden questions were refused?

### 3. A language model as the judge

**Idea.** Patterns cannot read meaning, so a model can be asked to judge an answer against a reference. A judge is itself a model that has to be tested. A first test needs examples whose verdict is known: an answer that is wrong by construction, such as the answer to another question, must be rejected. Here the judge is the same small model that wrote the answers; a judge from the same family can share the mistakes of the system it grades.

**Try it:** ask the judge about 16 answers that are wrong by construction (each is the answer of the next question), then about the 16 real answers, and compare its verdicts on the answers the system gave with the patterns.

```python
JUDGE = ("You grade an answer to a question about SQL. You get the question, a reference sentence from the lesson, and a candidate answer. "
         "Reply with exactly one word: yes if the candidate answer says what the reference says, no if it does not.")


def judge(question, reference, candidate):
    """True when the model says the candidate agrees with the reference."""
    prompt = f"Question: {question}\nReference: {reference}\nCandidate answer: {candidate}"
    return chat([{"role": "system", "content": JUDGE}, {"role": "user", "content": prompt}], max_new_tokens=3)["text"].strip().lower().startswith("yes")


gold_answers = [result["answer"] or "no answer" for result in runs["v1"]["gold"]]
wrong_answers = gold_answers[1:] + gold_answers[:1]                          # each question gets the answer of the next one
accepted_wrong = [judge(item[0], item[2][0], wrong) for item, wrong in zip(GOLD, wrong_answers)]
verdicts = [judge(item[0], item[2][0], real) for item, real in zip(GOLD, gold_answers)]
answered = [i for i, result in enumerate(runs["v1"]["gold"]) if result["answer"] is not None]       # the refusals have no answer to judge
agree = sum(verdicts[i] == checks[i][1] for i in answered)
print(sum(accepted_wrong), sum(verdicts[i] for i in answered), agree, len(answered))
```

**Predict:** How many wrong answers will the judge accept, and on how many of the answers the system gave will its verdict agree with the patterns?


</details>

*Why:* The first number is the answers the judge accepted among the 16 that are wrong by construction: none. The second is the answers it accepted among the 12 that the system gave (the four refusals have no answer to judge): 9. The third and fourth are the 10 of those 12 on which its verdict agreed with the patterns. So the judge rejects an answer that belongs to another question and mostly agrees with the patterns. That is a small test of an easy case, on 12 answers, with a judge of the same family as the system; it is a sign that the judge is usable here, not proof that it is right. The test is easier than it looks: 4 of the 16 wrong answers are the string "no answer" (the refusals, rotated in) and several are one word.

### 4. Run it again after a change, and read the cost

**Idea.** A change to a prompt is a change to the system, so the whole evaluation runs again and the two runs are compared question by question, not only by their totals: the same total can hide one question gained and one lost. A cost sits beside the quality, here the assumed prices of lesson MLE8, $1.00 per million prompt tokens and $5.00 per million completion tokens, for the answers that called the model. Rule 24 of the Google *Rules of Machine Learning* says to measure the delta between models before anyone uses the new one, and rule 2 to design the metrics first.

**Try it:** add "Answer in at most 15 words." to the prompt as version v2, run the evaluation again, and print for each version the answers that pass all three checks, the traps refused, the mean tokens, the dollars for 1,000 answers and the median seconds, then the golden questions that v2 lost and gained.

```python
PROMPTS["v2"] = PROMPTS["v1"] + " Answer in at most 15 words."                  # the change under test
runs["v2"] = {"gold": [answer(item[0], "v2") for item in GOLD], "traps": [answer(question, "v2") for question, _ in TRAPS]}
PRICE_IN, PRICE_OUT = 1.00, 5.00                                               # dollars per million tokens: assumed, not any provider's price


def report(version):
    """The numbers of one run: passes, refusals of traps, tokens, dollars per 1,000 answers (answers that called the model), median seconds."""
    gold, traps = runs[version]["gold"], runs[version]["traps"]
    passes = [all(check_one(item, result)) for item, result in zip(GOLD, gold)]
    called = [result for result in gold + traps if not result["abstained"]]
    cost = (statistics.mean(r["prompt_tokens"] for r in called) * PRICE_IN + statistics.mean(r["completion_tokens"] for r in called) * PRICE_OUT) / 1_000_000 * 1000
    return passes, sum(result["answer"] is None for result in traps), round(statistics.mean(r["prompt_tokens"] for r in called)), round(statistics.mean(r["completion_tokens"] for r in called)), round(cost, 3), round(statistics.median(r["seconds"] for r in called), 1)


for version in ["v1", "v2"]:
    passes, refused, prompt_mean, completion_mean, cost, seconds = report(version)
    print(version, sum(passes), refused, prompt_mean, completion_mean, cost, seconds)
before, after = report("v1")[0], report("v2")[0]
print("lost", [i for i in range(len(GOLD)) if before[i] and not after[i]], "gained", [i for i in range(len(GOLD)) if after[i] and not before[i]])
```

**Predict:** Will v2 cost less per answer, and will it keep every golden question that v1 answered correctly?

<summary>Reveal the result</summary>

```text
v1 7 6 451 21 0.557 10.3
v2 6 6 460 23 0.573 10.8
lost [8] gained []
```

</details>

*Why:* The columns are the version, the answers that pass all three checks, the traps refused, the mean prompt tokens, the mean completion tokens, the dollars for 1,000 answers that called the model, and the median seconds on this machine. Version v1 passes 7 and costs $0.557; 12 of the 22 questions called the model and the other 10 were stopped by the threshold. Version v2 passes 6 and costs $0.573, more and not less: the added sentence put tokens into every prompt (451 to 460) and the completions did not get shorter (21 to 23). The last line says which question changed: v2 lost the question numbered 8, the ninth, about `PARTITION BY`, and gained none. The totals say one fewer; the list says which one, and that nothing was gained.

<Aside type="tip" title="Remember">

- Write the right result before the run: a golden set with phrases and patterns, and traps that have no answer.
- Several yes-or-no checks say where a failure sits: the search, the answer or the citation.
- Score refusals on both sides: the traps it should refuse and the questions it should answer.
- A judge is a model that needs its own test, with answers whose verdict is known; a judge of the same family may share the system's mistakes; use a different one when you can.
- After every change, rerun everything and compare question by question, with the cost beside the quality.

**Common trap:** a change that is meant to save money saves money. Here the added sentence did not shorten the answers, and it cost a question.

</Aside>
