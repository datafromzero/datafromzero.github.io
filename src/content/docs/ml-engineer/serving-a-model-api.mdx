## The question

A teammate building the app says: *Send me ten values about a person and I will show their chance of leaving.* The churn model of lesson [*Tracking experiments and making runs reproducible*](/ml-engineer/experiment-tracking-and-reproducibility/) (MLE3) sits in a registry on your laptop, and a program in the app cannot open that. *What do we put around the model so that another program can ask it, and so that we know when it cannot answer?* The ten values of one person of the test part, which is the request this lesson sends again and again:

| channel | platform | region | sessions_7d | expenses_7d | recent_3d | active_days_7d | onboarded | saw_paywall | bought_plus |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|
| organic_search | android | europe | 3 | 6 | 7 | 2 | 1 | 1 | 0 |

By the end you can write a service that checks what comes in, says whether it is ready, is tested as a client calls it, and runs in a container.

<Aside type="note" title="You already know this">

**Match.** In [*Validating training and serving data*](/ml-engineer/validating-model-data/) (MLE2) the class `ChurnRequest` refused a request with a region the model never saw. The service uses the same class, so the refusal you wrote there is the one it makes.

**Diverge.** In MLE2 a refusal was a Python error inside your own script. Here the caller is another program, so a refusal is an HTTP status the caller can read, and units 1 and 2 show two different ones.

</Aside>

## The big idea

A service is a model with a door: the door checks what comes in, says when the model cannot answer, and names the model that did.

### 1. Check the request at the door

**Idea.** A request *body* is the data a client sends with its call. When a function takes a pydantic model as a parameter, the FastAPI request-body page says FastAPI reads the body as JSON, converts the types, validates the data, and, if the data is invalid, returns an error that says exactly where and what was wrong. The model of the request is the class of MLE2, so the check is written once.

```python
class Prediction(BaseModel):
    churn_chance: float
    model_version: str
```

```python
@app.post("/predict", response_model=Prediction)
def predict(person: ChurnRequest, request: Request):
    model = ready_model(request)
    row = pd.DataFrame([person.model_dump()])[FEATURES]
    chance = float(model.predict_proba(row)[0, 1])
    return Prediction(churn_chance=chance, model_version=version_of(request))
```

### 2. Say whether the service can answer

**Idea.** A service can be running and still unable to answer. A *health check* is an endpoint that says which. The model is loaded once, when the service starts, in a `lifespan` function: the FastAPI lifespan page says this code runs once before the application starts receiving requests, and names loading a shared machine learning model as an example. `ready_model` is the one place that says no model is loaded, and both endpoints call it.

```python
@asynccontextmanager
async def lifespan(app):
    """Load the model once, when the service starts, not on every request."""
    app.state.model, app.state.card = load_model(model_path())
    yield


app = FastAPI(title="churn", lifespan=lifespan)


def ready_model(request: Request):
    """The loaded pipeline, or a 503 answer: the service is up, but it cannot score anyone."""
    if request.app.state.model is None:
        raise HTTPException(status_code=503, detail="model not loaded")
    return request.app.state.model
```

```python
@app.get("/health")
def health(request: Request):
    ready_model(request)
    return {"status": "ok", "model_version": version_of(request)}
```

### 3. Test the service like a client calls it

**Idea.** A service is tested through its HTTP interface, not through its functions. `TestClient` calls the application in this process, so nothing has to be started. The FastAPI testing page says "To use TestClient, first install httpx", but the Starlette page says the client is built on `httpx2` and "Plain httpx is still supported, but deprecated - install httpx2 (included in starlette[full]) instead"; the lesson follows the Starlette page. The FastAPI testing-events page says that when lifespan code must run in a test, you use the client with a `with` statement, so the model is loaded inside `with TestClient(app) as client:`. The most useful test sends people through the service and through the model file and compares. Rule 37 of Google's Rules of Machine Learning says that a model applied to an example in the training data and to the same example at serving "should give you exactly the same result", and that a discrepancy probably indicates an engineering error.

```python
def test_a_person_is_scored_as_the_pipeline_scores_them(client):
    chances = PIPELINE.predict_proba(PEOPLE[FEATURES])[:, 1]
    for position in range(50):
        answer = client.post("/predict", json=as_request(position))
        assert answer.status_code == 200
        assert answer.json()["churn_chance"] == pytest.approx(chances[position], abs=1e-9)
```

**Try it:** the given script sends 200 people of the test part through the service one at a time, and gives the model file the same 200 in a single call. It counts the chances that differ at all.

```bash
uv run python scripts/compare_service.py
```

**Predict:** The service answers 200 requests; the model file answers one. How many of the 200 chances will be equal to the last digit, and how large will the largest difference be?

*Why:* 24 of 200 chances differ, by at most 1.1e-16: a rounding difference between scoring one row and scoring 200 rows in one call. That is not skew: a rounded answer or a column in another order would differ by a visible amount. Rule 37's "exactly the same result" holds to the precision that floating-point rounding allows, so the test compares with a tolerance of 1e-9 (the lesson's own choice) and not with `==`, and it fails when the service and the model disagree at the third decimal.

### 4. Package it in a container

**Idea.** A container image holds the service, its libraries and the model file, and runs the same wherever Docker runs. The file below is read from top to bottom, and its order is the point. The FastAPI Docker page says to copy the file with the dependencies first, so that Docker reuses the cached step, and that after the code is copied the cache "won't be used for this or any following steps easily"; the uv Docker page says the same for `uv sync --no-install-project`, because the project changes often and its dependencies do not. `uv sync` installs what `uv.lock` says, `--no-dev` leaves out the development libraries, and `--locked` makes it fail when the lock file is out of date: "If the lockfile is not up-to-date, uv will raise an error instead of updating the lockfile". The port comes from the variable `PORT` (8000 by default). `HEALTHCHECK` calls `/health`: the Dockerfile reference says the command's exit status gives the health, 0 for healthy and 1 for unhealthy, and a request that gets 503 makes the command exit with 1. The command is already a JSON array, the exec form that the FastAPI page asks for so that the service can shut down gracefully, but it starts `sh -c` so that `$PORT` is expanded. `exec` inside that string is what removes the shell: uvicorn replaces it and becomes the main process.

```dockerfile
# The churn service as a container. Build it after `uv run python -m ml_starter.export`, so that model/ exists.
FROM python:3.13-slim

RUN pip install --no-cache-dir uv==0.11.32
WORKDIR /app

# The libraries first: this layer is rebuilt only when pyproject.toml or uv.lock change.
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev --no-install-project

# Then the code and the model file, which change more often.
COPY src ./src
COPY model ./model

ENV PYTHONPATH=/app/src PATH="/app/.venv/bin:$PATH" PORT=8000
EXPOSE 8000
HEALTHCHECK --interval=10s --timeout=3s --start-period=10s --retries=3 \
  CMD python -c "import os, urllib.request; urllib.request.urlopen(f'http://127.0.0.1:{os.environ[\"PORT\"]}/health')"
# exec makes uvicorn the main process, so that `docker stop` reaches it and it can shut down cleanly.
CMD ["sh", "-c", "exec uvicorn ml_starter.serve:app --host 0.0.0.0 --port $PORT"]
```

<Aside type="tip" title="Remember">

- A request is checked by the same class that checks the table, before the model sees it: a bad body gets 422.
- A service that is up can still be unable to answer; `/health` says which, and a missing model gives 503.
- The model is loaded once at startup, not for every request.
- Test the service through its interface and compare its answers with the model file's, with a tolerance.
- An image is built from the top down: put what changes least first, and let the port and the model file come from the environment.

**Common trap:** a service whose answers nobody compared with the notebook's. Send the same people through both before anyone depends on it.

</Aside>

**Spot the flaw.** A colleague wants the service never to fail and wraps the work of `/predict` in a `try` that returns a chance of 0.5 on any error. Save the file below as `exercises/mle13_ex3.py` and run it: it asks the service for one person twice, once with no model file and once with the real one, and prints the two statuses. It prints `[200, 200]`, and the first should be a refusal. Change the route so that it prints the statuses a caller needs. Expected: it prints a list of two numbers.

```python
import json
import os
import tempfile

import pandas as pd
from fastapi import FastAPI, Request
from fastapi.testclient import TestClient

from ml_starter.config import FEATURES
from ml_starter.contract import ChurnRequest
from ml_starter.data import load_table
from ml_starter.serve import lifespan, ready_model

flawed = FastAPI(lifespan=lifespan)


@flawed.post("/predict")
def predict(person: ChurnRequest, request: Request):
    try:
        model = ready_model(request)
        row = pd.DataFrame([person.model_dump()])[FEATURES]
        return {"churn_chance": float(model.predict_proba(row)[0, 1])}
    except Exception:
        return {"churn_chance": 0.5}  # colleague: "the service should always answer"


body = json.loads(load_table().head(1)[FEATURES].to_json(orient="records"))[0]  # given: one person
statuses = []
for model_file in [os.path.join(tempfile.mkdtemp(), "missing.skops"), os.environ.get("MODEL_FILE", "model/churn.skops")]:  # given: no model file, then the real one
    os.environ["MODEL_FILE"] = model_file
    with TestClient(flawed) as client:
        statuses.append(client.post("/predict", json=body).status_code)
print(statuses)  # prints [200, 200]; with no model file the service should refuse
```
