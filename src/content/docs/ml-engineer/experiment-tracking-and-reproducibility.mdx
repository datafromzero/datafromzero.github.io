## The question

The best model was one run last Tuesday. Today it scores a little worse and nobody can say why: which settings, which data file, which version of the code and which libraries made it? *What do we record at training time so that any run can be explained, compared and repeated?* Every run of the churn pipeline reads the same file, `data/churn_table.csv`, whose first rows are these:

| user_id | signup_date | channel | platform | churned |
|---:|---|---|---|---:|
| 10001 | 2026-01-01 | organic_search | web | 1 |
| 10002 | 2026-01-01 | app_store | android | 1 |
| 10003 | 2026-01-01 | paid_search | android | 1 |
| 10004 | 2026-01-01 | organic_search | web | 0 |

If a byte of that file changes, so can every score that came from it.

By the end you can log a run, compare and register runs, record what a run depends on, and repeat a run from its record.

<Aside type="note" title="You already know this">

**Match.** In [*Git: branches, pull requests and review*](/core/git-branches-and-pull-requests/) (C30) every change was a commit with a hash that names its code. A run's record names its code the same way, and adds what a commit does not hold: the data and the numbers it produced.

**Diverge.** A commit records what you changed. A run record also holds results that change with the data and the seed, so two runs of the same commit can differ, and unit 3 shows when.

</Aside>

### 1. A run is a record

**Idea.** The MLflow tracking page describes an API for "logging parameters, code versions, metrics, and output files". *Parameters* are the settings of a run, *metrics* the numbers it produced, and an *artifact* a file it wrote; here the artifact is the fitted pipeline. `train` opens a run with `with mlflow.start_run(...)`, so the run is closed when the block ends.

```python
def train(C=1.0, seed=SEED, table_path=TABLE, uri=TRACKING_URI):
    """Cross-validate the pipeline on the training people, fit it on all of them, and record the whole run."""
    open_store(uri)
    X_train, X_test, y_train, y_test = split(load_table(table_path))
    with mlflow.start_run(run_name=f"C={C} seed={seed}"):
        mlflow.log_params({"C": C, "seed": seed, "data_sha256": fingerprint(table_path)})
        mlflow.set_tags({
            "git_commit": git("rev-parse", "--short", "HEAD"),
            "git_uncommitted_changes": str(bool(git("status", "--porcelain"))),
            "lock_sha256": fingerprint(ROOT / "uv.lock"),
        })
        pipeline = build_pipeline(C)
        folds = StratifiedKFold(5, shuffle=True, random_state=seed)
        scores = cross_val_score(pipeline, X_train, y_train, cv=folds, scoring="roc_auc")
        mlflow.log_metrics({"cv_auc_mean": float(scores.mean()), "cv_auc_min": float(scores.min()), "cv_auc_max": float(scores.max())})
        saved = mlflow.sklearn.log_model(pipeline.fit(X_train, y_train), name="pipeline", skops_trusted_types=TRUSTED_TYPES)
        mlflow.set_tag("model_uri", saved.model_uri)
    return float(scores.mean())
```

### 2. Compare, then register

**Idea.** Runs are rows that can be ordered by a metric. A *registry* keeps named models with numbered versions, and an *alias* such as `champion` points at one version; the MLflow registry page gives `models:/MyModel@champion` as the way to ask for the version an alias names, so a service can follow the alias while the version behind it changes.

**Try it:** train a third setting, list the runs, and register the best.

```bash
uv run python -m ml_starter.train --C 0.001
uv run python -m ml_starter.runs list
uv run python -m ml_starter.runs register
```

### 3. What a run depends on

**Idea.** A run's score depends on more than its parameters: on the seed that cuts the folds, on the data file, on the code and on the libraries. `train` records each: the seed as a parameter; `data_sha256`, the first 12 digits of the SHA-256 of the data file, which changes if one byte changes; `git_commit`, the abbreviated commit, as the Pro Git revision page describes short SHA-1 names, and whether files had uncommitted changes; and `lock_sha256`, the same kind of fingerprint of `uv.lock`. The uv documentation says the lockfile "contains the exact resolved versions that are installed in the project environment".

**Try it:** train `C` 0.1 again with the same seed, then with seed 7, and show the record of the first run of the list in unit 2.

```bash
uv run python -m ml_starter.train --C 0.1
uv run python -m ml_starter.train --C 0.1 --seed 7
uv run python -m ml_starter.runs show 615bf25e
```

**Predict:** Three runs have `C` 0.1: seed 2026 in unit 1, seed 2026 again now, and seed 7. Which of the printed `cv_auc_mean` values will be equal to the last digit?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python -m ml_starter.train --C 0.1
C=0.1 seed=2026: cv_auc_mean 0.691687
$ uv run python -m ml_starter.train --C 0.1 --seed 7
C=0.1 seed=7: cv_auc_mean 0.691585
```

*Why:* The two runs with seed 2026 print the same 0.691687, the same score to the sixth decimal, because the seed fixes the five folds and nothing else in the run is random. Seed 7 cuts other folds and prints 0.691585. The record answers what a colleague would ask: the data file (`data_sha256`), the commit, whether files were uncommitted (`False`, because of the commit above) and the lock file. A run made on files that were not committed would carry `True`, and its commit would not name its code.

### 4. Repeat a run from its record

**Idea.** To repeat a run, read its record and run again with its parameters. The function below does that and returns the recorded score beside the new one.

```python
def reproduce(prefix, uri=TRACKING_URI):
    """Run again with the recorded parameters, refusing when the data file is no longer the one that run read."""
    open_store(uri)
    recorded = find_run(prefix)
    now = fingerprint(TABLE)
    if recorded.data.params["data_sha256"] != now:
        raise SystemExit(f"Cannot reproduce: the data file changed (recorded {recorded.data.params['data_sha256']}, now {now})")
    again = train(float(recorded.data.params["C"]), int(recorded.data.params["seed"]), uri=uri)
    return recorded.data.metrics["cv_auc_mean"], again
```

**Try it:** reproduce the run from unit 3. Then change one number of the data file with the given script, reproduce again, and undo the change with Git.

```bash
uv run python -m ml_starter.runs reproduce 615bf25e
uv run python scripts/change_one_value.py
uv run python -m ml_starter.runs reproduce 615bf25e
git checkout data/churn_table.csv
```

**Predict:** What will `reproduce` print for the unchanged data, and what for the file with one number changed?

<summary>Reveal the result</summary>

```console
$ uv run python scripts/change_one_value.py
```

*Why:* On the unchanged data the new run scored exactly what the record says. After one number changed, `reproduce` stopped before training and printed both fingerprints, because a score from another file is not a reproduction. A run can be repeated exactly only while the seed, the data, the code and the libraries are the ones recorded. The commit and the lock file are in the record too, but `reproduce` here checks only the data: checking out the commit and installing the locked libraries are left to you.

<Aside type="tip" title="Remember">

- A run's record holds its parameters, its metrics, the fitted pipeline and fingerprints of the data, the code and the libraries.
- A failed run is recorded too, with its parameters and no metric.
- A registry names a model, numbers its versions and points an alias at one of them.
- A fingerprint changes when a byte changes: compare fingerprints, do not trust a file name.
- A score repeats exactly only when the seed, the data, the code and the libraries repeat.

**Common trap:** a result that nobody can run again. Record what the run depends on before you need it.

</Aside>

```python
import tempfile

import mlflow
from sklearn.model_selection import StratifiedKFold, cross_val_score

from ml_starter.config import SEED
from ml_starter.data import load_table, split
from ml_starter.pipeline import build_pipeline
from ml_starter.train import open_store

uri = f"sqlite:///{tempfile.mkdtemp()}/store.db"
X_train, X_test, y_train, y_test = split(load_table())
folds = StratifiedKFold(5, shuffle=True, random_state=SEED)
open_store(uri)
with mlflow.start_run(run_name="brier") as run:
    scores = cross_val_score(build_pipeline(1.0), X_train, y_train, cv=folds, scoring="neg_brier_score")

answer_2 = round(mlflow.get_run(run.info.run_id).data.metrics["cv_brier"], 3)
print(answer_2)
```
