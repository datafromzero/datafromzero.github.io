   <details>

2. To answer "which three products sold the most?" by hand, what spreadsheet steps would you take, in

   <summary>Answer</summary>

`QUERY` takes a range, a **query** written as text, and the number of header rows:
`=QUERY(range, "query", 1)`. The query is written in the Google Visualization API Query Language,
which Google's documentation describes as similar to SQL. It is not exactly SQL; that is why this
lesson calls it a first taste. Its rules, from Google's documentation:

- the clauses are optional, but they must come in this order: `select`, `where`, `group by`, `pivot`,
  `order by`, `limit`, `offset`, `label`, `format`, `options`;
- in Google Sheets, columns are named by their **letters** (`A`, `B`, `C`), not by their headers;
- when you use `group by`, every column you select must either be in the `group by` or be wrapped in
  an aggregate function such as `sum`, `count` or `avg`;
- text is written in quotes, and string matching is case sensitive;
- a date is written `date '2026-04-01'`.

Each clause does the same job as a step you already know. Following the rows through the clauses is
how SQL will be taught later.

## Worked example

Question: **which three products brought in the most money?** Open the practice file in Google Sheets
and follow along. Build the query one clause at a time, and look at the result after each clause.

1. **Write the expected output first.** *Three rows and two columns: the product and its sales,
   biggest first.* *Why:* it gives you something to check each version of the query against.

2. **Start with `select`.** On `output`, in cell A1, type:

   `=QUERY(raw_order_lines!A1:K3288, "select E, J", 1)`

   You get two columns, product and amount, for all **3,287** lines. *Why:* `select` picks the
   columns, like hiding the other ones. The last argument, `1`, says the range has one header row
   (Google: it sets how many header rows sit at the top of the data).

3. **Add `where`.**

   `=QUERY(raw_order_lines!A1:K3288, "select E, J where K = 'completed'", 1)`

   Now there are **3,286** lines. *Why:* `where` keeps the rows that meet a condition, like a filter.
   Check: 3,287 − 3,286 = 1, the one canceled line. The text `'completed'` is in quotes and must match
   the case of the data.

4. **Add `group by`, with `sum`.**

   `=QUERY(raw_order_lines!A1:K3288, "select E, sum(J) where K = 'completed' group by E", 1)`

   Now there are **15** rows, one per product that sold (Pumpkin Spice Latte was never sold). *Why:*
   `group by` collapses the lines into one row per product, and `sum(J)` says what to total. This is
   the Rows and Values of a pivot. Check: add up the second column, `=SUM(B2:B16)`, and compare it with
   `=SUMIFS(raw_order_lines!J:J,raw_order_lines!K:K,"completed")`. Both give **22,749.25**.

5. **Add `order by`.**

   `=QUERY(raw_order_lines!A1:K3288, "select E, sum(J) where K = 'completed' group by E order by sum(J) desc", 1)`

   Latte comes first, with **2,927.00**. *Why:* `order by` sorts, and `desc` puts the biggest on top.

6. **Add `limit`, and `label`.**

   `=QUERY(raw_order_lines!A1:K3288, "select E, sum(J) where K = 'completed' group by E order by sum(J) desc limit 3 label sum(J) 'sales_usd'", 1)`

   | product | sales_usd |
   |---|---:|
   | Latte | 2,927.00 |
   | Cappuccino | 2,115.50 |
   | Turkey Sandwich | 1,968.75 |

   *Why:* `limit 3` keeps the first three rows after sorting, and `label` names the aggregated column
   (without it, Sheets writes its own heading). Check two things. The fourth product, Cold Brew
   (1,852.00), is below the third, so the cut does not split a tie. And the top one matches the formula
   you know: `=SUMIFS(raw_order_lines!J:J,raw_order_lines!E:E,"Latte",raw_order_lines!K:K,"completed")`
   gives **2,927.00**.

7. **Match each clause to the step it replaced.**

   | Clause | The spreadsheet step it replaced |
   |---|---|
   | `select E, sum(J)` | choosing the columns to show |
   | `where K = 'completed'` | filtering the rows |
   | `group by E` | a pivot with product in Rows |
   | `order by sum(J) desc` | sorting, biggest first |
   | `limit 3` | keeping the first three rows |
   | `label sum(J) 'sales_usd'` | renaming the header |

   In SQL, the same question reads like this (the SQL stage teaches it properly; the table and column
   names are for illustration):

   ```sql
   SELECT product, SUM(amount_usd) AS sales_usd
   FROM order_lines
   WHERE status = 'completed'
   GROUP BY product
   ORDER BY SUM(amount_usd) DESC
   LIMIT 3;
   ```

   The differences are small: SQL names the table with `FROM` and uses column names; `QUERY` gets the
   range as an argument and uses column letters.

That answers the owner: **Latte, Cappuccino and Turkey Sandwich**, and the formula keeps answering when
the data changes, as long as the range includes the new rows.

<details>
<summary>Explain it in your own words: why did you add the clauses one at a time?</summary>

Because each clause changes the rows, and an error is easiest to find right after the clause that
caused it. After `where` the count dropped by exactly one canceled line; after `group by` the total
still matched `SUMIFS`. If you had typed the whole query at once and the total was wrong, you would
not know which clause to blame.

</details>

<Aside type="caution" title="Two traps in the query language">
`month()` starts counting at **0**: Google's documentation describes it as zero-based, with January
as 0. So `where month(C) = 3` selects **April**, not March. Safer: compare dates,
`where C >= date '2026-03-01' and C < date '2026-04-01'`. And string matching is case sensitive:
`'completed'` does not match `Completed`. The documentation suggests `lower()` or `upper()` to
compare without regard to case.
</Aside>

<details>

<Solution>

1. **Find the flaws.** The header is on **row 3** (a title and a blank row sit above it), and the data
   ends on row **462**. So the range starts at `A3`, and the header count stays `1`. Then
   `select D, sum(J) where K = 'completed' group by D` returns **six** rows, not two: `Campus`,
   `campus`, `CAMPUS`, `Old Town`, `old town` and `OLD TOWN`. The same store, spelled three ways.
2. **See what the naive query costs.** `where D = 'Campus'` is case sensitive, so it misses the lines
   written `campus` and `CAMPUS`: it returns 1,373.00 for Campus (the right answer is 1,440.75).
   Old Town would give 1,477.75 instead of 1,554.50. Together the two are 144.50 short.
3. **Fix it inside the query.** Compare in lower case:

   `=QUERY(raw_till_export!A3:K462, "select lower(D), sum(J) where K = 'completed' group by lower(D) order by lower(D) label sum(J) 'sales_usd'", 1)`

   | store (lower case) | sales_usd |
   |---|---:|
   | campus | 1,440.75 |
   | old town | 1,554.50 |

4. **Check.** 1,440.75 + 1,554.50 = **2,995.25**, the March total from the pivot lessons. In the
   status bar, the whole amount column of the export adds to 3,000.25, and 3,000.25 − 5.00 for the
   canceled line gives the same 2,995.25.

</Solution>
