A **table of records** is a sheet where:

- the first row holds the column names, and only the first row;
- every row below it is **one record**: one order, one customer, one day;
- every column is **one field**: one kind of fact, with one fact per cell.

The statistician Hadley Wickham calls this shape *tidy data*. Every tool you will meet later on this
roadmap (PivotTables, SQL, <Term id="glossary-pandas">pandas</Term>, a Python tool for tables) expects it. The messy sheet in the first picture looks fine to a person reading it, but a tool
cannot tell the title from a header, a blank row from the end of the data, or the total from a day.

## Worked example

Question: **how many orders are in `raw_orders`?** Open the practice file and follow along.

1. **Say what one row is.** Look at the first rows: each has a different `order_id`.
   *Why:* before you count anything, know what you are counting. Here one row is one order, so
   counting orders means counting rows.

2. **Find the header row.** Row 1 holds the names (`order_id`, `customer_id`, …), and there is no
   title above it. *Why:* the header is not an order, so it must not be counted.

3. **Select the `order_id` values.** Click cell **A2**, then press **Ctrl+Shift+Down arrow**
   (on a Mac: **Cmd+Shift+Down arrow**). The selection runs from A2 to the last filled cell.
   *Why `order_id`:* it is the key of the table (the column that names each row), so it is filled on
   every row. A column with empty cells would give a smaller count.

   **On a phone (Google Sheets app):** a phone cannot select 1,800 cells with a shortcut, and you do not
   need to. Step 4 counts them with a formula instead.

4. **Read the count from the status bar.**
   - **Excel:** the bar at the bottom of the window shows **Count: 1800**. If you do not see Count,
     right-click the status bar and tick it.
   - **Google Sheets:** the box at the bottom right shows **Sum: …** at first. Click it and choose
     **Count**: it shows **1800**.

   **On a phone (Google Sheets app):** use a formula instead of the status bar. First open the sheet named `calc`: the
   sheet names are the tabs along the bottom of the screen, so tap `calc` (if you cannot see the tabs, the Menu at the
   bottom left lists the sheets on Android). Then double-tap cell **A1** and type `=COUNTA(raw_orders!A:A)-1`, then confirm.
   Read it in three parts: `raw_orders!A:A` means *column A of the sheet named `raw_orders`*, where the `!` joins the
   sheet's name to the cells (Google's help writes it as the sheet name, an exclamation point and the cell). `COUNTA` counts
   the filled cells in that column, and `-1` leaves out the header. A formula starts with `=`; the next lesson explains
   them. It shows **1800**.

5. **Check it another way.** Press **Ctrl+Down arrow** (Mac: **Cmd+Down arrow**) from A1 to jump to the last record: it is on
   **row 1801**. Row 1 is the header, so 1801 − 1 = **1800 orders**. Two methods, one answer.

   **On a phone (Google Sheets app):** check with a second formula instead. In **A2** on `calc` type
   `=COUNT(raw_orders!A:A)`. `COUNT` counts only the cells that hold numbers, so it skips the header
   without any `-1`, and it shows **1800** too.

6. **Count the fields too.** Select **A1:F1**, the six names in the header row. The status bar shows
   **Count: 6**. So the table is 1800 records × 6 fields.

   **On a phone (Google Sheets app):** tap **A1**, drag the blue marker across to **F1**, and read **Count**
   in the row of calculations at the bottom of the screen. Or type `=COUNTA(raw_orders!1:1)` in **A3**.

That answers the owner's first question: **1,800 orders from January to June 2026** (canceled ones
included; we will separate them in a later lesson).

<details>
<summary>Explain it in your own words: why did step 1 come before step 3?</summary>

Because the count only answers the question if one row means one order. If the sheet had one row per
*product sold*, the same steps would count products sold, not orders. Saying what one row is comes first.

</details>

<Aside type="tip" title="The three-sheet habit">
The practice file has sheets called `raw_orders`, `raw_customers`, `raw_weekly_report`, `calc` and
`output`. Keep it that way in every file you build: **raw** sheets hold the data exactly as it
arrived and are never edited; **calc** is where you work; **output** holds only what you show
someone. If you break something in `calc`, the raw data is still there.
</Aside>

<Exercise id="excel-grid-and-tidy-layout-1">

**How many loyalty customers does the cafe have, and how many fields describe each one?** (Loyalty

**Make the Old Town weekly report usable.** Open `raw_weekly_report`. Do not change it: it is raw data.

<details>

<details>
<summary>Half-solution</summary>

Expected output: *"Seven rows, one per day of the week at Old Town, with a header row: `date`,
`store`, `orders`, `sales_usd`, and `note`."* The title, the blank rows and the TOTAL row are not

</details>

<Solution>

| date | store | orders | sales_usd | note |
|---|---|---:|---:|---|
| 2026-01-05 | Old Town | 4 | 36.75 | |
| 2026-01-06 | Old Town | 5 | 68.75 | |
| 2026-01-07 | Old Town | 5 | 40.50 | |
| 2026-01-08 | Old Town | 2 | 8.50 | card machine down until noon |
| 2026-01-09 | Old Town | 4 | 47.75 | |
| 2026-01-10 | Old Town | 3 | 47.00 | |
| 2026-01-11 | Old Town | 7 | 113.25 | |

Why each choice:

- The **title** goes away; the facts in it (store, week) move into the `store` column and the dates.
  Now every row says which store it is about, so this table could later sit under the other stores'
  weeks.
- The **blank rows** go away. **Ctrl+Shift+Down arrow** stops at a blank row, and so does the range
  Excel guesses for you when you make a Table or a PivotTable, so the rest of the week would be missed.
- **"4 orders, \$36.75"** becomes two cells, `4` and `36.75`, typed as numbers without the dollar
  sign. The currency lives in the column name, `sales_usd`.
- The **TOTAL row** goes away. It is not a day; leaving it in would count the week twice.
- The **note** stays, in its own column: it is a fact about that day.

**Check:** select the `orders` values: the status bar shows **Sum: 30**. Select the `sales_usd`
values: **Sum: 362.5**. Both match the manager's TOTAL line, so nothing was lost or typed twice.
**On a phone (Google Sheets app):** tap the first `orders` value and drag the blue marker down over the
seven values: the row of calculations at the bottom of the screen shows **Sum**. Do the same for
`sales_usd`.
The sums work only because you typed plain numbers: try selecting the *Result* cells on
`raw_weekly_report`, and the status bar has nothing to add up.

</Solution>

</Exercise>

**Spot the flaw.** A colleague counted the orders like this: *"I selected the `customer_id` values in
`raw_orders` (B2 down to the last row) and the status bar said Count: 1799. So we have 1,799
orders."* What went wrong, and how would you find the cause?

<Solution>

The real number is 1,800. Count shows how many selected cells are **filled**, and one `customer_id`

</Solution>
