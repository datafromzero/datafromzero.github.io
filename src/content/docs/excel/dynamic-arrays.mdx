## Warm-up

Answer from memory before you open anything. Then click to check.

1. In `raw_products` the codes are in A2:A17 and the prices in D2:D17. Write the formula that brings the
   price for the code in B2, so that it survives being filled down.

   <details>
   <summary>Answer</summary>

   `=XLOOKUP(B2,raw_products!$A$2:$A$17,raw_products!$D$2:$D$17)`. One cell, one result: B2 moves, the
   two ranges are locked.

   </details>

2. You have a list of orders in a sheet. In your own words, what does a filter do to the rows that do not
   match, and what does it do to the original list?

   <details>
   <summary>Answer</summary>

   It hides the rows that do not match, in place. The data is not deleted and not copied: the list is the
   same list, with some rows out of sight. Today's formulas do the opposite: they leave the list alone and
   write the matching rows somewhere else.

   </details>

3. You sort only one column of a list. What happens to the rows?

   <details>
   <summary>Answer</summary>

   They come apart: every value in the sorted column ends up next to the wrong values from the other
   columns. Sort the whole table.

   </details>

Until now a formula returned one value in one cell. A **dynamic array** formula returns a whole block
of values. You type it in **one** cell, and the block fills the cells below and beside it: this block is
the **spill range**. Its size is not something you set. It is the size of the result, so it grows when
more rows match and shrinks when fewer do.

Three functions do most of the work:

- `FILTER` keeps the rows that pass a test, like the conditions of `SUMIFS`, but it returns the rows
  instead of adding them up.
- `SORT` puts the rows in order.
- `UNIQUE` removes repeats, so each value appears once.

A spill needs free cells. If something is in the way, the formula shows `#SPILL!` (second picture)
instead of overwriting it.

## Worked example

Question: **which Campus orders were paid in cash in June, newest first, and what did Campus sell in
each category?** Open the practice file and follow along on the `calc` sheet.

1. **Say what one row is, and write the expected output.** Click **G7** and type: *"A list with one row
   per order (order_id, customer_id, store_id, ordered_at), only Campus cash orders from June, newest
   first; and one row per category with Campus's June sales, adding up to the store's June total."*
   *Why:* a formula that returns a block can be wrong in size or in order and still look tidy. The
   sentence tells you what to check it against.

2. **Type the conditions in cells.** In **G1:H5** type these pairs: `store_id` and `2`; `payment` and
   `cash`; `from (included)` and `2026-06-01`; `until (not included)` and `2026-07-01`; `store_name` and
   `Campus`. *Why:* to ask the same question for another store or month, you change a cell, not a formula.
   The two dates are real dates (right-aligned), as in the lesson on conditional totals.
   Also type the four column names in **A1:D1**: `order_id`, `customer_id`, `store_id` and `ordered_at`.

3. **Filter the orders.** In **A2** type:

   ```text
   =FILTER(raw_orders!A2:D1801,(raw_orders!C2:C1801=H1)*(raw_orders!F2:F1801=H2)*(raw_orders!D2:D1801>=H3)*(raw_orders!D2:D1801<H4),"no orders")
   ```

   Read it as: *from these four columns, keep the rows where all four tests are true; if none is,
   say "no orders".* Ten rows appear, in the order of the data (the oldest, order 2515, first).
   *Why the tests are multiplied:* each test gives TRUE or FALSE for every row, and TRUE times FALSE is
   0. A row survives only if every test is TRUE. Microsoft's help page shows exactly this: multiply
   for "and", add for "or". *Why the tests can use column F even though F is not returned:* the first
   argument says which columns come back, the second says which rows. They only need the same number of
   rows. *Why the last argument:* if no row passes, Excel returns `#CALC!` unless you give a fallback.

   **Google Sheets:** give each test as its own argument (multiplying them into one test also works).
   `FILTER` has no fallback argument, and with no match the result is `#N/A`, so wrap it in `IFNA`:

   ```text
   =IFNA(FILTER(raw_orders!A2:D1801,raw_orders!C2:C1801=H1,raw_orders!F2:F1801=H2,raw_orders!D2:D1801>=H3,raw_orders!D2:D1801<H4),"no orders")
   ```

4. **Sort it, newest first.** Wrap the formula in `SORT`, with the column to sort by (the 4th of the
   four returned, `ordered_at`) and the direction:

   ```text
   =SORT(FILTER(...),4,-1)
   ```

   Excel: `1` is ascending and `-1` is descending. **Google Sheets:** `=SORT(IFNA(FILTER(...),"no orders"),4,FALSE)`,
   where `TRUE` is ascending and `FALSE` is descending. Now order **2797** (June 30, 12:10) is at the top.
   *Why `SORT` goes outside:* sorting the whole result is one more step on a result that already exists.

5. **Verify.** *Is it ten?* `=COUNT(A2:A100)` counts the order numbers that came back: **10**. Then a
   second route that does not use `FILTER` at all:

   ```text
   =COUNTIFS(raw_orders!C:C,H1,raw_orders!F:F,H2,raw_orders!D:D,">="&H3,raw_orders!D:D,"<"&H4)
   ```

   It also gives **10**. The top row is 2797 and the bottom one is 2515: newest first, as asked.

6. **Watch it grow and shrink.** Change **H3** to `2026-05-01` and **H4** to `2026-06-01`. The block now
   fills **29** rows: the formula in A2 was not touched. Change them back and it shrinks to 10, and the
   cells that are no longer needed are empty again. Click any cell inside the block other than A2: the
   formula bar shows the formula grayed out, because only the first cell of a spill is editable.
   *Why this matters:* a list built by hand has the size it had on the day you made it. A spilled
   list always has the size of the question.

7. **Break it on purpose.** Back in June, click **A6** and type `x`. Cell **A2** now shows `#SPILL!`:
   the ten rows need A2:D11 and A6 is not empty. Click A2: a dashed border shows where the result
   wants to go, and Excel's error button offers **Select Obstructing Cells**, which jumps to A6.
   Delete the `x` and the block fills in again. *Why:* Microsoft's help lists the causes of `#SPILL!`:
   something is in the spill range, the range runs past the edge of the sheet, a merged cell is in it, or
   the formula is inside an Excel Table (spilled formulas are not supported there). In every case the
   formula is fine and the cells are not. Google Sheets also needs free cells for a result and does not
   overwrite data: clear the cell that is in the way, and the result fills in.

8. **Build the small table with `UNIQUE` and `SUMIFS`.** In **J1** type the heading `category`, and in
   **J2**:

   ```text
   =SORT(UNIQUE(FILTER(raw_sales_lines!E2:E3288,(raw_sales_lines!C2:C3288=H5)*(raw_sales_lines!D2:D3288="completed")*(raw_sales_lines!B2:B3288>=H3)*(raw_sales_lines!B2:B3288<H4))))
   ```

   It lists each category of the Campus June lines once, in alphabetical order: **bakery, coffee, food,
   tea**. In **K1** type `sales_usd` and in **K2**:

   ```text
   =SUMIFS(raw_sales_lines!J:J,raw_sales_lines!E:E,J2,raw_sales_lines!C:C,$H$5,raw_sales_lines!D:D,"completed",raw_sales_lines!B:B,">="&$H$3,raw_sales_lines!B:B,"<"&$H$4)
   ```

   then fill it down to **K5**. The sales are **369.50**, **705.00**, **363.50** and **152.75**. *Why the
   dollar signs:* J2 moves down the list, the conditions must not. *Why `UNIQUE` first:* you get the
   list of categories from the data, so a new category appears by itself. The `SUMIFS` column does
   not grow by itself: if the list ever got longer, you would have to fill it further down.
   **Google Sheets:** `=SORT(UNIQUE(FILTER(raw_sales_lines!E2:E3288,raw_sales_lines!C2:C3288=H5,raw_sales_lines!D2:D3288="completed",raw_sales_lines!B2:B3288>=H3,raw_sales_lines!B2:B3288<H4)),1,TRUE)`
   in J2.

   Verify: `=SUM(K2:K5)` gives **1,590.75**. The same `SUMIFS` without the category pair also gives
   **1,590.75**, the store's June total: the four rows add up to the whole.

<details>
<summary>Explain it in your own words: why did we type the formula in one cell and not in ten?</summary>

Because the formula decides how many cells it needs. If you wrote it into ten cells by hand, you would
have chosen the size on the day you wrote it, and a different month would leave empty rows or cut off
real ones. With one formula, the data decides the size: more matching orders mean a longer block.

</details>

<Aside type="caution" title="Which Excel has these functions?">
Microsoft's help pages for `FILTER`, `SORT` and `UNIQUE` list Excel for Microsoft 365, Excel 2021 and
Excel 2024 (and the Excel mobile apps). They do not list Excel 2019 or Excel 2016. Google Sheets has all
three functions. Keep a spilled block outside an Excel Table, because spilled array formulas are not
supported inside one.
</Aside>

1. Without looking back: what does `#SPILL!` mean, and how do you find the cause?

   <details>
   <summary>Answer</summary>

   In Excel, `#SPILL!` means something is in the way of the result: a cell in the spill range is not
   empty (or the range holds a merged cell, or runs past the edge of the sheet, or the formula is inside
   a Table). Click the cell with the error: a dashed border shows the intended range, and **Select
   Obstructing Cells** takes you to the blocking cell. The formula itself is fine. In Google Sheets the
   cause is the same, a result with no free cells to land in, so clear them.

   </details>

**Spot the flaw.** A colleague wants Campus cash orders from June and writes this formula (it is kept as text in `calc_ex3`, so you can copy it):

```text
=FILTER(raw_orders!A2:D1801,((raw_orders!C2:C1801=2)+(raw_orders!F2:F1801="cash"))*(raw_orders!D2:D1801>=DATE(2026,6,1)),"no orders")
```

It returns a long list: **146** rows. "That is a lot of cash orders for one small cafe," they say, and send
it on. What went wrong?

<details>
<summary>Hint</summary>

Look at the `store_id` column of the result. Is it all 2? Then look at the sign between the two tests.

</details>

<details>
<summary>Half-solution</summary>

`+` adds the TRUE and FALSE of the two tests, so a row survives if either one is TRUE. What does `*` do instead?

</details>

<Solution>

The right number is **10**. The `+` between the store test and the payment test means "or", so the formula
keeps June orders that were taken at Campus **or** paid in cash: 10 that are both, 21 cash orders at the
other two stores, and 115 Campus orders paid by card or mobile (10 + 21 + 115 = 146). For "and", multiply:
`(C=2)*(F="cash")*(D>=DATE(2026,6,1))`.

The sheet showed the problem as soon as someone looked: the `store_id` column of the result is not all
2. A second route, `COUNTIFS`, gives 10, and the difference with 146 is the proof. A list that is longer
than you expected is a reason to check, not to send.

</Solution>
