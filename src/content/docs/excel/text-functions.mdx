## Warm-up

Answer from memory before you open anything. Then click to check.

1. The formula `=C2*$F$1` sits in D2. You copy it down to D3. Write the formula that D3 now holds.

   <details>
   <summary>Answer</summary>

   **`=C3*$F$1`.** The row number in `C2` moves with the copy; the `$` signs lock `F1`, so it stays put.

   </details>

2. Cell A2 shows `1001`, but it sits at the left edge of the cell. Write a formula that answers TRUE
   only when A2 holds a real number, and say what it returns here.

   <details>
   <summary>Answer</summary>

   **`=ISNUMBER(A2)`**. It returns FALSE: the cell holds text that looks like a number, which is why it
   is left-aligned. Numbers are right-aligned by default.

   </details>

3. In a tidy sheet, how many facts go in one cell?

   <details>
   <summary>Answer</summary>

   One. Today's lesson is what you do when a cell arrives with three.

   </details>

A **text function** takes text in and gives text out. Almost every cleaning job is the same three moves,
in this order:

1. **Clean:** `TRIM` removes the stray spaces, `UPPER`, `LOWER` or `PROPER` fix the case.
2. **Cut:** `LEFT`, `MID` and `FIND` pull out the part you need. `MID(text, start, length)` counts
   characters from 1.
3. **Convert:** a cut-out piece is still text. `VALUE` turns `"1001"` into the number 1001, so it can
   match, sort and add up.

Every result goes in a **new column**. The raw column is never overwritten.

## Worked example

Question: **do all 1,800 till codes match an order, and how many orders did each store take?** Open the
practice file and follow along. Write the formulas on `calc`.

1. **Say what one row is.** In `raw_till_export`, one row is one till code, which stands for one order.
   There is a header in row 1 and the last code is on row 1801.
   *Why:* if the export holds 1,800 codes and the order list holds 1,800 orders, the match we are after
   is one-to-one.

2. **Clean the code.** In `calc!A2` type `=UPPER(TRIM(raw_till_export!A2))` and press Enter.
   Row 2 held `··s2-1001-mobile` (16 characters, `=LEN(raw_till_export!A2)` shows it) and now holds
   `S2-1001-MOBILE` (14 characters).
   *Why TRIM first:* the next steps cut by position, and two stray spaces would shift every position.
   *Why UPPER:* `=` and `COUNTIFS` ignore case, but SQL and Python will not, so `s2` and `S2` must become
   one spelling now.

3. **Cut out the store.** In `calc!B2` type `=VALUE(MID(A2,2,1))`. It returns the number **2**.
   *Why MID and VALUE:* the store is the character at position 2. It comes out as text, and
   `raw_orders` stores `store_id` as a number, so we convert before we compare.

4. **Cut out the order number.** In `calc!C2` type `=VALUE(MID(A2,4,4))`. It returns **1001**.
   *Why 4 characters:* order numbers in this export always have four digits, so the start and length are
   the same on every row.

5. **Fill down.** Select B2:C2 and fill down to row 1801 (double-click the fill handle, or **Ctrl+D**
   over the selection). Check the last row: `calc!C1801` should read **2800**, the last order.

6. **Match every code to an order.** In `calc!D2` type
   `=COUNTIFS(raw_orders!$A$2:$A$1801,C2,raw_orders!$C$2:$C$1801,B2)` and fill down. It counts the
   orders that have this order number **and** this store. A good row returns **1**.
   *Why both conditions:* an order number alone could match an order from another store, and that would
   be a wrong match that looks right. The `$` signs lock the ranges so they do not slide when you fill
   down.

7. **Reconcile.** Type `=SUM(D2:D1801)`. It shows **1800**: all 1,800 codes match one order each.
   Then count the stores: `=COUNTIFS(B2:B1801,1)`, the same with 2 and with 3. You get **729**, **716**
   and **355**. Compare with the order list: `=COUNTIFS(raw_orders!C2:C1801,1)` (then 2 and 3) gives
   the same three numbers, from a different sheet.

That answers the owner: **yes, all 1,800 till codes match an order. Old Town (store 1) took 729 orders,
Campus (store 2) took 716 and Harbor (store 3) took 355.**

<details>
<summary>Explain it in your own words: why did step 2 come before steps 3 and 4?</summary>

Because `MID` counts characters from the left edge of the cell. With two spaces in front, `MID(A2,2,1)`
would return a space, not the store. Cleaning first makes the positions the same on every row.

</details>

<Aside type="tip" title="Splitting and joining in one formula">
If the pieces are separated by a character, there are shortcuts. **Excel for Microsoft 365 and Excel 2024:**
`=TEXTSPLIT(A2,"-")` spills the three pieces across three cells, and `=TEXTBEFORE(A2,"-")` and
`=TEXTAFTER(A2,"-")` return one piece each (`TEXTBEFORE` is case-sensitive unless you ask otherwise).
**Google Sheets:** these three are not in Google's function list; use `=SPLIT(A2,"-")` instead, which
puts each piece in its own cell. Pieces come back as text, so check with `ISNUMBER` and convert with
`VALUE` where you need numbers.

Joining is the mirror image. `=B2&"-"&C2` glues two cells with a hyphen and works everywhere.
`=TEXTJOIN("-",TRUE,B2,C2)` does the same with any delimiter, and `TRUE` skips empty cells. It is in
Excel 2019 and later, and in Sheets.
</Aside>

<Aside type="tip" title="The three-sheet habit, again">
`raw_till_export` was never edited. If a formula in `calc` goes wrong, delete it and start again: the
export is still there, spaces and all.
</Aside>

<Exercise id="excel-text-functions-1">

**How many orders were paid by card, by mobile and by cash, according to the till export?** Expected
output: three counts that add up to 1,800 and equal the counts in `raw_orders`.

Work on the sheet `calc_ex1`. The first steps are done for you:

1. One row is one till code. Row 1 is the header.
2. `calc_ex1!A` holds the clean code, `=UPPER(TRIM(raw_till_export!A2))`, filled down to row 1801, with the
   store in B and the order number in C.

Now finish it: cut out the payment method, count each method, and compare with `raw_orders`
(`payment_method` is column F there).

<details>
<summary>Hint</summary>

The payment method starts at position 9 and runs to the end of the code. Which function cuts from a
start position, and which one makes the result lowercase so it looks like the order list?

</details>

<details>
<summary>Half-solution</summary>

In `calc_ex1!D2` use `=LOWER(MID(A2,9,10))` and fill down. Count with `=COUNTIFS(D2:D1801,"card")` and the
same for `"mobile"` and `"cash"`. If your three counts add up to one less than 1,800, do not type a
correction: find the one code that did not clean. `=LEN(D2)` should be 4 for card and cash and 6 for
mobile.

</details>

<Solution>

1. In `calc_ex1!D2`: `=LOWER(MID(A2,9,10))`, filled down. Row 2 gives `mobile`.
2. The counts: **card 1,000, mobile 546, cash 253**. That adds up to **1,799**, one short. The order list
   says card 1,001.
3. Find the missing code. In `calc_ex1!E2` type `=LEN(D2)` and fill down. Card and cash should be 4, mobile 6.
   One row returns **5**: row 802, order 1801. Its code ends with a **non-breaking space**
   (character 160). Microsoft's page on `TRIM` says it removes the space character with code 32 and
   "does not remove" the non-breaking space, and Google's page on `TRIM` says the same for Sheets.
   That left `card` with a hidden character, so it did not count as `card`.
4. Fix the cleaning step, not the count. In `calc_ex1!A2` use
   `=UPPER(TRIM(SUBSTITUTE(raw_till_export!A2,UNICHAR(160)," ")))` and fill down. `SUBSTITUTE` swaps the
   hidden character for an ordinary space, and `TRIM` then removes it. `UNICHAR(160)` returns the same
   character on every computer; `CHAR(160)` depends on the computer's own character set, according to
   Microsoft's page on `CHAR`.
5. The counts now read **card 1,001, mobile 546, cash 253**, total **1,800**, and all three equal the
   counts in `raw_orders`.

Why fix the formula: next week's export will have another hidden character somewhere. A repaired formula
cleans it on its own; a hand-typed fix does not.

</Solution>

</Exercise>

<Solution>

The sentence: *"150 rows, one per customer; columns customer_id (number), city (Proper case), tier
(lowercase), label."*

Helper columns that work in Excel and in Sheets, with the raw cell in `raw_customer_export!A2`:

| Column | Formula | Row 2 gives |
|---|---|---|
| `member_part` | `=LEFT(raw_customer_export!A2,FIND("\|",raw_customer_export!A2)-1)` | `··C-0001·` |
| `rest` | `=MID(raw_customer_export!A2,FIND("\|",raw_customer_export!A2)+1,200)` | `·BERKELEY\|bronze·` |
| `city_part` | `=LEFT(B2,FIND("\|",B2)-1)` | `·BERKELEY` |
| `tier_part` | `=MID(B2,FIND("\|",B2)+1,200)` | `bronze·` |
| `customer_id` | `=VALUE(MID(TRIM(A2),3,10))` | 1 |
| `city` | `=PROPER(TRIM(C2))` | Berkeley |
| `tier` | `=LOWER(TRIM(D2))` | bronze |
| `label` | `=F2&" ("&G2&")"` | Berkeley (bronze) |

In Excel for Microsoft 365 you can shorten the first four columns, for example
`=TRIM(TEXTBEFORE(raw_customer_export!A2,"|"))` for the id part.

Why this works where a fixed position does not: the three ids `C-7`, `C-62` and `C-118` are written without
zero padding. A formula that cuts the whole packed cell by position, such as
`=VALUE(MID(TRIM(raw_customer_export!A2),3,4))`, works on 148 rows and returns `#VALUE!` on two of them (`C-7`
and `C-62`); `C-118` survives only because of how its spaces happen to fall. The `|` is the one thing that
stays in place, so we cut at the `|`.

**Check:**

- `=COUNT(customer_id column)` gives **150** and `=SUM(...)` gives **11325** (the ids 1 to 150 added up,
  which also proves no id was lost or doubled).
- `=COUNTIFS(city column,"Alameda")` gives **60**, `"Berkeley"` **46**, `"Oakland"` **44**.
- `=COUNTIFS(tier column,"bronze")` gives **85**, `"silver"` **50**, `"gold"` **15**.

All of these match `raw_customers`.
