2. An imported column holds dates like `03/04/2026` and `11/02/2026`. How can you tell whether the first
   pair of digits is the month or the day (from [*Numbers are not numbers until you check*](/excel/numbers-dates-text-types/#the-picture), E4)?

   <details>
   <summary>Answer</summary>

   Look for a value where one pair is above 12. That pair cannot be a month, so it must be the day. If no

   </details>

3. From [*Cleaning text with TRIM, LEFT and TEXTSPLIT*](/excel/text-functions/#the-picture) (E10): A2 holds the text `2026-03-01`. Write a formula that returns the month part, `03`.

   <details>
   <summary>Answer</summary>

   **`=MID(A2,6,2)`**. Start at character 6 and take 2. The result is still text.

   </details>

A **date** is a number: the count of days since a starting day. Excel and Sheets both show it in a
costume, the **date format**, and you can change the costume without changing the number. A date written
as **text** is not a number at all, so it cannot be subtracted, it cannot be compared with another date, and
it sorts character by character, as the second picture shows.

Three building blocks cover most work:

- **Build and split:** `DATE(year, month, day)` builds a date from three numbers. `YEAR`, `MONTH` and `DAY`
  take a date apart.
- **Subtract:** one date minus another is the number of days between them.
- **Month end:** `EOMONTH(date, months)` returns the last day of a month: `months` of 0 means the month of
  `date`, 1 means the next month.

## Worked example

Question: **how long has the loyalty program been running, and how many members joined each month?** Open
the practice file and follow along. Write the formulas on `calc`.

1. **Say what one row is.** In `raw_signups_text`, one row is one customer. Row 1 is the header and the
   last row is 151: **150 customers**.
   *Why:* a count of members per month only works if each member is on one row.

2. **Check what is stored.** Type `=ISNUMBER(raw_signups_text!B2)`: it returns **FALSE**. The cells are
   left-aligned, and `=MIN(raw_signups_text!B2:B151)` returns **0**, because `MIN` skips text and finds
   no numbers. Sort the column A to Z (on a copy, never on the raw sheet) and the first value is
   `01/02/2026`, which is January 2026, ahead of every date from 2025.
   *Why check first:* a total or a minimum that quietly returns 0 is the most common sign of text dates.

3. **Find out which format it is.** Scan the column for a pair above 12. You find values such as
   `06/26/2026`: the second pair goes up to 26, and the first pair never goes above 12. So the format is
   **month/day/year**.
   *Why:* `06/04/2025` can be 4 June or 6 April. The data answers the question, so you do not have to guess.

4. **Build the real date.** In `calc!B2` type
   `=DATE(VALUE(RIGHT(raw_signups_text!B2,4)),VALUE(LEFT(raw_signups_text!B2,2)),VALUE(MID(raw_signups_text!B2,4,2)))`
   and fill down to row 151. Format column B as `yyyy-mm-dd` (in Excel, **Ctrl+1**, Custom; in Sheets,
   **Format > Number**). Row 2 shows **2025-06-04**.
   *Why DATE from pieces:* it does not depend on anyone's regional settings. Microsoft's page on `DATEVALUE`
   says your computer's date setting "may cause the results of a DATEVALUE function to vary", and
   Google's says the formats it understands "may depend on region and language settings". Why `VALUE` around
   each piece: Google's page on `DATE` says its inputs must be numbers, and `LEFT`, `MID` and `RIGHT` return
   text.

   **On a phone (Google Sheets app):** tap **B2**, tap the **Format** icon and pick a date format from the
   list (tap **More date/time** for more). Google's phone help lists ready-made formats only, so if none
   writes the year first, type `=TEXT(B2,"yyyy-mm-dd")` in a spare column to see the same date as text.

5. **See the number.** Select B2 and format it as **General**: it shows **45812**. That is the count of
   days since the starting day, and both apps count the same way for dates like these. Microsoft's `DATE`
   page says January 1, 2008 is 39448; Google's says Sheets counts from December 30, 1899, and 39448 days
   after that day is also January 1, 2008. Put the `yyyy-mm-dd` format back.

6. **Subtract to get a duration.** Type `=MAX(B2:B151)-MIN(B2:B151)`. It returns **387**: the first
   sign-up was on 2025-06-04 and the newest on 2026-06-26, so the program has been running 387 days
   between its first and its newest member. For "how long since the newest member as of June 30"
   type `=DATE(2026,6,30)-MAX(B2:B151)`: **4** days.
   *Why `DATE(2026,6,30)` and not `TODAY()`:* the data ends on June 30, 2026, and `TODAY()` would give a
   different answer every day.

7. **Bucket by month.** In `calc!C2` type `=EOMONTH(B2,0)` and fill down: every date becomes the last day
   of its month (row 2 gives 2025-06-30). On `output`, type `=EOMONTH(DATE(2025,6,1),0)` in A2 and
   `=EOMONTH(A2,1)` in A3, and fill A3 down to A14: thirteen month ends, from June 2025 to June 2026.
   In B2 type `=COUNTIFS(calc!$C$2:$C$151,A2)` and fill down.
   *Why month ends:* many different dates share one month end, so it works as a key you can count by.

8. **Reconcile.** The thirteen counts are **16, 11, 10, 12, 8, 18, 10, 11, 11, 9, 8, 10, 16**. Add them:
   `=SUM(B2:B14)` returns **150**, the number of customers. Also check `=COUNT(calc!B2:B151)` is **150**
   (all real dates) and that sorting `calc!B` puts 2025-06-04 first and 2026-06-26 last.

That answers the owner: **the program has run 387 days from its first member to its newest, the newest
joined 4 days before the end of June, and about 8 to 18 members joined each month.** (The busiest month
was November 2025 with 18; June 2025 and June 2026 each had 16.)

<details>
<summary>Explain it in your own words: why did step 3 come before step 4?</summary>

Because the pieces you cut out mean different things in different formats. `LEFT(…,2)` is the month only
if the text is month/day/year. If you build the date first and look afterwards, a wrong guess gives
plausible dates, and nothing warns you.

</details>

<Aside type="tip" title="Working days">
Both Excel and Google Sheets have `NETWORKDAYS`, which counts working days between two dates. We only
mention it here; the subtraction above counts every calendar day.
</Aside>

<Aside type="caution" title="Date setting in Google Sheets">
In Sheets, **File > Settings** sets the spreadsheet's locale, which Google's page says "changes the
spreadsheet's default currency, date, and number formatting". Open your file and check the locale before
you trust how it displays a date. A date built with `DATE` stays the same number either way.
</Aside>

## Check yourself

1. Without looking back: why does `=MIN()` over a column of text dates return 0?

   <details>
   <summary>Answer</summary>

   Because text dates are not numbers. `MIN` ignores text, finds no numbers, and returns 0. A real date is a
   number, so `MIN` returns the earliest one.

   </details>

<Exercise id="excel-date-functions-3">

**Spot the flaw.** Open `calc_ex3`: a colleague has a text date `2026-02-30` from a till export in A2. She
built the date in B2 with `DATE` from its pieces (that is `DATE(2026,2,30)`), saw `2026-03-02` and said: *"Great, no error, so the date is valid."* What went
wrong?

<details>
<summary>Hint</summary>

February 2026 has 28 days. What does `DATE` do with a day that is too big?

</details>

<details>
<summary>Half-solution</summary>

Both Microsoft's and Google's pages on `DATE` describe what happens to a month or day outside its range.
Does the function refuse it, or repair it?

</details>

<Solution>

`DATE` does not refuse a day that is too big: it rolls it over. Google's page says it "will silently
recalculate numeric dates which fall outside of valid month or day ranges", and Microsoft's gives
`DATE(2008,1,35)`, which returns February 4, 2008. So `DATE(2026,2,30)` is two days past the end of
February: March 2, 2026. The absence of an error proves nothing. The text date was invalid, and the
formula turned it into a different, valid date.

To catch it, compare the pieces with the result: `=DAY(B2)=VALUE(RIGHT(A2,2))` returns FALSE here
(`DAY` gives 2, the text says 30). Count the FALSE rows and look at each one.

</Solution>

</Exercise>
