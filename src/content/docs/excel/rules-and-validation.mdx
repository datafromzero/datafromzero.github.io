## Warm-up

Answer from memory before you open anything. Then click to check.

1. Write a formula that returns `"late"` when B2 is above 30 and `"ok"` otherwise.

   <details>
   <summary>Answer</summary>

   **`=IF(B2>30,"late","ok")`**. The condition, then the result when it is true, then the result when it is
   false.

   </details>

2. The formula `=$B2*C$1` sits in D2. You copy it to E3. Write what E3 holds.

   <details>
   <summary>Answer</summary>

   **`=$B3*D$1`**. The `$` before B locks the column, so it stays B; the row moves from 2 to 3. The `$` before
   1 locks the row, so it stays 1; the column moves from C to D.

   </details>

3. You filter a column to show one value. What happens to the other rows?

   <details>
   <summary>Answer</summary>

   They are hidden, not deleted. Clear the filter and they are back.

   </details>

A **rule** is a sentence the sheet can check. Two features turn the sentence into behavior:

- **Conditional formatting** paints cells or rows that meet a rule. The rule is checked again whenever
  the data changes. It changes how a cell looks, not what it holds.
- **Data validation** limits what can be typed into a cell: a value from a list, or a number in a range.
  It acts at entry.

They have one idea in common: write the rule as a sentence first ("if status is canceled, shade the
row"; "quantity is a whole number from 1 to 10"), and only then as a setting.

## Worked example

Question: **which orders are canceled, which cash orders were taken, and what is wrong in the order-lines
sheet?** Open the practice file and follow along.

1. **Say what one row is, and where to work.** In `raw_orders`, one row is one order. Select `raw_orders`
   A1:F1801, copy it, and paste it into `calc!A1`. Do the formatting on `calc`.
   *Why a copy:* the raw sheet stays as it arrived, as in every lesson.

2. **Write the first rule as a sentence.** *"Shade the whole row when status is `canceled`."* The status is
   in column E.

3. **Turn it into a rule.** Select `calc!A2:F1801`.
   - **Excel:** **Home > Conditional Formatting > New Rule > Use a formula to determine which cells to
     format**.
   - **Google Sheets:** **Format > Conditional formatting**, check that **Apply to range** is `A2:F1801`,
     then under **Format cells if** choose **Custom formula is**.

   Type `=$E2="canceled"`, choose a fill color, and confirm.
   *Why `$E2`:* the rule is written for the **first cell** of the range, A2, and then applied to every other
   cell as if it had been copied there. The `$` locks the column, so every cell in a row looks at column E;
   the missing `$` before 2 lets the row move, so each row looks at its own status. Google's page gives the
   same example, `=$B1="Yes"`, to shade a whole row. Microsoft's says that a formula rule "must return True
   or False" and that you should use relative references if you want Excel to adjust the references for each
   cell in the selected range.

4. **Check the rule against a count.** One row on the sheet is shaded: row **462**, order **1461**, taken at
   Campus on March 1 and paid in cash. Now `=COUNTIFS(E2:E1801,"canceled")` gives **1**. The number of
   shaded rows (1) and the count (1) agree.
   *Why check:* a rule can be wrong without any error message. A count from a formula is the independent
   second opinion.

5. **Highlight single cells.** Select `calc!F2:F1801` (`payment_method`). In Excel, **Conditional Formatting >
   Highlight Cells Rules > Equal To**, type `cash`. In either app, the formula rule `=F2="cash"` does the
   same. Count: `=COUNTIFS(F2:F1801,"cash")` gives **253**.
   *Why this is a different kind of rule:* it paints only the cell it tests, and not the row. The canceled
   order's cash cell now matches both rules. Microsoft's page says a rule higher in the list "has greater
   precedence"; Google's says "the first rule found to be true will define the format".

6. **Restrict an entry to a list.** On `calc`, type `store` in H1 and select H2.
   - **Excel:** **Data > Data Validation**, **Allow: List**, and in **Source** type `Old Town,Campus,Harbor`
     (options separated by commas), keeping the in-cell dropdown ticked.
   - **Google Sheets:** **Data > Data validation > Add rule**, criteria **Dropdown from a range**, and pick
     `lists!A2:A4`. (**Dropdown** lets you type the items instead.)

   Click the arrow and pick **Harbor**. Then try typing `Harbour`: the entry is refused.
   *Why a list:* a free-text cell lets `Harbor`, `harbor` with a trailing space, and `Harbour` all in, and each is a different
   label to every tool that counts. The dropdown stops new spelling variants from getting in; it does not repair the old ones.

7. **Restrict an entry to a number range.** Type `quantity` in I1 and select I2.
   - **Excel:** **Data > Data Validation**, **Allow: Whole number**, **Data: between**, minimum 1, maximum
     10. On the **Error Alert** tab keep the style **Stop**.
   - **Google Sheets:** the same **Data validation** window, with a number criterion between 1 and 10.

   Type `3`: accepted. Type `20`: refused.
   *Why an alert style:* Microsoft lists three: **Stop** prevents the entry, **Warning** lets the user say
   yes or no, and **Information** only informs. Use Stop when the rule is a hard rule.

8. **Find what is wrong in an inherited sheet.** Open `raw_order_items`. Someone has already put a
   validation rule on the `quantity` column (whole number, 1 to 10). Which cell breaks it?
   - **Excel:** **Data > Data Validation arrow > Circle Invalid Data**. One cell is circled: **D1953**, order
     item 6952, order 2075, quantity **20**. Microsoft's page says the circles include values that were
     "typed, copied, or filled", and that this command is for the desktop versions of Excel.
   - **Google Sheets:** Google's help describes no circle command. Its filter menu can filter cells "that have
     valid or invalid data validation rules": filter the `quantity` column by that condition to list the
     offending cells.

   Check with a formula: `=COUNTIFS(D2:D3288,">10")` gives **1**, so the circle and the count agree.
   *Why the rule did not stop it:* Microsoft says validation is "designed to show messages and prevent
   invalid entries only when users type data directly in a cell", and that when data is copied or filled
   the messages do not appear. It also says Excel does not tell you about existing invalid data, which is
   what the circle command is for.

That answers the owner: **one canceled order (1461, on row 462), 253 cash orders, and one quantity of 20
on order item 6952 that breaks the rule of 1 to 10.** The dataset's own notes say that 20 was meant to be 2.

<details>
<summary>Explain it in your own words: why does the rule have a `$` before the E but not before the 2?</summary>

Because the rule has to do two opposite things at once. Every cell in a row must look at the same column
(E, so the `$` locks it), and every row must look at its own status (so the row number must be free to move).

</details>

<Aside type="note" title="Excel and Google Sheets">
Conditional formatting and data validation exist in both, with different menus. **Circle Invalid Data** is
an Excel desktop command; in Sheets you filter by the data validation condition instead. In Sheets, an
entry that is not on a dropdown list is rejected unless you open **Advanced options** and set the invalid-data
action to **Show a warning**.
</Aside>

## Finish it

<Exercise id="excel-rules-and-validation-1">

**Shade the rows of Harbor orders paid in cash.** Work on `calc_ex1`. Expected output: every matching row
shaded, and a count from a formula that agrees with the number of shaded rows.

The first steps are done for you:

1. One row is one order. `calc_ex1` already holds a copy of `raw_orders` in `A1:F1801`.
2. The rule as a sentence: *"Shade the whole row when `store_id` is 3 and `payment_method` is `cash`."*
   Harbor is store 3.

Now finish it: write the formula rule, apply it to the right range, and check it with a count.

<details>
<summary>Hint</summary>

You need a formula that is TRUE only when both conditions hold. Which function from the IF lesson combines two
conditions? Which column letters need a `$`, and which part must stay free?

</details>

<details>
<summary>Half-solution</summary>

Select `A2:F1801`, choose a formula rule, and write the formula for the first cell, A2: an `AND` of one test on
column C and one test on column F, with the column locked in both. The count is a `COUNTIFS` with the same two
conditions.

</details>

<Solution>

1. On `calc_ex1`, select `A2:F1801` and add a formula rule: `=AND($C2=3,$F2="cash")`. Each `$` locks a column so every
   cell in the row tests columns C and F; the row number stays free.
2. Check: `=COUNTIFS(C2:C1801,3,F2:F1801,"cash")` gives **55**. Fifty-five rows are shaded.
3. A sanity check from the other side: the cash orders in total are **253** (from the worked example), and Campus
   and Old Town took the rest, so 55 is plausible for the smallest store.

If you had written `=AND(C2=3,F2="cash")` with no `$`, the rule would slide right with each column, and only
the cells in column A would ever be shaded; the spot-the-flaw exercise below shows the same effect.

</Solution>

</Exercise>

write down why 10 is the limit.

</Solution>

<Exercise id="excel-rules-and-validation-3">

**Spot the flaw.** Open `calc_ex3`, a colleague's sheet. She wants the canceled order's whole row shaded, so she
selected `A2:F1801` and wrote the rule `=E2="canceled"`. Only the `order_id` cell of order 1461 (A462) turns red,
not the row. She says: *"Conditional formatting can't shade a whole row."* What is wrong, and what is the fix?

<details>
<summary>Hint</summary>

The rule is written for the first cell, A2, and applied to the others as if it had been copied. Copied one
column to the right, what does `=E2="canceled"` become for B462?

</details>

<details>
<summary>Half-solution</summary>

For B462 it becomes `=F462="canceled"`, and for C462 `=G462="canceled"`. What is in F462 and G462?

</details>

<Solution>

Conditional formatting can shade a whole row; her rule does not ask it to. Without a `$`, the formula slides to the
right with each column: A462 tests `E462` (which is `canceled`, so it is shaded), B462 tests `F462` (`cash`),
C462 tests `G462` (empty), and so on. Only the cell in column A ever sees the word, so only A462 is shaded.

The fix is to lock the column: `=$E2="canceled"`. Now every cell in a row looks at column E of its own row.
Check with a count: `=COUNTIFS(E2:E1801,"canceled")` is **1**, and the shaded row must be the one row, **462**. It is
the same mistake as copying a formula without its `$`; this lesson is the cell-references lesson again, working in a
rule.

</Solution>
