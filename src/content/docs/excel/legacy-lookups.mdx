## Warm-up

Answer from memory before you open anything. Then click to check.

1. In `raw_products` the codes are in A2:A17 and the prices in D2:D17. Write the formula that brings the
   price for the code in B2, so that it survives being filled down.

   <details>
   <summary>Answer</summary>

   `=XLOOKUP(B2,raw_products!$A$2:$A$17,raw_products!$D$2:$D$17)`. B2 is free to move down with each
   row, and both ranges are locked.

   </details>

2. What does a lookup show when the code is not in the table, and how do you change that?

   <details>
   <summary>Answer</summary>

   `#N/A`. Give the fourth argument, for example `"not on menu"`, and the row shows those words instead.

   </details>

3. You fill a formula down and check only the first row. It is right. Why is that not enough?

   <details>
   <summary>Answer</summary>

   Because a reference that is not locked slides as you fill down, and the cells further down may
   point at the wrong place. One correct cell is not yet a correct column: check a row far down too.

   </details>

## The question

The owner of the cafes asks:

> A colleague left me this price sheet, `raw_inherited`. It has four price columns that should all show
> the same price. Can I trust them? And can you write the one we use now?

The sheet has twelve order lines (`order_item_id`, `product_id`, `quantity`, `discount_usd`) and four
columns of formulas. Here are the formulas of row 2:

| Column | Formula in row 2 |
|---|---|
| `price_a` | `=VLOOKUP(B2,raw_products!$A$2:$D$17,4,FALSE)` |
| `price_b` | `=INDEX(raw_products!$D$2:$D$17,MATCH(B2,raw_products!$A$2:$A$17,0))` |
| `price_c` | `=VLOOKUP(B2,raw_old_menu!$A$2:$D$14,4)` |
| `price_d` | `=VLOOKUP(B2,raw_menu_v2!$A$2:$E$17,4,FALSE)` |

By the end of this lesson you will read each of these formulas aloud, rewrite one as `XLOOKUP`, and
know which two warning signs to look for in any workbook you inherit.

All three formulas in the first picture do the same job, and each has the same four parts: what to find,
where to look, what to bring back, and whether the match must be exact. They only write the parts in a
different order. `XLOOKUP` is the one to write today, but the other two are in countless files, and
you will be asked to read them. (`HLOOKUP` is `VLOOKUP` turned on its side: it searches the top row of
a table and brings back a value from a row number you give.)

The second picture shows the two warning signs that make an old lookup silently wrong, and neither shows
an error. Both are explained in the worked example and used in *On your own*.

## Worked example

Question: **is `price_a` right, and what are the same formula as `XLOOKUP` and as `INDEX` with `MATCH`?**
Open `raw_inherited` and follow along. Do not change it: it is raw data.

1. **Read the `VLOOKUP` in four parts.** Click `price_a` in row 2 and read
   `=VLOOKUP(B2,raw_products!$A$2:$D$17,4,FALSE)` from left to right:
   - `B2`: what to find, the product code of this line;
   - `raw_products!$A$2:$D$17`: where to look. `VLOOKUP` always searches the **first column** of this
     table, here column A, and the table must include the column you want back;
   - `4`: bring back the **4th column** of the table, counting from its first column. Column D is the
     fourth, and it holds `unit_price_usd`;
   - `FALSE`: the match must be exact.

   *Why read it in this order:* the four parts are always there. Once you can name them you can read
   any lookup, in any file, in any order. In Google Sheets the same formula has the same four parts,
   called `search_key`, `range`, `index` and `is_sorted`.

2. **Write the `XLOOKUP` twin.** In `calc!A2` type:

   ```text
   =XLOOKUP(raw_inherited!B2,raw_products!$A$2:$A$17,raw_products!$D$2:$D$17)
   ```

   and fill down to row 13. The table of `VLOOKUP` splits into two ranges: the column to search, and the
   column to bring back. The `4` is gone, and so is `FALSE`: exact is what `XLOOKUP` does unless you
   say otherwise. *Why this is better:* a column number is a number someone typed, and Excel will not
   keep it in step with the table. A range is attached to its column.

3. **Read the `INDEX` with `MATCH`, inside out.** Read `price_b`:
   `=INDEX(raw_products!$D$2:$D$17,MATCH(B2,raw_products!$A$2:$A$17,0))`. The inner part is `MATCH`:
   it returns the **position** of B2 in the list of codes. For code 6, `MATCH` returns 6, because 6 is
   the sixth code in the list. The outer part is `INDEX`: it returns the item at that position in the list
   of prices. The sixth price is **4.75**. *Why two functions:* the first finds where, the second says
   what is there. The final `0` of `MATCH` means exact. If you leave it out, `MATCH` assumes `1`, which
   expects a sorted list and returns the largest value that does not exceed the one you ask for.

4. **Check that the readings agree.** In `calc!B2` type
   `=AND(raw_inherited!E2=A2,raw_inherited!F2=A2)` and fill down to row 13. Every row shows `TRUE`: the
   `VLOOKUP`, the `INDEX` with `MATCH` and your `XLOOKUP` return the same price on all 12 lines.
   *Why:* three formulas written three ways that agree are a stronger proof than one formula you
   believe.

5. **Know the two warning signs.** Two details in a lookup never produce an error, and both
   have the same effect: a wrong price that looks like a price.
   - **The last argument is missing.** `VLOOKUP` and `HLOOKUP` default to an *approximate* match when
     you leave it out. Microsoft's page says: *"If you don't specify anything, the default value will
     always be TRUE or approximate match."* Google Sheets does the same with `is_sorted`. An approximate
     match expects the first column to be **sorted**, and when the code is not there it returns the row
     of the closest code that does not exceed it (Microsoft's `MATCH` page spells the rule out). It gives
     `#N/A` only if your code is smaller than the first one in the list.
   - **A column number typed into the formula.** The `4` does not follow the price column. If someone
     inserts a column into the table, the same `4` points at a different column.

   *Why these two:* an error value is loud. These two are quiet, so they are the first things to
   check in an inherited workbook.

<details>
<summary>Explain it in your own words: why does a missing last argument not show an error, even when the code is not in the list?</summary>

Because approximate match is not "find it or fail". It is "find the closest row that does not go
above". Unless your code is smaller than every code in the list, there is always such a row, so a price
comes back, only it is the price of a neighbor.

</details>

<Aside type="tip" title="Which one do you write?">
Write `XLOOKUP`. Keep `VLOOKUP` and `INDEX` with `MATCH` for reading, and for files that must open in an
older Excel: Microsoft's page says `XLOOKUP` is not available in Excel 2016 and Excel 2019, while
`INDEX` with `MATCH` works there. Google Sheets has all of them.
</Aside>

## Finish it

<Exercise id="excel-legacy-lookups-1">

**Translate a store lookup.** A colleague's report has this formula, where B2 holds a `store_id`:

```text
=VLOOKUP(B2,raw_stores!$A$2:$D$4,3,FALSE)
```

`raw_stores` has the columns `store_id`, `store_name`, `city` and `opened_on`. Write the same lookup as an
`XLOOKUP` and as an `INDEX` with `MATCH`, and say what each returns for `store_id` 3 and for 4. Expected
output: two formulas, and two results.

The first steps are done for you:

1. What to find: `B2`. Where to look: the first column of the table, `raw_stores!$A$2:$A$4`.
2. What to bring back: the third column of the table, counting from column A.

Now finish it: name the column to bring back, write both formulas, and try 3 and 4 in B2 on `calc`.

<details>
<summary>Hint</summary>

Which column is the third one counted from column A? In `XLOOKUP` and in `INDEX`, you point at that
column directly, with a range.

</details>

<details>
<summary>Half-solution</summary>

The third column is `city`, which is `raw_stores!$C$2:$C$4`. `XLOOKUP` takes the find cell, the column to
search and this column. `INDEX` takes this column and a `MATCH` of the find cell in `raw_stores!$A$2:$A$4`
with `0` at the end.

</details>

<Solution>

```text
=XLOOKUP(B2,raw_stores!$A$2:$A$4,raw_stores!$C$2:$C$4)
=INDEX(raw_stores!$C$2:$C$4,MATCH(B2,raw_stores!$A$2:$A$4,0))
```

For `store_id` 3 both return **Alameda** (Harbor), and so does the original `VLOOKUP`. For 4 there is no
such store, so all three return `#N/A`. Give `XLOOKUP` a fourth argument, such as `"no such store"`, to
show words instead.

</Solution>

</Exercise>

**Spot the flaw.** A colleague inherits `price_c`, tests it on four codes, 1, 3, 10 and 15, and gets
the right price each time. "It works: no errors and the right prices." What went wrong with the test?

<Solution>

All four codes are in `raw_old_menu`, so the test only tried the cases where an approximate match and
an exact match agree. A good test includes a code that is **not** in the list. Try 99, a code that
does not exist: `=VLOOKUP(99,raw_old_menu!$A$2:$D$14,4)` returns **5.50**, the price of the last row

above, as in the previous exercise.

Test a lookup with one code that is present, one that is absent and one that is outside the range. An
exact match with `FALSE` (or `XLOOKUP`) says `#N/A` for the absent ones, which is the honest answer.
