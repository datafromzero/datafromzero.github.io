## The question

The owner asks:

> What did order 1107 bring in?

Order 1107 has two lines, and each line has a discount. The price of each product is in the `products` table:

| order_item_id | product_id | quantity | discount_usd |
|---:|---:|---:|---:|
| 5192 | 5 | 2 | 0.50 |
| 5193 | 4 | 1 | 0.50 |

| product_id | product_name | unit_price_usd |
|---:|---|---:|
| 4 | Cappuccino | 4.50 |
| 5 | Mocha | 5.00 |

The amount of a line is `quantity × unit_price_usd − discount_usd`, and you will need it again for every line. This lesson names that step once, as a function, and uses it as often as you like. By the end of this page Python will total the order.

<Aside type="note" title="You already know this">

**Match.** The amount of a line is the computed column of *Computed columns and data types* (S5), `quantity * unit_price - discount`. A function is that formula with a name, so you can reuse it, as *Saving a query as a view* (S28) gives a query a name.

**Diverge.** A computed column works on every row by itself. A function works only on the values you hand it: one call, one answer. Later, the pandas method `apply` calls a function once for each value of a column. And `print` shows a value while `return` gives it back, which a spreadsheet formula always does (unit 2).

</Aside>

## Learn by doing

About 20 minutes, 4 new ideas: defining a function, `return` against `print`, default values and imports. The last unit only checks them.

<OpenInColab />

### 1. Define a function

**Idea.** `def` starts a function: its name, its parameters in brackets, a colon, and an indented body. `return` ends the function and hands a value back. A parameter is a name that takes the value of each call, as an input cell does.

**Try it:**

```python
def line_amount(quantity, unit_price, discount):
    return quantity * unit_price - discount


line_amount(2, 5.00, 0.50) + line_amount(1, 4.50, 0.50)
```

**Predict:** order 1107 has 2 Mochas and 1 Cappuccino, each line with a discount of 0.50. What does the last line give?

<details>
<summary>Reveal the result</summary>

```text
13.5
```

</details>

*Why:* the function ran twice. The first call gives 9.5 and the second 4.0, and because `return` hands each value back, the two can be added. That answers the owner: order 1107 brought in 13.5 dollars.

### 2. return is not print

**Idea.** `return` gives a value back to the place of the call. `print` only writes it on the screen.

**Try it:**

```python
def show_amount(quantity, unit_price, discount):
    print(quantity * unit_price - discount)


result = show_amount(2, 5.00, 0.50)
result is None
```

**Predict:** what do the two lines show, and is `result` a number?

<details>
<summary>Reveal the result</summary>

```text
9.5
True
```

</details>

*Why:* `print` wrote 9.5, so it looks right on the screen, but the function gave back nothing: a function with no `return` gives back `None`, so `result` is `None`. A calculation such as `result + 1` would stop with `TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'`.

### 3. Defaults

**Idea.** A parameter can have a default value, written `discount=0.0`. A caller may leave that argument out, or name it, as in lesson P2. A default turns a parameter into an optional argument of the formula.

**Try it:**

```python
def line_amount(quantity, unit_price, discount=0.0):
    return quantity * unit_price - discount


line_amount(3, 3.5), line_amount(2, 5.0, discount=0.5)
```

**Predict:** what do the two calls give?

<details>
<summary>Reveal the result</summary>

```text
(10.5, 9.5)
```

</details>

*Why:* the first call leaves the discount out, so it is 0.0 and the line is 3 times 3.5. 3,119 of the 3,287 order lines have no discount, so the default saves typing a zero. The second call names the argument, as in P2.

### 4. Import from the standard library

**Idea.** A module is a file of ready-made functions. `import math` makes `math.ceil` available, and `from statistics import mean` brings in one name. Python ships a standard library of such modules: `math`, `statistics`, `datetime`, `collections` and `random` are the ones you will meet. It is a function from a library, as `ROUNDUP` and `AVERAGE` are built in to Excel.

**Try it:**

```python
import math
from statistics import mean

math.ceil(4.25), round(mean([3.0, 3.5, 4.5]), 2)
```

**Predict:** a Bagel's 4.25 rounded up to a whole dollar, and the mean of three prices to two decimals. What do you get?

<details>
<summary>Reveal the result</summary>

```text
(5, 3.67)
```

</details>

*Why:* `ceil` rounds up to the next whole number, so 4.25 becomes 5. The mean of 3.0, 3.5 and 4.5 is 11 divided by 3, which `round` cuts to 3.67.

### 5. Check: predict, then run

`line_amount` and `mean` are defined above. Predict the three values, then run the cell.

```python
print(line_amount(2, 3.5))
print(line_amount(2, 5.0, discount=1.0))
print(round(mean([line_amount(1, 3.0), line_amount(1, 4.5)]), 2))
```

<details>
<summary>Reveal the result</summary>

```text
7.0
9.0
3.75
```

</details>

*Why:* the first call leaves the discount out, so it is 0.0; the second names the discount; the third passes two returned amounts to `mean`, which only works because the function returns them.

<Aside type="tip" title="Remember">

- `def name(parameters):` and an indented body define a function; the call fills the parameters.
- `return` gives a value back; `print` only shows it, and the call then gives back `None`.
- A parameter with a default, `discount=0.0`, may be left out by the caller.
- `import module` or `from module import name` brings in the standard library.

**Common trap:** a function that prints its answer. It looks right on the screen, but the value cannot be stored or added, because the call gave back `None`.

</Aside>
