## The question

The owner asks two things:

> What is a 5.00-dollar coffee worth in euros for a tour group that pays in euros, and how many orders did each cafe take?

The orders come from the till's database, and the exchange rate from outside. A few rows of the first table:

| order_id | customer_id | store_id |
|---:|---:|---:|
| 1001 | 15 | 2 |
| 1002 | 46 | 1 |
| 1003 | 61 | 2 |

By the end of this page you will ask an API for the rate, read the rows of a database into a table, and know why a value never goes into a query by pasting.

<Aside type="note" title="You already know this">

**Match.** In *GROUP BY and HAVING* (S8) a query with `GROUP BY store_id` gave one row for each store. The same query text goes to `pd.read_sql(query, con)`, and the answer comes back as a DataFrame you can group, reshape and chart.

**Diverge.** In the SQL stage you typed every value into the query yourself. In Python a value often arrives from a variable or from a user, and unit 4 shows what pasting it into the query text can do.

</Aside>

## The big idea

An API answers a request with a status code and data, usually JSON that becomes a table, and a database answers a query the same way; in both cases what you send must not be mixed up with what you ask.

### 1. Request, response, status code

**Idea.** An **API** is a web address that answers with data instead of a page. `requests.get(url, params=...)` sends a **request**: the address and a dictionary of **parameters**, which requests writes after a `?` in the address. The **response** carries a **status code**: 200 means it worked, and a code from 400 up means it did not. `response.json()` turns the body into Python lists and dicts. Some APIs ask for a secret key, which never goes into a notebook you share; this one needs none.

**Try it.** The dollar to euro rates for the working days from January 5 to 9, 2026:

```python
URL = "https://api.frankfurter.dev/v2/rates"
params = {"providers": "ecb", "from": "2026-01-05", "to": "2026-01-09", "base": "USD", "quotes": "EUR"}
response = requests.get(URL, params=params, timeout=30)
print(response.status_code)
print(response.url)
```

**Predict:** what will the status code be, and what will the address that was really sent look like?

<details>
<summary>Reveal the result</summary>

```text
200
https://api.frankfurter.dev/v2/rates?providers=ecb&from=2026-01-05&to=2026-01-09&base=USD&quotes=EUR
```

</details>

*Why:* 200, and the address is the URL followed by `?` and the five parameters joined by `&`: requests built the text for you. `providers=ecb` pins the provider, because the API's default blends several sources. Now an address that does not exist:

```python
missing = requests.get("https://api.frankfurter.dev/v2/nothing", timeout=30)
print(missing.status_code, missing.ok)
print(missing.text)
show_error("missing.raise_for_status()", short=True)
```

**Predict:** will `requests.get` stop with an error for a page that is not there? What will the status code, `ok` and the text of the answer be?

<details>
<summary>Reveal the result</summary>

```text
404 False
{"status":404,"message":"not found"}
requests.exceptions.HTTPError: 404 Client Error: Not Found for url: https://api.frankfurter.dev/v2/nothing
```

</details>

*Why:* it does not stop: the answer comes back with 404 and `ok` is `False`, and its text says what went wrong. `raise_for_status()` is the call that turns a bad code into an error, as the requests page says.

### 2. JSON in, DataFrame out

**Idea.** When the JSON is a list of records, one dict for each row, `pd.DataFrame(records)` makes a table with a column for each key. The dates arrive as text, so `pd.to_datetime` turns them into dates, as in lesson P17.

**Try it.** The five rates, and a coffee priced in euros each day:

```python
records = response.json()
print(type(records).__name__, len(records))
print(records[0])
rates = pd.DataFrame(records)
rates["date"] = pd.to_datetime(rates["date"])
rates["coffee_eur"] = (5.00 * rates["rate"]).round(4)
print(rates[["date", "rate", "coffee_eur"]])
```

**Predict:** how many records will there be, and on which day will the 5.00-dollar coffee be cheapest in euros?

<details>
<summary>Reveal the result</summary>

```text
list 5
{'date': '2026-01-05', 'base': 'USD', 'quote': 'EUR', 'rate': 0.85734}
        date     rate  coffee_eur
0 2026-01-05  0.85734      4.2867
1 2026-01-06  0.85419      4.2710
2 2026-01-07  0.85587      4.2794
3 2026-01-08  0.85653      4.2826
4 2026-01-09  0.85896      4.2948
```

</details>

*Why:* a list of 5 records, one for each working day, with the keys `date`, `base`, `quote` and `rate`. In these answers a row with base USD, quote EUR and rate 0.85734 gives the euros for one dollar, so a 5.00-dollar coffee is `5.00 * rate` euros. January 6 has the lowest rate, 0.85419, so the coffee is cheapest then, 4.2710 euros.

### 3. read_sql: a database as a source

**Idea.** `sqlite3` is in Python's standard library. `sqlite3.connect(":memory:")` makes an empty database that lives in memory. `table.to_sql("name", con, index=False)` writes a DataFrame into it as a table; here it only builds the database from the five cafe-sales tables, so that you need no file. `pd.read_sql(query, con)` runs a SQL query and returns its result as a DataFrame.

**Try it.** The query of S8, run from Python:

```python
con = sqlite3.connect(":memory:")
for name, table in {"stores": stores, "customers": customers, "products": products, "orders": orders, "order_items": order_items}.items():
    table.to_sql(name, con, index=False)
query = "SELECT store_id, COUNT(*) AS orders FROM orders GROUP BY store_id ORDER BY store_id"
per_store = pd.read_sql(query, con)
print(per_store)
```

**Predict:** what will `per_store` hold: how many rows and columns, and which counts?

<details>
<summary>Reveal the result</summary>

```text
   store_id  orders
0         1     729
1         2     716
2         3     355
```

</details>

*Why:* 3 rows and 2 columns: 729, 716 and 355 orders, the same counts as in P14, from a database this time.

### 4. Parameters, never pasted text

**Idea.** Put a `?` in the query where a value belongs, and pass the values in `params=(...)`. The database treats them as values and never as SQL. Gluing a value into the text with an f-string makes it part of the SQL. The `sqlite3` page says to use placeholders instead of string formatting, to avoid SQL injection attacks.

**Try it.** Both ways, with a value that a user typed into a search box, and an honest one first:

```python
sql = "SELECT COUNT(*) AS orders FROM orders WHERE store_id = ?"
print(pd.read_sql(sql, con, params=(3,)).iloc[0, 0])
store = "3 OR 1=1"
pasted = pd.read_sql(f"SELECT COUNT(*) AS orders FROM orders WHERE store_id = {store}", con).iloc[0, 0]
bound = pd.read_sql(sql, con, params=(store,)).iloc[0, 0]
print(pasted, bound)
```

**Predict:** how many orders will store 3 have? Then the user typed `3 OR 1=1`: how many will the pasted query and the parameter query count?

<details>
<summary>Reveal the result</summary>

```text
355
1800 0
```

</details>

*Why:* 355 for the honest value. The pasted query became `WHERE store_id = 3 OR 1=1`, which is true for every row, so it counted all 1,800 orders. The parameter was compared as the text it is and matched no store, so it counted 0. A pasted value can change what the query means.

### 5. Check: two routes to the same counts

Write down what you expect, then run the cell. `per_store` is the table of unit 3.

```python
by_groupby = orders.groupby("store_id").size()
print(per_store["orders"].tolist() == by_groupby.tolist(), per_store["orders"].sum())
```

**Predict:** does the database give the same counts as `groupby` on the table, and what do they add up to?

<details>
<summary>Reveal the result</summary>

```text
True 1800
```

</details>

*Why:* `True` and 1,800: the three counts add up to all the orders, the canceled one included.

<Aside type="tip" title="Remember">

- `requests.get(url, params=...)` sends the request; look at `response.status_code` and `response.ok` before you use `response.json()`.
- A list of records becomes a table with `pd.DataFrame(records)`; convert date text with `pd.to_datetime`.
- `pd.read_sql(query, con)` returns a query's result as a DataFrame.
- Put `?` in the query and pass the values in `params`; never paste them into the text.
- Reconcile: the same count from two routes.

**Common trap:** a value pasted into a query with an f-string becomes part of the SQL, so a typed `3 OR 1=1` counts every row.

</Aside>

def orders_in_city(city):
    sql = "SELECT COUNT(*) AS n FROM orders JOIN customers ON orders.customer_id = customers.customer_id WHERE customers.city = ?"
