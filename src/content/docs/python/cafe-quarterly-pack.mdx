### 1. Stack the monthly files with concat

**Idea.** `pd.concat([a, b, c])` puts the tables one under the other and lines their columns up by name, as the pandas page for `concat` describes. It takes a list of DataFrames.

**Try it.** Read the April, May and June files and stack them:

```python
frames = [pd.read_csv(f"monthly/orders_2026_{m:02d}.csv") for m in (4, 5, 6)]
stack = pd.concat(frames)
print(stack.shape, stack.index.is_unique)
```

**Predict:** the three files hold 349, 380 and 353 orders. What shape will `stack` have, and will its row labels be unique?

<details>
<summary>Reveal the result</summary>

```text
(1082, 6) False
```

</details>

*Why:* 1,082 rows is 349 + 380 + 353, with the same 6 columns. Every file brought its own row labels, 0 to its last row, so the labels repeat and the index is not unique. `ignore_index=True` numbers the rows again, as the pandas page says.

**Try it.** Stack them again with `ignore_index=True`:

```python
stack = pd.concat(frames, ignore_index=True)
print(stack.index.is_unique, stack.index.max())
```

**Predict:** will the labels be unique now, and what will the largest label be?

<details>
<summary>Reveal the result</summary>

```text
True 1081
```

</details>

*Why:* `True` and 1081: the 1,082 rows are numbered 0 to 1,081. From here on `stack` is the orders of the quarter.

### 2. Reconcile each step with assert

**Idea.** `assert condition, "message"` does nothing when the condition is true and stops with an `AssertionError` and your message when it is false, unless Python runs with the `-O` option, which turns `__debug__` off; the Python reference gives it as `if __debug__: if not condition: raise AssertionError`. After a step, assert a number you get a second way.

**Try it.** Join the order lines to the quarter's orders, price them, and compare with a second route that never merges. The lines come from `order_items` (3,287 lines for all six months):

```python
lines = order_items.merge(stack[["order_id", "store_id", "ordered_at"]], on="order_id", validate="many_to_one")
lines = lines.assign(amount=lines["quantity"] * lines["product_id"].map(price) - lines["discount_usd"])
# the second route: pick the quarter's lines with isin, price them with map, never merge
picked = order_items[order_items["order_id"].isin(stack["order_id"])]
picked_total = (picked["quantity"] * picked["product_id"].map(price) - picked["discount_usd"]).sum()
assert stack["status"].eq("completed").all(), "the pack counts completed orders only"
assert len(lines) == len(picked), "the merge changed the number of lines"
assert round(lines["amount"].sum(), 2) == round(picked_total, 2), "the two totals differ"
print(len(lines), round(lines["amount"].sum(), 2))
```

**Predict:** will `lines` have fewer, the same or more rows than the 3,287 lines of the whole file? Will any assert stop the cell? What will it print?

<details>
<summary>Reveal the result</summary>

```text
1979 13974.0
```

</details>

*Why:* nothing stopped, and the cell printed the rows and the total as recorded: 1,979 lines and 13,974.00 dollars. The quarter's orders are all completed, one merge and one `isin` found the same lines, and two sums gave the same total.

**Try it.** What does a failing assert print? Check the quarter against the whole year:

```python
show_error('assert len(stack) == 1800, "the quarter has fewer orders than the whole file"', short=True)
```

**Predict:** `stack` has 1,082 rows. What will the cell print?

<details>
<summary>Reveal the result</summary>

```text
AssertionError: the quarter has fewer orders than the whole file
```

</details>

*Why:* the error type, then your message. In a notebook a failed assert stops the cell, which is what you want from a check; `show_error` only keeps it from stopping Run all.

### 4. Write the note from variables

**Idea.** An f-string puts values into a sentence: `f"{store} sold {amount:,.2f}"` writes the value of each variable, and `:,.2f` gives thousands separators and 2 decimals. Write the note from the variables that hold the numbers, so that every figure in it is one the notebook computed.

**Try it.** The dataset README says one line has a quantity of 20 where 2 was meant: the line of order 2075, which sits in this quarter. Total each store as recorded and with that line counted as 2, and write the note:

```python
typo = lines["order_item_id"] == 6952
order_no, said, meant = lines.loc[typo, "order_id"].iloc[0], lines.loc[typo, "quantity"].iloc[0], 2
fixed = np.where(typo, meant * lines["product_id"].map(price) - lines["discount_usd"], lines["amount"])
totals = lines.groupby("store")["amount"].sum().sort_values(ascending=False)
fixed_totals = lines.assign(amount=fixed).groupby("store")["amount"].sum().sort_values(ascending=False)
first, second = totals.index[0], totals.index[1]
lead, lead_fixed = totals.iloc[0] - totals.iloc[1], fixed_totals.iloc[0] - fixed_totals.iloc[1]
note = (f"{first} sold the most from April to June 2026: {totals.iloc[0]:,.2f} dollars as recorded, {lead:,.2f} ahead of {second}. "
        f"One line of order {order_no} says {said} units where {meant} were meant; counted as {meant}, {first} leads by {lead_fixed:,.2f}. "
        f"Harbor, open since April 1, sold {totals['Harbor']:,.2f} in its first quarter.")
print(list(fixed_totals.index) == list(totals.index))
print(note)
```

**Predict:** does the order of the three stores change when the 20 counts as 2? Which store leads, and by how many dollars before and after?


</details>

*Why:* the order stays and the lead shrinks: the one line is worth 185.00 as recorded and 18.50 as 2 units, so 166.50 of the 230.50 lead was one typing slip. The note says so because its numbers come from `totals` and `fixed_totals`; change the data and the note changes with it, and a number typed by hand could not. The three sentences are the conclusion of the pack: who led and by how much, the caveat, and Harbor's first quarter.

<Aside type="tip" title="Remember">

- `pd.concat(list_of_tables, ignore_index=True)` stacks tables and numbers the rows again.
- After a merge, `assert` the row count and a total against a second route.
- A chart of bars starts at zero, and its numbers are the table's.
- Write the note with f-strings from variables, and put the caveat in it.

**Common trap:** trusting a stacked table because its row count is right.

</Aside>
