## The question

The owner asks:

> Count the drinks that the tills record, one name for each drink, and list the lines of the menu boards that name a café drink.

The same drink is typed in several ways at the tills, and the name of a drink on a menu board looks the same on each board:

| menu_item_id | store_id | product_id | board_name |
|---:|---:|---:|---|
| 1 | 1 | 1 | Café espresso |
| 17 | 2 | 1 | Café espresso |
| 33 | 3 | 1 | Café espresso |

The first table looks clean, and it still hides a trap. By the end of this page you will clean typed names, pull a size out of a note, and find out why a name that looks the same does not always match.

### 1. str: clean a whole column

**Idea.** `.str` opens the text methods of a column: `.str.strip()` cuts the spaces at both ends of each value, `.str.lower()` lowercases it, and `.str.replace(old, new)` swaps one text for another. Each returns a new column. Put it in a new column with `assign`, and the raw column stays as it was typed, as in E10.

**Try it.** Six till entries for two drinks, typed by different staff (a small list typed here, not cafe-sales data):

```python
till = pd.DataFrame({"typed": [" Latte", "latte ", "LATTE", "Cold  Brew", "cold brew", "Cold Brew "]})
till = till.assign(clean=till["typed"].str.strip().str.lower())
print(till["typed"].nunique(), till["clean"].nunique())
```

**Predict:** the six entries are two drinks, Latte and Cold Brew. How many different texts are in `typed`, and how many are left in `clean`?

<details>
<summary>Reveal the result</summary>

```text
6 3
```

</details>

*Why:* six in `typed` and three in `clean`, not two. `strip()` cut the spaces at the ends and `lower()` merged the capitals, but `Cold  Brew` has two spaces inside, and `strip()` leaves the inside alone. The Microsoft Support page says that `TRIM` removes all spaces except single spaces between words, so Excel would have merged them. Now the swap:

```python
till = till.assign(clean=till["clean"].str.replace("  ", " "))
print(till["clean"].nunique())
print(till["typed"].tolist())
```

**Predict:** after two spaces become one, how many texts are left in `clean`, and does `typed` still hold the six entries as typed?

<details>
<summary>Reveal the result</summary>

```text
2
[' Latte', 'latte ', 'LATTE', 'Cold  Brew', 'cold brew', 'Cold Brew ']
```

</details>

*Why:* two texts, one for each drink. `typed` is exactly as it was: `assign` made a new column, so the raw one can always be compared with the clean one. `replace` swaps the exact text you give it, two spaces here; the next unit gives a pattern that swaps any number.

### 2. A small regular expression

**Idea.** A regular expression is a pattern for text. `\d` matches one digit and `\s` one white space character (a space, a tab). `+` after a piece means one or more of it, and `*` means zero or more. Brackets mark the part to take out. `str.extract(pattern)` returns that part, and `str.replace(pattern, new, regex=True)` swaps whatever the pattern matches. The Python Regular Expression HOWTO lists them.

**Try it.** The size in ounces, inside notes typed at the till (a small list typed here, not cafe-sales data):

```python
notes = pd.Series(["Latte 12oz", "Mocha 16 oz", "Cold Brew 16OZ", "Espresso", "Chai Latte 12 oz", "Latte 16oz"])
sizes = notes.str.extract(r"(\d+)\s*oz", flags=re.IGNORECASE, expand=False)
print(sizes.tolist())
print(sizes.isna().sum())
```

**Predict:** the pattern takes the digits in front of `oz`, with or without a space, in any case. What does it return for each note, and for how many notes is there no size?

<details>
<summary>Reveal the result</summary>

```text
['12', '16', '16', nan, '12', '16']
1
```

</details>

*Why:* the sizes come back as text, `'12'` and `'16'`, and `Espresso`, which has no size, gives `nan`. To add them, turn the text into numbers with `astype(float)`. Now spaces of any number, and a tab:

```python
spellings = pd.Series(["Cold Brew", "Cold  Brew", "Cold   Brew", "Cold \tBrew"])
print(spellings.str.replace(r"\s+", " ", regex=True).nunique())
```

**Predict:** four spellings of one drink, with one, two or three spaces and with a space and a tab. How many different texts are left after the replace?

<details>
<summary>Reveal the result</summary>

```text
1
```

</details>

*Why:* one: `\s+` matches a whole run of white space, whatever its length and kind, and `" "` puts one space in its place.

### 3. NFC: texts that look the same

**Idea.** An accented letter can be stored in two ways, called **NFC** and **NFD**, and `.str.normalize("NFC")` turns every value of a column into the NFC form, as `unicodedata.normalize` does for one string.

**Try it.** Product 1 on the three boards. The setup cell made `menu`, and each board was typed on a different device:

```python
name1 = menu[menu["product_id"] == 1]
print(name1["board_name"].tolist())
print(name1["board_name"].str.len().tolist())
```

**Predict:** the three boards print the name of product 1 the same way. What are the lengths of the three texts?

<details>
<summary>Reveal the result</summary>

```text
['Café espresso', 'Café espresso', 'Café espresso']
[13, 14, 13]
```

</details>

*Why:* the three names print alike, but the lengths are 13, 14 and 13. In NFC, `é` is one character; in NFD it is an `e` followed by a separate accent mark, two characters, and the second board stores it that way. A filter on the typed name, `Café espresso`, will meet two of the three:

```python
typed_name = "Café espresso"
print((menu["board_name"] == typed_name).sum())
clean_names = menu["board_name"].str.normalize("NFC")
print((clean_names == typed_name).sum())
```

**Predict:** how many lines equal the typed name as stored, and how many after the whole column is normalized to NFC?

<details>
<summary>Reveal the result</summary>

```text
2
3
```

</details>

*Why:* 2 as stored, and 3 after normalizing: the typed name is in NFC, and the second board is in NFD, so the filter lost a line without a word. The Python page on `unicodedata` warns that two strings that look the same to a reader may not compare equal when one has combining characters and the other does not. Normalize to NFC before any filter, `groupby` or merge on a text that may have accents. The letters are the same to the eye and different to the computer.

### 4. Check: one name for each product

The products table has 16 products, and every product is on the board of each of the three cafes. After normalizing, one name must be one product. Write down what you expect, then run the cell.

```python
menu = menu.assign(clean_name=menu["board_name"].str.normalize("NFC"))
print(menu["clean_name"].nunique())
per_name = menu.groupby("clean_name").size()
print(per_name.min(), per_name.max())
```

**Predict:** how many different clean names are there, and how many lines does each one have?

<details>
<summary>Reveal the result</summary>

```text
16
3 3
```

</details>

*Why:* 16 names with 3 lines each, one line for each board: 48 lines, 16 products. `board_name` is untouched beside `clean_name`. A grouped count that is not the same for every name would have shown a name still split in two.

<Aside type="tip" title="Remember">

- `.str.strip()`, `.str.lower()` and `.str.replace()` clean a whole column. Put the result in a new column, so that the raw one stays.
- `strip()` cuts only the ends. `\s+` replaced by one space cuts the inside as well.
- `\d+` is one or more digits, `\s*` is any white space or none, brackets mark what `str.extract` returns.
- Normalize accented text to NFC before a filter, a `groupby` or a merge.

**Common trap:** two texts that print the same are not always equal: an accent can be stored as two characters.

</Aside>
