## The question

The owner asks:

> Which products brought in the most money, and how many orders did each cafe take?

The two lines of order 1107 hold an amount each, and an order holds a store:

| order_item_id | order_id | product_id | amount |
|---:|---:|---:|---:|
| 5192 | 1107 | 5 | 9.50 |
| 5193 | 1107 | 4 | 4.00 |

| order_id | store_id |
|---:|---:|
| 1001 | 2 |
| 1002 | 1 |
| 1003 | 2 |

The tables have one row for each line and one row for each order, and the owner wants one row for each product and one row for each cafe. By the end of this page you will sort, group and add up, then check the totals against numbers you already know.

<Aside type="note" title="You already know this">

**Match.** In *GROUP BY and HAVING* (S8), `SELECT store_id, COUNT(*) FROM orders GROUP BY store_id` gave one row for each store. `orders.groupby("store_id").size()` gives the same rows, as a PivotTable with the store in Rows does (*Summarize with a PivotTable*, E15). The `ORDER BY ... DESC` of *SELECT, ORDER BY and LIMIT* (S2) is `sort_values(..., ascending=False)`.

**Diverge.** In S8, `GROUP BY customer_id` made 146 groups: 145 customers and one group for the walk-in order, whose customer id is blank. What `groupby` does with a blank key is the second check of unit 2.

</Aside>

## Learn by doing

About 50 minutes, 4 new ideas: `sort_values`, `groupby`, named aggregation, and `size` against `count`. The last unit only checks them. The setup cell made `lines`, the order lines of lesson P13 with their price and amount.

### 1. sort_values, and where the blanks go

**Idea.** `table.sort_values("column")` returns the table with its rows in a new order, lowest first. `ascending=False` puts the highest first.

**Try it.** The three most expensive products:

```python
priciest = products.sort_values("unit_price_usd", ascending=False)
print(priciest[["product_name", "unit_price_usd"]].head(3))
print(products["product_id"].head(3).tolist(), priciest["product_id"].head(3).tolist())
```

**Predict:** which three products come first, and does `products` itself change its order?

<details>
<summary>Reveal the result</summary>

```text
           product_name  unit_price_usd
14      Turkey Sandwich            9.25
13        Avocado Toast            8.50
15  Pumpkin Spice Latte            5.50
[1, 2, 3] [15, 14, 16]
```

</details>

*Why:* the three most expensive are the Turkey Sandwich, the Avocado Toast and the Pumpkin Spice Latte. The numbers on the left are row labels, and they traveled with their rows (14, 13, 15). `products` still starts with products 1, 2 and 3: `sort_values` returned a new table. Now a column with blanks. `referred_by` holds the id of the customer who referred a customer, and it is blank for most customers:

```python
by_referrer = customers.sort_values("referred_by", ascending=False)
print(by_referrer["referred_by"].head(3).tolist())
print(by_referrer["referred_by"].tail(3).tolist())
```

**Predict:** sorted from the highest, are the first three values numbers or blanks, and the last three?

<details>
<summary>Reveal the result</summary>

```text
[117.0, 106.0, 88.0]
[nan, nan, nan]
```

</details>

*Why:* the blanks, shown as `nan`, came last, although the sort was descending. A descending sort does not bring them to the top. Excel does the same: its sort puts blank cells last, in ascending and in descending order (*Sort data in a range or table*, Microsoft Support). A parameter of `sort_values` decides where the blanks go, and the pandas page for `sort_values` documents it. Count the blanks before you read a sorted table, so that you know what is waiting at the bottom.

### 2. groupby: split, apply, combine

**Idea.** `table.groupby("key")` splits the rows into one group for each different value of the key. A calculation then runs on each group, and the results come back as a new table with one row for each group. `.size()` is the calculation that counts the rows of a group, the `COUNT(*)` of S8.

**Try it.** The orders of each cafe:

```python
per_store = orders.groupby("store_id").size()
print(per_store)
print(per_store.sum(), len(orders))
```

**Predict:** how many rows will `per_store` have, and will its numbers add up to the rows of `orders`?

<details>
<summary>Reveal the result</summary>

```text
store_id
1    729
2    716
3    355
dtype: int64
1800 1800
```

</details>

*Why:* one row for each store, ordered by store id, and the three counts add up to the 1,800 rows of `orders`: every order sits in exactly one group. Now the key with a blank, the customer of each order:

```python
per_customer = orders.groupby("customer_id").size()
print(len(per_customer), per_customer.sum())
```

**Predict:** the walk-in order has a blank `customer_id`. How many groups will there be, and will their sizes add up to 1,800?

<details>
<summary>Reveal the result</summary>

```text
145 1799
```

</details>

*Why:* 145 groups hold 1,799 orders. The walk-in order is in no group: by default, pandas leaves out the rows whose key is blank. The pandas page on groupby says that any group of blank keys will be dropped, and that the `dropna` parameter, `True` by default, is what decides it. Where S8 counted 146 groups, with one for the blank, pandas counts 145 and says nothing. A grouped result that does not add up to the table is the first thing to look for.

### 3. agg: several named results in one pass

**Idea.** `.agg(name=("column", "function"))` runs several calculations on each group at once. Each keyword is the name of a result column, and each value says which column to use and which function to apply: `"sum"`, `"mean"`, `"min"`, `"max"`, `"size"`. It is the several aggregates of one `SELECT` in S7, with a name for each result column.

**Try it.** One row for each product, with its units, its sales and its lines:

```python
by_product = lines.groupby("product_id").agg(
    units=("quantity", "sum"),
    sales=("amount", "sum"),
    n_lines=("order_item_id", "size"),
)
print(by_product.shape)
print(by_product.head(3))
```

**Predict:** how many rows and columns will `by_product` have? The `products` table has 16 products.

<details>
<summary>Reveal the result</summary>

```text
(15, 3)
            units   sales  n_lines
product_id                        
1             286   855.0      192
2             430  1498.0      293
3             653  2927.0      420
```

</details>

*Why:* 15 rows and 3 columns. A group exists only for a key that is in the data, and the Pumpkin Spice Latte, product 16, was never sold. The three result columns carry the names given in `agg`. Now the question of the owner, which product comes first by sales:

```python
ranked = by_product.sort_values("sales", ascending=False)
print(ranked.head(3))
```

**Predict:** which three product ids come first when the products are sorted by sales, highest first?

<details>
<summary>Reveal the result</summary>

```text
            units    sales  n_lines
product_id                         
3             653  2927.00      420
4             472  2115.50      305
15            213  1968.75      125
```

</details>

*Why:* products 3, 4 and 15 lead. The Turkey Sandwich, product 15, is third although it has only 125 lines, because each line is dear. Sorting the result of a `groupby` is the pandas form of `GROUP BY` followed by `ORDER BY`, and the sort is the last step.

### 4. size counts rows, count counts values

**Idea.** `size` counts the rows of each group. `count` counts the values that are not blank, one column at a time. They are the `COUNT(*)` and the `COUNT(column)` of *Counting and summing: aggregate functions* (S7), under two names. The pandas page on SQL says why it uses `size()` where SQL counts rows: `count()` goes column by column and counts the records that are not null.

**Try it.** The rows and the known customers of each payment method:

```python
by_method = orders.groupby("payment_method").agg(
    orders=("order_id", "size"),
    with_customer=("customer_id", "count"),
)
print(by_method)
print(by_method["orders"] - by_method["with_customer"])
```

**Predict:** the walk-in order has no customer id. For which payment method will the two numbers differ, and by how much?

<details>
<summary>Reveal the result</summary>

```text
                orders  with_customer
payment_method                       
card              1001           1001
cash               253            253
mobile             546            545
payment_method
card      0
cash      0
mobile    1
dtype: int64
```

</details>

*Why:* the walk-in order was paid by mobile, so mobile has 546 orders and 545 customer ids, and the other two methods have none missing. `size` counted the order, and `count` skipped its blank. Choose by the question: `size` for how many rows, `count` for how many values are there.

### 5. Check: the groups add up

Write down what you expect, then run the cell. The groups are the products of unit 3.

```python
print(by_product["sales"].sum(), lines["amount"].sum())
print(by_product["n_lines"].sum(), len(lines))
```

**Predict:** do the totals of the 15 groups equal the totals of the whole table?

<details>
<summary>Reveal the result</summary>

```text
22754.25 22754.25
3287 3287
```

</details>

*Why:* the same control total as in *New columns from old: assign, map and apply* (P13), *Summarize with a PivotTable* (E15) and *Counting and summing: aggregate functions* (S7): all 3,287 lines, the canceled order and the extra-zero line included. This time every line has a product, so no key is blank and the groups lose nothing. In unit 2 they did, and the check was what showed it.

<Aside type="tip" title="Remember">

- `sort_values("column", ascending=False)` returns a new, sorted table. Blank values go last in both directions.
- `groupby("key")` splits the rows into groups, runs a calculation on each group and combines the results into one row for each group.
- `agg(name=("column", "function"))` gives several named results in one pass.
- `size` counts rows, `count` counts values that are not blank.
- Check the groups against the table: the sizes of the groups must add up to its rows.

**Common trap:** rows with a blank key are left out of a `groupby` without a message, so the groups can add up to less than the table.

</Aside>

## Check yourself

1. Without looking back: a group holds a blank in one column. What do `size` and `count` give for that group?

   <details>
   <summary>answer</summary>

   `size` counts every row of the group, the row with the blank included. `count` counts only the values that are not blank in that column, so it gives one less.

   </details>
