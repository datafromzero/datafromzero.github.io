### 1. isna: finding the gaps

**Idea.** A missing value is `NaN` in a column of numbers, `NaT` in a column of dates and `pd.NA` in the newer types. `isna()` is the test for a gap, `.sum()` of it counts the gaps, and `notna()` is the opposite test.

**Try it.** The gaps of `orders`, and two ways to look for them in `customer_id`:

```python
print(orders.isna().sum())
print((orders["customer_id"] == np.nan).sum(), orders["customer_id"].isna().sum())
```

**Predict:** which columns of `orders` have gaps, and how many? On the last line, how many rows will the test `== np.nan` find, and how many will `isna()` find?

<details>
<summary>Reveal the result</summary>

```text
order_id          0
customer_id       1
store_id          0
ordered_at        0
status            0
payment_method    0
dtype: int64
0 1
```

</details>

*Why:* only `customer_id` has a gap, and it is one row, the walk-in order. `== np.nan` found none, although the gap is there. A missing value does not compare as equal to anything, itself included, so `==` cannot say yes, and no error tells you so. The pandas page on missing data gives `isna()` and `notna()` as the way to detect them. Now the kinds of missing value:

```python
print(np.nan == np.nan)
print(pd.isna(np.nan), pd.isna(None), pd.isna(pd.NaT), pd.isna(pd.NA))
```

**Predict:** does `np.nan` equal itself? And what does `isna` say for NaN, `None`, `NaT` and `pd.NA`?

<details>
<summary>Reveal the result</summary>

```text
False
True True True True
```

</details>

*Why:* `np.nan == np.nan` is `False`, the pandas page lists it among the comparisons that do not act like `None == None`, and all four are gaps for `isna`. Count the gaps with `isna().sum()` before any other step.

### 2. dropna and fillna: choose, then count

**Idea.** `dropna(subset=["column"])` removes the rows where that column has a gap. `fillna(value)` writes a value into the gaps. Which one fits depends on the question, and you count what changed. A median would not help here, because the only numbers missing in cafe-sales are ids, and the middle of a list of ids is not an id.

**Try it.** The walk-in order, dropped and filled with 0:

```python
kept = orders.dropna(subset=["customer_id"])
coded = orders.assign(customer_id=orders["customer_id"].fillna(0))
print(len(orders), len(kept), len(coded))
print(lines.loc[lines["order_id"] == 1335, "amount"].sum())
```

**Predict:** how many rows will `kept` and `coded` have, and how much money did the dropped order carry?

<details>
<summary>Reveal the result</summary>

```text
1800 1799 1800
7.0
```

</details>

*Why:* `kept` lost the walk-in order, and with it \$7.00 of sales that every total of the lines still counts; `coded` kept all 1,800 rows. Now the other side:

```python
print(orders["customer_id"].nunique(), coded["customer_id"].nunique())
```

**Predict:** how many different customers are there before the fill, and after it?

<details>
<summary>Reveal the result</summary>

```text
145 146
```

</details>

*Why:* 145 before and 146 after: the fill made the walk-in a customer, number 0. E13 left the blank blank for this reason. If the question is how much we sold, keep the row and the gap. If it is how many customers ordered, the row has nothing to say, and the gap is the honest answer.

### 3. dtype: read the type you want

**Idea.** `read_csv(..., dtype={"column": type})` sets the type of a column as the file is read. Two types matter here. `"Int64"` holds whole numbers and allows gaps. `"string"` holds text, and is the type for a code that you match but never add: a card number, a postal code, an id.

**Try it.** The customer ids of `orders`, read in two ways:

```python
as_read = orders["customer_id"].head(3).tolist()
whole = pd.read_csv(BASE + "orders.csv", dtype={"customer_id": "Int64"})
print(as_read, whole["customer_id"].head(3).tolist(), whole["customer_id"].isna().sum())
```

**Predict:** customer ids are whole numbers, and one is missing. How do the first three print as read, and with `dtype="Int64"`?

<details>
<summary>Reveal the result</summary>

```text
[15.0, 46.0, 61.0] [15, 46, 61] 1
```

</details>

*Why:* as read, the ids are decimals, 15.0, because the gap is a float `NaN` and a float column holds only floats. The pandas page says that `NaN` coerces the type to float, and that `NA` in the `Int64` type keeps the original type. `isna()` still finds the one gap. Now a code with leading zeros, in a small file typed here, not cafe-sales data:

```python
card_file = "card_no,tier\n0042,gold\n0107,silver\n0003,bronze\n"
as_number = pd.read_csv(io.StringIO(card_file))
as_text = pd.read_csv(io.StringIO(card_file), dtype={"card_no": "string"})
print(as_number["card_no"].tolist(), as_text["card_no"].tolist())
```

**Predict:** a loyalty card number is a code, not a quantity. What does each read give?

<details>
<summary>Reveal the result</summary>

```text
[42, 107, 3] ['0042', '0107', '0003']
```

</details>

*Why:* read as numbers, `0042` became 42, and the zeros are gone for good: the original text can no longer be matched. Read as text, it stays `0042`. Choose the type when you read the file, not afterwards.

### 4. duplicates: say what makes a row the same

**Idea.** `duplicated()` flags repeated rows with `True`, and `drop_duplicates()` removes them. `subset=["column"]` chooses the columns to compare.

**Try it.** First the real orders, then a copy of the first five in which one order was typed twice, planted here for the example:

```python
print(orders.duplicated().sum())
exact = orders.head(5).loc[[0, 1, 2, 2, 3, 4]]
print(exact.duplicated().tolist())
```

**Predict:** how many repeated orders does `orders` hold? In `exact`, order 1003 is typed twice: which of the six rows does `duplicated()` mark?

<details>
<summary>Reveal the result</summary>

```text
0
[False, False, False, True, False, False]
```

</details>

*Why:* none in `orders`, so the repeat had to be planted. The first typing of 1003 is `False` and the second is `True`: a row is a duplicate of an earlier row, and the earlier one stays. Now the second typing is a little different:

```python
near = exact.assign(payment_method=["mobile", "mobile", "mobile", "cash", "mobile", "mobile"])
print(len(near.drop_duplicates()), len(near.drop_duplicates(subset=["order_id"])))
```

**Predict:** order 1003 is typed twice again, as mobile and then as cash. How many rows does `drop_duplicates()` leave, and how many with `subset=["order_id"]`?

<details>
<summary>Reveal the result</summary>

```text
6 5
```

</details>

*Why:* 6 against 5. Every column has to match for the plain call, and the cash copy differs, so both stay. An order is its `order_id`, so the key says they are one order. Decide the key before you drop, and write it down.

### 5. Check: a cleaning log

Keep a log of the rows before and after each step, as in E13. Write down what you expect, then run the cell.

```python
log = [("start", len(orders))]
step = orders.drop_duplicates(subset=["order_id"])
log.append(("drop_duplicates", len(step)))
step = step.dropna(subset=["customer_id"])
log.append(("dropna", len(step)))
print(log)
```

**Predict:** how many rows are left after each step?

<details>
<summary>Reveal the result</summary>

```text
[('start', 1800), ('drop_duplicates', 1800), ('dropna', 1799)]
```

</details>

*Why:* the first step changes nothing, which is worth a line in the log too, and the second removes the walk-in order of unit 2. A log makes every loss visible, so that a total that no longer matches has a reason.

<Aside type="tip" title="Remember">

- `isna()` and `notna()` find missing values: NaN, NaT, `pd.NA` and `None`. `==` and `!=` cannot find them.
- `dropna` loses rows and what they carried; `fillna` invents a value. Say which, and count.
- Read a column with the type you want: `dtype="Int64"` keeps whole numbers whole with a gap, and text keeps codes whole.
- `duplicated(subset=[key])` and `drop_duplicates(subset=[key])` need the key to be named.
- Keep a log: the rows before and after each step.

**Common trap:** a gap turns a column of whole numbers into decimals, and ids come out as `15.0`.

</Aside>
