## The question

The owner asks:

> An assistant gave me a function for "the share of each store's sales that came from coffee". It ran and printed three numbers. Can I use them?

The data the function runs on, one row for each order line, the first rows of `lines`:

| order_id | store | month | category | amount |
|---:|---|---:|---|---:|
| 1001 | Campus | 1 | bakery | 3.25 |
| 1001 | Campus | 1 | coffee | 4.75 |
| 1001 | Campus | 1 | coffee | 6.00 |

By the end of this page you will have a way to decide, from numbers you worked out yourself.

## Learn by doing

About 30 minutes, 4 new ideas: the prompt, reading the draft, the tiny frame, and the second route with a note. "The assistant" means any chatbot or tool that drafts code; the drafts on this page were written by hand for the lesson, and no text on it is the output of a real assistant. The setup cell built `lines`: all 3,287 order lines of the six months, the canceled order and the line of order 2075 with its extra zero included.

### 1. Ask with the columns, the grain and a few rows

**Idea.** An assistant has never seen your table. Tell it what it cannot see: the column names, what one row is (the **grain**), what the money is, and the exact question, with three rows as an example. Not the whole table: the caution box in E22 lists what never to paste, and invented cafe rows are safe.

**Try it.** Build the prompt from the table, so that the names are the real ones, and count its lines:

```python
sample = lines.head(3).to_string(index=False)
prompt = (
    "I have a pandas DataFrame called lines: one row for each order line of a cafe chain, "
    f"with the columns {', '.join(lines.columns)}. The amount is in US dollars.\n"
    f"Here are the first three rows:\n{sample}\n"
    "Write a function coffee_share(lines) that returns, for each store, "
    "the share of that store's sales that came from coffee."
)
print(prompt)
print(len(prompt.splitlines()), "lines;", len(lines), "rows in the table")
```

**Predict:** the table has 3,287 rows. How many lines long will the prompt be?

<details>
<summary>Reveal the result</summary>

```text
I have a pandas DataFrame called lines: one row for each order line of a cafe chain, with the columns order_id, store, month, category, amount. The amount is in US dollars.
Here are the first three rows:
 order_id  store  month category  amount
     1001 Campus      1   bakery    3.25
     1001 Campus      1   coffee    4.75
     1001 Campus      1   coffee    6.00
Write a function coffee_share(lines) that returns, for each store, the share of that store's sales that came from coffee.
7 lines; 3287 rows in the table
```

</details>

*Why:* the prompt is 7 lines whatever the table holds: the columns, the grain, three rows and the question. The other 3,284 rows never left your notebook. Send it to any assistant and what comes back is a draft.

### 2. Read the draft before you run it

**Idea.** Say what each line of a draft does, in your own words, and name every number it divides by. A draft that runs has shown only that it runs: NIST's generative AI profile defines confabulation as the production of "confidently stated but erroneous or false content", and adds that generated explanations can be confabulated too and may lead people to trust a wrong answer.

Here is a reply written for this lesson. **It is an illustrative example, not the output of any assistant.**

> Here is the function. It returns each store's coffee sales as a share of its sales.

```python
def coffee_share(lines):
    coffee = lines[lines["category"] == "coffee"]
    return coffee.groupby("store")["amount"].sum() / lines["amount"].sum()
```

**Try it.** Paste the function into a cell and run it on the real table:

```python
def coffee_share(lines):
    coffee = lines[lines["category"] == "coffee"]
    return coffee.groupby("store")["amount"].sum() / lines["amount"].sum()


print(coffee_share(lines).round(3).to_dict())
```

**Predict:** will it run without an error, and how many numbers will it print?

<details>
<summary>Reveal the result</summary>

```text
{'Campus': 0.182, 'Harbor': 0.095, 'Old Town': 0.198}
```

</details>

*Why:* it ran and gave one number for each of the 3 stores, and the output has no error message and only numbers between 0 and 1. The sentence above the code says each store's share of its own sales; the code is what runs. The next unit tests the function without trusting either the sentence or the code.

### 3. Test it on a frame you worked by hand

**Idea.** A **known answer** is a small frame whose result you work out on paper first, so that the draft's number cannot sway yours. Then `assert` that the function gives it: the Python reference gives `assert` as `if __debug__: if not condition: raise AssertionError` (a program started with the `-O` option skips asserts), and the message after the comma is what you will read.

Six real lines, `tiny`, the rows at positions 0, 1, 2, 3, 4 and 9 of `lines`:

| store | category | amount |
|---|---|---:|
| Campus | bakery | 3.25 |
| Campus | coffee | 4.75 |
| Campus | coffee | 6.00 |
| Old Town | bakery | 3.25 |
| Old Town | food | 9.25 |
| Old Town | coffee | 4.75 |

Work out each store's coffee share of its own sales to 3 decimals. The cell below holds the values worked out for this page in `hand`; compare yours with them before you run it.

**Try it.** Test the function against your hand answers. They are in `hand`:

```python
tiny = lines.iloc[[0, 1, 2, 3, 4, 9]]
hand = {"Campus": 0.768, "Old Town": 0.275}  # coffee over all sales of the same store, by hand
got = coffee_share(tiny).round(3).to_dict()
print(got)
show_error('assert got == hand, f"hand {hand}, draft {got}"', short=True)
```

**Predict:** what will the draft give for each store on `tiny`, and will the assert stop?

<details>
<summary>Reveal the result</summary>

```text
{'Campus': 0.344, 'Old Town': 0.152}
AssertionError: hand {'Campus': 0.768, 'Old Town': 0.275}, draft {'Campus': 0.344, 'Old Town': 0.152}
```

</details>

*Why:* Campus 10.75 of 14.00 is 0.768 and Old Town 4.75 of 17.25 is 0.275. The draft gave 0.344 and 0.152 and the assert stopped with both dictionaries. Both of the draft's numbers divide by 31.25, the sales of both stores together: the return line of the function divides by `lines["amount"].sum()`, the total of the whole chain, where the question said that store's sales. The shape was right (one number per store) and the numbers were wrong.

### 4. Reconcile on the real data and keep a note

**Idea.** After the fix passes the tiny frame, check it on the real table against a second route that takes a different order of steps, then write down what you checked: the question, the date, the checks and where the draft came from.

**Try it.** The fix divides by each store's own total. The second route adds up, for the coffee lines, each line's share of its own store's sales, with `transform`:

```python
def coffee_share(lines):
    coffee = lines[lines["category"] == "coffee"]
    return coffee.groupby("store")["amount"].sum() / lines.groupby("store")["amount"].sum()


line_share = lines["amount"] / lines.groupby("store")["amount"].transform("sum")
second = line_share[lines["category"] == "coffee"].groupby(lines["store"]).sum()
assert coffee_share(tiny).round(3).to_dict() == hand, "the tiny frame disagrees"
assert coffee_share(lines).round(6).to_dict() == second.round(6).to_dict(), "the second route disagrees"
print(coffee_share(lines).round(3).to_dict())
note = {"asked": "coffee share of each store's sales", "date": "2026-11-20", "draft": "illustrative, written for the lesson",
        "checks": "tiny frame worked by hand; second route with transform", "rows": f"all {len(lines):,} order lines"}
for key, value in note.items():
    print(f"{key}: {value}")
```

**Predict:** will either assert stop the cell, and what will the three shares be?

<details>
<summary>Reveal the result</summary>

```text
{'Campus': 0.459, 'Harbor': 0.47, 'Old Town': 0.493}
asked: coffee share of each store's sales
date: 2026-11-20
draft: illustrative, written for the lesson
checks: tiny frame worked by hand; second route with transform
rows: all 3,287 order lines
```

</details>

*Why:* both asserts passed in silence, and the three shares are 0.459, 0.470 and 0.493, so coffee is about 46 to 49 percent of each store's sales. The draft's three numbers, which add up to 0.475, were each store's coffee as a share of the whole chain. The note is five lines you can paste above the cell, so that the next reader knows what stands behind it.

<Aside type="tip" title="Remember">

- Give the assistant the columns, the grain, three rows and an exact question, never the table.
- A draft that runs has shown only that it runs: read it and name every number it divides by.
- Work a tiny frame by hand first, then `assert` the function against it.
- Reconcile on the real data with a second route, and keep a note of the question, the date and the checks.

**Common trap:** trusting a clear explanation. NIST notes that a generated explanation can be confabulated too, and may lead people to trust a wrong answer.

</Aside>

## Finish it

<Exercise id="python-ai-assisted-code-1">

**A drafted function for the average number of lines in an order printed a number. Is it right?** The cell below holds the draft (illustrative, written for this lesson) and three tiny frames of real lines: `one` is order 1001 alone, `five` is orders 1001 and 1002, `four` is orders 1003 to 1005. Work out the answer for `five` by hand first, then run the cell and compare. Finish it: fix the function so that it gives the number of lines divided by the number of different orders for every frame. Expected: `lines_per_order(five)` is the number you worked out by hand.

```python
def lines_per_order(frame):  # the assistant's draft (illustrative)
    return len(frame) / frame["order_id"].count()


one = lines.iloc[[0, 1, 2]]
five = lines.iloc[[0, 1, 2, 3, 4]]
four = lines.iloc[[5, 6, 7, 8]]
print(lines_per_order(five))  # compare with your hand answer
```

<details>
<summary>Hint</summary>

`count()` counts the rows that have a value in the column, and every row has an order id. Which method counts different values?

</details>

<details>
<summary>Half-solution</summary>

```python
def lines_per_order(frame):
    return len(frame) / frame["order_id"]...
```

</details>

<Solution>

```python
def lines_per_order(frame):
    return len(frame) / frame["order_id"].nunique()


one = lines.iloc[[0, 1, 2]]
five = lines.iloc[[0, 1, 2, 3, 4]]
four = lines.iloc[[5, 6, 7, 8]]
print(lines_per_order(five))
```

`five` holds 5 lines of 2 orders, so 2.5; `one` is 3 lines of 1 order, 3.0; `four` is 4 lines of 3 orders. The draft divided the rows by the rows that have an order id, which is every row, and gave 1.0 for each frame, so its number never changed whatever the orders. Grouping by order and adding the group sizes gives the row count again, also 1.0, and the check cell calls both.

</Solution>

</Exercise>

**Spot the flaw.** An illustrative draft, written for this lesson, prints the average amount of a tea line at Old Town over the six months, as the average of the six monthly averages. The owner wants the average of all the tea lines of the store. Fix the lines so that `answer_3` is that average, rounded to 2 decimals. Expected: `answer_3` is a number with 2 decimals.

```python
tea = lines[(lines["store"] == "Old Town") & (lines["category"] == "tea")]
answer_3 = round(tea.groupby("month")["amount"].mean().mean(), 2)  # the draft: the average of the monthly averages
```

<details>
<summary>Hint</summary>

Print `tea.groupby("month").size()`. Does the average of six averages give every tea line the same weight?

</details>

<details>
<summary>Half-solution</summary>

```python
answer_3 = round(tea[...].mean(), 2)
```

</details>

<Solution>

```python
tea = lines[(lines["store"] == "Old Town") & (lines["category"] == "tea")]
answer_3 = round(tea["amount"].mean(), 2)
```
