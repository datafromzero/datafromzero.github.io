## The question

The owner asks:

> Which product names mention Latte, and how will each print on a receipt, in capital letters?

Five of the 16 products, as the `products` table holds them:

| product_id | product_name | unit_price_usd |
|---:|---|---:|
| 3 | Latte | 4.50 |
| 8 | Chai Latte | 4.75 |
| 10 | Croissant | 3.25 |
| 13 | Bagel with Cream Cheese | 4.25 |
| 16 | Pumpkin Spice Latte | 5.50 |

A name is text, so the question is about pieces of text: finding a word and changing letters. By the end of this page Python will find the names and print them.

<Aside type="note" title="You already know this">

**Match.** `strip`, `lower` and `replace` are the `TRIM`, `LOWER` and `SUBSTITUTE` of *Cleaning text with TRIM, LEFT and TEXTSPLIT* (E10), and the `trim`, `lower` and `replace` of *Cleaning text in SQL* (S10). `name[0:5]` is `LEFT(name, 5)`, and the test `"Latte" in name` is the `LIKE '%Latte%'` of *Filtering rows with WHERE* (S3).

**Diverge.** Python counts positions from 0, and a slice leaves out its end: `MID(name, 1, 5)` starts at 1, `name[0:5]` starts at 0 (unit 1). Excel's `TRIM` also squeezes the spaces inside a text to one; `strip` only cuts the two ends (unit 2).

</Aside>

## Learn by doing

About 20 minutes, 4 new ideas: slicing, string methods, searching with `in` and `find`, and f-strings. The last unit only checks them.

<OpenInColab />

### 1. Index and slice

**Idea.** `name[i]` picks the character at position `i`, and `name[a:b]` picks the characters from position `a` up to, but not including, position `b`. The first character is position 0. The start is always included and the end is always left out.

**Try it:**

```python
name = "Green Tea"
name[0:5], name[6:9]
```

**Predict:** `Green Tea` has nine characters, with a space at position 5. What do the two slices pick?

<details>
<summary>Reveal the result</summary>

```text
('Green', 'Tea')
```

</details>

*Why:* `[0:5]` takes positions 0 to 4, the five letters of Green. `[6:9]` takes positions 6 to 8, the three letters of Tea, and skips the space at position 5. Excel's `LEFT(name, 5)` is `name[0:5]`, but `MID(name, 7, 3)` starts at 7 where Python starts at 6.

### 2. The common string methods

**Idea.** A method is a function that belongs to a value, written after a dot: `raw.strip()`. `strip` cuts the spaces at both ends, `lower` makes every letter lowercase, `replace` swaps a piece of text for another, `split` cuts a text into a list at a separator, and `join` glues a list together.

**Try it.** The till typed the name with spaces at both ends and three spaces in the middle:

```python
raw = "  chai   LATTE "
raw.strip().lower()
```

**Predict:** Excel's `TRIM` would give `chai latte` with one space. What does this give?

<details>
<summary>Reveal the result</summary>

```text
'chai   latte'
```

</details>

*Why:* `strip` cuts only the two ends, so the three inner spaces stay, while Excel's `TRIM` squeezes them. To squeeze them in Python, split the text on its spaces and join it again: `" ".join(raw.split()).lower()` gives `'chai latte'`. And `split` and `join` also work on a list of store names:

```python
stores_text = "Old Town, Campus, Harbor"
names = stores_text.split(", ")
names, " / ".join(names)
```

```text
(['Old Town', 'Campus', 'Harbor'], 'Old Town / Campus / Harbor')
```

### 3. Membership and position

**Idea.** `in` asks whether a piece of text is inside another text and answers `True` or `False`. `find` gives the position where the piece starts. Both tell capitals from small letters.

**Try it:**

```python
"Latte" in "Chai Latte", "Chai Latte".find("Latte"), "Croissant".find("Latte")
```

**Predict:** what do the three tests give?

<details>
<summary>Reveal the result</summary>

```text
(True, 5, -1)
```

</details>

*Why:* Latte starts at position 5 of Chai Latte, after `Chai` and a space. It is nowhere in Croissant, so `find` gives `-1`, the Python documentation's sign for not found, where Excel's `FIND` gives the error `#VALUE!`. Python counts from 0 and Excel from 1. The same test on the whole menu answers the owner. In the notebook, the pre-written cell with `.str.contains("Latte")` returns the rows of products 3, 8 and 16:

```text
    product_id         product_name category  unit_price_usd
2            3                Latte   coffee            4.50
7            8           Chai Latte      tea            4.75
15          16  Pumpkin Spice Latte   coffee            5.50
```

### 4. f-strings

**Idea.** An f-string is text that starts with `f` and holds names or calculations in curly brackets; Python puts their values in. A format code after a colon controls how a number shows. It is the `&` join of a message in Excel and the `||` of SQL.

**Try it:**

```python
name = "Latte"
price = 4.5
f"{name} costs ${price}"
```

**Predict:** how does the price appear, `4.5` or `4.50`?

<details>
<summary>Reveal the result</summary>

```text
'Latte costs $4.5'
```

</details>

*Why:* the number 4.5 has no trailing zero to show. Add `:.2f` after the name, which asks for two decimals: `f"{name} costs ${price:.2f}"` gives `'Latte costs $4.50'`. Chart titles and findings text later in this stage are built the same way.

### 5. Check: strings cannot change in place

Predict the two values, then run the cell. A method returns a new string.

```python
product = "Bagel with Cream Cheese"
product.upper(), product
```

<details>
<summary>Reveal the result</summary>

```text
('BAGEL WITH CREAM CHEESE', 'Bagel with Cream Cheese')
```

</details>

*Why:* `upper()` gave back a new string and left `product` as it was. A string cannot be changed in place (the Python documentation says strings are immutable), as `TRIM` returns a new value and leaves the cell alone.

<Aside type="tip" title="Remember">

- A string is numbered from 0, and a slice `[a:b]` includes `a` and leaves out `b`.
- `strip` cuts the two ends only; `lower`, `replace`, `split` and `join` return new values.
- `in` gives `True` or `False`; `find` gives a position or `-1`.
- An f-string puts values in curly brackets; `:.2f` shows two decimals.

**Common trap:** calling a string method and not keeping what it returns.

</Aside>
