## The question

The owner asks:

> How many orders were taken at Campus, and how many were paid by mobile at Harbor? Also fix the payment method of Harbor's mobile orders, which the till recorded as card.

The first three orders, with the columns this lesson needs:

| order_id | store_id | status | payment_method |
|---:|---:|---|---|
| 1001 | 2 | completed | mobile |
| 1002 | 1 | completed | mobile |
| 1003 | 2 | completed | mobile |

A table has too many rows and columns for one question. By the end of this page you will pick the rows and columns you want, count them, and change a value in the one way pandas 3 lets you.

<Aside type="note" title="You already know this">

**Match.** In *Filtering rows with WHERE* (S3), `WHERE store_id = 2` kept the rows where the test was true. `orders[orders["store_id"] == 2]` does the same, and both give the 716 rows of Campus. The test in the brackets is a mask, a column of `True` and `False` that pandas lets you look at.

**Diverge.** SQL's `<>` drops a row whose value is missing, because the comparison is unknown (*NULL: unknown is not zero*, S4). What pandas `!=` does with a missing value is the second check of unit 3.

</Aside>

## Learn by doing

About 30 minutes, 4 new ideas: picking by name, label and position; masks; several conditions; and changing values in one step. The last unit only checks them. The setup cell made `orders_by_id`, the orders table with `order_id` as its index.

<OpenInColab />

### 1. Pick by name, by label and by position

**Idea.** `df[["a", "b"]]` picks columns by name: a list of names inside the brackets, and the result is a table. `.loc[row label, column name]` picks cells by label, and `.iloc[row position, column position]` picks them by position, counted from 0. In `orders_by_id` the row labels are order ids, so a label and a position are not the same number.

**Try it:**

```python
print(orders[["order_id", "ordered_at"]].head(3))
print(orders_by_id.loc[1107, "ordered_at"])
print(orders_by_id.iloc[106, 2])
print(orders_by_id.iloc[1107, 2])
```

**Predict:** order 1107 is the 107th row of `orders_by_id`, so its position is 106. Which of the last three prints show the time of order 1107, and which one does not?

<details>
<summary>Reveal the result</summary>

```text
   order_id           ordered_at
0      1001  2026-01-01 08:02:00
1      1002  2026-01-01 15:38:00
2      1003  2026-01-01 15:47:00
2026-01-15 16:57:00
2026-01-15 16:57:00
2026-05-03 17:05:00
```

</details>

*Why:* `.loc[1107, ...]` looks for the label 1107 and `.iloc[106, ...]` for the 107th row, which is the same row. `.iloc[1107, ...]` reads the 1,108th row, which is order 2108, taken in May. Column 2 is `ordered_at` because `order_id` is the index, not a column. Use `.loc` when you know the name, `.iloc` when you know only the place.

### 2. A mask, then a filter

**Idea.** A comparison on a column gives a mask: `True` for each row that passes the test. Look at the mask and its shape first. Then `orders[mask]` keeps the rows where it is `True`, and its shape tells you how many.

**Try it:**

```python
campus = orders["store_id"] == 2
print(campus.head(3))
print(campus.shape, campus.sum())
campus_orders = orders[campus]
print(orders.shape, campus_orders.shape)
```

**Predict:** the first three orders were taken in stores 2, 1 and 2. What does the mask hold for them? The shape of the filtered table is for you to read.

<details>
<summary>Reveal the result</summary>

```text
0     True
1    False
2     True
Name: store_id, dtype: bool
(1800,) 716
(1800, 6) (716, 6)
```

</details>

*Why:* the mask is `True, False, True` for stores 2, 1 and 2, and it has one value for each of the 1,800 rows. `campus.sum()` counts the `True` values, 716, and the filtered table has exactly those rows with all 6 columns. The shape before and after, `(1800, 6)` and `(716, 6)`, is the quickest check that a filter did what you meant.

### 3. Several conditions

**Idea.** `&` joins two masks into the rows where both are `True`, and `|` into the rows where either is. Put each condition in its own parentheses: without them Python applies `&` before `==` and the line fails. `and` and `or` do not work on a whole column. `notna()` is `True` where a value is present.

**Try it.** Store 1 and mobile payment:

```python
both = (orders["store_id"] == 1) & (orders["payment_method"] == "mobile")
either = (orders["store_id"] == 1) | (orders["payment_method"] == "mobile")
print(both.head(3).tolist())
print(either.head(3).tolist())
print(both.sum(), either.sum())
```

**Predict:** for the first three orders, which are in store 1 and paid by mobile? Which are in store 1 or paid by mobile? All three were paid by mobile, in stores 2, 1 and 2. The counts are for you to read.

<details>
<summary>Reveal the result</summary>

```text
[False, True, False]
[True, True, True]
217 1058
```

</details>

*Why:* only the second order is in store 1 and mobile, while all three are mobile, so `|` is `True` for all of them. Over the whole table, 217 orders are both and 1,058 are either. Now a test with `!=` on a column that has a missing value:

```python
not_15 = orders["customer_id"] != 15
print(not_15.sum())
print((not_15 & orders["customer_id"].notna()).sum())
```

**Predict:** customer 15 placed 16 of the 1,800 orders, and one order has no customer. How many orders does each of the two counts give?

<details>
<summary>Reveal the result</summary>

```text
1784
1783
```

</details>

*Why:* `!= 15` keeps the walk-in order, because a missing value is not equal to 15, and 1,800 minus 16 is 1,784. SQL's `customer_id <> 15` gives 1,783, the second count, because it drops the row whose customer is unknown (S4). Adding `notna()` is how you ask pandas the SQL question.

### 4. Change values in one step

**Idea.** `.loc[mask, column] = value` changes the cells of the chosen rows in one step; read the same address and you get the cells back. `orders.copy()` is a table of its own, so a change to it leaves `orders` alone (`work = orders` would only be a second name for the same table). Two pairs of brackets, `df[mask]["column"] = value`, are a chained assignment; the second try of this unit uses one.

**Try it.** Relabel Harbor's mobile payments as card, on a copy:

```python
work = orders.copy()
print((work["payment_method"] == "mobile").sum())
harbor_mobile = (work["store_id"] == 3) & (work["payment_method"] == "mobile")
work.loc[harbor_mobile, "payment_method"] = "card"
print((work["payment_method"] == "mobile").sum(), harbor_mobile.sum())
```

**Predict:** will the number of mobile orders go up, go down or stay the same? The first number is the count before the change.

<details>
<summary>Reveal the result</summary>

```text
546
426 120
```

</details>

*Why:* 120 of the 546 mobile orders were Harbor's, and the one `.loc` line relabeled exactly those, so 426 are left. Now the same change with two pairs of brackets, on a fresh copy:

```python
fresh = orders.copy()
mask = (fresh["store_id"] == 3) & (fresh["payment_method"] == "mobile")
fresh[mask]["payment_method"] = "card"
print((fresh["payment_method"] == "mobile").sum())
```

**Predict:** what does the count of mobile orders show afterwards?

<details>
<summary>Reveal the result</summary>

```text
546
```

</details>

*Why:* nothing changed: 546 are still mobile. In pandas 3 a table taken from another table always behaves as a copy, and `fresh[mask]` is one, so the assignment went to a copy that is thrown away. pandas 3 warns with a `ChainedAssignmentError`, and pandas 2.2 usually warns with a `SettingWithCopyWarning`; the warning shows below the cell and does not stop it. On pandas 2.2 a chained form may still change the table, with a warning; on pandas 3 it never does. The `.loc` form of the first try works the same on both.

### 5. Check: read the cells with a mask

Write down the answer, then run the cell. It reads cells with the same `.loc[mask, column]` address that unit 4 wrote to.

```python
print(orders.loc[orders["status"] == "canceled", "order_id"].tolist())
```

<details>
<summary>Reveal the result</summary>

```text
[1461]
```

</details>

*Why:* the one canceled order of the data is order 1461. The same address picks cells to read or to change.

<Aside type="tip" title="Remember">

- `df[["a", "b"]]` picks columns; `.loc` picks by label and `.iloc` by position, counted from 0.
- Print the mask and its shape before you filter, and the shape again after.
- `&` and `|` join masks, each condition in parentheses; `!=` keeps a missing value, so add `notna()` for the SQL answer.
- Change values in one step: `.loc[mask, column] = value`, on a table you copied.

**Common trap:** an assignment through two pairs of brackets that changes nothing, and shows only a warning.

</Aside>
