## The question

The owner asks:

> How much did order line 5192 bring in?

The line is in the `order_items` table, and its price is in `products`. Python needs one number from each:

| order_item_id | order_id | product_id | quantity | discount_usd |
|---:|---:|---:|---:|---:|
| 5192 | 1107 | 5 | 2 | 0.50 |

| product_id | product_name | unit_price_usd |
|---:|---|---:|
| 5 | Mocha | 5.00 |

The amount of a line is `quantity × unit_price_usd − discount_usd`. By the end of this page Python will compute it, and you will know why a price that arrives as text gives the wrong answer without an error.

<Aside type="note" title="You already know this">

**Match.** In *Numbers are not numbers until you check* (E4) you told a number from text, and in *Computed columns and data types* (S5) the amount was a computed column, `quantity * unit_price - discount`. In Python the same formula is one line, `amount = quantity * unit_price - discount`, and it gives the same 9.5.

**Diverge.** Python never converts text to a number for you. `"4.50" * 2` does not fail and does not give 9: it repeats the text. You convert on purpose with `float()`, the twin of the `CAST` of S5. Unit 3 shows it.

</Aside>

### 1. Variables

**Idea.** A variable is a name for a value, like a named cell. The equals sign stores the value on its right under the name on its left; it does not compare. Each line runs after the one above it, so a name must be set before a later line uses it.

**Try it:**

```python
unit_price = 5.00
quantity = 2
discount = 0.50
amount = quantity * unit_price - discount
amount
```

**Predict:** what does the last line show? The picture above did the same for order line 5026, an Americano with a discount.

<details>
<summary>Reveal the result</summary>

```text
9.5
```

</details>

*Why:* line 4 used the three values the earlier lines stored. 2 times 5.0 is 10.0, minus 0.5 is 9.5, the amount of line 5192.

### 2. The four basic types

**Idea.** There are four basic types you meet first. `int` is a whole number, `float` is a number with a decimal point, `str` is text in quotes, and `bool` is `True` or `False`. `type()` names the type. They are the number, text and logical values of the spreadsheet, and the types of a SQL column.

**Try it:**

```python
print(type(5.00))
print(type(2))
print(type("Mocha"))
print(type(2 > 1))
```

**Predict:** what are the four types?

<details>
<summary>Reveal the result</summary>

```text
<class 'float'>
<class 'int'>
<class 'str'>
<class 'bool'>
```

</details>

*Why:* `5.00` has a decimal point, so it is a `float`; `2` has none, so it is an `int`. A comparison such as `2 > 1` gives a `bool`. `print` shows a type with its wrapper, `<class 'float'>`: the name inside the quotes is the type. Division always gives a `float`: `6 / 2` gives `3.0`, not `3`.

### 3. Converting between types

**Idea.** Python does not guess. Text that looks like a number is still text. `float()` and `int()` turn text into numbers, and `str()` turns a number into text.

**Try it.** The price arrives as text:

```python
price_text = "4.50"
price_text * 2
```

**Predict:** what does the second line show: 9.0, an error, or something else?

<details>
<summary>Reveal the result</summary>

```text
'4.504.50'
```

</details>

*Why:* times on text repeats the text, so there is no error and the answer is wrong. Convert first: `float(price_text) * 2` gives `9.0`. Pick the converter by the number: `int("4.50")` is refused (`ValueError: invalid literal for int() with base 10: '4.50'`), and `int(4.75)` cuts the decimals off and gives 4. DuckDB's `CAST('4.50' AS INTEGER)` gives 5, but Python does not round for you.

### 4. Calling a function

**Idea.** A function takes arguments in brackets. A **positional** argument is read by its place; a **keyword** argument carries its name, as the labels in a formula tooltip do. `help()` shows the signature, the list of names a function accepts.

**Try it.** Three Chai Lattes at 4.75 cost 14.25. Round that to one decimal:

```python
total = 3 * 4.75
round(total, 1)
```

**Predict:** 14.3 or 14.2?

<details>
<summary>Reveal the result</summary>

```text
14.2
```

</details>

*Why:* when two results are equally close, Python's `round` picks the even last digit (the Python documentation says so, and gives `round(0.5)` as 0). DuckDB's `ROUND(14.25, 1)` gives 14.3 for the same number, so the two tools differ here. The keyword form `round(total, ndigits=1)` gives the same `14.2`, and `help(round)` prints a first signature line, `round(number, ndigits=None)`, that names both arguments.

### 5. Check: predict, then run

Predict each value, then run the cell as you would check a formula before pressing Enter.

```python
print(type(2 * 4.5))
print("2" + "3")
print(2 + 3 == 5)
```

<details>
<summary>Reveal the result</summary>

```text
<class 'float'>
23
True
```

</details>

*Why:* a whole number times a decimal is a `float`; plus on two texts joins them; and `2 + 3 == 5` is a comparison, so it is `True`.

<Aside type="tip" title="Remember">

- A variable is a name for a value; `=` stores, it does not compare.
- Four basic types: `int`, `float`, `str`, `bool`. `type()` names one.
- Python never converts for you: use `int()`, `float()` or `str()` on purpose.
- Arguments go by place or by name; `help()` shows the signature.

**Common trap:** text that looks like a number. `"4.50" * 2` repeats the text instead of failing, so the total looks like a price twice over.

</Aside>
