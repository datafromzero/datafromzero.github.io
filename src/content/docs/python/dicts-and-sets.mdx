## The question

The owner asks:

> Put the store name, not just the store id, next to every order.

The first three orders carry a store id, and the `stores` table says which name belongs to which id:

| order_id | store_id |
|---:|---:|
| 1001 | 2 |
| 1002 | 1 |
| 1003 | 2 |

| store_id | store_name |
|---:|---|
| 1 | Old Town |
| 2 | Campus |
| 3 | Harbor |

A small table that turns one value into another is a lookup table, and Python has one built in. By the end of this page Python will turn the three ids into names, and you will have built a table from dictionaries and found the value that the build left out.

<Aside type="note" title="You already know this">

**Match.** A dictionary is a lookup table. `store_name_of[2]` is the exact-match `XLOOKUP` of *Bring in a value by key with XLOOKUP* (E8), and it is the join to a small table of *LEFT JOIN and finding rows with no match* (S20): a key goes in, its value comes out.

**Diverge.** A key that is not in the table does not give a blank. `XLOOKUP` returns `#N/A` unless you give it a not-found text, but `store_name_of[4]` stops with an error, and `store_name_of.get(4, "unknown store")` is the not-found text (unit 1). And a table built from dictionaries fills a missing key with `NaN` and says nothing (unit 3).

</Aside>

## Learn by doing

About 20 minutes, 4 new ideas: dictionary lookups, looping over a dictionary, the dictionaries that pandas reads, and sets. The last unit only checks them.

<OpenInColab />

### 1. Keys and values

**Idea.** A dictionary is written in curly brackets as `key: value` pairs. You read a value by its key in square brackets. `get(key, default)` reads it too, and takes a second argument, the default.

**Try it:**

```python
store_name_of = {1: "Old Town", 2: "Campus", 3: "Harbor"}
store_name_of[2], store_name_of.get(4, "unknown store")
```

**Predict:** what do the two lookups give? Store 4 is not in the dictionary.

<details>
<summary>Reveal the result</summary>

```text
('Campus', 'unknown store')
```

</details>

*Why:* key 2 finds `'Campus'`. Key 4 is not there, so `get` hands back the default you chose, where the square brackets would fail. The square-bracket form `store_name_of[4]` stops instead, with `KeyError: 4`. The table of keys and values is the lookup table of E8, and a key can appear only once.

### 2. Loop over a dictionary

**Idea.** `.items()` gives every key with its value, one pair for each pass of a loop; `.keys()` and `.values()` give one side only. It reads the lookup table row by row.

**Try it.** Old Town's orders by payment method, from the `GROUP BY` of S8:

```python
payments = {"card": 421, "cash": 91, "mobile": 217}  # Old Town, by payment method
for method, count in payments.items():
    print(f"{method}: {count}")
sum(payments.values()), list(payments.keys())
```

**Predict:** what do the loop and the last line show?

<details>
<summary>Reveal the result</summary>

```text
card: 421
cash: 91
mobile: 217
(729, ['card', 'cash', 'mobile'])
```

</details>

*Why:* the loop wrote one line for each key. The values add up to 729, the number of orders of store 1 (S8), so the three counts are complete.

### 3. Dictionaries that pandas uses

**Idea.** pandas reads dictionaries in four places: `rename(columns={...})`, `map({...})`, `agg({...})` and `DataFrame({...})`. Here you meet two of them. `map` is the real twin of a lookup column, `XLOOKUP` or a join to a small table, for one column of ids. `DataFrame` builds a table from a dictionary of columns.

**Try it.** First the lookup, which you only read:

```python
orders["store_id"].head(3).map(store_name_of).tolist()
```

```text
['Campus', 'Old Town', 'Campus']
```

That is the answer to the owner's question for the first three orders. Now build a table from a dictionary of dictionaries, one inner dictionary for each store. Harbor's has only two entries:

```python
payments_by_store = {
    "Old Town": {"card": 421, "cash": 91, "mobile": 217},
    "Campus": {"card": 400, "cash": 107, "mobile": 209},
    "Harbor": {"card": 180, "mobile": 120},
}
pd.DataFrame(payments_by_store, index=["card", "cash", "mobile"])
```

**Predict:** will pandas stop with an error, fill a zero, or do something else? What shows in the Harbor column?

<details>
<summary>Reveal the result</summary>

```text
        Old Town  Campus  Harbor
card         421     400   180.0
cash          91     107     NaN
mobile       217     209   120.0
```

</details>

*Why:* there was no error and no zero. Harbor's dictionary has no `"cash"` key, so pandas left that cell as `NaN`, its sign for a missing value, as `NULL` is in SQL, and turned the whole column into decimals (180.0). Harbor did take cash orders: 55 of them. The number exists in the data, and the construction lost it.

### 4. Sets, for recognition

**Idea.** A set holds each value once and in no fixed order. `set(list)` drops the repeats. You rarely build one: pandas has `unique()`, `isin()` and `drop_duplicates()` for the same jobs on a column. It is the `UNIQUE` of *Spilling results with FILTER, SORT and UNIQUE* (E19) and the `DISTINCT` of SQL.

**Try it:**

```python
methods = ["card", "mobile", "card", "cash", "card"]
len(set(methods)), sorted(set(methods))
```

**Predict:** how many different payment methods are there, and which?

<details>
<summary>Reveal the result</summary>

```text
(3, ['card', 'cash', 'mobile'])
```

</details>

*Why:* five orders, but only three values occur, and `sorted` puts them in order, because a set has none. That is all the sets you need here.

### 5. Check: list or dictionary?

Predict the type of each value, then run the cell. The brackets decide.

```python
print(type({"card": 421}))
print(type(["card", 421]))
print(type({"card", "cash"}))
```

<details>
<summary>Reveal the result</summary>

```text
<class 'dict'>
<class 'list'>
<class 'set'>
```

</details>

*Why:* curly brackets with `key: value` pairs make a dictionary, square brackets a list, and curly brackets without pairs a set. Use a dictionary to look a value up by name, a list when the order or the position matters, and a set when you only need to know which values occur.

<Aside type="tip" title="Remember">

- A dictionary maps keys to values: `d[key]` reads one, `d.get(key, default)` reads one without stopping.
- `.items()` loops over keys and values together.
- pandas reads dictionaries in `rename`, `map`, `agg` and `DataFrame`; the direction is always key, then value.
- A set keeps each value once: `unique()` and `drop_duplicates()` do its work on a column.
- Curly brackets with pairs are a dictionary, square brackets a list.

**Common trap:** a table built from dictionaries with a key missing. pandas fills `NaN` without a word, the column turns into decimals, and its total no longer matches the store's total.

</Aside>
