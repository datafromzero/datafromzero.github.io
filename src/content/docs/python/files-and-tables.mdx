### 1. Where is the file?

**Idea.** A path says where a file is. A relative path such as `cafe_data/products.csv` starts in the working directory, the folder the notebook runs in. An absolute path starts at the top of the disk. `Path("cafe_data") / "products.csv"` builds a path with `/`, and `exists()` asks whether a file is there.

**Try it.** The setup cell saved the price list in a folder called `cafe_data`:

```python
from pathlib import Path

price_file = Path("cafe_data") / "products.csv"
print(price_file, price_file.exists())
print(Path("products.csv").exists())
print(price_file.is_absolute(), Path.cwd().is_absolute())
```

**Predict:** what do the three prints show? `Path.cwd()` is the working directory.

<details>
<summary>Reveal the result</summary>

```text
cafe_data/products.csv True
False
False True
```

</details>

*Why:* the first path goes into `cafe_data`, and the file is there. The second asks for `products.csv` in the working directory itself, where there is no such file: the same name in another place is another path. The working directory is absolute, and the path you built is relative to it. Run `Path.cwd()` in a cell to see yours.

### 2. A CSV file, and how its letters were saved

**Idea.** `pd.read_csv(path)` reads a CSV file into a table, a DataFrame; the next lesson but one explains the object. `.shape` gives its rows and columns, and `.head(3)` its first three rows. Letters are saved as bytes, in an encoding, and `read_csv` expects UTF-8. `encoding="..."` names another one.

**Try it.** First the price list, then a file of board names that the till saved as `latin-1`:

```python
price_table = pd.read_csv(Path("cafe_data") / "products.csv")
print(price_table.shape)
print(price_table.head(3))
```

<details>
<summary>Reveal the result</summary>

```text
(16, 4)
   product_id product_name category  unit_price_usd
0           1     Espresso   coffee             3.0
1           2    Americano   coffee             3.5
2           3        Latte   coffee             4.5
```

</details>

*Why:* 16 products with 4 columns, and the first rows are the first products of the menu. Nothing tells the table where the file's path came from; a table has no memory of it.

**Try it.** Read the board names file as it is, then with its encoding:

```python
board_file = Path("cafe_data") / "board_names.csv"
try:
    pd.read_csv(board_file)
    print("read without a problem")
except ValueError:
    print("stopped with a ValueError")
board_names = pd.read_csv(board_file, encoding="latin-1")
board_names["board_name"].tolist()
```

**Predict:** the till saved this file as `latin-1`. Does the first read work or stop, and what do the names look like after the second?

<details>
<summary>Reveal the result</summary>

```text
stopped with a ValueError
['Café espresso', 'Café au lait', 'Chai latté']
```

</details>

*Why:* the é was saved as the single byte `0xe9`. UTF-8 does not read that byte on its own, so the first read stopped with a `UnicodeDecodeError`, a kind of `ValueError`; with `encoding="latin-1"` the same byte reads as é. The error is the file telling you to find out how it was saved. If you can, save it again as UTF-8.

### 3. A JSON file

**Idea.** JSON is text in which values nest: curly brackets are dictionaries and square brackets are lists, the ones of lessons P6 and P5. `json.loads(text)` turns JSON text into those dictionaries and lists, and `Path.read_text` gives the text of a file. A list of records, one dictionary for each line, becomes a table with `pd.DataFrame(records)`.

**Try it.** The file `cafe_data/order_1107.json` holds one order with its lines:

```json
{
  "order_id": 1107,
  "store": "Old Town",
  "ordered_at": "2026-01-15 16:57:00",
  "lines": [
    {"product": "Mocha", "quantity": 2, "discount_usd": 0.5},
    {"product": "Cappuccino", "quantity": 1, "discount_usd": 0.5}
  ]
}
```

```python
import json

order = json.loads((Path("cafe_data") / "order_1107.json").read_text(encoding="utf-8"))
print(order["store"], len(order["lines"]))
print(pd.DataFrame(order["lines"]))
```

**Predict:** what do the two prints show, and what does the table look like?

<details>
<summary>Reveal the result</summary>

```text
Old Town 2
      product  quantity  discount_usd
0       Mocha         2           0.5
1  Cappuccino         1           0.5
```

</details>

*Why:* `order` is a dictionary, so `order["store"]` reads a value and `order["lines"]` is a list of two dictionaries. `DataFrame` turned that list into a table with one row for each dictionary and one column for each key. The order itself, its id and its store, stayed outside the table.

### 4. An Excel sheet

**Idea.** A workbook holds several sheets, so `pd.read_excel(file, sheet_name="orders")` names the one you want and returns it as a table. The workbook of the cafe data is `cafe-sales.xlsx`: five tables, one sheet each.

**Try it.**

```python
orders_excel = pd.read_excel(BASE + "cafe-sales.xlsx", sheet_name="orders")
print(orders_excel.shape)
```

**Predict:** what shape does the `orders` sheet have?

<details>
<summary>Reveal the result</summary>

```text
(1800, 6)
```

</details>

*Why:* the sheet has the rows and columns of the orders table. Excel gave the same kind of table as the CSV file did, from another kind of file: the reader changed, the table did not.

### 5. Check: two routes, one table

Write down the two shapes and the answer to the last line, then run the cell. The CSV file is the orders file of the release, and the sheet is the one of unit 4.

```python
orders_csv = pd.read_csv(BASE + "orders.csv")
print(orders_csv.shape, orders_excel.shape)
print(list(orders_csv.columns) == list(orders_excel.columns))
```

<details>
<summary>Reveal the result</summary>

```text
(1800, 6) (1800, 6)
True
```

</details>

*Why:* the two sources hold the same table, and the shape and the column names are the quickest check that nothing was lost on the way in.

<Aside type="tip" title="Remember">

- A relative path starts in the working directory; `Path("folder") / "file.csv"` builds one and `exists()` asks.
- `read_csv` expects UTF-8; `encoding="..."` names how the file was saved.
- `json.loads` gives dictionaries and lists; a list of records becomes a table with `pd.DataFrame`.
- `read_excel` needs the sheet to read.
- After every read, look at `.shape`.

**Common trap:** an accented name that comes out as other letters, or with letters missing: the file was read with an encoding it was not saved in.

</Aside>
