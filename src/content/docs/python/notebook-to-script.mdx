## Learn by doing

About 30 minutes, 4 new ideas: saving and running a script, `main`, parameters at the top, and a loop over files. The last unit only checks them. The setup cell cut `orders.csv` into six monthly files in a folder called `monthly`. Each unit writes a new version of the same file, `pack.py`.

<OpenInColab />

### 1. Save a cell as a script and run it

**Idea.** A **script** is a text file of Python lines that `python name.py` runs from the top. In a notebook, `%%writefile name.py` as the first line of a cell makes the rest of the cell the text of that file (the IPython page for `%%writefile`). A line that starts with `!` runs a command, as in lesson P24, and `!{sys.executable} name.py` names the notebook's own Python, the safe way to run it.

**Try it.** Save a first script that counts the April orders:

```python
%%writefile pack.py
import pandas as pd

orders = pd.read_csv("monthly/orders_2026_04.csv")
print(len(orders), "orders in April")
```

**Predict:** will this cell run the lines, or only save them? What will it print?

<details>
<summary>Reveal the result</summary>

```text
Writing pack.py
```

</details>

*Why:* the cell printed only the name of the file it wrote, so the lines are saved, not run. Now run the file.

**Try it.** Run the script, then print the number of rows of `orders` in the notebook:

```python
!{sys.executable} pack.py
print(len(orders))
```

**Predict:** the notebook's `orders` has 1,800 rows, and April has 349 orders. What will the script print, and what will `len(orders)` print afterwards?

<details>
<summary>Reveal the result</summary>

```text
349 orders in April
1800
```

</details>

*Why:* the script printed its 349 and the notebook still has 1,800 rows. The script ran in its own Python, and its `orders` was its own, so nothing it did changed the notebook's variables. A script gets everything from its own lines and its files.

### 2. Functions and a main block

**Idea.** Put the steps in functions and call them from `main()`, under `if __name__ == "__main__":`. The Python `__main__` page describes this test.

**Try it.** Write the second version, import it in the notebook, call one of its functions, and then run it as a script:

```python
%%writefile pack.py
import pandas as pd


def count_orders(path):
    orders = pd.read_csv(path)
    return len(orders)


def main():
    print(count_orders("monthly/orders_2026_04.csv"), "orders in April")


if __name__ == "__main__":
    main()
```

**Predict:** this file already exists. What will the cell print?

<details>
<summary>Reveal the result</summary>

```text
Overwriting pack.py
```

</details>

```python
import pack
print("imported")
print(pack.count_orders("monthly/orders_2026_05.csv"))
!{sys.executable} pack.py
```

**Predict:** what does `import pack` itself print, and what will the other three lines give, in order?

<details>
<summary>Reveal the result</summary>

```text
imported
380
349 orders in April
```

</details>

*Why:* `import pack` printed nothing, so `main()` did not run on the import: the test is false when another module imports the file, and the `__main__` page says the code in that block does not run unless the module is the top-level program; `pack.count_orders` gave May's orders for any path you pass it, and `python pack.py` ran `main()`. One file now works as a script and as a module of functions.

### 3. Parameters at the top

**Idea.** Put the values you may change, such as file names, in names written in capitals at the top of the script, before any function. A run is changed by editing one line at the top and never the code below. The script now writes its table to a file with `to_csv`.

**Try it.** Write the third version, run it, and read the file it wrote:

```python
%%writefile pack.py
import pandas as pd

# Parameters: the only lines to change between runs.
ORDER_FILE = "monthly/orders_2026_05.csv"
OUT_FILE = "orders_by_store.csv"


def orders_by_store(path):
    orders = pd.read_csv(path)
    return orders.groupby("store_id").size().rename("orders")


def main():
    table = orders_by_store(ORDER_FILE)
    table.to_csv(OUT_FILE)
    print("wrote", OUT_FILE, "with", len(table), "rows")


if __name__ == "__main__":
    main()
```

**Predict:** this file already exists. What will the cell print?

<details>
<summary>Reveal the result</summary>

```text
Overwriting pack.py
```

</details>

```python
!{sys.executable} pack.py
print(Path("orders_by_store.csv").read_text())
```

**Predict:** May had 380 orders. What will the script print, and what will the file hold: which columns, and how many rows of numbers?

<details>
<summary>Reveal the result</summary>

```text
wrote orders_by_store.csv with 3 rows
store_id,orders
1,125
2,134
3,121
```

</details>

*Why:* the file has a header and one row for each of the 3 stores, and the 3 numbers add up to the 380 of unit 2. To run it for another month you would change `ORDER_FILE` and nothing else.

### 4. Loop over the files, write one output

**Idea.** `Path().glob("monthly/orders_2026_*.csv")` lists the files whose names match the pattern, and `sorted(...)` puts them in name order. Read each file in a list comprehension, stack them with `concat`, clean the stack once, and write one output: one script then handles one file or twelve.

**Try it.** Write the fourth version. It keeps the completed orders, adds the month, and counts orders for each store and month:

```python
%%writefile pack.py
from pathlib import Path

import pandas as pd

# Parameters: the only lines to change between runs.
ORDER_FILES = "monthly/orders_2026_*.csv"
OUT_FILE = "orders_by_store_month.csv"


def read_orders(pattern):
    files = sorted(Path().glob(pattern))
    frames = [pd.read_csv(path) for path in files]
    return pd.concat(frames, ignore_index=True), len(files)


def main():
    orders, n_files = read_orders(ORDER_FILES)
    orders = orders[orders["status"] == "completed"]
    orders = orders.assign(month=pd.to_datetime(orders["ordered_at"]).dt.month)
    table = orders.groupby(["store_id", "month"]).size().rename("orders").reset_index()
    table.to_csv(OUT_FILE, index=False)
    print(n_files, "files,", len(orders), "orders,", len(table), "rows written to", OUT_FILE)


if __name__ == "__main__":
    main()
```

**Predict:** this file already exists. What will the cell print?

<details>
<summary>Reveal the result</summary>

```text
Overwriting pack.py
```

</details>

```python
!{sys.executable} pack.py
```

**Predict:** the folder has 6 files and 3 stores. How many rows will the table have, and how many orders will the script report?

<details>
<summary>Reveal the result</summary>

```text
6 files, 1799 orders, 15 rows written to orders_by_store_month.csv
```

</details>

*Why:* 15 rows, not 3 × 6 = 18, because Harbor opened on April 1 and has no orders in the first three months. The script reports 1,799 orders: the one canceled order was dropped by the filter, as the dataset README says there is one.

### 5. Check: the script gives the notebook's table

Before you share a notebook, restart the session and run every cell from the first, as in lesson P1; before you share a script, compare what it writes with a table you can trust. Write down what you expect, then run it. The notebook builds the same table in one expression.

```python
expected = (orders.assign(month=pd.to_datetime(orders["ordered_at"]).dt.month)
            .query("status == 'completed'")
            .groupby(["store_id", "month"]).size().rename("orders").reset_index())
from_script = pd.read_csv("orders_by_store_month.csv")
print(from_script.to_numpy().tolist() == expected.to_numpy().tolist())
```

**Predict:** will the numbers the script wrote equal the numbers the notebook builds?

<details>
<summary>Reveal the result</summary>

```text
True
```

</details>

*Why:* `True`: the file holds the same numbers, built by a program that never saw the notebook. (Comparing the lists of numbers sidesteps the number type: the file is read back as 64-bit whole numbers, the month in the notebook is a smaller one.) That is the test of a script: someone else runs it and gets your numbers.

<Aside type="tip" title="Remember">

- `%%writefile name.py` saves a cell as a file, and `!{sys.executable} name.py` runs it.
- Put the steps in functions, and call `main()` under `if __name__ == "__main__":`.
- Put the parameters in capitals at the top; change a run by editing those lines.
- Read all the files in a loop, stack them, clean once and write one output.

**Common trap:** assuming a script sees the notebook's variables. It runs in its own Python and has only its own lines and files.

</Aside>

**How many orders did one store place in one month?** The function below answers for the store and month written at the top. Finish it: make `store_id` and `month` parameters of the function, so that the same function answers for any store and month. Expected: `count_orders(orders, 3, 5)` gives the orders of Harbor, store 3, in May.

```python
STORE_ID = 2  # parameters at the top
MONTH = 4


def count_orders(orders):
    month = pd.to_datetime(orders["ordered_at"]).dt.month
    return int(((orders["store_id"] == STORE_ID) & (month == MONTH)).sum())
```

<Solution>

```python
def count_orders(orders, store_id, month):
    months = pd.to_datetime(orders["ordered_at"]).dt.month
    return int(((orders["store_id"] == store_id) & (months == month)).sum())
```

The function now takes the store and the month as arguments, so each call answers its own question. A function that kept reading `STORE_ID` and `MONTH` from the top would answer the same question for every call, and the check cell calls it for store 3 and May.
