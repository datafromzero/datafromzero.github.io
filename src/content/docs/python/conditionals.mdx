## The question

The owner asks:

> Which price tier does each product belong to? Premium is 8 dollars or more, regular is 4.50 or more, and everything else is cheap.

Three of the 16 products:

| product_id | product_name | unit_price_usd |
|---:|---|---:|
| 15 | Turkey Sandwich | 9.25 |
| 3 | Latte | 4.50 |
| 1 | Espresso | 3.00 |

A tier is a decision, so this lesson teaches Python's way to decide. By the end of this page you can write the rule once and check it on boundary prices such as 4.50 and 8.

<Aside type="note" title="You already know this">

**Match.** `if`, `elif` and `else` are the nested `IF` of *Decisions with IF, AND and OR* (E6) and the `CASE WHEN` of *Labels and buckets with CASE* (S6): the tests run in order and the first true one wins. `and`, `or` and `not` are `AND`, `OR` and `NOT`.

**Diverge.** Excel and SQL compare with one equals sign. In Python `=` stores a value and `==` compares, so `price = 4.5` and `price == 4.5` are different lines (unit 1). A Python block also has no brackets and no `END`: a colon and four spaces of indentation mark what belongs to each branch (unit 2).

</Aside>

## The big idea

## Learn by doing

About 20 minutes, 4 new ideas: conditions, `if` chains, `and` with `or` with `not`, and flat against nested conditions. The last unit only checks them.

<OpenInColab />

### 1. A condition is a question with a True or False answer

**Idea.** A comparison such as `price >= 4.5` is a condition: Python answers `True` or `False`. `==` asks whether two values are equal, while a single `=` stores a value. It is the test inside a `WHERE`, asked for one value instead of a column.

**Try it:**

```python
price = 4.5
price >= 4.5, price > 4.5, price == 4.5
```

**Predict:** a Latte costs 4.50. What do the three tests give?

<details>
<summary>Reveal the result</summary>

```text
(True, False, True)
```

</details>

*Why:* `>=` includes the boundary and `>` leaves it out, so the Latte is exactly on the line that decides its tier. Soon every condition will become a whole column of `True` and `False` that you can look at, and a `WHERE` keeps the rows where it is `True`.

### 2. if, elif and else

**Idea.** An `if` chain tests from the top and runs only the block of the first test that is `True`; the rest are skipped. `else` takes whatever is left. The block under each test is indented by four spaces.

**Try it:**

```python
price = 9.25
if price >= 8:
    tier = "premium"
elif price >= 4.5:
    tier = "regular"
else:
    tier = "cheap"
tier
```

**Predict:** 9.25 is at least 8 and also at least 4.5. Which tier does the chain choose?

<details>
<summary>Reveal the result</summary>

```text
'premium'
```

</details>

*Why:* the chain stopped at the first true test. It never looked at the second one, as a `CASE` stops at its first matching `WHEN`. The order of the tests is part of the rule.

### 3. and, or, not

**Idea.** `a and b` is true when both are true, `a or b` when at least one is, and `not a` flips the answer. Each side of `and` and `or` must be a complete condition of its own.

**Try it:**

```python
store_id = 3
payment = "cash"
store_id == 3 and payment == "card", store_id == 3 or payment == "card", not store_id == 3
```

**Predict:** an order from store 3 was paid in cash. What do the three tests give?

<details>
<summary>Reveal the result</summary>

```text
(False, True, False)
```

</details>

*Why:* store 3 is true and card is false, so `and` fails, `or` passes, and `not` flips the true. Now a test that reads like English:

```python
store_id == 1 or 2
```

**Predict:** the store is 3. Is it 1 or 2?

<details>
<summary>Reveal the result</summary>

```text
2
```

The complete test, `store_id == 1 or store_id == 2`, gives:

```text
False
```

</details>

*Why:* `store_id == 1` is false, so `or` hands back its right side, the number 2, and Python counts any non-zero number as true. Write both sides in full. The same habit will matter when conditions become columns.

### 4. Flatten a nested condition

**Idea.** A condition can sit inside another one. A nested `if` works, but a flat `elif` chain says the same thing in less room and reads like a `CASE`. Each `elif` already knows that every test above it was false.

**Try it:**

```python
price = 4.5
if price >= 4.5:
    if price >= 8:
        tier = "premium"
    else:
        tier = "regular"
else:
    tier = "cheap"
tier
```

**Predict:** which tier does the nested version give for 4.50?

<details>
<summary>Reveal the result</summary>

```text
'regular'
```

</details>

*Why:* the outer test passes at 4.5, the inner test fails, so the inner `else` runs. The flat chain of unit 2 gives the same tier with one level less.

### 5. Check: which branch runs?

Run the chain of unit 2 three times, with the first line `price = 8.0`, then `4.25`, then `5.5`. Write down your three tiers first.

<details>
<summary>Reveal the result</summary>

```text
'premium'
'cheap'
'regular'
```

</details>

*Why:* 8.0 passes the first test because `>=` includes it, 4.25 passes neither test, and 5.5 fails the first and passes the second.

<Aside type="tip" title="Remember">

- A condition gives `True` or `False`; `==` compares, `=` stores.
- An `if` chain runs only the first true branch, so the order of the tests is part of the rule.
- `and`, `or` and `not` need a complete condition on each side: `store_id == 1 or store_id == 2`.
- Prefer a flat `elif` chain to a nested `if`.
- Soon a condition becomes a column of `True` and `False` for a whole table.

**Common trap:** a boundary or an order you did not test. `>` against `>=` moves the Latte's tier, and a broad test placed first catches every price below it.

</Aside>
