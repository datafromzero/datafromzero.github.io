## Learn by doing

About 25 minutes, 4 new ideas: an environment, installing into the Python you name, `requirements.txt`, and printing versions. Lines that start with `!` run in the computer's shell, as in a terminal. The setup cell holds three helpers, `env_python`, `run_in` and `make_env`, that you use but do not write.

<OpenInColab />

### 1. An environment is a folder with its own Python

**Idea.** A **virtual environment** is a folder that holds a Python of its own and the packages installed for it. In a terminal you make one with `python -m venv cafe-env`; in the notebook the same words work after a `!`. `run_in` runs a few lines with the Python of an environment and gives back the last line it printed.

**Try it.** Make `cafe-env` and ask its Python to import pandas, which this notebook already uses:

```python
!{sys.executable} -m venv {env_dir}
print(run_in(env_python, "import pandas"))
```

**Predict:** this notebook has pandas. Will the Python of the new folder find it, and what is the last line it prints?

<details>
<summary>Reveal the result</summary>

```text
ModuleNotFoundError: No module named 'pandas'
```

</details>

*Why:* the new environment starts with a Python and its own pip, not with the packages installed elsewhere. Python's own `venv` page says that an environment can see the system packages only when it is created to (`system_site_packages`, off by default), and `{sys.executable}` is the Python this notebook runs on, so the new folder holds a Python made from it.

### 2. pip installs into the Python you name

**Idea.** `python -m pip install name==version` installs the exact version it names. Put the Python you mean in front: here the one inside `cafe-env`. In a notebook, `%pip install` is the notebook's own shortcut (IPython's `%pip` page). A bare `!pip` leaves it to the shell to find some pip.

**Try it.** Install pandas 2.2.3 into `cafe-env`, then ask both Pythons for their pandas:

```python
!{env_python} -m pip install -q pandas==2.2.3
print("notebook:", pd.__version__)
print("cafe-env:", run_in(env_python, "import pandas; print(pandas.__version__)"))
```

**Predict:** after this install, will the notebook's own version change, and what will `cafe-env` print?

<details>
<summary>Reveal the result</summary>

```text
notebook: 3.1.1
cafe-env: 2.2.3
```

</details>

*Why:* the install went into `cafe-env` and nowhere else, so the notebook's version stays as it was and `cafe-env` has the pin. The first line shows the pandas of your own notebook, so it may not match this page; the two lines differ whenever your notebook's pandas is not 2.2.3. To install into the notebook's own Python, use `%pip`.

**Try it.** Install a small package, pinned, into the notebook's own Python and import it:

```python
%pip install -q tabulate==0.9.0
import tabulate
print(tabulate.__version__)
```

**Predict:** which version will the notebook report, and which of the two Pythons got the package?

<details>
<summary>Reveal the result</summary>

```text
Note: you may need to restart the kernel to use updated packages.
0.9.0
```

</details>

*Why:* `0.9.0`, the pin, and the notebook's own Python got it, because the IPython page says `%pip` runs pip within the current kernel. `cafe-env` did not get it. The first line is a note from `%pip`: a package that was already imported before the install may need a restart of the notebook to change, and this one had not been imported.

### 3. requirements.txt: write down what you pinned

**Idea.** A requirements file is a text file with one package on each line, and `name==version` pins an exact version. `python -m pip install -r requirements.txt` installs every line, and `pip freeze` lists what is installed in the same format, which the pip user guide offers for repeatable installs.

**Try it.** Write a file with two pins, install it into `cafe-env`, and read what `pip freeze` says (`frozen = !command` keeps the lines of a command in a list):

```python
requirements = work / "requirements.txt"
requirements.write_text("pandas==2.2.3\ntabulate==0.9.0\n")
!{env_python} -m pip install -q -r {requirements}
frozen = !{env_python} -m pip freeze
print(len(frozen) > 2)
print([line for line in frozen if line.startswith(("pandas", "tabulate"))])
```

**Predict:** the file names 2 packages. Will `pip freeze` print more than 2 lines, and which lines hold the two pins?

<details>
<summary>Reveal the result</summary>

```text
True
['pandas==2.2.3', 'tabulate==0.9.0']
```

</details>

*Why:* `True`: the file named 2 packages, but `pip freeze` lists everything installed, and pip also installed the packages that pandas needs, without being asked. On the day this page was written it printed 6 lines in all, and which packages pandas needs, and so the count, can change. Only the two lines you pinned are fixed by your file. On Python 3.12 and later `pip freeze` leaves out pip itself, as its documentation says.

### 4. Print the versions: one file, two Pythons

**Idea.** A shared notebook starts by printing what it runs on: `sys.version_info[:2]` for Python and `pd.__version__` for pandas.

**Try it.** Read the orders file in the notebook and in `cafe-env`, and print the number of rows and the type that each Python gives the `status` column:

```python
print("python:", sys.version_info[:2])
orders_in_env = f'import pandas as pd; orders = pd.read_csv("{BASE}orders.csv"); print(len(orders), orders["status"].dtype)'
print("notebook:", len(orders), orders["status"].dtype)
print("cafe-env:", run_in(env_python, orders_in_env))
```

**Predict:** the file and the call are the same in both. Will the two lines print the same row count, and the same type for `status`?

<details>
<summary>Reveal the result</summary>

```text
python: (3, 13)
notebook: 1800 str
cafe-env: 1800 object
```

</details>

*Why:* both read 1,800 rows, and the types differ in this run: pandas 3 reads a text column as `str` and pandas 2.2 as `object`, as lesson P11 showed. The first two lines show the Python and pandas of your own notebook; if your notebook has pandas 2, both lines say `object`. A different version can change what a column is called without changing one row.

<Aside type="tip" title="Remember">

- An environment is a folder with its own Python and its own packages.
- `python -m pip install` installs into the Python you put in front of it, and `%pip` installs into the notebook's own.
- Pin an exact version with `==`, keep the pins in `requirements.txt`, and read `pip freeze` to see everything installed.
- Print the Python and pandas versions at the top of a notebook you share.

**Common trap:** installing with the pip of one Python and importing in another: the install succeeds and the `import` still fails. A bare `!pip` leaves the choice to the shell.

</Aside>

## On your own

<Exercise id="python-environments-and-pip-2">

**The cafe notebook needs pandas 2.2.3 or newer. How does a script know whether an installed version is new enough?** Before you start, say in a sentence what `version_at_least("2.10.0", "2.9.1")` should give. Then write `version_at_least(installed, needed)`: it gives `True` when the first version is the same as or newer than the second. A version is text with three numbers separated by dots, such as `"2.2.3"`. Write the function in the empty cell of the notebook. Expected: `version_at_least("2.10.0", "2.9.1")` gives `True` and `version_at_least("2.2.3", "3.0.0")` gives `False`.

<details>
<summary>Hint</summary>

Cut the text at the dots with `split(".")`, turn each piece into a whole number with `int`, and compare the two lists of numbers. A list compares item by item, from the first.

</details>

<details>
<summary>Half-solution</summary>

Expected output in words: *"True for 2.10.0 against 2.9.1, because 10 is more than 9; False for 2.2.3 against 3.0.0."*

```python
def version_at_least(installed, needed):
    return [int(part) for part in ...] >= [...]
```

</details>

<Solution>

```python
def version_at_least(installed, needed):
    return [int(part) for part in installed.split(".")] >= [int(part) for part in needed.split(".")]
```

The function turns each version into a list such as `[2, 10, 0]` and lets Python compare the lists item by item, so 10 beats 9. Comparing the texts directly looks at one character at a time, and `"1"` comes before `"9"`, so `"2.10.0"` would count as older than `"2.9.1"`; the check cell calls it with that pair.

</Solution>

</Exercise>

<Exercise id="python-environments-and-pip-3">

**Spot the flaw.** A colleague wrote a check that lists the packages the cafe notebook imports but its `requirements.txt` does not name. It prints all four packages as missing, so nobody trusts it. Fix the check so that `missing` holds only the package that is really absent. Expected: `missing` is `['seaborn']`.

```python
imports_used = ["pandas", "matplotlib", "seaborn", "numpy"]  # what the cafe notebook imports
colleague_file = "pandas==2.2.3\nmatplotlib==3.9.2\nnumpy==2.1.2\n"  # the requirements.txt, written by hand
listed = colleague_file.splitlines()  # the colleague's check
missing = [name for name in imports_used if name not in listed]
```

<details>
<summary>Hint</summary>

Print `listed` and read one item. Does any item equal the bare name `"pandas"`?

</details>

<details>
<summary>Half-solution</summary>

```python
listed = [line.split(...)[0] for line in colleague_file.splitlines()]
```

</details>

<Solution>

```python
imports_used = ["pandas", "matplotlib", "seaborn", "numpy"]
colleague_file = "pandas==2.2.3\nmatplotlib==3.9.2\nnumpy==2.1.2\n"
listed = [line.split("==")[0] for line in colleague_file.splitlines()]
missing = [name for name in imports_used if name not in listed]
```

`listed` held whole lines such as `pandas==2.2.3`, so no bare name was ever in it and every package looked missing. Cutting each line at `==` and keeping the first piece leaves the names, and only `seaborn` is absent. The fix handles `==` lines only: a real file can also hold comments, blank lines and other forms such as `>=`.

</Solution>
