## The question

The owner asks:

> How many orders did the cafes take in each month, and did the count go up or down from the month before?

The time of an order is in the file as text, and a text does not know that it is a date:

| order_id | ordered_at |
|---:|---|
| 1001 | 2026-01-01 08:02:00 |
| 1002 | 2026-01-01 15:38:00 |
| 1003 | 2026-01-01 15:47:00 |

By the end of this page you will turn the text into dates, filter a range of days, count the orders of each month and set each month beside the one before.

### 1. to_datetime: name the format

**Idea.** `pd.to_datetime(column, format="...")` reads text as dates. The format says which part is which: `%Y` is the year, `%m` the month, `%d` the day, `%H:%M:%S` the time (the codes of Python's `datetime` page). Name it, because a text such as `03/04/2026` can be the 3rd of April or the 4th of March, and a guess can be wrong without a sign.

**Try it.** The order times, read with their format:

```python
orders = orders.assign(when=pd.to_datetime(orders["ordered_at"], format="%Y-%m-%d %H:%M:%S"))
print(orders["when"].min(), orders["when"].max())
print(orders["when"].isna().sum())
```

**Predict:** `ordered_at` is text. What are the first and the last order times after the conversion, and how many dates are missing?

<details>
<summary>Reveal the result</summary>

```text
2026-01-01 08:02:00 2026-06-30 16:30:00
0
```

</details>

*Why:* the first order is on January 1 and the last on June 30, and no date is missing, because every text fitted the format. Now three dates typed by hand, day first, as a bakery supplier writes them (a small list typed here, not cafe-sales data). With `errors="coerce"`, a text that does not fit becomes `NaT`, the missing date, instead of an error:

```python
typed = pd.Series(["03/04/2026", "13/04/2026", "05/11/2026"])
as_days = pd.to_datetime(typed, format="%d/%m/%Y")
as_months = pd.to_datetime(typed, format="%m/%d/%Y", errors="coerce")
print(as_days.dt.month.tolist())
print(as_months.isna().sum())
```

**Predict:** read day first, which month does each text give? Read month first, with `errors="coerce"`, how many dates are missing?

<details>
<summary>Reveal the result</summary>

```text
[4, 4, 11]
1
```

</details>

*Why:* day first the months are 4, 4 and 11. Month first, the second text asked for month 13, which does not exist, so `coerce` turned it into `NaT` and printed nothing: one date vanished, and the first and third were read as other dates. Name the format, and count the missing dates after every parse.

### 2. dt and date ranges: parts, and the last day

**Idea.** The `dt` accessor opens the parts of a date column: `dt.month`, `dt.hour`, `dt.day_name()`. A date also compares with a text date.

**Try it.** The orders of each weekday:

```python
weekday = orders["when"].dt.day_name()
print(weekday.value_counts())
```

**Predict:** which day of the week has the most orders, and which the fewest?

<details>
<summary>Reveal the result</summary>

```text
when
Saturday     340
Sunday       315
Monday       249
Wednesday    232
Friday       230
Tuesday      223
Thursday     211
Name: count, dtype: int64
```

</details>

*Why:* Saturday leads and Thursday is last. The column `when` carries no time zone: by default pandas objects are time zone unaware, the pandas page says, and the hours are the till's own local times. Now a range of days. A colleague keeps January to March with the last day written out:

```python
first_quarter = orders[(orders["when"] >= "2026-01-01") & (orders["when"] <= "2026-03-31")]
whole_quarter = orders[(orders["when"] >= "2026-01-01") & (orders["when"] < "2026-04-01")]
print(len(first_quarter), len(whole_quarter))
```

**Predict:** how many orders does each version keep?

<details>
<summary>Reveal the result</summary>

```text
710 718
```

</details>

*Why:* 710 against 718. `"2026-03-31"` means midnight at the start of March 31, so every order of that day after 00:00 is cut off, eight of them. As in S11, ask for the rows before the first moment of the next day: `< "2026-04-01"`. A range that ends on a date and a day that is not complete is a common way to lose rows.

### 3. resample: one row for each month

**Idea.** `resample("MS")` groups a table by calendar month, `"MS"` for the month start, and it needs the dates as the index, so `set_index("when")` comes first. It is the `date_trunc` and `GROUP BY` of S11 in one call, and it puts the months in time order.

**Try it.** The orders of each month:

```python
monthly = orders.set_index("when").resample("MS")["order_id"].size()
print(monthly)
print(monthly.sum())
```

**Predict:** how many rows will `monthly` have, and will its numbers add up to 1,800?

<details>
<summary>Reveal the result</summary>

```text
when
2026-01-01    242
2026-02-01    218
2026-03-01    258
2026-04-01    349
2026-05-01    380
2026-06-01    353
Freq: MS, Name: order_id, dtype: int64
1800
```

</details>

*Why:* six months, January to June, and the counts add up to the 1,800 orders. The counts rise from April, when Harbor opened. Now a month with no rows. Customer 5 ordered in January, April, May and June, and not in February or March:

```python
one = orders[orders["customer_id"] == 5]
by_resample = one.set_index("when").resample("MS")["order_id"].size()
by_month = one.groupby(one["when"].dt.month).size()
print(by_resample.tolist())
print(by_month.to_dict())
```

**Predict:** what will each version list for the months in which customer 5 did not order?

<details>
<summary>Reveal the result</summary>

```text
[1, 0, 0, 3, 1, 1]
{1: 1, 4: 3, 5: 1, 6: 1}
```

</details>

*Why:* `resample` lists every month from the first order to the last, and writes 0 for February and March. `groupby` on the month number lists only the four months that have rows, as `GROUP BY` did in S11. If the answer needs every month, use `resample`, or fill the gaps yourself as S27 did.

### 4. shift: the month before

**Idea.** `series.shift(1)` moves every value down one place, so each month sits beside the month before it. `monthly - monthly.shift(1)` is then the change from the previous month. It is the `LAG` of S16, and it needs the rows in time order, which `resample` gives.

**Try it.** The change in the orders from month to month:

```python
change = monthly - monthly.shift(1)
print(change.tolist())
```

**Predict:** what will the first value be, and in which month did the orders grow the most?

<details>
<summary>Reveal the result</summary>

```text
[nan, -24.0, 40.0, 91.0, 31.0, -27.0]
```

</details>

*Why:* the first value is `nan`: January has no month before it, as `LAG` gave `NULL` in S16. The biggest rise, 91 orders, is April, when Harbor opened. The values are decimals because the `nan` is a float, as in lesson P16.

### 5. Check: two routes to the same months

A result is trusted more when a second route gives it. Write down what you expect, then run the cell.

```python
by_number = orders.groupby(orders["when"].dt.month).size()
print(by_number.tolist() == monthly.tolist())
```

**Predict:** do `groupby` on the month number and `resample` give the same six counts?

<details>
<summary>Reveal the result</summary>

```text
True
```

</details>

*Why:* `True`: the two routes agree, because all six months have orders, so neither route has a gap to fill. Had a month been empty, the two would have disagreed, as in unit 3.

<Aside type="tip" title="Remember">

- `to_datetime(column, format="...")` turns text into dates. Name the format, and count the `NaT` after.
- `dt.month`, `dt.hour` and `dt.day_name()` open the parts of a date.
- Filter a range with `>=` the first day and `<` the day after the last. A date written alone means midnight.
- `resample("MS")` gives one row for each month, and a row of 0 for a month with no rows. `groupby` gives only months that have rows.
- `shift(1)` puts the previous month beside this one.

**Common trap:** a range that ends on a date written alone leaves out the orders of that day after midnight.

</Aside>
