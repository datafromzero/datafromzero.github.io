## The question

The owner asks:

The first three orders, as the file holds them:

| order_id | customer_id | store_id | ordered_at | status | payment_method |
|---:|---:|---:|---|---|---|
| 1001 | 15 | 2 | 2026-01-01 08:02:00 | completed | mobile |
| 1002 | 46 | 1 | 2026-01-01 15:38:00 | completed | mobile |
| 1003 | 61 | 2 | 2026-01-01 15:47:00 | completed | mobile |

A first look is five questions you can ask any table: how big, what types, what values, how many of each, and how do two columns combine. By the end of this page you will have asked them of the cafe data.

<Aside type="note" title="You already know this">

**Match.** In *Counting and summing: aggregate functions* (S7), `COUNT(*)` gave the number of rows and `COUNT(DISTINCT customer_id)` the number of different customers. In pandas they are `orders.shape[0]`, which gives the same 1,800, and `orders["customer_id"].nunique()`. `MIN`, `AVG` and `MAX` come back together in one call, `describe()`.

**Diverge.** SQL lines up tables only where you write a `JOIN` and its `ON`. Arithmetic between two pandas columns lines them up by the labels of their rows, without being asked; unit 4 shows what that does to a label that is on one side only.

</Aside>

### 1. A table, its index and its types

**Idea.** A DataFrame is a table. `.shape` is a pair, the rows and then the columns. `.head(3)` shows the first three rows, and the numbers on their left are the index, the label of each row. `.dtypes` lists the <Term id="glossary-dtype">type</Term> of every column: `int64` is a whole number, `float64` a decimal number and `str` text.

**Try it:**

```python
print(orders.shape)
print(orders.head(3))
print(orders.dtypes)
```

**Predict:** what type does each column have? The shape is for you to read; the ids of the first three rows look like whole numbers.

<details>
<summary>Reveal the result</summary>

```text
(1800, 6)
   order_id  customer_id  store_id           ordered_at     status  \
0      1001         15.0         2  2026-01-01 08:02:00  completed   
1      1002         46.0         1  2026-01-01 15:38:00  completed   
2      1003         61.0         2  2026-01-01 15:47:00  completed   

  payment_method  
0         mobile  
1         mobile  
2         mobile  
order_id            int64
customer_id       float64
store_id            int64
ordered_at            str
status                str
payment_method        str
dtype: object
```

</details>

*Why:* 1,800 rows and 6 columns, the 1,800 orders of S7. The index runs from 0, one label for each row. `customer_id` is `float64`, not `int64`: one order, the walk-in, has no customer, and pandas writes a missing value as `NaN`, a decimal-number value, so a column that has one is stored as decimals and shows the ids as 15.0. On pandas 2 the three text columns show `object` where pandas 3 shows `str`.

### 2. Summarize one column

**Idea.** `describe()` summarizes a number column: how many values, the mean, the spread, the smallest, the quartiles and the largest. `value_counts()` counts how often each value of a category column occurs, most common first. Its result has the values as labels, so you can read one count by its label, as in `counts["canceled"]`.

**Try it:**

```python
print(order_items["quantity"].describe())
status_counts = orders["status"].value_counts()
print(status_counts)
print(status_counts["canceled"])
```

**Predict:** how many order lines are there, and what are the average and the largest quantity? How many orders does each status have?

<details>
<summary>Reveal the result</summary>

```text
count    3287.000000
mean        1.570429
std         0.801217
min         1.000000
25%         1.000000
50%         1.000000
75%         2.000000
max        20.000000
Name: quantity, dtype: float64
status
completed    1799
canceled        1
Name: count, dtype: int64
1
```

</details>

*Why:* `count` is 3,287 lines, the 3,287 of S7, and the average of 1.57 units is the one S7 found. The largest quantity, 20, is far from the others: it is the extra-zero line of order 2075, where 2 was meant. A first look shows it before any total uses it. `value_counts` found 1,799 completed orders and one canceled.

### 3. A column is a Series

**Idea.** One column of a DataFrame is a Series: values with the same index. In Python everything is an object, and an object has attributes and methods. An attribute is a fact it holds and takes no brackets, as `.shape` does. A method is something it does and takes brackets, as `.nunique()` and `.head(3)` do. `type(x).__name__` names the kind of object.

**Try it:**

```python
store = orders["store_id"]
print(type(store).__name__)
print(store.shape)
print(store.nunique())
print(store.head(3))
```

**Predict:** what kind of object is `store`? What do `.shape` and `.nunique()` give? What are the first three rows?

<details>
<summary>Reveal the result</summary>

```text
Series
(1800,)
3
0    2
1    1
2    2
Name: store_id, dtype: int64
```

</details>

*Why:* a column is a Series, so what you learn about one Series works on any column. `.shape` is a fact the Series stores, so it has no brackets; `.nunique()` has to count, so it is a call. The Series has the index of the table, which is why `head(3)` shows 0, 1 and 2 beside the store ids. `.nunique()` counts each store once: three cafes. By default it leaves empty cells out.

### 4. Arithmetic lines up on the index

**Idea.** An operation between two Series pairs the values by their index labels, not by their positions. `a.sub(b, fill_value=0)` is the same subtraction with a stand-in value, here 0, for a label that is missing on one side.

**Try it.** The orders of each store, and the orders of the first three, which are already billed. The first three orders were taken in stores 2, 1 and 2:

```python
all_orders = orders["store_id"].value_counts()
billed = orders["store_id"].head(3).value_counts()
print(billed)
print(all_orders - billed)
print(all_orders.sub(billed, fill_value=0))
```

**Predict:** what does `all_orders - billed` give for each store? Harbor, store 3, is in `all_orders` and not in `billed`.

<details>
<summary>Reveal the result</summary>

```text
store_id
2    2
1    1
Name: count, dtype: int64
store_id
1    728.0
2    714.0
3      NaN
Name: count, dtype: float64
store_id
1    728.0
2    714.0
3    355.0
Name: count, dtype: float64
```

</details>

*Why:* `billed` lists store 2 first, and `all_orders` lists store 1 first; the result still pairs each store with itself: store 1 is 729 minus 1, store 2 is 716 minus 2. Harbor is a label on one side only, so its row is `NaN`, the sign of a missing value, and the numbers became decimals. The subtraction with `fill_value=0` counts Harbor's missing billed orders as 0 and keeps its 355. SQL would have needed a join to pair the stores, and a `LEFT JOIN` to keep Harbor.

### 5. Check: which products were sold?

Write down the two numbers, then run the cell. The menu is the products table, and the lines are the order lines.

```python
print(products["product_id"].nunique(), order_items["product_id"].nunique())
```

<details>
<summary>Reveal the result</summary>

```text
16 15
```

</details>

*Why:* the menu has 16 products and the order lines hold 15 of them: the Pumpkin Spice Latte was never sold, the same count as in S7. Counting different values in two tables is the quickest way to find a row that has no partner.

<Aside type="tip" title="Remember">

- `.shape` is (rows, columns); `.head(n)` shows the first rows; `.dtypes` lists the type of each column.
- `describe()` summarizes a number column; `value_counts()` counts a category column, and its labels are the values.
- A column is a Series: an attribute has no brackets, a method has them.
- Arithmetic between two Series pairs the index labels, and a label on one side only gives `NaN`.
- Check the shape and the types right after you read a table.

**Common trap:** subtracting two Series and trusting the total: a label that is on one side only comes out as `NaN`, not as a number.

</Aside>
