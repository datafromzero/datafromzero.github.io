## Learn by doing

About 25 minutes, 3 new ideas: `map`, `assign` and `apply`. The last unit only checks them.

<OpenInColab />

### 1. map, a lookup for a whole column

**Idea.** `Series.map(dictionary)` replaces each value of a column by the value its key has in the dictionary. A dictionary of product ids and prices is a lookup table: the dictionary half of lesson P6, run on a whole column. The result is a new Series of the same length.

**Try it.** The prices of the two lines of order 1107:

```python
price_of = dict(zip(products["product_id"], products["unit_price_usd"]))
order_1107 = order_items[order_items["order_id"] == 1107]
print(order_1107["product_id"].tolist())
print(order_1107["product_id"].map(price_of).tolist())
```

**Predict:** order 1107 has two lines, for product 5 and product 4. Product 4 costs 4.50 and product 5 costs 5.00. What does `map` give for the two lines?

<details>
<summary>Reveal the result</summary>

```text
[5, 4]
[5.0, 4.5]
```

</details>

*Why:* the lines are products 5 and 4, in that order, so the prices come back in that order: 5.00 and 4.50. `map` kept the order of the lines and looked each key up. Now a dictionary that is missing a key:

```python
store_name_of = {1: "Old Town", 2: "Campus"}
names = orders["store_id"].map(store_name_of)
print(names.isna().sum(), names.notna().sum())
```

**Predict:** this dictionary was written before Harbor opened: it has stores 1 and 2 only. What does `map` give for an order of store 3, and for how many of the 1,800 orders? Choose between an error, a blank and something else.

<details>
<summary>Reveal the result</summary>

```text
355 1445
```

</details>

*Why:* there was no error and no `#N/A`: the 355 orders of store 3 became `NaN`, the sign of a missing value, and the other 1,445 got their names. The pandas page for `map` says that values not in the dictionary are converted to `NaN`. Count the `NaN` after every lookup, as you would look for `#N/A` after a `VLOOKUP`.

### 2. assign, a new column from other columns

**Idea.** `table.assign(name=expression)` returns a new table with all the old columns and the new one. The expression works on whole columns at once, like the computed column of lesson S5, and the old table is left as it was.

**Try it.** The price of each line, then its amount, which is quantity times price minus discount:

```python
lines = order_items.assign(price=order_items["product_id"].map(price_of))
lines = lines.assign(amount=lines["quantity"] * lines["price"] - lines["discount_usd"])
print(order_items.shape, lines.shape)
print(lines[lines["order_id"] == 1107]["amount"].tolist())
print(lines["amount"].sum())
```

**Predict:** what shape will `lines` have, and what are the amounts of the two lines of order 1107 (quantities 2 and 1, discounts 0.50 and 0.50)? The total is for you to read.

<details>
<summary>Reveal the result</summary>

```text
(3287, 5) (3287, 7)
[9.5, 4.0]
22754.25
```

</details>

*Why:* `lines` has the 5 old columns and 2 new ones, and `order_items` still has 5: `assign` made a new table. The two amounts are 2 times 5.00 minus 0.50, and 4.50 minus 0.50. The total, 22754.25, adds all 3,287 lines, the canceled order and the extra-zero line of order 2075 included; the arithmetic is the one of lesson P10, here as a column of a table.

### 3. apply, your own function for each value

**Idea.** `Series.apply(function)` calls your function once for each value of the column and collects what it returns, like the loop of lesson P5. Reach for it only when no whole-column form fits: arithmetic, `np.where` and `map` do their work on the whole column at once.

**Try it.** A function with three branches, written as in lesson P4:

```python
def size_label(quantity):
    if quantity >= 3:
        return "bulk"
    elif quantity == 2:
        return "double"
    return "single"


lines = lines.assign(size=lines["quantity"].apply(size_label))
print(lines["size"].value_counts())
```

**Predict:** the function labels a quantity of 3 or more `bulk`, a quantity of 2 `double` and anything else `single`. Which label gets the most lines? The counts are for you to read.

<details>
<summary>Reveal the result</summary>

```text
size
single    1911
double     894
bulk       482
Name: count, dtype: int64
```

</details>

*Why:* most lines are for one unit, so `single` leads, and the three counts add up to 3,287. The same labels with `np.where`, without a function:

```python
size_np = np.where(lines["quantity"] >= 3, "bulk", np.where(lines["quantity"] == 2, "double", "single"))
print((lines["size"].to_numpy() == size_np).all())
```

**Predict:** do the two columns agree on every line?

<details>
<summary>Reveal the result</summary>

```text
True
```

</details>

*Why:* they agree on all 3,287 lines, so the function was not needed. Write the whole-column form first, and keep `apply` for a rule that is too long for one expression.

### 4. Check: the control total

Write down the number, then run the cell. The amounts are the `amount` column of unit 2.

```python
print(lines["amount"].sum())
```

<details>
<summary>Reveal the result</summary>

```text
22754.25
```

</details>

*Why:* the same control total as the sum of all line amounts in *Summarize with a PivotTable* (E15) and *Counting and summing: aggregate functions* (S7): all 3,287 lines, the canceled order of \$5.00 and the extra-zero line included. A new column is only trustworthy once its total agrees with a number you already know.

<Aside type="tip" title="Remember">

- `map(dictionary)` is the lookup for a column; count the `NaN` it leaves for keys the dictionary lacks.
- `assign(name=expression)` returns a new table with the new column; the old table stays as it was.
- Write the whole-column form first: arithmetic, `np.where`, `map`. `apply` calls a function once for each value.
- Check a new column against a total you already know.

**Common trap:** a key or a branch that nothing covers gives `NaN` or `None` and no error, where a spreadsheet shows `#N/A`.

</Aside>
