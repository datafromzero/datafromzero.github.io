## The question

A colleague's cell totals the line of order 1107 that sold 2 Mochas, and it stops with a wall of red text. The line comes from the till export, and its quantity arrives as the text `"2"`:

| order_item_id | quantity | unit_price_usd | discount_usd |
|---:|---|---:|---:|
| 5192 | "2" | 5.00 | 0.50 |

Which line of the report do you read first, and what does it tell you? By the end of this page you can name the cause of the failure in one sentence, before you search for anything or paste it anywhere.

<Aside type="note" title="You already know this">

**Match.** In *Formula errors and auditing* (E12) every error value, `#N/A`, `#VALUE!` or `#DIV/0!`, had one usual cause, and the first move was to read it before changing the formula. A Python error works the same way: its name, such as `TypeError`, points at the cause, and the message after it says more. `try` and `except` catch an error the way `IFERROR` does, but `except ValueError` names the one error it catches, where `IFERROR` catches them all.

**Diverge.** A spreadsheet puts the error in one cell and goes on calculating the rest. In a notebook, an error that nothing catches ends the cell at the failing line, which is what the report of unit 1 describes. `try` and `except` let the cell go on past a failure you expect (unit 4).

</Aside>

## Learn by doing

About 25 minutes, 4 new ideas: reading a report, the five common errors, printing to find a bug, and `try` with `except`. The last unit only checks them. The cells that fail on purpose run through a helper called `show_error` that prints the report and lets the notebook go on.

<OpenInColab />

### 1. Read the traceback from the last line

**Idea.** When a line fails, Python prints a report of the calls that were running, oldest first. Read it from the bottom up. The last line holds the name of the error and a message. The line above it is the one that was running. A report that is long, such as one from inside pandas, still ends the same way.

**Try it.** The function and the call from the question:

```python
def line_amount(quantity, unit_price, discount):
    return quantity * unit_price - discount


line_amount("2", 5.00, 0.50)
```

**Predict:** the quantity is the text `"2"`. Which kind of error will the report end with? Read the report from its last line.

<details>
<summary>Reveal the result</summary>

```text
Traceback (most recent call last):
  File "<cell>", line 5, in <module>
    line_amount("2", 5.00, 0.50)
    ~~~~~~~~~~~^^^^^^^^^^^^^^^^^
  File "<cell>", line 2, in line_amount
    return quantity * unit_price - discount
           ~~~~~~~~~^~~~~~~~~~~~
TypeError: can't multiply sequence by non-int of type 'float'
```

</details>

*Why:* the last line names `TypeError`: the text `"2"` cannot be multiplied by the decimal number 5.0. The line above it shows the line that was running, `return quantity * unit_price - discount`, and the first call shows who asked. Your notebook may draw the report with colors and arrows; the last line is still the error. Name the error type before you search for it or paste the report anywhere: the name is what you search for.

### 2. The five common errors

**Idea.** Each error name points at one usual cause. `SyntaxError`: Python cannot read the line, for example a missing comma or bracket. `NameError`: a name does not exist yet, through a typo or a cell that has not run. `TypeError`: the wrong kind of value for the operation. `ValueError`: the right kind of value, but one the operation cannot use. `KeyError`: a key or column that is not there. Like error codes, each has one usual cause.

**Try it.** Five lines, one error each, printed as the last line of each report:

```python
show_error('print("Total:" 4.5)', short=True)
show_error('print(refund_total)', short=True)
show_error('"2" * 4.5', short=True)
show_error('int("two")', short=True)
show_error('stores["population"]', short=True)
```

**Predict:** name the error of each line before you run the cell.

<details>
<summary>Reveal the result</summary>

```text
SyntaxError: invalid syntax. Perhaps you forgot a comma?
NameError: name 'refund_total' is not defined
TypeError: can't multiply sequence by non-int of type 'float'
ValueError: invalid literal for int() with base 10: 'two'
KeyError: 'population'
```

</details>

*Why:* the first line has no comma, so Python cannot even read it. The second uses a name that was never set, and in a notebook that is also what an unrun cell looks like (lesson P1). The third multiplies text, the fourth gives `int` text that is not a number, and the fifth asks for a column the table does not have. The message of a `SyntaxError` is worded differently in different Python versions; its name is not.

### 3. Isolate a bug with print

**Idea.** A wrong answer with no error needs a different move: print the values between the steps, and compare each with what you expect. The first value that is wrong sits next to the bug. It is selecting part of a formula and evaluating it, as the Evaluate Formula tool of E12 does.

**Try it.** Order 1107 without discounts, 2 Mochas at 5.00 and 1 Cappuccino at 4.50, should total 14.5:

```python
def order_total(prices, quantities):
    total = 0
    for price, quantity in zip(prices, quantities):
        line = price * quantity
        total = line
        print("line:", line, "total so far:", total)
    return total


order_total([5.0, 4.5], [2, 1])
```

**Predict:** what does the function return? The `print` lines show what happens inside.

<details>
<summary>Reveal the result</summary>

```text
line: 10.0 total so far: 10.0
line: 4.5 total so far: 4.5
4.5
```

</details>

*Why:* the lines are right, 10.0 and 4.5, but the total so far is not growing: after the second line it is 4.5, not 14.5. The bug is the line that sets `total`, which replaces the total instead of adding to it. Printing found it in one run, without guessing.

### 4. Handle an expected failure

**Idea.** `try:` runs a block. If it raises the error named after `except`, the block stops and the `except` block runs instead, and the cell goes on. Name the one error you expect, as `except ValueError:`. It works like `IFERROR`, but for one named error.

**Try it.** One of the three prices of the till export is the text `n/a`:

```python
raw_prices = ["4.50", "n/a", "3.25"]
prices = []
for text in raw_prices:
    try:
        prices.append(float(text))
    except ValueError:
        prices.append(None)
prices
```

**Predict:** what does the list hold at the end?

<details>
<summary>Reveal the result</summary>

```text
[4.5, None, 3.25]
```

</details>

*Why:* `float("n/a")` raised a `ValueError`, the `except` block caught it for that one item, and the loop went on.

### 5. Check: name the error

Name the error of each of these three lines, then run the cell.

```python
show_error('int("4.50")', short=True)
show_error('{"card": 421}["cash"]', short=True)
show_error('len(5)', short=True)
```

<details>
<summary>Reveal the result</summary>

```text
ValueError: invalid literal for int() with base 10: '4.50'
KeyError: 'cash'
TypeError: object of type 'int' has no len()
```

</details>

*Why:* `int("4.50")` is the right kind of value, text, with a content that `int` cannot use: a `ValueError`. A missing dictionary key is a `KeyError`. A number has no length, so `len(5)` is the wrong kind of value: a `TypeError`.

<Aside type="tip" title="Remember">

- Read the report from the last line: the error's name, then the message. Name the type before you search.
- The five common errors: `SyntaxError`, `NameError`, `TypeError`, `ValueError`, `KeyError`.
- A wrong answer with no error: print the values between the steps.
- `try` and `except ValueError:` handle the one failure you expect, and nothing else.

**Common trap:** pasting the whole wall of red text into a search without reading it. The last line already says what happened, and it is the line to search for.

</Aside>

<Exercise id="python-errors-and-debugging-3">

**Spot the flaw.** A colleague wanted no more red errors, wrapped the loop in `try` and a bare `except`, and now the total reads 0. The four prices include one that cannot be read, so the total of the three readable ones should not be 0. Fix the code: name the one error you expect, and find the typo that the `except` was hiding. Expected: one decimal number.

```python
raw_prices = ["4.50", "n/a", "3.25", "4.75"]
total = 0
for text in raw_prices:
    try:
        total = totl + float(text)  # a typo hides in this line
    except:
        pass
print("total:", total)
```

<details>
<summary>Hint</summary>

Take the `try` and `except` away for a moment and run the line on its own: what does the last line of the report say? Then put back an `except` that names only the error you expect.

</details>

<details>
<summary>Half-solution</summary>

```text
total: 0
```

The code ran without an error and printed a total of 0.

</details>

<Solution>

```python
raw_prices = ["4.50", "n/a", "3.25", "4.75"]
total = 0
for text in raw_prices:
    try:
        total = total + float(text)
    except ValueError:
        pass
print("total:", total)
```

The answer is 12.5: 4.5 plus 3.25 plus 4.75. The typo `totl` raised a `NameError` on every pass, and the bare `except` swallowed all four of them, so the total stayed 0 and nothing looked wrong. Naming `ValueError` catches only the `n/a`.

</Solution>
