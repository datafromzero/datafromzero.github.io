## The question

The team has a model that no better algorithm has beaten (the models of lessons DS6 to DS8 tie it), so a teammate proposes better columns: a ratio, a log, a weekday, a target encoding of the signup cohort. *Which of them helps, and how would we know?* The table is the one of lesson DS3:

|---:|---|---|---:|---:|

## The big idea

A column is only as good as the folds say it is: every step that learns from the rows goes inside the folds, and every change is judged by its paired gain over the base.

## Learn by doing

### 1. Fill a gap, and flag it

**Idea.** A *missing* value is a gap the model cannot read. The ratio `expenses_per_day` (expenses divided by active days) is undefined for a person with no active day. Fill the gap with a number the model can use, here the median of the people it learns from. `SimpleImputer` learns that median in `fit`, so inside a pipeline it learns it from the fitting rows of each fold only. The scikit-learn guide notes that, with imputation, "preserving the information about which values had been missing can be informative"; `add_indicator=True` stacks a 0/1 column for it.

**Try it:** count the people with no value and compare their churn rate, then score the ratio with a median fill, with and without the flag, against the day-7 model on the five folds.

```python
missing = Xt["expenses_per_day"].isna()
print(round(float(missing.mean()), 3), y_train.groupby(missing).mean().round(3).to_dict())          # the share without a value, and the churn rate of those with and without
COLS_R = BASE_COLS + ["expenses_per_day"]
for tag, options in [("median fill", dict(fill=True)), ("median fill and flag", dict(fill=True, flag=True))]:
    s = folds_auc(recipe(num=WEEK1 + ["expenses_per_day"], **options), COLS_R)
    print(f"{tag:22s} mean {s.mean():.4f}   gain over the day-7 model {gain(s, base_scores)}")
print("the day-7 model:", round(float(base_scores.mean()), 4))
```

**Predict:** How many of the training people will have no value, and will they churn at a different rate? And will filling the gap, with or without the flag, lift the mean AUC by more than 0.005?

*Why:* A quarter of the training people, 0.250, have no value, and they churn at 0.704 against 0.491 for the rest, so the gap carries information. The day-7 model holds it already, because `active_days_7d` is 0 for exactly those people. The fill gains 0.0004 and the fill with the flag 0.0007, and the five fold differences of each cross zero (from -0.0011 to 0.0012 for the flag). A column that restates what the model already has adds nothing.

### 2. Encode to match the model

**Idea.** A model reads numbers, so a text column needs an encoding. *One-hot* makes one 0/1 column for each value, which the recipe has used so far. *Ordinal* codes write the values as 0, 1, 2 and so on, in alphabetical order here. The scikit-learn guide warns that such integers "would interpret the categories as being ordered, which is often not desired". Which encoding is safe depends on the model that reads it.

**Try it:** write `channel`, `platform` and `region` as one-hot columns and as ordinal codes, and score a logistic regression and a random forest on the five folds.

```python
def forest_scores(ordinal):
    encoder = OrdinalEncoder(handle_unknown="use_encoded_value", unknown_value=-1) if ordinal else OneHotEncoder(handle_unknown="ignore")
    m = make_pipeline(ColumnTransformer([("cat", encoder, STATIC), ("num", "passthrough", WEEK1)]), RandomForestClassifier(200, min_samples_leaf=100, n_jobs=-1, random_state=SEED))
    return folds_auc(m, BASE_COLS)


enc_rows = []
for tag, ordinal in [("one-hot columns", False), ("codes 0, 1, 2, ...", True)]:
    enc_rows.append((tag, round(float(folds_auc(recipe(ordinal=ordinal), BASE_COLS).mean()), 3), round(float(forest_scores(ordinal).mean()), 3)))
print(pd.DataFrame(enc_rows, columns=["the text columns as", "logistic regression", "random forest"]).to_string(index=False))
```

**Predict:** With the three text columns written as codes, will a logistic regression lose about 0.001, about 0.03 or about 0.1 AUC? And a random forest?

    one-hot columns                0.692          0.691
 codes 0, 1, 2, ...                0.662          0.688

*Why:* The logistic regression falls from 0.692 to 0.662; paired fold by fold, the loss is 0.029. Alphabetically the channels are app store 0, organic search 1, paid search 2, paid social 3 and referral 4, so the code puts the channel that churns most (paid social) next to the one that churns least (referral), and a line in the code cannot give two neighbors opposite effects. The forest asks yes/no questions of the code, so it can cut out any one channel with two questions: it loses only 0.003 (0.691 to 0.688).

### 3. Transforms, judged by paired gains

**Idea.** A transform changes how a column is written, not what it knows. A log, `np.log1p`, pulls in the long tail of a count; a *date part* turns a date into something a model can use, such as the weekday or the days since the data began; a flag writes a rule down. Whether any of them helps is a question for the folds: score each recipe on the same five folds as the base, take the five differences, and read their mean and their lowest and highest. A gain smaller than the spread of its differences is no evidence.

**Try it:** score four changes against the day-7 model on the same five folds and print each paired gain.

```python
menu = {"counts on a log scale": (recipe(log=COUNTS), BASE_COLS),
        "weekday of signup, one-hot": (recipe(cat=STATIC + ["weekday"]), BASE_COLS + ["weekday"]),
        "days since January 1": (recipe(num=WEEK1 + ["days_since_jan1"]), BASE_COLS + ["days_since_jan1"]),
        "flag: no active day": (recipe(num=WEEK1 + ["no_active_day"]), BASE_COLS + ["no_active_day"])}
menu_gains = {}
for tag, (model, cols) in menu.items():
    menu_gains[tag] = gain(folds_auc(model, cols), base_scores)
    print(f"{tag:30s} gain {menu_gains[tag][0]:+.4f}   fold differences from {menu_gains[tag][1]:+.4f} to {menu_gains[tag][2]:+.4f}")
```

**Predict:** Four changes: the four counts on a log scale, the weekday of signup, the days since January 1, and a flag for no active day. Will any of them gain more than the spread of its own fold differences?

days since January 1           gain -0.0003   fold differences from -0.0020 to +0.0002

*Why:* None does. The gains are +0.0004, +0.0003, -0.0003, +0.0005, and the five differences of every change run from below zero to above it. The log reshapes the counts and the model, a line in the log-odds, hardly moves; the signup date and the flag add nothing the columns did not hold. A column you can build is not a column that helps. The folds decide, and here they say that none of these four earns its place.

### 4. A column made from the labels

**Idea.** Some columns have too many values to one-hot. Here a `cohort` is the day and the channel of the signup, 755 groups (the middle group has 16 people). *Target encoding* replaces each group by the share of churners in it. That share is computed from the labels, so it is a learning step and belongs inside the folds (lesson DS5). Try two routes: the share computed from all training people before the folds are cut, and the same share learned in each fold by a small transformer, `GroupShare`, that sits in the pipeline.

**Try it:** score the two routes on the five folds and print the day-7 model beside them.

```python
T["cohort"] = T["signup_date"].dt.strftime("%m-%d") + "_" + T["channel"]       # the day and the channel of the signup
Xt = T.loc[X_train.index]
print(Xt["cohort"].nunique(), "groups, the middle one with", int(Xt["cohort"].value_counts().median()), "people")
shares = y_train.groupby(Xt["cohort"]).mean()                                  # the share of churners in each group, from every training person
outside = Xt[BASE_COLS].assign(cohort_share=Xt["cohort"].map(shares))
leaky = cross_val_score(recipe(num=WEEK1 + ["cohort_share"]), outside, y_train, cv=folds, scoring="roc_auc")


class GroupShare(BaseEstimator, TransformerMixin):
    """The share of churners in each group, learned in fit() from the fitting people only; a group it has not seen gets the overall share."""

    def fit(self, X, y):
        self.shares_ = pd.Series(np.asarray(y)).groupby(np.asarray(X).ravel()).mean()
        self.overall_ = float(np.mean(y))
        return self

    def transform(self, X):
        return pd.Series(np.asarray(X).ravel()).map(self.shares_).fillna(self.overall_).to_numpy().reshape(-1, 1)


inside_model = make_pipeline(ColumnTransformer([("cat", OneHotEncoder(handle_unknown="ignore"), STATIC), ("num", StandardScaler(), WEEK1),
                                                ("share", make_pipeline(GroupShare(), StandardScaler()), ["cohort"])]), LogisticRegression(max_iter=2000))
honest = folds_auc(inside_model, BASE_COLS + ["cohort"])
print("outside the folds", round(float(leaky.mean()), 3), "inside the folds", round(float(honest.mean()), 3), "the day-7 model", round(float(base_scores.mean()), 3))
```

**Predict:** What will the two routes report on the folds: near the day-7 model's 0.692, above 0.70, or below 0.67?

<details>
<summary>Reveal the result</summary>

```text
755 groups, the middle one with 16 people
outside the folds 0.726 inside the folds 0.647 the day-7 model 0.692
```

</details>

*Why:* Computed before the folds the share scores 0.726, a paired gain of 0.0345 from a column of groups of about 16 people. Learned inside the folds it scores 0.647, a paired loss of 0.0441 against the day-7 model. In the first route every person's own label is in their group's share, so the column seems to know the answer. In the second the model learns to trust the share on its fitting people, where it holds their own labels, and the people it is scored on have groups that tell it little. The honest number says that this encoder harms: `GroupShare` has no cross fitting, so the model learns on shares that hold the fitting people's own labels, and no shrinkage, so a group of 16 people gets its raw share. scikit-learn's `TargetEncoder` differs on both counts. The guide says its `fit_transform` "internally relies on a cross fitting scheme to prevent target information from leaking into the train-time representation" (and that `fit(X, y).transform(X)` does not equal `fit_transform(X, y)`), and its formula pulls each group's share toward the global mean with a smoothing factor, where a group of few people gets a small weight. It is not run here.

### 5. The verdict on the test part

**Idea.** Fit the recipe with the ratio, the median fill and the flag (the best of the changes by mean) on the training part, and score it on the 4,454 test people once, beside the day-7 model, with a 95 percent interval on the gain from 2,000 resamples (seed 2026) on which both models are scored.

**Try it:** score the day-7 model and the recipe with the ratio on the test part.

```python
p_day7 = recipe().fit(Xt[BASE_COLS], y_train).predict_proba(Xs[BASE_COLS])[:, 1]                       # the test part is used once, here
final = recipe(num=WEEK1 + ["expenses_per_day"], fill=True, flag=True).fit(Xt[COLS_R], y_train)
p_final = final.predict_proba(Xs[COLS_R])[:, 1]
print("day-7 model", round(float(roc_auc_score(y_test, p_day7)), 3), "with the ratio, fill and flag", round(float(roc_auc_score(y_test, p_final)), 3))
print(auc_gain(p_final, p_day7, y_test))
```

**Predict:** Will the recipe with the new column beat the day-7 model by more than 0.005 AUC?

<details>
<summary>Reveal the result</summary>

```text
day-7 model 0.69 with the ratio, fill and flag 0.688
[-0.001, -0.003, 0.0]
```

</details>

*Why:* No. The day-7 model scores 0.690 and the new recipe 0.688, a gain of -0.001 with a 95 percent interval of -0.003 to 0.000. On the folds it had gained 0.0007; both numbers are the size of the noise. This is the plain result of the lesson: the new columns add nothing on this table, the one wrong encoding costs 0.029, and the leaky route would have shown a gain of 0.0345 that is not there.

<Aside type="tip" title="Remember">

- A gap can carry information, so fill it from the fitting rows (a pipeline does) and consider a flag; if the model already holds the same information, the fill adds nothing.
- Encode to match the model: one-hot for a line, codes only where a split can isolate a value.
- Judge a change by the five paired differences from the base, not by one mean.
- A column made from the labels is a learning step: build it inside the folds, or the score is a fake.
- Most new columns add nothing. Say so, with the spread beside it.

**Common trap:** a cross-validated gain from a column that was built with the labels before the folds were cut.

</Aside>
