## The big idea

Boosting builds a model one small tree at a time, each fitted to what the trees so far get wrong, and it stops when new trees stop helping people it has not seen.

### 1. Trees in sequence

**Idea.** In a *gradient-boosted* model the trees are built one after another, and each is fitted to correct the errors of the ones before it; the scikit-learn guide puts it as each tree being "trained to correct the errors made by the previous ones". The model's score for a person adds up the trees' contributions, each scaled by the `learning_rate`. Friedman's 2001 paper, where the method comes from, connects this to steepest-descent minimization of the loss, which is the gradient in the name. `max_iter` is the number of trees, and `max_leaf_nodes` and `min_samples_leaf` size each tree. The model is `HistGradientBoostingClassifier`.

**Try it:** fit two boosted models of 300 trees, one with the default settings and one with small trees, and score them on the fitting part and on the validation part after every tree.

```python
SMALL = dict(learning_rate=0.05, max_leaf_nodes=4, min_samples_leaf=100)           # many small trees: each one has at most 4 leaves
stages = {}
for tag, settings in {"defaults": {}, "small trees": SMALL}.items():
    m = boost(max_iter=300, **settings).fit(X_fit, y_fit)                          # 300 trees, one after another
    stages[tag] = (staged_auc(m, X_fit, y_fit), staged_auc(m, X_val, y_val))
rows = [(k, *[round(stages[t][j][k - 1], 3) for t in stages for j in (0, 1)]) for k in [1, 5, 10, 25, 50, 100, 300]]
print(pd.DataFrame(rows, columns=["trees", "defaults: fitting", "defaults: validation", "small: fitting", "small: validation"]).to_string(index=False))
print({t: (int(np.argmax(stages[t][1])) + 1, round(max(stages[t][1]), 3)) for t in stages})       # the number of trees with the best validation AUC, and that AUC
```

**Predict:** With the default settings (trees of up to 31 leaves, a learning rate of 0.1) the AUC on the fitting rows keeps rising. At about which tree will the AUC on the validation rows be highest: about the 6th, about the 60th or about the 300th?

### 2. Early stopping

**Idea.** Instead of watching a validation part yourself, switch early stopping on. The model holds back a share of the training people (`validation_fraction`) and stops when none of the last `n_iter_no_change` scores is better than the one before them. By default it follows the loss, not the AUC; `n_iter_` says how many trees it built.

**Try it:** fit the default model with early stopping and compare it with all 300 trees on the validation part, then repeat the stopping with ten other seeds.

```python
full = boost(max_iter=300).fit(X_fit, y_fit)                                                  # the default settings, all 300 trees
stopped = boost(max_iter=300, early_stopping=True, validation_fraction=0.15, n_iter_no_change=10).fit(X_fit, y_fit)
auc_full, auc_stopped = (roc_auc_score(y_val, m.predict_proba(X_val)[:, 1]) for m in (full, stopped))
print(300, round(float(auc_full), 3), stopped[-1].n_iter_, round(float(auc_stopped), 3))
stops = []
for seed in range(100, 110):                                                                  # ten other seeds: the held-back 15 percent changes
    m = make_pipeline(prep(), HistGradientBoostingClassifier(max_iter=300, early_stopping=True, validation_fraction=0.15, n_iter_no_change=10, random_state=seed)).fit(X_fit, y_fit)
    stops.append(int(m[-1].n_iter_))
print(stops)
```

**Predict:** Will early stopping cost AUC compared with all 300 trees, and about how many trees will it keep: about 30, about 100 or all 300?

With ten other seeds (another 15 percent held back each time) the model stopped after 26 to 38 trees. The stopping point is a draw from the people held back, so report it as a range and never as a number to copy. The held-back 15 percent comes out of the people the model learns from; the validation people took no part.

### 3. The learning rate sets how many trees

**Idea.** The learning rate scales every tree's contribution; the class's documentation calls it a multiplicative factor for the leaves' values. A small rate takes small steps and needs more trees to get as far. The guide's section on shrinkage (for the older gradient-boosting classes) says that small values of the learning rate "favor better test error", and that the authors of *The Elements of Statistical Learning* recommend a small constant, 0.1 or less, with the number of trees found by early stopping.

**Try it:** give early stopping up to 2,000 trees at four learning rates, and read the trees it kept and the validation AUC.

```python
lr_rows = []
```

<Aside type="tip" title="Remember">

- Boosting adds small trees one after another; each is fitted to what the model so far gets wrong, and the learning rate scales its contribution.
- Small trees, a small learning rate and early stopping are a safe start; big trees memorize within a few trees.
- Early stopping holds back part of the training people, and its stopping point moves from seed to seed.
- The learning rate mostly sets how many trees are needed, not how good the model gets.
- Tune on folds, then put the model beside the simpler ones on the same people, with an interval.

**Common trap:** choosing the number of trees by looking at the test part.

</Aside>
