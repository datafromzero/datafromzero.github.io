## How it works

A **date** names a day. A **timestamp** names a day and a time of day, and `ordered_at` is one. A date function either
takes a part out of it (`year`, `month`, `dayname`) or cuts it back to the start of a period with `date_trunc`. The cut
is what turns orders into months: rows cut to the same value belong together.

In the first picture above, 1,800 orders become six bars. Logically, SQL does this:

1. `FROM orders` supplies every order with its `ordered_at`. A `WHERE` on that column would remove rows here.
2. For each row, `date_trunc('month', ordered_at)` keeps the year and the month and sets everything after them to its
   starting value, so `2026-01-01 08:02:00` becomes `2026-01-01 00:00:00`. Every order of one month gets the same value.
3. `GROUP BY` that value puts those orders in one group, and `COUNT(*)` counts it. `ORDER BY` runs last and puts the
   months in time order.

The rules:

- `date_trunc` returns a `TIMESTAMP`, even when you give it a `DATE`. Wrap it in `CAST(... AS DATE)` to show a day
  without the time.
- A part keeps less than a cut: `month(x)` returns 1 to 12 with no year, so January 2026 and January 2027 give the same
  number, while `date_trunc('month', x)` keeps the year.
- A `TIMESTAMP` holds no time zone: DuckDB calls it a timestamp without time zone, usually a local reading of the clock
  in an unspecified zone. The column cannot say which zone; the dataset notes do. In cafe-sales, `ordered_at` is local
  time at the cafes in the San Francisco Bay Area (Pacific time), so 08:02 is 8:02 on the cafe's clock. Data from
  another zone needs converting first.

**Excel.** Excel stores a date as a serial number so that dates can be used in calculations, such as `=B2-A2` for the
days between two of them (*Dates as numbers*, E11). `YEAR`, `MONTH` and `DAY` take a date apart, and `EOMONTH` returns
the last day of a month.

**A common misconception: "`date_trunc` rounds to the nearest month."** It cuts down, never up. The last order in the
data, order 2800, was placed at 16:30 on 2026-06-30, on the last day of June, and `date_trunc('month', ordered_at)`
still gives `2026-06-01`, not July 1.

| Function | What it returns | In Excel (E11) |
|---|---|---|
| `year(x)`, `month(x)`, `day(x)` | that part as a number | `YEAR`, `MONTH`, `DAY` |
| `dayname(x)`, `isodow(x)` | the weekday name; the weekday number, Monday = 1 to Sunday = 7 | |
| `date_trunc('month', x)` | the start of the month of `x` (also `'week'`, `'day'`) | |
| `last_day(x)` | the last day of the month of `x` | `EOMONTH(date, 0)` |
| `x + INTERVAL 7 DAY` | a date or timestamp moved by an interval | |
| `date1 - date2` | the days between two dates | subtraction |

## Worked example

Question: **how many orders per month, and is every month complete?** Run the notebook's setup cell, then one cell per
step.

1. **Look at the type.**

   ```sql
   SELECT order_id, ordered_at, typeof(ordered_at) AS type
   FROM orders
   ORDER BY order_id
   LIMIT 3;
   ```

   Expected: 3 rows, 3 columns; `type` reads `TIMESTAMP`. *Why:* no time zone in the type, so you name it yourself: local
   time at the cafes.

2. **Take a timestamp apart.**

   ```sql
   SELECT order_id, ordered_at, year(ordered_at) AS yr, month(ordered_at) AS mo, day(ordered_at) AS dom,
          dayname(ordered_at) AS weekday, isodow(ordered_at) AS dow
   FROM orders
   ORDER BY order_id
   LIMIT 3;
   ```

   Expected: 3 rows, 7 columns; all three orders fall on Thursday, January 1, `dow` 4. *Excel:* `YEAR`, `MONTH` and `DAY`.
   *Why:* each function returns one part, so you can group or filter by it.

3. **Subtract two dates.**

   ```sql
   SELECT store_name, opened_on, DATE '2026-06-30' - opened_on AS days_open
   FROM stores;
   ```

   Expected: 3 rows, 3 columns; Harbor's `days_open` is `90`: 90 days between opening and June 30 (91 open days counting both ends). *Excel:* subtract one date from the other. *Why:* a date
   behaves like a number of days, as in a sheet.

4. **Add and subtract an interval.**

   ```sql
   SELECT COUNT(*) AS last_week_orders
   FROM orders
   WHERE ordered_at >= DATE '2026-07-01' - INTERVAL 7 DAY
     AND ordered_at < DATE '2026-07-01';
   ```

   Expected: 1 row, 1 column: `82`. *Why:* July 1 minus 7 days is June 24, so the range covers June 24 to 30, seven
   whole days. It includes the first day and stops before the next, as in *Filtering rows with WHERE* (S3).

5. **Cut a timestamp to the start of its day, week and month.**

   ```sql
   SELECT order_id, ordered_at,
          CAST(ordered_at AS DATE) AS day,
          CAST(date_trunc('week', ordered_at) AS DATE) AS week_start,
          CAST(date_trunc('month', ordered_at) AS DATE) AS month_start
   FROM orders
   ORDER BY order_id
   LIMIT 3;
   ```

   Expected: 3 rows, 5 columns; `week_start` is Monday, December 29, 2025, before the data begins. *Excel:* none; you
   would build it with `DATE(YEAR(A2), MONTH(A2), 1)`. *Why:* `date_trunc` returns a timestamp here, so `CAST(... AS DATE)`
   drops the `00:00:00`.

6. **Group by month.**

   ```sql
   SELECT CAST(date_trunc('month', ordered_at) AS DATE) AS month, COUNT(*) AS orders
   FROM orders
   GROUP BY CAST(date_trunc('month', ordered_at) AS DATE)
   ORDER BY month;
   ```

   Expected: 6 rows, 2 columns, January to June. *Why:* every order in a month is cut to the same first day, so the
   groups are months. All 1,800 orders are counted, the canceled one included.

7. **Keep the last day.**

   ```sql
   SELECT COUNT(*) AS june_between
   FROM orders
   WHERE ordered_at BETWEEN '2026-06-01' AND '2026-06-30';
   ```

   ```sql
   SELECT COUNT(*) AS june
   FROM orders
   WHERE ordered_at >= '2026-06-01' AND ordered_at < '2026-07-01';
   ```

   Expected: 1 row, 1 column each. The first returns `344`, the second `353`, which is the June row of step 6. *Why:*
   `'2026-06-30'` stands for the very start of that day, so `BETWEEN` loses the 9 orders placed on June 30 after
   midnight. Include the first day and stop before the next.

8. **Flag an incomplete period.** The real data ends on June 30. To practice, pretend the file was exported on June 12,
   by keeping only orders before June 13.

   ```sql
   SELECT CAST(date_trunc('month', ordered_at) AS DATE) AS month,
          COUNT(*) AS orders,
          MAX(CAST(ordered_at AS DATE)) AS last_order_day,
          last_day(MAX(ordered_at)) AS month_end,
          MAX(CAST(ordered_at AS DATE)) < last_day(MAX(ordered_at)) AS is_partial
   FROM orders
   WHERE ordered_at < TIMESTAMP '2026-06-13'
   GROUP BY CAST(date_trunc('month', ordered_at) AS DATE)
   ORDER BY month;
   ```

   Expected: 6 rows, 5 columns; only June has `is_partial` true: 130 orders up to June 12, against 353 in the full
   month. *Excel:* `EOMONTH(date, 0)` gives the same month end. *Why:* a month is partial when its last order day comes before
   its last calendar day. A partial month looks like a drop but is only missing days. Without the `WHERE`, every month is
   complete.

9. **Verify.** The six monthly counts, 242 + 218 + 258 + 349 + 380 + 353, add up to 1,800, the Count you read in
   *Rows, columns and tidy layout* (E1), and June's 353 matches step 7. Answer: **242, 218, 258, 349, 380 and 353
   orders**, and every month is complete.

<details>
<summary>Explain it in your own words: why does `BETWEEN '2026-06-01' AND '2026-06-30'` return fewer orders than June has?</summary>

A date written alone means the start of that day, 00:00:00. An order at 10:15 on June 30 comes after it, so it is left
out. The safe range starts on the first day and stops before the first day of the next month.

</details>

**Spot the flaw.** A colleague counts orders per week and reports that the quietest weeks of the half-year are the week
of June 29 and the week of December 29, "so sales fall at New Year and at the end of June". The query:

```sql
SELECT CAST(date_trunc('week', ordered_at) AS DATE) AS week_start, COUNT(*) AS orders
FROM orders
GROUP BY CAST(date_trunc('week', ordered_at) AS DATE)
ORDER BY orders
LIMIT 3;
```

Expected: 3 rows, 2 columns. Find the flaw and fix the query.

<Solution>

The query returns the week of June 29 with 21 orders, the week of December 29 with 26, then the week of February 2 with 47. The first two weeks are partial. The data starts on Thursday, January 1, so the week that starts on Monday, December 29 holds 4 days; it ends on Tuesday, June 30, so the week of June 29 holds 2 days. Count the days in each week and keep only whole weeks:

```sql
SELECT CAST(date_trunc('week', ordered_at) AS DATE) AS week_start,
       COUNT(*) AS orders,
       COUNT(DISTINCT CAST(ordered_at AS DATE)) AS days
FROM orders
GROUP BY CAST(date_trunc('week', ordered_at) AS DATE)
HAVING COUNT(DISTINCT CAST(ordered_at AS DATE)) = 7
ORDER BY orders
LIMIT 3;
```

Expected: 3 rows, 3 columns. The quietest whole week is the week of February 2, with 47 orders.

</Solution>
