## Warm-up

Answer from memory before you open anything. Then click to check.

1. In *SELECT, ORDER BY and LIMIT* (S2) you cut a sorted list. Write a query that shows `order_id` and `ordered_at` of
   the three newest orders, newest first, with `order_id` as the tie-breaker.

   <details>
   <summary>Answer</summary>

   ```sql
   SELECT order_id, ordered_at
   FROM orders
   ORDER BY ordered_at DESC, order_id DESC
   LIMIT 3;
   ```

   </details>

2. In Excel or Google Sheets (*Decisions with IF, AND and OR*, E6), when is `AND(test1, test2)` true, and when is
   `OR(test1, test2)` true?

   <details>
   <summary>Answer</summary>

   `AND` is true only when every test is true. `OR` is true when at least one test is true. SQL uses the same two words
   in `WHERE`.

   </details>

3. In S1, which clause keeps only some rows, and how do you write a text value in it?

   <details>
   <summary>Answer</summary>

   `WHERE` keeps the rows that match. A text value goes in single quotes, as in `WHERE category = 'tea'`.

   </details>

In the first picture, filters A and B differ by one pair of parentheses, and order 1023 is the row where they disagree;
steps 3 and 4 explain why. The second picture belongs to step 7. A `WHERE` keeps a row only when its condition is true.
The comparison operators, and the words that join them:

| SQL | Reads as | In Excel |
|---|---|---|
| `=` and `<>` | equal, not equal | tick or clear a value in the filter list (E5) |
| `<`, `<=`, `>`, `>=` | less, at most, greater, at least | the tests inside `IF` (E6) |
| `a AND b` | both must hold | `AND(a, b)` (E6) |
| `a OR b` | at least one holds | `OR(a, b)` (E6) |
| `NOT (a)` | flips a condition | none in E5 or E6 |
| `x IN (1, 2)` | equal to one of the values | tick several values in the filter list (E5) |
| `x BETWEEN a AND b` | from `a` to `b`, both included | **Date Filters > Between** (E5) |
| `text LIKE 'a%'` | matches a text pattern | none in E5 |

## Worked example

Question: **how many March 2026 orders at Old Town were paid by mobile or cash, and which lattes cost between \$4.00 and
\$5.00?** Run the notebook's setup cell, then one cell per step. Each step gives the shape of the result to expect.

1. **Compare a number.**

   ```sql
   SELECT product_name, unit_price_usd
   FROM products
   WHERE unit_price_usd >= 4.50;
   ```

   Read it: *keep the products whose price is at least 4.50*. Expected: 8 rows, 2 columns. *Excel:* a filter on the
   price column (E5). *Why:* a number has no quotes, and `>=` keeps 4.50 itself. `<>` means not equal.

2. **Combine two conditions with AND.**

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1 AND payment_method = 'mobile';
   ```

   Expected: 1 row, 1 column: `217`. *Excel:* two filters on two columns. *Why:* `AND` keeps a row only when both
   conditions are true. `COUNT(*)` is the row count from S1.

3. **Add OR, the wrong way.**

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1 AND payment_method = 'mobile' OR payment_method = 'cash';
   ```

   Expected: 1 row, 1 column: `470`. That is too many. *Why:* standard SQL applies `AND` before `OR`, and the count shows it, so the query reads *(Old Town and mobile) or (cash, in any store)*. It counts the cash orders of all three stores.

4. **Put parentheses around the OR.**

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1 AND (payment_method = 'mobile' OR payment_method = 'cash');
   ```

   Expected: 1 row, 1 column: `308`. *Excel:* an `AND(...)` that contains an `OR(...)` (E6). *Why:* the parentheses make the `OR`
   a single condition, and `AND` then needs it and the store. Whenever one `WHERE` has both `AND` and `OR`, write the
   parentheses, even where they change nothing.

5. **Shorten it with IN.**

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1 AND payment_method IN ('mobile', 'cash');
   ```

   Expected: 1 row, 1 column: `308`, the same as step 4. *Why:* `IN` tests one column against a list, as a chain of
   `OR`s on that column would, and it needs no extra parentheses.

6. **Add the date range.**

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1
     AND payment_method IN ('mobile', 'cash')
     AND ordered_at >= '2026-03-01'
     AND ordered_at < '2026-04-01';
   ```

   Expected: 1 row, 1 column: `52`. That answers the first question: **52 orders**, of any status (the one canceled
   order of the data is a Campus order, not Old Town's). *Why:* the range starts at the first day and stops before the next
   month: `>=` includes midnight of March 1, `<` leaves out midnight of April 1. Dates are written year-month-day, as in
   DuckDB's date documentation, and a bare date means midnight at its start.

7. **See why not BETWEEN for dates.** First the half-open range for all stores, then the same month with `BETWEEN`:

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE ordered_at >= '2026-03-01' AND ordered_at < '2026-04-01';
   ```

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE ordered_at BETWEEN '2026-03-01' AND '2026-03-31';
   ```

   Expected: 1 row, 1 column each: `258` and `250`. *Why:* `BETWEEN a AND b` means `a <=` the value `<= b`, and the end
   `'2026-03-31'` means midnight at the start of March 31, so every order later that day is lost. The 8 missing orders are
   the eight on March 31 in the second picture. The half-open range cannot lose a day.

8. **Match text and a range.**

   ```sql
   SELECT product_name, unit_price_usd
   FROM products
   WHERE product_name LIKE '%Latte%' AND unit_price_usd BETWEEN 4.00 AND 5.00;
   ```

   Expected: 2 rows, 2 columns. *Excel:* two filters on two columns (E5). *Why:* in a `LIKE`
   pattern `%` stands for any run of characters, including none, and `_` for exactly one character. `LIKE` has to match the
   whole text, so `'%Latte%'` means *Latte anywhere*. `BETWEEN` includes both ends, so 4.00 and 5.00 count. Pumpkin Spice Latte has the word but not the
   price (5.50). Matching is case-sensitive: `'%latte%'` finds nothing, and `ILIKE` ignores case. That answers the second question: **Latte and Chai Latte**.

9. **Verify.** Split Old Town's March orders into the two groups. `NOT` flips the condition, and the parentheses make it flip the whole test:

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1
     AND NOT (payment_method IN ('mobile', 'cash'))
     AND ordered_at >= '2026-03-01'
     AND ordered_at < '2026-04-01';
   ```

   ```sql
   SELECT COUNT(*) AS orders
   FROM orders
   WHERE store_id = 1
     AND ordered_at >= '2026-03-01'
     AND ordered_at < '2026-04-01';
   ```

   Expected: 1 row, 1 column each: `81` and `133`. The 52 of step 6 and the 81 card orders make 133, all of Old Town's March
   orders. A second method, and the groups reconcile.

<details>
<summary>Explain it in your own words: why do steps 3 and 4 return different counts when they use the same words?</summary>

Without parentheses, `AND` is applied first, so step 3 means *(Old Town and mobile) or cash anywhere*. The parentheses in
step 4 make the `OR` one condition that `AND` combines with the store, so only Old Town's mobile and cash orders count.

</details>
