## The question

The Campus cafe keeps a paper sign-up sheet for its loyalty card. A barista typed eight sign-ups into a list, one city
each, exactly as written. The owner asks:

> How many different cities are on the list, and how many sign-ups does each one have?

The list is `typed_cities`. It was made for this lesson and is not part of cafe-sales, whose `customers` table is clean.
The quotes show the spaces:

| signup_id | raw_city |
|---:|---|
| 1 | `'Berkeley'` |
| 2 | `' berkeley'` |
| 3 | `'BERKELEY '` |
| 4 | `'berkeley'` |
| 5 | `'Oakland, CA'` |
| 6 | `'oakland '` |
| 7 | `'OAKLAND'` |
| 8 | `'Alameda'` |

You can see three cities. SQL sees eight different texts. By the end you will count **3 cities**, and `raw_city` will
be exactly as typed.

## How it works

A **text function** takes a piece of text and returns a new value built from it: more text, or a number about it, as
`LENGTH` does. You use one in the `SELECT` list to build a new column, or in `WHERE` to compare on a changed version of
a column.

Take a query that builds a cleaned column from `raw_city`. Logically, SQL does this:

1. `FROM typed_cities` supplies the rows, all eight. A `WHERE`, if the query had one, would remove rows here.
2. For each row, SQL reads the value in `raw_city` and runs the innermost function on it. It hands the result to the
   next function out, and so on: in `f(g(x))`, `g` runs first. In the picture above, row 3 passes through two
   functions in turn.
3. The final text goes into a new column of that row's output, and `AS` names it.

The rules:

- Positions count from 1. In `SUBSTRING(x, 1, 3)`, 1 is the first character and 3 is how many to take.
  `SPLIT_PART(x, ',', 1)` numbers the pieces from 1, and the separator itself is in no piece, as the second picture
  shows.
- `TRIM` removes characters from the two ends of the text, and only spaces unless you name other characters. A space
  inside the text stays.
- `LOWER` and `UPPER` convert letters to lower and upper case. `REPLACE(x, 'a', 'b')` swaps every `a` for `b`, and it
  matches exactly: a capital `A` is not an `a`.

**Excel.** `LEFT` returns the first characters of a text, as `SUBSTRING(x, 1, n)` does, and `TEXTSPLIT` splits text by
a delimiter into cells (*Cleaning text with TRIM, LEFT and TEXTSPLIT*, E10), while `SPLIT_PART` returns only the one
piece you ask for.

**A common misconception: "`TRIM` removes every extra space, as in Excel."** Excel's `TRIM` also collapses runs of
spaces between words to one. DuckDB's `TRIM` touches only the two ends: `TRIM('  iced  tea  ')` returns
`iced  tea`, 9 characters, with both spaces in the middle still there. A repeated space inside the text needs another
tool.

The functions in this lesson:

| Function | What it returns |
|---|---|
| `TRIM(x)` | `x` cleaned at its ends |
| `LOWER(x)`, `UPPER(x)` | `x` in small or capital letters |
| `REPLACE(x, 'a', 'b')` | `x` with `a` swapped for `b` |
| `SUBSTRING(x, start, length)` | a piece of `x` cut by position |
| `SPLIT_PART(x, ',', 2)` | a piece of `x` cut at a separator |

## Worked example

Question: **how many different cities are on the list, and how many sign-ups does each have?** Run the notebook's setup
cell, the given cell that builds `typed_cities`, then one cell per step.

1. **Exact text, on real data.**

   ```sql
   SELECT COUNT(*) AS berkeley_customers FROM customers WHERE city = 'berkeley';
   ```

   Expected: 1 row, 1 column. Predict the number before you run it: the `customers` table has Berkeley customers.
   *Why:* the data says `Berkeley` with a capital B, so `'berkeley'` matches no row. The count is 0, with no error.

2. **Change case on the column, not on the table.**

   ```sql
   SELECT COUNT(*) AS berkeley_customers FROM customers WHERE LOWER(city) = 'berkeley';
   ```

   Expected: 1 row, 1 column: `46`. *Why:* `LOWER` builds a lowercase copy of `city` for each row, and the
   comparison uses the copy. The table is not changed.

3. **Trim the typed list.**

   ```sql
   SELECT raw_city, LENGTH(raw_city) AS chars, TRIM(raw_city) AS trimmed, LENGTH(TRIM(raw_city)) AS chars_after
   FROM typed_cities;
   ```

   Expected: 8 rows, 4 columns; find which rows lose characters. *Excel:* `TRIM`. *Why:* `LENGTH` shows which texts hide
   a stray space, and `raw_city` stays next to the new column.

4. **Cut out a piece.**

   ```sql
   SELECT raw_city, SPLIT_PART(raw_city, ',', 1) AS before_comma
   FROM typed_cities;
   ```

   Expected: 8 rows, 2 columns; find which row changes. *Excel:* `TEXTSPLIT`. *Why:* a text with no comma has one piece, so
   it comes back whole.

5. **Build the key.**

   ```sql
   SELECT signup_id, raw_city, LOWER(TRIM(SPLIT_PART(raw_city, ',', 1))) AS city_key
   FROM typed_cities
   ORDER BY city_key, signup_id;
   ```

   Expected: 8 rows, 3 columns; count the different values in `city_key`. *Why:* the order of the calls is in How it
   works. A **key** is a cleaned copy you compare on; the source column is never overwritten.

6. **Match on the key.**

   ```sql
   SELECT COUNT(*) AS berkeley_signups
   FROM typed_cities
   WHERE LOWER(TRIM(SPLIT_PART(raw_city, ',', 1))) = 'berkeley';
   ```

   Expected: 1 row, 1 column: `4`. *Why:* `WHERE raw_city = 'Berkeley'` finds only 1 of the 4 Berkeley sign-ups. A join
   matches rows with the same `=`, so a key typed several ways drops rows from the join, and the result comes up short
   with no error. The joins lessons, starting with *INNER JOIN: pairing rows on a key* (S19), return to this.

7. **Cut and swap on real menu names.**

   ```sql
   SELECT product_name,
          UPPER(SUBSTRING(product_name, 1, 3)) AS code,
          REPLACE(product_name, ' ', '_') AS underscored
   FROM products;
   ```
