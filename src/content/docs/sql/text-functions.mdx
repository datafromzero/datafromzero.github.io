### 1. Change the case of a copy

A text function returns a new value built from the text: more text, or a number about it. In the `SELECT` list it builds
a new column. In `WHERE` it lets you compare on a changed version of a column. `LOWER` and `UPPER` convert letters to
lower and upper case.

**Try it**. Before you run it, predict the number: the `customers` table has Berkeley customers.

<RunSQL query={`SELECT COUNT(*) AS berkeley_customers FROM customers WHERE city = 'berkeley';`} />

Expected: 1 row, 1 column. *Why:* the data says `Berkeley` with a capital B, so `'berkeley'` matches no row. The count
is 0, with no error.

**Try it**: compare on a lowercase copy instead.

<RunSQL query={`SELECT COUNT(*) AS berkeley_customers FROM customers WHERE LOWER(city) = 'berkeley';`} />

Expected: 1 row, 1 column: `46`. *Why:* `LOWER` makes a lowercase copy of `city` for each row, and the comparison uses the
copy.

<details>
<summary>Explain it in your own words: step 2 matches 46 rows, yet the table still says <code>Berkeley</code>. How?</summary>

A `SELECT` only reads. The changed text exists while the query runs and nothing writes it back, so `SELECT city FROM
customers` still shows the capital B.

</details>

### 2. Trim the ends

`TRIM` removes characters from the two ends of the text, and only spaces unless you name other characters. A space
inside the text stays. To spot a stray space, `LENGTH(x)` counts the characters.

**Try it**: the typed list.

<RunSQL query={`SELECT raw_city, LENGTH(raw_city) AS chars, TRIM(raw_city) AS trimmed, LENGTH(TRIM(raw_city)) AS chars_after
FROM typed_cities
ORDER BY signup_id;`} />

Expected: 8 rows, 4 columns; find which rows lose characters. *Excel:* `TRIM`, with one difference you meet in the trap
below.

*Why:* `LENGTH` shows which texts hide a stray space, and `raw_city` stays next to the new column.

### 3. Cut a piece, swap a piece

Positions count from 1. In `SUBSTRING(x, 1, 3)`, 1 is the first character and 3 is how many to take. `SPLIT_PART(x, ',', 1)`
numbers the pieces from 1, and the separator itself is in no piece. `REPLACE(x, 'a', 'b')` swaps every `a` for `b`, and it
matches exactly: a capital `A` is not an `a`.

**Try it**: cut and swap on real menu names.

<RunSQL query={`SELECT product_name,

### 4. Build a key

Functions nest from the inside out: in `f(g(x))`, `g` runs first. Chain them and you get a **key**, a cleaned copy you
compare on. The source column is never overwritten: the key sits in a new column beside it.

### 5. Check the cities

**Try it**:

<RunSQL query={`SELECT COUNT(*) AS matched
FROM typed_cities
WHERE LOWER(TRIM(SPLIT_PART(raw_city, ',', 1))) IN ('berkeley', 'oakland', 'alameda');`} />

Expected: 1 row, 1 column: `8`. Every row of the list lands in one of the three cities: 4 Berkeley, 3 Oakland,
1 Alameda. Answer: **3 cities**.

<Aside type="tip" title="Remember">

- A text function returns a new value; the column it read is never changed.
- `TRIM` cuts spaces from the two ends only. `LOWER` and `UPPER` change case. `REPLACE` swaps exactly.
- Positions count from 1, and the separator is in no piece.
- Nest from the inside out, clean into a new key column, and compare on the key.

**Common trap: "`TRIM` removes every extra space, as in Excel."** Excel's `TRIM` also collapses runs of spaces between
words to one. DuckDB's `TRIM` touches only the two ends: `TRIM('  iced  tea  ')` returns `iced  tea`, 9 characters, with
both spaces in the middle still there. A repeated space inside the text needs another tool.

</Aside>

**Make a web slug for each tea.** A slug is a menu name in lowercase with hyphens instead of spaces, such as
`green-tea`. Expected: 3 rows, 2 columns (the name and the slug).

The first steps are done for you: the query lists the teas, and the slug column is a stand-in that repeats the name:

<RunSQL query={`SELECT product_name, product_name AS slug
FROM products
WHERE category = 'tea';`} />

Now finish it: replace the second `product_name` with an expression that uses `REPLACE` and `LOWER`.

<details>
<summary>Hint</summary>

Read unit 4 again: functions nest from the inside out. Which character goes in, and which comes out?

</details>

<details>
<summary>Half-solution</summary>

```sql
LOWER(REPLACE(product_name, '...', '...')) AS slug
```

</details>

<Solution>

```sql
SELECT product_name, LOWER(REPLACE(product_name, ' ', '-')) AS slug
FROM products
WHERE category = 'tea';
```

The result is `green-tea`, `chai-latte` and `iced-lemon-tea`. Lowercasing first and replacing second gives the same slugs.

</Solution>

</Exercise>

## On your own

<Exercise id="sql-text-functions-2">

**Clean a typed sign-up list.** This block builds `typed_signups`: six sign-ups with an
email typed by hand, `raw_email`. Press Run once.

<RunSQL query={`CREATE OR REPLACE TABLE typed_signups (signup_id INTEGER, raw_email VARCHAR);
INSERT INTO typed_signups VALUES
  (1, 'Mia@Example.com'), (2, ' mia@example.com'),
  (3, 'NOAH@EXAMPLE.ORG'), (4, 'noah@example.org '),
  (5, 'li@example.net'), (6, 'LI@Example.net ');
SELECT * FROM typed_signups ORDER BY signup_id;`} />

| signup_id | raw_email |
|---:|---|
| 1 | `'Mia@Example.com'` |
| 2 | `' mia@example.com'` |
| 3 | `'NOAH@EXAMPLE.ORG'` |
| 4 | `'noah@example.org '` |
| 5 | `'li@example.net'` |
| 6 | `'LI@Example.net '` |

Before you run anything else, write one sentence: what each query will return. Then write two queries.
The first shows each sign-up with `raw_email`, an `email_key` (trimmed, lowercase) and a `domain` (the part after the
`@`). The second counts the sign-ups whose domain is `example.org`.

Expected shape, to check your sentence against: the first query returns 6 rows, 4 columns; the second returns 1 row,
1 column.

<RunSQL query={`-- Write your query here, then press Run.`} />

<details>
<summary>Hint</summary>

`SPLIT_PART(x, '@', 2)` is the piece after the `@`. Clean the text before you split it, or a trailing space stays in
the domain.

</details>

<details>
<summary>Half-solution</summary>

Expected output: *"Six rows with four columns, where each person's two rows share one `email_key`; then one number, the rows whose domain is `example.org`."*

</details>

<Solution>

```sql
SELECT signup_id, raw_email,
       LOWER(TRIM(raw_email)) AS email_key,
       SPLIT_PART(LOWER(TRIM(raw_email)), '@', 2) AS domain
FROM typed_signups
ORDER BY signup_id;

SELECT COUNT(*) AS org_signups
FROM typed_signups
WHERE SPLIT_PART(LOWER(TRIM(raw_email)), '@', 2) = 'example.org';
```

The first query shows three different keys, each typed twice. The second returns `2`. Counting on the raw text,
`WHERE raw_email LIKE '%@example.org'`, returns `0`: `LIKE` is case-sensitive, and the other row ends in a space.

</Solution>

</Exercise>

<Exercise id="sql-text-functions-3">

**Spot the flaw.** A colleague counts the Berkeley sign-ups in `typed_cities` and says "two". The query runs without an
error:

<RunSQL query={`SELECT COUNT(*) AS berkeley_signups
FROM typed_cities
WHERE LOWER(raw_city) = 'berkeley';`} />

Expected: 1 row, 1 column. The list shows four Berkeley sign-ups. Find the flaw and fix the query.

<Solution>

`LOWER` changes capitals but not spaces, so `' berkeley'` and `'berkeley '` still differ from `'berkeley'`. Only rows 1 and
4 match, which is why the count is `2`. Trim first:

```sql
SELECT COUNT(*) AS berkeley_signups
FROM typed_cities
WHERE LOWER(TRIM(raw_city)) = 'berkeley';
```

Expected: 1 row, 1 column: `4`. A wrong count with no error is the risk with text: compare the number with the list by eye.

</Solution>

</Exercise>
