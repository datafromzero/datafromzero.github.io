## The question

The owner of the three cafes will hand the repository to a new analyst on Monday:

> Can they read your code without asking you, and how do I know it works?

A reader opening `summary.py` today meets this line and has three questions about it:

```python
def orders_per_store(orders, since):
```

| the reader asks | what the code says today |
|---|---|
| What do I pass for `orders`? | nothing: read the body |
| For `since`: a date or text? | nothing: read the body again |
| What comes back? | nothing: read the last line |

By the end you can answer all three on the line itself, let a tool tidy the code, read how a library class is built, give a cafe record a class, and check that the whole repository is done.

### 1. Hints and docstrings

**Idea.** A *type hint* says what a parameter or a result is meant to be: `since: date`, `-> dict[str, int]`. A *docstring* says what a function does. PEP 257 defines it as a string literal that is the first statement of a function, in triple quotes, and asks for a phrase that ends with a period and says what the function does as a command, "Return that", not as a description.

**Try it.** Save as `hints_demo.py` in the project folder and run it with `uv run python hints_demo.py`:

```python
def double(quantity: int) -> int:
    return quantity * 2


print(double(3))
print(double("ab"))
```

**Predict:** What do the two lines print?

<details>
<summary>Reveal the result</summary>

```text
6
abab
```

</details>

*Why:* the second call broke the hint and nothing stopped it: the typing page says the Python runtime does not enforce type annotations, and that third-party tools such as type checkers, IDEs and linters can use them. `"ab" * 2` is a legal expression, so it ran. A hint is a statement to the reader and to such tools; the tests of C27 are the check. Delete `hints_demo.py`.

Now give the two counting functions hints and docstrings. In `summary.py` the import becomes `from datetime import date, datetime`; in `monthly.py` add `from pathlib import Path` above `import pandas as pd`. ### 2. Let ruff check and format

**Idea.** Ruff is a Python linter and code formatter. `ruff check` reports problems in the code, and `--fix` applies the fixes it marks safe. `ruff format` rewrites the layout of the files in place, and `--check` only reports whether it would change anything, with a non-zero exit status when it would. Ruff goes in the development group like pytest, and its settings go in `pyproject.toml`.

**Try it.** Add ruff, then add its settings at the end of `pyproject.toml`. `select` names the rule families by code prefix: `E` for style errors, `F` for plain mistakes such as unused names, `I` for the order of imports. Then check the whole project:

```bash
uv add --dev ruff
```

```toml
[tool.ruff]
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I"]
```

```bash
uv run ruff check
uv run ruff format --check
```

### 3. Read a class from its docs

**Idea.** A *class* is a recipe for objects. Calling the class makes one object, an *instance*, which holds values (attributes) and functions that act on it (methods). You have used classes since C24 without writing one: `argparse.ArgumentParser`, `Path`, `date`, `pd.DataFrame`. To read one, start at its documentation page: the signature first (a parameter with `=` has a default), then the parameters, then the methods. Then ask the terminal the same questions.

**Try it.** Print the signature of `ArgumentParser`, and save a script `parser_demo.py` in the project folder:

```bash
uv run python -c 'import argparse, inspect; print(inspect.signature(argparse.ArgumentParser))'
```

```python
import argparse

parser = argparse.ArgumentParser(prog="cafe_report")
parser.add_argument("--since")
args = parser.parse_args(["--since", "2026-04-01"])
print(args)
print(args.since)
print(type(args).__name__)
```

**Predict:** What do the three lines of the script print?

<details>
<summary>Reveal the result</summary>

```text
Namespace(since='2026-04-01')
2026-04-01
Namespace
```

The signature on Python 3.13 reads `(prog=None, usage=None, description=None, epilog=None, parents=[], formatter_class=<class 'argparse.HelpFormatter'>, prefix_chars='-', fromfile_prefix_chars=None, argument_default=None, conflict_handler='error', add_help=True, allow_abbrev=True, exit_on_error=True)`; later Pythons print more.

</details>

*Why:* the argparse page lists the same parameters, all with defaults, and says to pass them as keyword arguments, which is why `cli.py` writes `ArgumentParser(prog="cafe_report", description=...)`. `inspect.signature` returns the signature of any callable. The page also says `parse_args` returns the populated namespace, and `Namespace` is a simple class that holds attributes: `args.since` is an attribute of an instance, like the `args.orders_file` your `cli.py` reads. Without `type=`, the value stays text, which is why `cli.py` passes `type=date.fromisoformat`. `inspect.getsource` returns the source of a class, and unit 4 uses it. Delete `parser_demo.py`.

### 4. One dataclass, and inheritance when you meet it

**Idea.** A record is a small class that holds a few named values. The `@dataclass` decorator writes `__init__`, `__repr__` and `__eq__` for a class from its list of fields. `frozen=True` is an option of the decorator, explained below.

**Try it.** Save the record in `cafe_report/models.py`, and use it in `record_demo.py` in the project folder:

```python
# cafe_report/models.py
"""The records of the report."""

from dataclasses import dataclass


@dataclass(frozen=True)
class StoreOrders:
    """The completed orders of one store."""

    store_id: str
    orders: int

    def label(self) -> str:
        """Return the line the report prints for this store."""
        return f"store {self.store_id}: {self.orders} orders"
```

```python
# record_demo.py
from cafe_report.models import StoreOrders

record = StoreOrders("2", 362)
print(record)
print(record == StoreOrders("2", 362))
print(record.label())
record.orders = 5
```

**Predict:** What do the first three lines print, and what happens at the last line?

<details>
<summary>Reveal the result</summary>

```text
StoreOrders(store_id='2', orders=362)
True
store 2: 362 orders
```

The last line stops the script with this error:

```text
dataclasses.FrozenInstanceError: cannot assign to field 'orders'
```

</details>

*Why:* you wrote no `__init__`, `__repr__` or `__eq__`: `print` shows every field by name, and two records with equal fields are equal. The dataclasses page says `frozen` makes assigning to a field raise an exception, and that nothing in `@dataclass` examines the type in an annotation (two special cases aside), so `StoreOrders(2, "many")` is accepted too: the types are notes. The store number is text, because the CSV file holds it as text. Delete `record_demo.py`, and use the record: add `summarize` at the end of `summary.py` with `from cafe_report.models import StoreOrders` among the imports, then replace the lines of `main` from `counts = orders_per_store(...)` to the end with the loop below (import `summarize` too):

```python
def summarize(counts: dict[str, int]) -> list[StoreOrders]:
    """Turn the counts of `orders_per_store` into one record for each store, in store order."""
    return [StoreOrders(store_id, counts[store_id]) for store_id in sorted(counts)]
```

```python
    counts = orders_per_store(orders, args.since)
    for record in summarize(counts):
        if record.orders < config["min_orders"]:
            log.warning("store %s has %d orders since %s, under %d", record.store_id, record.orders, args.since, config["min_orders"])
        print(record.label())
    if args.send:
        log.info("the report would be sent now")
```

The report prints the same lines as before. Run `uv run ruff format` once more: it wraps the long `log.warning` line.

Now the inheritance you may already have met: `pd.read_csv` raises `pd.errors.EmptyDataError` on an empty file. Print the first line of its source:

```bash
uv run python -c 'import inspect, pandas as pd; print(inspect.getsource(pd.errors.EmptyDataError).splitlines()[0])'
```

**Predict:** What does the line say, and what does that mean for an `except ValueError`?

<details>
<summary>Reveal the result</summary>

```text
class EmptyDataError(ValueError):
```

</details>

*Why:* a class that takes another class in brackets, `class A(B):`, is built on `B` and inherits what `B` has, so an `EmptyDataError` is a kind of `ValueError`. The Python tutorial says an `except` clause matches an exception that is an instance of the class or of one of its derived classes, so `except ValueError` also catches it, the way `except OSError` caught `FileNotFoundError` in C26. You will read this line often; writing such classes comes in the later tracks.

<Aside type="tip" title="Remember">

- Hints and a docstring answer the reader's three questions on the function itself; a hint is not a check.
- `ruff check` finds problems, `--fix` repairs the safe ones, `ruff format` sets the layout; name the rules in `pyproject.toml`.
- A class makes objects: attributes hold values, methods act on them; read the signature, then the parameters, then the methods.
- `@dataclass` writes `__init__`, `__repr__` and `__eq__` from the fields, and `frozen=True` stops assignment.
- `class A(B):` reads "A is a kind of B".

**Common trap:** believing a hint is a check. `double("ab")` ran and printed `abab`.

</Aside>

<Exercise id="core-readable-code-and-classes-1">

**A record for a menu item.** Finish the dataclass for one row of a products file with the columns `product_id`, `product_name`, `category` and `unit_price_usd`. Save the script as `product_demo.py` in the project folder and run it. Two fields are missing:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Product:
    product_id: int
    product_name: str
    ...  # the two missing fields, with their types


row = {"product_id": "14", "product_name": "Avocado Toast", "category": "food", "unit_price_usd": "8.50"}
product = Product(int(row["product_id"]), row["product_name"], row["category"], float(row["unit_price_usd"]))
print(product)
print(product == Product(14, "Avocado Toast", "food", 8.5))
```

Expected: two lines, the record with its four fields by name, and `True`.

<details>
<summary>Hint</summary>

The call passes four values in the order of the file. A field is a name, a colon and a type; the category is text and the price has cents.

</details>

<details>
<summary>Half-solution</summary>

```python
    category: str
    unit_price_usd: ...
```

</details>

<Solution>

```python
@dataclass(frozen=True)
class Product:
    product_id: int
    product_name: str
    category: str
    unit_price_usd: float
```

```text
Product(product_id=14, product_name='Avocado Toast', category='food', unit_price_usd=8.5)
True
```

The order of the fields is the order of the arguments of the generated `__init__`. The two `int` and `float` calls turn text from the CSV row into numbers; the dataclass does not do that for you, because it does not look at the types.

</Solution>

</Exercise>

**Spot the flaw.** A colleague writes a dataclass for the lines of an order, and it fails as soon as the file is imported. Save it as `basket_demo.py` in the project folder and run it. Expected: an error that stops the script. What does its last line say, and what is the fix?

<details>
<summary>Hint</summary>

Read the last line of the traceback, as in C26. The dataclasses page has a section on mutable default values and says what to use for a field that starts as an empty list.

</details>

<details>
<summary>Half-solution</summary>

```python
from dataclasses import dataclass, field
...
    products: list = field(...)
```

</details>

<Solution>

```text
ValueError: mutable default <class 'list'> for field products is not allowed: use default_factory
```

```python
from dataclasses import dataclass, field


@dataclass
class Basket:
    order_id: int
    products: list = field(default_factory=list)
```

The dataclasses page says a `field` with a `default_factory` calls it with no arguments whenever a default is needed, which gives each record its own new list. A plain `[]` would be one list shared by every record, so Python refuses it when the class is made.

</Solution>
