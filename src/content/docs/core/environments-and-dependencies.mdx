## Learn by doing

About 30 minutes, 4 new ideas: a project and its environment, a dependency and its contract, the wrong environment, and a rebuild from the repository alone. Start in the folder `cafe-report` after the last lesson, with `git status` clean.

### 1. A project and its environment

**Idea.** A uv *project* is a folder with a `pyproject.toml`; `uv init --bare` writes one and nothing else. The first `uv run` builds the project's *environment*, a folder `.venv` with its own Python, and runs your command in it. `sys.executable` is the path of the Python that is running.

**Try it.** Make the folder a project, read the file, and print the path of the Python that `uv run` uses:

```console
uv init --bare
cat pyproject.toml
uv run python -c "import sys; print(sys.executable)"
git status -s
```

**Predict:** what does `pyproject.toml` hold, which Python does the third command print, and which new files does `git status -s` list?

<details>
<summary>Reveal the result</summary>

```console
$ uv init --bare
Initialized project `cafe-report`
$ cat pyproject.toml
[project]
name = "cafe-report"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = []
$ uv run python -c "import sys; print(sys.executable)"
Using CPython 3.13.18 interpreter at: /usr/local/bin/python3
Creating virtual environment at: .venv
/home/ana/cafe-report/.venv/bin/python
$ git status -s
?? pyproject.toml
?? uv.lock
```

</details>

*Why:* the file names the project and lists no dependencies yet. `requires-python` records the Python that uv found, so yours says the version of your Python. The Python that ran is the one inside the new `.venv`, not the one uv found on the system. uv wrote `uv.lock` as well, and `.venv` is not listed, because uv keeps it out of Git.

### 2. A dependency and its contract

**Idea.** `uv add pandas` installs pandas into `.venv` and writes it into `pyproject.toml`, under `dependencies`. The file `uv.lock` pins exact versions. Together they are the contract that lets another machine rebuild the same environment, so you commit both.

**Try it.** Add pandas, then read the two files:

```console
uv add pandas
cat pyproject.toml
grep -A1 '^name = ' uv.lock
```

**Predict:** is numpy, which you never asked for, in `pyproject.toml`? Is it in `uv.lock`?

<details>
<summary>Reveal the result</summary>

```console
$ uv add pandas
Resolved 5 packages in 11ms
Installed 4 packages in 21ms
 + numpy==2.5.5
 + pandas==3.1.1
 + python-dateutil==4.0.0
 + tzdata==2026.6

[project]
name = "cafe-report"
version = "0.1.0"
requires-python = ">=3.13"
dependencies = [
    "pandas>=3.1.1",

$ grep -A1 '^name = ' uv.lock

--

--

version = "3.1.1"
--
name = "python-dateutil"
version = "4.0.0"
--
name = "tzdata"
version = "2026.6"
```

</details>

*Why:* `pyproject.toml` holds one line, the package you asked for, with a lower bound that uv chose from the newest version. `uv.lock` holds the project and every package pandas needs, each with an exact version, numpy included. These are the versions of 21 November 2026; yours will be newer. Do not edit `uv.lock` by hand: uv manages it.

**Try it.** Use the dependency. Save `cafe_report/monthly.py`, add the import and the `--monthly` option to `cafe_report/cli.py` (the lines shown; the rest of the file stays), and run it:

```python
# cafe_report/monthly.py
import pandas as pd


def orders_by_store_month(path):
    """A table of completed orders: one row for each store, one column for each month."""
    orders = pd.read_csv(path)
    completed = orders[orders["status"] == "completed"]
    month = pd.to_datetime(completed["ordered_at"]).dt.strftime("%Y-%m").rename("month")
    return completed.groupby(["store_id", month]).size().unstack(fill_value=0)
```

```python
# cafe_report/cli.py (new lines)
from cafe_report.monthly import orders_by_store_month
...
    parser.add_argument("--monthly", action="store_true", help="print a table of stores and months instead")
    args = parser.parse_args(argv)
    if args.monthly:
        print(orders_by_store_month(args.orders_file))
        return
```

```console
uv run python -m cafe_report data/orders.csv --monthly
```

**Predict:** Harbor, store 3, opened on April 1. What do its first three month columns show?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python -m cafe_report data/orders.csv --monthly
month     2026-01  2026-02  2026-03  2026-04  2026-05  2026-06
store_id                                                      
1             128      103      133      123      125      117
2             114      115      124      103      134      125
3               0        0        0      123      121      111
```

</details>

*Why:* Harbor has no orders before April, and `fill_value=0` writes the missing store and month pairs as 0 instead of leaving them empty. The table counts completed orders only. Commit the contract with the code: `git add pyproject.toml uv.lock cafe_report`, then `git commit -m "Declare pandas and add the monthly table"`.

### 3. The wrong environment

**Idea.** A computer can hold many Pythons, each with its own packages: the one in `.venv`, the one uv found on your system, and any environment you make. A command runs in exactly one of them, and `sys.executable` says which. Inside a project, `uv run` uses the project's, unless you tell it not to.

**Try it.** Make a second environment, `other-env`, with Python's `venv` module, run the monthly table with its Python, print the path of the Python that `uv run` uses, and delete the second environment (on Windows, its Python is `other-env/Scripts/python`):

```console
uv run --no-project python -m venv other-env
other-env/bin/python -c "import sys; print(sys.executable)"
other-env/bin/python -m cafe_report data/orders.csv --monthly
uv run python -c "import sys; print(sys.executable)"
rm -r other-env
```

**Predict:** pandas was installed with `uv add`. What does each of the three middle commands print, and can both Pythons import pandas?

<details>
<summary>Reveal the result</summary>

```console
$ uv run --no-project python -m venv other-env
$ other-env/bin/python -c "import sys; print(sys.executable)"
/home/ana/cafe-report/other-env/bin/python
$ other-env/bin/python -m cafe_report data/orders.csv --monthly
Traceback (most recent call last):
  ...
  File "/home/ana/cafe-report/cafe_report/monthly.py", line 1, in <module>
    import pandas as pd
ModuleNotFoundError: No module named 'pandas'
$ uv run python -c "import sys; print(sys.executable)"
/home/ana/cafe-report/.venv/bin/python3
$ rm -r other-env
```

The path of the last Python points inside `.venv`; on your system it may end in `python` or `python3`.

</details>

*Why:* the second environment has its own Python and was never given pandas, so the same code fails there, and the message says a package is missing, not which environment is missing it. `sys.executable` tells you which Python ran. With `uv run` inside the project you do not choose: it runs in the project's environment, with the locked versions of what the project declares.

### 4. Rebuild from the repository alone

**Idea.** `git clone` copies a repository, with its whole history, into a new folder; the copy holds what was committed and nothing else. `uv sync` builds the environment from `uv.lock`, and `download_data.py` fetches the data again. A GitHub address works in place of a folder path.

**Try it.** Clone the project next to itself, and rebuild it there:

```console
git clone ~/cafe-report ~/cafe-report-check
cd ~/cafe-report-check
ls -a
uv sync
uv run download_data.py
uv run python -m cafe_report data/orders.csv --since 2026-04-01
```

**Predict:** what does `ls -a` list in the clone, and what do the last three commands print?

<details>
<summary>Reveal the result</summary>

```console
$ git clone ~/cafe-report ~/cafe-report-check
Cloning into '/home/ana/cafe-report-check'...
done.
$ cd ~/cafe-report-check
$ ls -a
.   .git        cafe_report           download_data.py  uv.lock
..  .gitignore  check_environment.py  pyproject.toml
$ uv sync
Using CPython 3.13.18 interpreter at: /usr/local/bin/python3
Creating virtual environment at: .venv
Resolved 5 packages in 2ms
Installed 4 packages in 33ms
 + numpy==2.5.5
 + pandas==3.1.1
 + python-dateutil==4.0.0
 + tzdata==2026.6
$ uv run download_data.py
saved data/orders.csv with 82348 bytes
$ uv run python -m cafe_report data/orders.csv --since 2026-04-01
store 1: 365 orders
store 2: 362 orders
store 3: 355 orders
```

</details>

*Why:* the clone has the code and the two contract files, and neither `.venv` nor `data`. `uv sync` rebuilt the environment with the versions of the lock, the download script fetched the data again, and the counts match the ones of the last lesson. If a package were missing from the contract, this is where it would announce itself. Go back with `cd ~/cafe-report`; the check folder can be deleted.

<Aside type="tip" title="Remember">

- A uv project is a `pyproject.toml`; `uv run` builds `.venv` and runs your command in it.
- `uv add name` installs a package and declares it in `pyproject.toml`; `uv.lock` pins every package at an exact version. Commit both.
- A command runs in exactly one Python; `sys.executable` shows which, and `uv run` picks the project's.
- `.venv` and `data` stay out of Git; `uv sync` and `download_data.py` rebuild them.
- The proof that a project is reproducible is a fresh clone that runs.

**Common trap:** a "package not found" error for a package you installed: it is installed in another environment.

</Aside>
