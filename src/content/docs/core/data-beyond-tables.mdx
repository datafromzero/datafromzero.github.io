## The question

The mobile team sends each order as one JSON record with its lines inside, and a log of events. The owner asks:

|---:|---|---|---:|
| 1001 | Campus | Croissant | 1 |
| 1001 | Campus | Cold Brew | 1 |

### 1. Read nested JSON, then flatten it

**Idea.** `json.load` turns a JSON object into a dict (a *record* of named values, whose names are *keys*), an array into a list and `null` into `None`. *Nested* means a record inside a record, or a list inside a record. `pd.json_normalize` *flattens* nested records into columns whose names join the keys with a dot; a list stays whole in one cell.

### 2. Explode a list, then normalize

**Idea.** To *explode* a list is to make one row for each element, repeating the other columns on each row. `json_normalize` with `record_path` (the list to explode) and `meta` (the fields to repeat) flattens and explodes in one call. To *normalize*, in the sense of C18, is to split the rows into tables with keys so that each fact is stored once. MongoDB's manual calls the same choice embedding against referencing.

**Try it.** Save as `verbs.py` and run it:

```python
import json

import pandas as pd

with open("data/orders_nested.json") as file:
    orders = json.load(file)

flat = pd.json_normalize(orders)
lines = flat.explode("items")
print(lines.shape)
print(lines["items"].iloc[0])

items = pd.json_normalize(orders, record_path="items", meta=["order_id"])
print(items)

stores = flat[["store.store_id", "store.store_name"]].drop_duplicates()
print(stores)
print(len(flat), len(items), len(stores))
print(sum(len(order["items"]) for order in orders))
```

**Predict:** how many rows does the exploded table have, what columns and rows does `items` have, and how many rows has `stores`?

### 3. An event stream is rows with a time

**Idea.** Kafka's documentation says an *event* records the fact that something happened, and that it has a key, a value and a timestamp. A log of events is often *JSON Lines*: one JSON value on each line, which a program can process one record at a time. Land the events as rows: parse each line, flatten it, turn the time text into a date and time, sort by it, and group by the hour with `dt.floor("h")`.

**Try it.** Save as `data/events.jsonl` (the placing of orders 1001 to 1008, in the order the lines arrived):

### 4. Two pairs of formats

**Idea.** Four formats come in two pairs. **Text you can open:** CSV, flat lines of text with no types, and JSON, nested. **Binary you cannot open:** Parquet, which stores the values of each column together and, as its documentation says, is built for very efficient compression and encoding, with the compression chosen for each column; and Avro, which stores its records in blocks and keeps its schema in the file header. Columns suit analysis, because a reader can load only the columns it needs; records suit moving data between systems; text is for people and binary is for scale. `to_parquet` needs a Parquet library, `pyarrow`.

**Try it.** Work on a branch, as in C30. Save as `cafe_report/export.py`, run it once, then add the library with `uv add pyarrow` and run it again:

```bash
git switch -c export-parquet
```

```python
"""Write the orders in the Parquet format."""

from pathlib import Path

import pandas as pd


def write_parquet(csv_path: str | Path, parquet_path: str | Path) -> int:
    """Write the orders of a CSV file as a Parquet file, and return how many there are.

    The order time is stored as a date and time, not as text.
    """
    orders = pd.read_csv(csv_path, parse_dates=["ordered_at"])
    orders.to_parquet(parquet_path, index=False)
    return len(orders)
```

```python
for i in range(group.num_columns):
    column = group.column(i)
    print(column.path_in_schema, column.total_compressed_size)
print(file.schema_arrow.field("ordered_at").type)


def milliseconds(read, times=200):
    start = time.perf_counter()
    for _ in range(times):
        read()
    return (time.perf_counter() - start) / times * 1000

print("csv, status only:", round(csv_ms, 2), "ms")
print("parquet, status only:", round(parquet_ms, 2), "ms")
```

<Aside type="tip" title="Remember">

- Flatten nested records into dotted columns, explode a list into rows, normalize repeated facts into tables with keys.
- `record_path` names the list that becomes rows; `meta` names the fields repeated on each row.
- An event is a fact with a time; land it as a row, convert the time, sort, then group.
- CSV and JSON are text for people; Parquet and Avro are binary for scale; columns suit analysis, records suit moving data.

**Common trap:** thinking a nested file is already a table. Explode multiplies the rows: three orders became seven lines.

</Aside>
