## The question

The Harbor manager wants to run the order counts herself, and writes:

> I want to give the script a file and a first day, and get the orders of each store. I do not want to open the code.

At the moment the file name and the day are typed inside the code. The same file holds three jobs: reading the orders, counting them and printing. These are the first rows of the file, `data/orders.csv` of the fictional chain `cafe-sales`:

| order_id | customer_id | store_id | ordered_at | status | payment_method |
|---:|---:|---:|---|---|---|
| 1001 | 15 | 2 | 2026-01-01 08:02:00 | completed | mobile |
| 1002 | 46 | 1 | 2026-01-01 15:38:00 | completed | mobile |
| 1003 | 61 | 2 | 2026-01-01 15:47:00 | completed | mobile |

By the end the manager can run `python -m cafe_report data/orders.csv --since 2026-04-01`, and the code is split so that a test can reach each job.

Here the functions move into files of their own, and the parameters move out of the code, onto the command line.

**Diverge.** In P26, `import pack` worked because the notebook's folder held `pack.py`. Python looks for an import in a list of places, and units 2 and 4 show which ones come first.

Run everything in the terminal, in `cafe-report`, the project folder you made in [*Your laptop setup and the terminal*](/core/laptop-setup-and-terminal/#1-three-tools-and-a-check-script) (C22) and put under Git in [*Git: saving a history of your work*](/core/git-save-history/) (C23), with `git status` clean (no unsaved changes). Each unit ends with a commit.

### 1. Split the jobs into modules

**Idea.** A *module* is a Python file, and `import load` makes Python look for a file `load.py`. Give each job its own module, so that a job can be found, reused and changed alone: `load.py` reads the orders, `summary.py` counts them, and `report.py` runs the two. `csv.DictReader` turns each row of a CSV file into a dictionary with the header as keys.

**Try it.** Save three files in the project folder. The first reads the orders; save it as `load.py`:

```python
import csv


def read_orders(path):
    """Read an orders file into a list of dictionaries, one for each order."""
    with open(path, newline="") as file:
        return list(csv.DictReader(file))
```

The second counts them; save it as `summary.py`:

```python
from datetime import datetime


def orders_per_store(orders, since):
    """Count the completed orders of each store on or after the day `since`."""
    counts = {}
    for order in orders:
        day = datetime.fromisoformat(order["ordered_at"]).date()
        if order["status"] == "completed" and day >= since:
            counts[order["store_id"]] = counts.get(order["store_id"], 0) + 1
    return counts
```

The third runs the two; save it as `report.py`, then run `uv run report.py`:

```python
from datetime import date

from load import read_orders
from summary import orders_per_store

orders = read_orders("data/orders.csv")
print(orders_per_store(orders, date(2026, 4, 1)))
```

**Predict:** `report.py` imports the two files next to it. What does it print, and are the store numbers in the answer numbers or text?

<details>
<summary>Reveal the result</summary>

```console
$ uv run report.py
{'2': 362, '1': 365, '3': 355}
```

</details>

*Why:* the store numbers have quotes, so they are text: a CSV file holds text, and `DictReader` hands it over as read. The answer is the completed orders of each store from April 1. Commit the three files: `git add load.py summary.py report.py`, then `git commit -m "Split the report into load, summary and report"`.

### 2. A package with an entry point

**Idea.** A *package* is a folder that holds a file `__init__.py`; the file can be empty. `python -m cafe_report` runs the package: it executes the file `__main__.py` inside it.

**Try it.** Move the files into a folder `cafe_report` (`git mv` renames a file that Git tracks), make `report.py` the entry point, add the empty `__init__.py`, and run the package without touching the code:

```console
mkdir cafe_report
git mv load.py summary.py cafe_report/
git mv report.py cafe_report/__main__.py
touch cafe_report/__init__.py
uv run python -m cafe_report
```

**Predict:** the code is unchanged. What does the last command print?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python -m cafe_report
Traceback (most recent call last):
  File "<frozen runpy>", line 203, in _run_module_as_main
  File "<frozen runpy>", line 88, in _run_code
  File "/home/ana/cafe-report/cafe_report/__main__.py", line 3, in <module>
    from load import read_orders
ModuleNotFoundError: No module named 'load'
```

</details>

*Why:* the package started, because the command found `cafe_report` from the folder you ran it in, and `__main__.py` ran. Its import `from load import ...` then looked for a top-level `load`, and the file now lives inside the package. Name the package in the imports, as in `from cafe_report.load import read_orders`. Replace `cafe_report/__main__.py` with this, and run again:

```python
from datetime import date

from cafe_report.load import read_orders
from cafe_report.summary import orders_per_store

orders = read_orders("data/orders.csv")
print(orders_per_store(orders, date(2026, 4, 1)))
```

```console
$ uv run python -m cafe_report
{'2': 362, '1': 365, '3': 355}
```

The numbers are the same as in unit 1; only the layout changed. Commit: `git add cafe_report`, `git commit -m "Make the report a package"`.

### 3. Arguments from the command line

**Idea.** The `argparse` module reads the command line for you. `add_argument("orders_file")` declares a value the user must give; `add_argument("--since", ...)` declares an option that may be left out. `type=` names a function that turns the text into a value. Put the parser in a function `main()` in its own file, and keep `__main__.py` short: it only calls `main()`.

**Try it.** Save this as `cafe_report/cli.py`:

```python
import argparse
from datetime import date

from cafe_report.load import read_orders
from cafe_report.summary import orders_per_store


def main(argv=None):
    parser = argparse.ArgumentParser(prog="cafe_report", description="Count the completed orders of each store.")
    parser.add_argument("orders_file", help="path to orders.csv")
    parser.add_argument("--since", type=date.fromisoformat, default=date.min,
                        help="count orders on or after this day, as YYYY-MM-DD (default: every day)")
    args = parser.parse_args(argv)
    counts = orders_per_store(read_orders(args.orders_file), args.since)
    for store_id in sorted(counts):
        print(f"store {store_id}: {counts[store_id]} orders")
```

Replace `cafe_report/__main__.py` with this:

```python
from cafe_report.cli import main

main()
```

Run the report three ways:

```console
uv run python -m cafe_report data/orders.csv --since 2026-04-01
uv run python -m cafe_report -h
uv run python -m cafe_report data/orders.csv --since 2026-13-01
```

**Predict:** what does each of the three commands print?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python -m cafe_report data/orders.csv --since 2026-04-01
store 1: 365 orders
store 2: 362 orders
store 3: 355 orders
$ uv run python -m cafe_report -h
usage: cafe_report [-h] [--since SINCE] orders_file

Count the completed orders of each store.

positional arguments:
  orders_file    path to orders.csv

options:
  -h, --help     show this help message and exit
  --since SINCE  count orders on or after this day, as YYYY-MM-DD (default:
                 every day)
$ uv run python -m cafe_report data/orders.csv --since 2026-13-01
usage: cafe_report [-h] [--since SINCE] orders_file
cafe_report: error: argument --since: invalid fromisoformat value: '2026-13-01'
```

</details>

*Why:* the manager's two choices are now arguments, and `-h` prints the help you wrote in the `help=` texts. `date.fromisoformat` is a function that takes text, so `type=` accepts it, and `2026-13-01` is refused: a value that the function rejects stops the program with a message, before any counting starts. Delete `peek.py`, which this package replaces, and commit: `git rm peek.py`, `git add cafe_report`, `git commit -m "Read the file and the first day from the command line"`.

### 4. A file name that shadows a library

**Idea.** An `import` looks a name up in a list of places, in order. Your own folder is one of the places. `load.py` imports `csv`, so the name `csv` is looked up every time the report runs.

**Try it.** Save a helper of your own as `csv.py` in the project folder, run the report, and delete the helper:

```console
echo 'print("converting orders to csv")' > csv.py
uv run python -m cafe_report data/orders.csv --since 2026-04-01
rm csv.py
```

**Predict:** which `csv` does `load.py` get, and what does the run print?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python -m cafe_report data/orders.csv --since 2026-04-01
converting orders to csv
Traceback (most recent call last):
  ...
AttributeError: module 'csv' has no attribute 'DictReader' (consider renaming '/home/ana/cafe-report/csv.py' since it has the same name as the standard library module named 'csv' and prevents importing that standard library module)
```

The traceback lines are left out; the hint in brackets is printed by recent versions of Python, and older versions stop after `'DictReader'`.

</details>

*Why:* running with `-m` puts the current folder at the start of the search path, ahead of the standard library, so Python imported your `csv.py` (it printed its line) and your file has no `DictReader`. The message is about a missing attribute, and does not say that a file of yours is in the way. The first match wins, so never name a file after a library: `csv`, `json`, `random`, `datetime` or `pandas`.

A notebook is where you explore; a package is what a teammate runs and a test can import. When a cell works, move its function into a module and call it from the notebook.

<Aside type="tip" title="Remember">

- A module is a file; one job for each file lets a job be found, reused and tested alone.
- A package is a folder with `__init__.py`; `python -m package` runs its `__main__.py`, which only calls `main()`.
- Files inside a package import each other by the package name: `from cafe_report.load import read_orders`.
- `argparse` turns text on the command line into values: required ones, options, a `type=` and free help with `-h`.
- Never name a file after a library; the folder you run in is searched before the standard library.

**Common trap:** a file named `csv.py`, `json.py` or `pandas.py` in your project: the library you meant is not the one you get, and the message talks about a missing attribute.

</Aside>
