## The question

The owner of the three cafes has an offer from a supplier:

> We should "put it in the cloud". What is the cloud, where would our files go, and who could read them?

Today the sales are in `data/orders.csv` (82,348 bytes) on one laptop, and the key of the mailing service is in `.env` on the same laptop, which Git ignores (C28). Eight words come with every talk about the cloud, one sentence each; the rest of the lesson makes some of them run on your laptop.

| the word | in one sentence |
|---|---|
| Cloud platform | Rented data centers: computing power, storage and databases that you use on demand and pay for by use, instead of buying machines. AWS, Google Cloud and Microsoft Azure are providers. |
| Region and zone | A region is an independent geographic area made of zones; using several zones and regions lowers the risk that one outage takes everything. |
| Object, block and file storage | Object storage keeps whole files under names; block storage is a machine's raw disk, cut into equal blocks; file storage is a shared folder many machines open. |
| CPU and GPU | A CPU runs a few tens of threads, each as fast as possible; a GPU runs thousands in parallel and gives up speed on any one. Model training is typical GPU work. |
| Cluster | Many machines, called nodes, that work as one: a program hands tasks to processes on the nodes. Imagine 18 billion orders instead of 1,800. |
| HPC | High performance computing pools many machines into one big shared computer, and a job scheduler queues each person's jobs. |
| Container and virtual machine | A virtual machine pretends to be a whole computer with its own operating system; a container is an isolated process that shares the host's kernel. |
| Batch and streaming | Batch runs a big job on a finished pile of data at set times; streaming handles each event as it arrives, like each sale as the till rings it. |

## Learn by doing

About 30 minutes, 4 new ideas: object storage, compute and region, policies, and what stays private. Nothing here needs a cloud account: you run small models of the real services on your laptop, in `cafe-report` with the repository clean, and delete the model files at the end.

### 1. Object storage: a whole file under a key

**Idea.** An *object store* keeps *objects*, each a file plus a description of it, in a *bucket* (a container), and each object has a *key*, its unique name in the bucket. The Amazon S3 guide describes the whole service as a map from a bucket and a key to an object. A spreadsheet lets you change one cell and a database answers "which rows have this value?"; an object store does three things: put an object under a key, get the object with a key, and list the keys that start with some text.

**Try it.** Save as `object_store.py` in the project folder and run it with `uv run python object_store.py`:

```python
from pathlib import Path


class ObjectStore:
    """A toy object store: whole objects under keys, kept in a dictionary."""

    def __init__(self):
        self.objects = {}

    def put(self, key, data):
        self.objects[key] = data  # a new object replaces the old one as a whole

    def get(self, key):
        return self.objects[key]

    def list(self, prefix=""):
        return sorted(key for key in self.objects if key.startswith(prefix))


store = ObjectStore()
store.put("raw/orders.csv", Path("data/orders.csv").read_bytes())
store.put("reports/2026-04.txt", b"store 1: 123 orders\n")
store.put("reports/2026-05.txt", b"store 1: 125 orders\n")

print(store.list("reports/"))
print(store.list("rep"))

store.put("reports/2026-05.txt", b"store 1: 125 orders\nstore 2: 134 orders\n")
print(len(store.get("reports/2026-05.txt")), "bytes now")
```

**Predict:** What do the two `list` lines print, and how many bytes does the May report hold after the second `put`?

<details>
<summary>Reveal the result</summary>

```text
['reports/2026-04.txt', 'reports/2026-05.txt']
['reports/2026-04.txt', 'reports/2026-05.txt']
40 bytes now
```

</details>

*Why:* `list("rep")` returns the same two keys as `list("reports/")`. The slash is part of the key, and a "folder" is only a prefix that keys share: the S3 guide contrasts its general purpose buckets, a flat structure, with directory buckets that organize objects into directories. The second `put` did not edit the file: it replaced the whole object, and the class has no method that changes one byte. The model leaves out what makes the real service worth renting: versions, access rules, copies in other zones. Delete `object_store.py`.

### 2. Compute, and the region it runs in

**Idea.** *Compute* is machine time you rent: cores, memory and hours. A *region* is a geographic area where a provider keeps its machines, and a region is made of *zones*. The S3 guide says you might choose a region to optimize latency, minimize costs or meet regulatory requirements, and that objects stored in a region never leave it unless you transfer or replicate them. So run the compute in the region that holds the data it reads.

**Try it.** Ask your own machine how much compute it has:

```bash
uv run python -c 'import os; print(os.cpu_count(), "cores")'
```

**Predict:** What number do you expect, more or fewer than 16?

<details>
<summary>Reveal the result</summary>

```text
4 cores
```

Yours differs.

</details>

*Why:* the cloud rents you the same quantity in other sizes, for the hours you run. The Sheffield HPC guide says a researcher's laptop has between 4 and 16 CPU cores, and a cluster usually has at least an order of magnitude more. The Compute Engine page adds that resources in different zones of a region are less likely to fail together, and resources in different regions even less.

### 3. A role holds permissions, and the default is no

**Idea.** A *policy* is a list of lines, each Allow or Deny, for an *action* (read, write) on a *resource* (a path). A *role* is a named set of permissions that a person or a program takes on; the IAM guide says it is meant to be taken on by whoever needs it, not tied to one person. Three rules of the AWS guides decide a request: access is denied by default, an Allow line grants access, and an explicit Deny overrides an Allow.

**Try it.** Save as `access_demo.py` and run it. The real policy language writes `Effect`, `Action` and `Resource`, and writes a resource as a path such as `arn:aws:s3:::cafe-data/reports/*`; the model keeps the three names, and its star `*` matches any text, slashes included:

```python
from fnmatch import fnmatchcase

POLICY = [
    {"Effect": "Allow", "Action": "read", "Resource": "cafe-data/reports/*"},
    {"Effect": "Deny", "Action": "read", "Resource": "cafe-data/reports/draft/*"},
]


def decide(policy, action, resource):
    allowed = False
    for line in policy:
        if fnmatchcase(action, line["Action"]) and fnmatchcase(resource, line["Resource"]):
            if line["Effect"] == "Deny":
                return "deny (a Deny line)"
            allowed = True
    return "allow" if allowed else "deny (no line matched)"


if __name__ == "__main__":
    for action, resource in [
        ("read", "cafe-data/reports/2026-05.txt"),
        ("read", "cafe-data/raw/orders.csv"),
        ("read", "cafe-data/reports/draft-plan.txt"),
        ("write", "cafe-data/reports/2026-05.txt"),
        ("read", "cafe-data/reports/draft/plan.txt"),
    ]:
        print(f"{action:<5} {resource:<36} {decide(POLICY, action, resource)}")
```

**Predict:** Which of the five requests are allowed?

<details>
<summary>Reveal the result</summary>

```text
read  cafe-data/reports/2026-05.txt        allow
read  cafe-data/raw/orders.csv             deny (no line matched)
read  cafe-data/reports/draft-plan.txt     allow
write cafe-data/reports/2026-05.txt        deny (no line matched)
read  cafe-data/reports/draft/plan.txt     deny (a Deny line)
```

</details>

*Why:* line 1 matches the Allow. Lines 2 and 4 match no line, so the default answers. Line 5 matches both lines, and the Deny wins. Line 3 is the surprise: `draft-plan.txt` matches the Allow, and the Deny pattern needs the slash after `draft`, so the file is allowed. A line covers the names that match its pattern, not the names that look like it. Grant the narrowest path that does the job, and test one request that must be refused. Keep `access_demo.py` for the exercises.

### 4. What never goes in a public bucket

**Idea.** *Data governance* is the set of rules for who may take what action on which data: the AWS page says it "outlines who can take what action, upon what data, using what methods, and in what situations". The S3 guide says new buckets and their objects do not allow public access until someone changes a policy. Three kinds of file never belong in a public bucket. *Keys and passwords*: OWASP lists API keys, database credentials, SSH keys and certificates as secrets. *Personal data*: anything that names or reaches a person. *Copies of a database*: one file that holds every table, with both of the others inside.

**Try it.** Save as `upload_check.py`. It reads file names and CSV headers, not meaning:

```python
import csv
import sys
from pathlib import Path

PERSONAL = {"name", "email", "phone", "address"}


def problem(path):
    """Say why a file must not go into a public bucket, or return None."""
    if path.name == ".env" or path.suffix in {".pem", ".key"}:
        return "a key or a password"
    if path.suffix in {".dump", ".sql", ".duckdb"}:
        return "a copy of a database"
    if path.suffix == ".csv":
        with open(path, newline="") as file:
            found = PERSONAL & {column.lower() for column in next(csv.reader(file), [])}
        if found:
            return "personal data: " + ", ".join(sorted(found))


flagged = 0
for path in sorted(Path(sys.argv[1]).rglob("*")):
    if path.is_file() and (why := problem(path)):
        print(f"BLOCK {path}: {why}")
        flagged += 1
print(f"{flagged} files must stay private")
```

Make a folder to upload, with one harmless report and three files that should stay home, and check it and the real data folder:

```bash
mkdir -p outbox/reports outbox/exports
printf 'store 1: 125 orders\n' > outbox/reports/2026-05.txt
printf 'customer_id,name,email,city\n15,Ana Example,ana@example.com,Oakland\n' > outbox/exports/customers.csv
echo "CAFE_REPORT_TOKEN=demo-key-not-real" > outbox/.env
printf 'dump' > outbox/cafe.dump
uv run python upload_check.py outbox
uv run python upload_check.py data
```

**Predict:** Which files of `outbox` does the check block, and what does it say about `data`?

<details>
<summary>Reveal the result</summary>

```text
BLOCK outbox/.env: a key or a password
BLOCK outbox/cafe.dump: a copy of a database
BLOCK outbox/exports/customers.csv: personal data: email, name
3 files must stay private
0 files must stay private
```

The first four lines come from `outbox`, the last from `data`.

</details>

*Why:* the check models one habit: decide what may leave before anything is uploaded. It cannot decide the hard cases: `customer_id` alone passes, because a script sees a column name, and whether a customer number identifies a person is a decision for the owner and the written rules. The same goes for who may read `reports/`: a policy states the decision, and a person with authority makes it. Delete `outbox`, `upload_check.py` and `object_store.py`.

<Aside type="note" title="Docker, in one box">

A container is an ordinary process that runs in isolation: it sees only the files it was started with, and you can cap its memory and CPU. Every container shares the machine's kernel, so there is no operating system to boot, and the Docker guide says a container starts in about a second. You build none in the core; the Data Engineer and ML Engineer tracks do. Operating Kubernetes, tuning a cluster, writing GPU code, running a job scheduler and designing across regions belong to the tracks too: the core verbs are recognize and explain.

</Aside>

<Aside type="tip" title="Remember">

- An object store holds whole objects under keys; a "folder" is a shared start of keys.
- Compute is rented machine time in a region; keep it near the data it reads.
- A policy: no access by default, an Allow line grants, a Deny line wins.
- Keys, personal data and copies of a database stay out of a public bucket; decide before the upload.

**Common trap:** trusting a line that looks like it covers a file. `reports/draft-plan.txt` was allowed, although the Deny line says `draft`.

</Aside>

<details>
<summary>Hint</summary>

One Allow line with the action `write` and the resource `cafe-data/raw/*` is enough. Everything else is already denied by default, so the proof is the requests that fail.

</details>

<details>
<summary>Half-solution</summary>

Expected output in words: *"The write to `raw/orders.csv` and the write to a deeper path under `raw/` say allow; the read of `raw/orders.csv`, the write under `reports/` and the write to the top of the bucket say deny (no line matched)."* The policy has one line.

</details>

<Solution>

```python
from access_demo import decide

LOADER = [{"Effect": "Allow", "Action": "write", "Resource": "cafe-data/raw/*"}]

for action, resource in [
    ("write", "cafe-data/raw/orders.csv"),
    ("write", "cafe-data/raw/2026/april.csv"),
    ("read", "cafe-data/raw/orders.csv"),
    ("write", "cafe-data/reports/2026-05.txt"),
    ("write", "cafe-data/notes.txt"),
]:
    print(f"{action:<5} {resource:<32} {decide(LOADER, action, resource)}")
```

The output is two `allow` lines, then three `deny (no line matched)` lines. The write permission does not give the read permission: each action needs its own line.

</Solution>
