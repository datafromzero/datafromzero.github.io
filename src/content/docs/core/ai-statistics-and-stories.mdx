## The question

An assistant has run statistics on the cafe data and written a short story. The output looks correct: a table, a p-value, a tidy paragraph. The mistake to catch is not arithmetic. It is a wrong choice of method inside correct-looking output, and a story that claims more than the data carries.

Every AI answer here was written for this lesson, in the style of an assistant, and none is a real transcript or comes from a product. The code is real, and the numbers are what it prints. The Python blocks are read only: run them in order in one notebook or terminal. The SQL runs in the page.

## Warm-up

From memory first, then click to check.

1. In *Hypothesis tests and p-values, honestly* (C8), you run 20 tests on data with no real effect at the 0.05 bar. About how many come out significant?

   <details>
   <summary>answer</summary>

   About one: 20 tests at 0.05 give 20 times 0.05.

   </details>

2. In *Correlation is not causation* (C10), what is the strongest design that earns a causal verb?

   <details>
   <summary>answer</summary>

   </details>

## Learn by doing

About 35 minutes, 4 new ideas: a test whose conditions fail, a count of the tests run, a story traced back to its code and a citation that must resolve.

### 1. A test whose assumptions fail

**Idea.** Every test comes with conditions. SciPy's page for the chi-square test calls it an often quoted guideline that the test should be used only if the observed and expected frequencies in each cell are at least 5. For a small table, `fisher_exact` is the exact test.

<Aside type="note" title="An answer written for this lesson">

**Did Harbor's cash use differ from Campus at the start?** In Harbor's first three days, April 1 to 3, none of its 10 completed orders was paid in cash, against 4 of 12 at Campus. A chi-square test gives p = 0.0435, so the difference is significant at the 5 percent level.

</Aside>

```python
import pandas as pd
from scipy import stats

BASE = "https://raw.githubusercontent.com/datafromzero/datafromzero.github.io/v0.1.0/datasets/cafe-sales/v1/"
orders = pd.read_csv(BASE + "orders.csv", parse_dates=["ordered_at"])
done = orders[orders["status"] == "completed"]
window = done[(done["ordered_at"] >= "2026-04-01") & (done["ordered_at"] < "2026-04-04")]
pair = window[window["store_id"].isin([2, 3])]
table = pd.crosstab(pair["store_id"], pair["payment_method"] == "cash")
print(table)
result = stats.chi2_contingency(table, correction=False)
print(round(float(result.pvalue), 4))
```

**Predict:** run the assistant's code. Does its p-value match the 0.0435 it reports?

<details>
<summary>Reveal the result</summary>

```text
payment_method  False  True 
store_id                    
2                   8      4
3                  10      0
0.0435
```

</details>

**Try it.** Check the condition, then the exact test:

```python
print(result.expected_freq.round(2))
print(round(float(stats.fisher_exact(table).pvalue), 4))
```

**Predict:** how many of the four expected counts are below 5, and is the exact p-value above or below 0.05?

<details>
<summary>Reveal the result</summary>

```text
[[9.82 2.18]
 [8.18 1.82]]
0.0964
```

</details>

*Why:* two expected counts, 2.18 and 1.82, are below 5. The arithmetic is right, but the choice of test is wrong: the table has 22 orders and only four cash payments, too few for that formula. The exact test gives 0.0964, above the bar. The call also passes `correction=False`, which turns off Yates' correction, SciPy's default for a 2 x 2 table; with the default, p = 0.1434 here, not 0.0435.

**Write the check.** In a sentence or two of your own: what do you ask of any test an assistant picked?

<details>
<summary>A check in words</summary>

Read the conditions of the test on its documentation page and check them on these data, here the expected counts. If they fail, use the test built for small counts, or collect more data.

</details>

### 2. Count the tests that were run

**Idea.** A p-value answers one question asked once. If the same data are cut many ways and only the best cut is reported, the p-value answers a different question. Ask how many tests were run, and whether the hypothesis was written before the results.

<Aside type="note" title="An answer written for this lesson">

**What explains mobile payments?** I looked for what explains mobile payments and found one clear result: orders placed in the morning (before 10:00) are 35.0 percent mobile, against 30.4 percent overall (p = 0.008).

</Aside>

```python
customers = pd.read_csv(BASE + "customers.csv")
o = done.merge(customers[["customer_id", "loyalty_tier"]], on="customer_id", how="left")
o["weekday"] = o["ordered_at"].dt.day_name()
o["month"] = o["ordered_at"].dt.month_name()
o["daypart"] = pd.cut(o["ordered_at"].dt.hour, [0, 10, 14, 24], right=False, labels=["morning", "midday", "afternoon"]).astype(str)
o["store"] = o["store_id"].map({1: "Old Town", 2: "Campus", 3: "Harbor"})
o["mobile"] = o["payment_method"] == "mobile"

rows = []
for cut in ["store", "weekday", "month", "daypart", "loyalty_tier"]:
    for group in o[cut].dropna().unique():
        inside = o[cut] == group
        p = stats.chi2_contingency(pd.crosstab(inside, o["mobile"]), correction=False).pvalue
        rows.append((cut, group, round(float(p), 4)))
results = pd.DataFrame(rows, columns=["cut", "group", "p"]).sort_values("p")
print(results.iloc[0])
```

**Predict:** the loop tests one group of each cut against all the other orders. How many tests does it run, and how many do you expect under 0.05 if mobile use never depends on any cut?

**Try it.** What the assistant did not print:

```python
print(len(results), int((results["p"] < 0.05).sum()))
print(results.head(4).to_string(index=False))
```

<details>
<summary>Reveal the result</summary>

```text
22 3
    cut   group      p
daypart morning 0.0079
  month    June 0.0211
  month   March 0.0402
  store  Harbor 0.1143
```

</details>

*Why:* 22 tests ran, 3 came out under 0.05, and about 1 was expected from 22 times 0.05. If no cut mattered, the chance of at least one under 0.05 would be 1 minus 0.95 to the power 22: about two in three, as a rough guide, because the cuts overlap. The morning, 0.0079, is the best of 22. The [build script](https://github.com/datafromzero/datafromzero.github.io/blob/main/scripts/build-cafe-sales.py) of this dataset draws every payment with the same chances (card 55, mobile 30, cash 15 in 100) whatever the store, hour or month, so every gap here is chance. The counts are completed orders, order 2075 included.

**Write the check.** In a sentence or two of your own: what do you ask before you believe "one clear result"?

<details>
<summary>A check in words</summary>

How many tests were run, and was the hypothesis written before the results? Here 22 tests, 3 under 0.05 and about 1 expected, and no hypothesis in advance.

</details>

### 3. A story, traced to its code

**Idea.** Every sentence of a story is traced back: a number to output you can rerun, a verb of cause to a design. A verb such as "raised" needs a design behind it (*Correlation is not causation*, C10); without one, write "went together".

<Aside type="note" title="An answer written for this lesson">

**What did opening Harbor do?** Harbor's opening in April raised the average order by 5.5 percent, from 12.24 dollars to 12.91. Orders at Harbor average 14.20 dollars. New cafes lift the sales of their neighbors (Example and Example, 2099).

</Aside>

**Predict:** before you run anything, will the 5.5 percent and Harbor's 14.20 both come back from the data, only one of them, or neither?

**Try it.** The average order of each quarter, completed orders:

**Try it.** The same orders split by Harbor and the other two cafes:

*Why:* 12.24 to 12.91 is a rise of 5.5 percent, so that number traces. Harbor's 14.20 does not: its average is 12.98. The verb fails too. Harbor's 12.98 is barely above the 12.89 of the other two cafes in the same quarter, so adding them moves the chain's average by under 3 cents. The rise is mostly at cafes where nothing opened, from 12.24 to 12.89. One order of 20 sandwiches, an extra zero that the dataset README lists, is in that second figure. A before and after in one chain, with no comparison group and nothing assigned, supports "went with", not "raised".

**Write the check.** In a sentence or two of your own: how do you test a number and a verb?

<details>
<summary>A check in words</summary>

For a number, find the query that gives it: 12.91 traces and 14.20 does not. For a verb of cause, ask what design stands behind it: here none, and the cafes where nothing opened moved as well.

</details>

### 4. A citation must resolve

**Idea.** A citation claims two things: that a document exists and that it says what the sentence says. Check both. A DOI, the permanent identifier of a paper, should open that paper at doi.org. A reference that resolves nowhere is treated as nonexistent.

<Aside type="caution" title="A reference made up for this lesson">

The last sentence of the story cites "Example and Example, 2099". Its reference reads: Example, A. and Example, B. (2099). Imaginary cafes and their neighbors. Journal of Examples, 1(1). doi:10.99999/made-up-for-this-lesson. It is not a real paper.

</Aside>

**Predict:** open `https://doi.org/10.99999/made-up-for-this-lesson` and then `https://doi.org/10.1038/s41598-023-41032-5` in a browser. What does each do?

<details>
<summary>Reveal the result</summary>

On 2026-11-22 the first page said "This DOI cannot be found in the DOI System." The second opened the page of Walters and Wilder, "Fabrication and errors in the bibliographic citations generated by ChatGPT", in Scientific Reports.

</details>

*Why:* the first does not exist, so the sentence has no source. The second resolves, and still supports nothing about cafes: it studies citations that a chatbot made up. A reference can resolve and still not support the claim.

**Write the check.** In a sentence or two of your own: what do you do with every citation in an AI answer?

<details>
<summary>A check in words</summary>

Resolve the DOI or search the exact title, open the source, and read whether it says what the sentence claims. If it does not resolve, treat it as nonexistent.

</details>

<Aside type="note" title="As of 2026-11-22: what published research measured">

**Method choice.** StatQA (Zhu and colleagues, NeurIPS 2024) has 11,623 examples on choosing statistical methods. The best model, GPT-4o, reached 64.83 percent. Models mostly applied a method whose conditions the data did not meet, which the paper calls applicability errors; humans mostly confused the task.

**Causal questions.** On CLadder (Jin and colleagues, NeurIPS 2023, dataset version 1.5), GPT-4 scored 62.03 percent overall, and random guessing 49.27.

**Citations.** Walters and Wilder (Scientific Reports, 2023) counted 636 citations in 84 short reviews: 55 percent from ChatGPT-3.5 and 18 percent from ChatGPT-4 were fabricated, and 43 and 24 percent of the real ones had substantive errors. Magesh and colleagues (2025) found that retrieval-based legal research tools hallucinated between 17 and 33 percent of the time.

These models are from 2023 and 2024; newer ones change the numbers, and the checks stay. This box is reviewed every six months.

</Aside>

<Aside type="tip" title="Remember">

- A test has conditions: read them, check them on these data, and use the test built for the case.
- Ask how many tests were run, and whether the hypothesis came first.
- Trace every number to code that reruns, and every verb of cause to a design.
- A citation counts only if it resolves and says what the sentence says.

**Common trap:** believing a result because the output is correct: right formula, tidy table, small p-value.

</Aside>
