### 1. A list scan against a set

**Idea.** `x in a_list` and `x in a_set` ask the same question of containers that keep their items differently. A list keeps them in a row and compares `x` with them one after another, until it finds it or reaches the end. A set keeps each item at a place worked out from its value, and looks there.

**Try it.** Save as `scan.py` and run it. It checks 1,800 ids that are not in the file, against the first 450, 900 and all 1,800 order ids, as a list and as a set, and prints the best of three times:

```python
import csv
import time

with open("data/orders.csv", newline="") as file:
    ids = [int(row["order_id"]) for row in csv.DictReader(file)]
wanted = [i + 10_000 for i in ids]  # ids that are not in the file


def check(known):
    """Count the wanted ids found in `known`; return the count and the best of 3 times in ms."""
    times = []
    for _ in range(3):
        start = time.perf_counter()
        found = sum(1 for i in wanted if i in known)
        times.append((time.perf_counter() - start) * 1000)
    return found, min(times)


print(len(wanted), "ids to check")
for size in (450, 900, 1800):
    as_list = ids[:size]
    found, ms_list = check(as_list)
    _, ms_set = check(set(as_list))
    print(f"{size:5} known ids: list {ms_list:7.2f} ms, set {ms_set:6.3f} ms, found {found}")
```

**Predict:** about how many times longer does the list check take with 1,800 known ids than with 450, and what is that ratio for the set?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python scan.py
1800 ids to check
  450 known ids: list    4.16 ms, set  0.038 ms, found 0
  900 known ids: list    8.13 ms, set  0.052 ms, found 0
 1800 known ids: list   16.03 ms, set  0.031 ms, found 0
```

Your times differ and wobble.

</details>

*Why:* with four times the items the list took about 3.9 times as long (16.03 against 4.16 ms), and the set time did not grow (0.031 against 0.038 ms). The Python time-complexity page says the same: a list test grows with the length of the list, and a set or dict test is constant on average. The same 1,800 ids were checked each time; only the container changed, so the cost belongs to the structure, not to the data. Each missing id forced the list to look at every item. A found id stops a scan early, so this test is the worst case for a list; the time to build the set is not counted, and you pay it once. A dict keyed by id behaves like the set.

### 2. Name a structure by its question

**Idea.** You rarely write these structures; you meet them in libraries and job ads, so learn them by the question each answers. A structure is a way to keep items so that one question is cheap.

| structure | the question it answers | in Python | in the cafe data |
|---|---|---|---|
| stack | what came last? (last in, first out) | `list.append`, `list.pop` | undoing the last edit |
| queue | who has waited longest? (first in, first out) | `collections.deque`, `popleft` | orders waiting at the till |
| heap | which is the smallest right now, again and again, as items arrive? | `heapq.heappush`, `heappop`; `heap[0]` is the smallest; `nlargest` for the biggest few | the busiest days |
| tree | what sits under this? | nested dicts and lists | an order and its lines (C31) |
| graph | who is linked to whom, in any direction? | a dict of lists | customers and the products they order, many links on both sides |

The tutorial recommends `deque` for a queue because `list` is slow at the front.

**Try it.** Save as `heap.py` and run it: the two busiest days, found with a heap and with a full sort.

```python
import heapq
from collections import Counter

with open("data/orders.csv") as file:
    next(file)  # skip the header line
    per_day = Counter(line.split(",")[3][:10] for line in file)

print(len(per_day), "days")
print(heapq.nlargest(2, per_day, key=per_day.get))
print(sorted(per_day, key=per_day.get, reverse=True)[:2])
```

**Predict:** how many days does the file cover, and which two days come out?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python heap.py

['2026-05-16', '2026-06-21']
['2026-05-16', '2026-06-21']
```

</details>

*Why:* the file covers January 1 to June 30, 181 days, and May 16 and June 21 have the most orders, 19 each. The result of `nlargest` is the same as the sorted version cut at `n`, which is how the heapq page defines it; the page adds that it performs best for small `n` and that `sorted` is better for larger values. A heap keeps its smallest item at `heap[0]`, and the two functions here are the helpers for the biggest few. A tree and a graph are shapes of data first: the C31 record is a tree, and customers and products form a graph.

### 3. Read a file in chunks

**Idea.** When a file does not fit in memory, read it in pieces and keep only a small running result. `pd.read_csv(path, chunksize=n)` gives chunks of at most `n` rows, one after another. The pandas page says chunking works when the operation needs little coordination between chunks, and that the peak memory is the largest chunk plus the running result. `Series.add(other, fill_value=0)` adds counts and treats a missing label as 0.

**Try it.** Save as `chunks.py` and run it. It counts completed orders for each store chunk by chunk, and by one full read:

```python
import pandas as pd

whole = pd.read_csv("data/orders.csv")
print("whole file:", whole.memory_usage(deep=True).sum(), "bytes in memory")

completed = None
for number, chunk in enumerate(pd.read_csv("data/orders.csv", chunksize=500), start=1):
    print(f"chunk {number}: {len(chunk)} rows, {chunk.memory_usage(deep=True).sum()} bytes")
    counts = chunk[chunk["status"] == "completed"].groupby("store_id").size()
    completed = counts if completed is None else completed.add(counts, fill_value=0)

print(completed.astype(int).to_dict())
print(whole[whole["status"] == "completed"].groupby("store_id").size().to_dict())
```

**Predict:** how many chunks come out and how many rows has the last, and do the two answers agree?

<details>
<summary>Reveal the result</summary>

```console
$ uv run python chunks.py

chunk 1: 500 rows, 40431 bytes
chunk 2: 500 rows, 40402 bytes
chunk 3: 500 rows, 40448 bytes
chunk 4: 300 rows, 24338 bytes
{1: 729, 2: 715, 3: 355}
{1: 729, 2: 715, 3: 355}
```

The byte counts depend on the pandas version.

</details>

*Why:* 1,800 rows make four chunks, the last one short, and the sums agree. The largest chunk held about 28 percent of what the whole file needs. Harbor (store 3) opened in April, so the first chunk has no Harbor row; `fill_value=0` let the sum go on. This file is small; the pattern is for the file that is not.

<Aside type="tip" title="Remember">

- A list scan grows with the list; a set or dict lookup stays about the same.
- The cost belongs to the structure, not to the data: the same ids, another container.
- Stack, queue, heap, tree and graph are named by the question each answers.
- Read a big file in chunks, keep a small running result, and combine the pieces.

**Common trap:** trusting a check because it ran fast on the sample. A list scan that is fine on 1,800 rows can crawl on 18 million.

</Aside>

<Exercise id="core-a-feel-for-scale-1">

**Count the orders of each customer.** Counting with a list of pairs scans the pairs for every order. Save the script below as `ex1.py` (delete each exercise script when you are done) and run it; then add the same count with a dict, time it the same way, and check that both counts are equal. Expected: three lines, the pairs line with its time, a dict line with a much smaller time, and `True`. Both lines say 145 customers.

```python
import csv
import time

with open("data/orders.csv", newline="") as file:
    customers = [row["customer_id"] for row in csv.DictReader(file) if row["customer_id"]]

pairs = []  # [customer_id, orders], one pair for each customer
start = time.perf_counter()
for customer in customers:
    for pair in pairs:
        if pair[0] == customer:
            pair[1] += 1
            break
    else:
        pairs.append([customer, 1])
ms = (time.perf_counter() - start) * 1000
print(len(customers), "orders,", len(pairs), "customers:", round(ms, 2), "ms with a list of pairs")
```

<details>
<summary>Hint</summary>

A dict keyed by customer replaces the inner loop: read the count with `get(customer, 0)`, add 1 and store it back.

</details>

<details>
<summary>Half-solution</summary>

```python
counts = {}
for customer in customers:
    counts[customer] = ...
```

</details>

<Solution>

```python
counts = {}
start = time.perf_counter()
for customer in customers:
    counts[customer] = counts.get(customer, 0) + 1
ms = (time.perf_counter() - start) * 1000
print(len(counts), "customers:", round(ms, 2), "ms with a dict")
print(counts == {customer: orders for customer, orders in pairs})
```

```console
1799 orders, 145 customers: 3.83 ms with a list of pairs
145 customers: 0.16 ms with a dict
True
```

The one order with no customer was skipped, so 1,799 orders count. The dict went straight to each customer, while the pairs were scanned from the start for every order. Your times differ.

<details>
<summary>Hint</summary>

</details>

<details>
<summary>Half-solution</summary>

```python
total = None

    ...
```

<Solution>

```python
import pandas as pd

total = None
rows = 0
for chunk in pd.read_csv("data/orders.csv", chunksize=400):
    rows += len(chunk)
    done = chunk[chunk["status"] == "completed"]
    hours = pd.to_datetime(done["ordered_at"]).dt.hour
    counts = done.groupby(hours).size()
    total = counts if total is None else total.add(counts, fill_value=0)

print(rows, "rows read")
print(total.astype(int).to_dict())
print(int(total.sum()))
```

```console

{7: 172, 8: 156, 9: 169, 10: 181, 11: 169, 12: 142, 13: 150, 14: 161, 15: 168, 16: 169, 17: 162}
1799
```

The canceled order is not counted, which is why 1,800 rows give 1,799. `add` turns the counts into decimals; `astype(int)` puts them back.

</Solution>

```python
import pandas as pd

shares = []
for chunk in pd.read_csv("data/orders.csv", chunksize=700):
    shares.append((chunk["payment_method"] == "mobile").mean())

```

<details>
<summary>Hint</summary>

The chunks hold 700, 700 and 400 rows. Does a chunk of 400 rows deserve as much weight as one of 700? What could you keep from each chunk instead of a share?

</details>

<details>
<summary>Half-solution</summary>

```python
mobile = 0
rows = 0
for chunk in pd.read_csv("data/orders.csv", chunksize=700):
    mobile += ...
```

</details>

<Solution>

```console
3 chunks
share of mobile orders: 0.31
```

The average of three shares gives the last, shorter chunk the same weight as the others, so it is not the share of all orders. Keep the pieces that add up, the number of mobile orders and the number of rows, and divide once at the end:

```python
import pandas as pd

mobile = 0
rows = 0
for chunk in pd.read_csv("data/orders.csv", chunksize=700):
    mobile += (chunk["payment_method"] == "mobile").sum()
    rows += len(chunk)

print("share of mobile orders:", round(mobile / rows, 4))
```

```console
share of mobile orders: 0.3033
```

That is 546 of 1,800 orders, the same as one full read.

</Solution>
