## The question

The owner of the three cafes asks:

> I want to see what the report did when it ran, and change the data folder and the warning limit without touching code. I will also give you the key to the mailing service. It must never end up on GitHub, even by accident.

Three kinds of thing live in the repository, and they need three different homes:

| thing | example | where it lives |
|---|---|---|
| code | the function `in_month` | in Git |
| a setting | the data folder, the lowest number of orders before a warning | a file in Git |
| a secret | the key of the mailing service | outside Git |

By the end you can make the report tell you what it did, read its settings from a file, read a key from the environment, and explain why a key that was committed once is not safe even after you delete it.

**Diverge.** A parameter at the top of a script sits in the code, so it travels with the code to everyone who reads it. Unit 2 moves it to a file that an argument can override, and unit 3 moves a secret out of the repository altogether.

## Learn by doing

### 1. Log with levels, not print

**Idea.** `print` has one level: always. The `logging` module has five, from `DEBUG` to `CRITICAL`: the Python HOWTO calls `INFO` confirmation that things are working as expected, `WARNING` an indication that something unexpected happened, and `ERROR` a function that could not be performed. Each module gets its own logger with `logging.getLogger(__name__)`, and the entry point configures once what is shown and how it looks.

**Try it.** In `report.py`, add `import logging` at the top and the logger below the imports, and replace `read_orders` and `in_month` by:

```python
log = logging.getLogger(__name__)


def read_orders(path):
    orders = pd.read_csv(path, parse_dates=["ordered_at"])
    log.info("read %d orders from %s", len(orders), path)
    return orders


def in_month(orders, month):
    start = pd.Timestamp(f"{month}-01")
    end = start + pd.offsets.MonthBegin(1)
    kept = orders[(orders["ordered_at"] >= start) & (orders["ordered_at"] < end)]
    log.info("%d of %d orders are in %s", len(kept), len(orders), month)
    if kept.empty:
        log.warning("no orders in %s", month)
    return kept
```

Run the report for April and for a month with no orders, with nothing configured yet:

Add `%(asctime)s` for the time, which makes your lines differ from these. The values are passed as arguments, which the HOWTO says are merged into the message only when it is shown. The HOWTO says the call to `basicConfig` should come before any logger call, so it is the first line of `main`.

### 2. Move settings into a file

**Idea.** A setting is a value that differs between runs or machines while the logic stays the same: a folder, a level, a limit. The Twelve-Factor App asks for a strict separation of config from code. Keep the settings in a TOML file next to the code, give each one a default in code, and let the command line carry the same settings. `tomllib` reads TOML from a file opened in binary mode and returns a dictionary.

**Try it.** Create `cafe-report.toml` in the repository folder, and `src/cafe_report/config.py`:

```toml
data_dir = "data"
log_level = "INFO"
min_orders = 110
```

```python
import tomllib
from pathlib import Path

DEFAULTS = {"data_dir": "data", "log_level": "WARNING", "min_orders": 0}


def load_config(path="cafe-report.toml"):
    config = dict(DEFAULTS)
    if Path(path).exists():
        with open(path, "rb") as f:
            config.update(tomllib.load(f))
    return config
```

Replace `cli.py` by this version. The folder becomes optional, there is a `--log-level` option, and each cafe with fewer than `min_orders` orders gets a warning:

```python
import argparse
import logging
from pathlib import Path

import pandas as pd

from cafe_report.config import load_config
from cafe_report.report import in_month, order_totals, read_orders, store_sales

log = logging.getLogger(__name__)


def main():
    parser = argparse.ArgumentParser(prog="cafe-report")
    parser.add_argument("data_dir", nargs="?")
    parser.add_argument("--month", required=True)
    parser.add_argument("--log-level")
    args = parser.parse_args()
    config = load_config()
    data = Path(args.data_dir or config["data_dir"])
    logging.basicConfig(
        level=args.log_level or config["log_level"],
        format="%(levelname)s %(name)s: %(message)s",
    )
    try:
        orders = read_orders(data / "orders.csv")
    except FileNotFoundError:
        raise SystemExit(f"cafe-report: no orders.csv in {data}")
    try:
        orders = in_month(orders, args.month)
    except ValueError:
        raise SystemExit(f"cafe-report: --month must look like 2026-04, not {args.month!r}")
    items = pd.read_csv(data / "order_items.csv")
    products = pd.read_csv(data / "products.csv")
    sales = store_sales(orders, order_totals(items, products))
    for row in sales.itertuples():
        if row.orders < config["min_orders"]:
            log.warning(
                "store %d has %d orders in %s, under %d",
                row.store_id, row.orders, args.month, config["min_orders"],
            )
    print(sales.to_string(index=False))
```

### 3. A secret comes from the environment

**Idea.** A secret is a value that must not be readable by everyone who can read the repository. The Twelve-Factor App gives a test: the codebase could be made open source at any moment without compromising any credentials. A running program can read the environment variables of its process with `os.getenv("NAME")`, which returns the value as a string, or a default if the variable does not exist. Keep the value in a file named `.env`, commit `.env.example` with a placeholder, and have uv load the file for one run with `uv run --env-file .env`.

**Try it.** The mailing service does not exist yet, so `--send` only checks that the key is there and logs that the report would be sent; the value `demo-key-not-real` stands for a real key. Add this to `config.py` (with `import os` at the top):

```python
def get_token():
    token = os.getenv("CAFE_REPORT_TOKEN")
    if not token:
        raise SystemExit("cafe-report: set CAFE_REPORT_TOKEN (see .env.example)")
    return token
```

In `cli.py`, import `get_token` with `load_config`, add the option `parser.add_argument("--send", action="store_true")` after `--log-level`, add `if args.send: get_token()` as the first lines after `args = parser.parse_args()`, and, as the last lines of `main`:

```python
    if args.send:
        log.info("the report would be sent now")
```

### 4. Deleting a committed key does not make it safe

**Idea.** Git keeps every commit, and everyone who clones the repository gets the history.

**Try it.** Work in a throwaway folder outside your repository, so nothing here touches `cafe-report`:

```bash
mkdir leak-demo && cd leak-demo && git init
echo "CAFE_REPORT_TOKEN=demo-key-not-real" > .env
git add .env && git commit -m "add settings"
git rm .env && git commit -m "remove the key"
ls -a
git log --oneline
git show HEAD~1:.env
```

**Predict:** The key is gone from the folder and from the last commit. What does the last command print?

<details>
<summary>Reveal the result</summary>

```text
$ ls -a
.
..
.git
$ git log --oneline
abc1234 remove the key
abc1234 add settings
$ git show HEAD~1:.env
CAFE_REPORT_TOKEN=demo-key-not-real
```

Your hashes differ; these are masked.

</details>

*Why:* `HEAD~1` is the commit before the removal, and it still holds the file: a file that one commit added stays in the history after a later commit removes it. GitHub's guide says that the first step after a secret was committed is to revoke or rotate it, which can make it useless without any further cleanup. Rewriting the history locally with `git filter-repo` and force-pushing is not enough on its own: the page warns that commits with the data may still be accessible elsewhere, that a fork keeps the commit, and that you cannot remove data from other people's clones. GitHub's push protection blocks pushes that contain supported secrets, and the page says it is enabled by default for users pushing to public repositories; it is a net under the habit, not a replacement.

<Aside type="tip" title="Remember">

- Use `logging` with levels, a logger for each module, and configure it once in the entry point.
- The default level is `WARNING`: lower it for the run you want to see.
- Settings go in a file with defaults in code, and an argument beats the file.
- A secret comes from the environment, loaded from a `.env` that Git ignores; commit only `.env.example`.
- A committed key is in the history: rotate it first.

**Common trap:** a real key in the file you commit as the example.

</Aside>

def store_sales(orders, totals):
    done = orders[orders["status"] == "completed"]
    missing = int(done["customer_id"].isna().sum())
    if missing:
        log.warning("orders without a customer: %d", missing)
    joined = done.merge(totals, on="order_id", how="left", validate="one_to_one")
    return joined.groupby("store_id", as_index=False).agg(
        orders=("order_id", "count"), sales=("amount", "sum")
    )
