## The question

The owner of the three cafes asks:

> I want to see what the report did when it ran, and change the file name and a warning limit without touching code. I will also give you the key to the mailing service. It must never end up on GitHub, even by accident.

Three kinds of thing live in the repository, and they need three different homes:

| thing | example | where it lives |
|---|---|---|
| code | the function `orders_per_store` | in Git |
| a setting | the orders file, the lowest number of orders before a warning | a file in Git |
| a secret | the key of the mailing service | outside Git |

By the end you can make the report tell you what it did, read its settings from a file, read a key from the environment, and check the whole history for a key that went in by mistake.

## Learn by doing

About 35 minutes, 4 new ideas: logging with levels, settings in a file, a secret from the environment, and a search of the history for a key. Work in the folder `cafe-report` after C27 (with the repository clean), in the terminal; unit 4 uses a throwaway folder outside it.

### 1. Log with levels, not print

**Idea.** `print` has one level: always. The `logging` module has five, from `DEBUG` to `CRITICAL`: the Python HOWTO calls `INFO` confirmation that things are working as expected, `WARNING` an indication that something unexpected happened, and `ERROR` a function that could not be performed. Each module gets its own logger with `logging.getLogger(__name__)`, and the entry point configures once what is shown and how it looks.

**Try it.** In `cafe_report/load.py` and `cafe_report/summary.py`, add a logger and two messages each; the other lines stay as they are:

```python
# cafe_report/load.py
import csv
import logging

log = logging.getLogger(__name__)


def read_orders(path):
    """Read an orders file into a list of dictionaries, one for each order."""
    with open(path, newline="") as file:
        orders = list(csv.DictReader(file))
    log.info("read %d orders from %s", len(orders), path)
    return orders
```

```python
# cafe_report/summary.py
import logging
from datetime import datetime

log = logging.getLogger(__name__)


def orders_per_store(orders, since):
    """Count the completed orders of each store on or after the day `since`."""
    counts = {}
    seen = set()
    for order in orders:
        if order["order_id"] in seen:
            continue
        seen.add(order["order_id"])
        day = datetime.fromisoformat(order["ordered_at"]).date()
        if order["status"] == "completed" and day >= since:
            counts[order["store_id"]] = counts.get(order["store_id"], 0) + 1
    log.info("%d completed orders since %s", sum(counts.values()), since)
    if not counts:
        log.warning("no completed orders since %s", since)
    return counts
```

*Why:* the HOWTO says the default level is `WARNING`, and the logging module page says the root logger is created with `WARNING`, so the `INFO` lines stay hidden and the July warning gets through. `basicConfig(level=logging.INFO)` lets `INFO` and above through, and the `format` names the parts of each line: level, logger name (the module) and message. Add `%(asctime)s` for the time, which makes your lines differ from these. The values are passed as arguments, which the HOWTO says are merged into the message only when it is shown. The HOWTO says the call to `basicConfig` should come before any logger call, so it is the first line of `main`.

### 2. Move settings into a file

**Idea.** A setting is a value that differs between runs or machines while the logic stays the same: a file name, a level, a limit. The Twelve-Factor App asks for a strict separation of config from code. Keep the settings in a TOML file next to the code, give each one a default in code, and let the command line carry the same settings. `tomllib` reads TOML from a file opened in binary mode and returns a dictionary.

**Try it.** Create `cafe-report.toml` in the project folder, and `cafe_report/config.py`:

```toml
orders_file = "data/orders.csv"
log_level = "INFO"
min_orders = 360
```

```python
# cafe_report/config.py
import tomllib
from pathlib import Path

DEFAULTS = {"orders_file": "data/orders.csv", "log_level": "WARNING", "min_orders": 0}


def load_config(path="cafe-report.toml"):
    config = dict(DEFAULTS)
    if Path(path).exists():
        with open(path, "rb") as f:
            config.update(tomllib.load(f))
    return config
```

Replace `cafe_report/cli.py` by this version. The file argument becomes optional, there is a `--log-level` option, and each store with fewer than `min_orders` orders gets a warning:

```python
# cafe_report/cli.py
import argparse
import logging
from datetime import date

from cafe_report.config import load_config
from cafe_report.load import read_orders
from cafe_report.monthly import orders_by_store_month
from cafe_report.summary import orders_per_store

log = logging.getLogger(__name__)


def main(argv=None):
    parser = argparse.ArgumentParser(prog="cafe_report", description="Count the completed orders of each store.")
    parser.add_argument("orders_file", nargs="?", help="path to orders.csv (default: the file named in cafe-report.toml)")
    parser.add_argument("--since", type=date.fromisoformat, default=date.min,
                        help="count orders on or after this day, as YYYY-MM-DD (default: every day)")
    parser.add_argument("--monthly", action="store_true", help="print a table of stores and months instead")
    parser.add_argument("--log-level", help="DEBUG, INFO, WARNING or ERROR (default: the level in cafe-report.toml)")
    args = parser.parse_args(argv)
    config = load_config()
    logging.basicConfig(level=args.log_level or config["log_level"], format="%(levelname)s %(name)s: %(message)s")
    orders_file = args.orders_file or config["orders_file"]
    if args.monthly:
        try:
            table = orders_by_store_month(orders_file)
        except FileNotFoundError:
            raise SystemExit(f"cafe_report: no file {orders_file}")
        print(table)
        return
    try:
        orders = read_orders(orders_file)
    except FileNotFoundError:
        raise SystemExit(f"cafe_report: no file {orders_file}")
    counts = orders_per_store(orders, args.since)
    for store_id in sorted(counts):
        if counts[store_id] < config["min_orders"]:
            log.warning("store %s has %d orders since %s, under %d", store_id, counts[store_id], args.since, config["min_orders"])
        print(f"store {store_id}: {counts[store_id]} orders")
```

### 3. A secret comes from the environment

**Idea.** A secret is a value that must not be readable by everyone who can read the repository. The Twelve-Factor App gives a test: the codebase could be made open source at any moment without compromising any credentials. A running program can read the environment variables of its process with `os.getenv("NAME")`, which returns the value as a string, or a default if the variable does not exist. Keep the value in a file named `.env`, commit `.env.example` with a placeholder, and have uv load the file for one run with `uv run --env-file .env`.

**Try it.** The mailing service does not exist yet, so `--send` only checks that the key is there and logs that the report would be sent; the value `demo-key-not-real` stands for a real key. Add this to `cafe_report/config.py` (with `import os` at the top):

```python
def get_token():
    token = os.getenv("CAFE_REPORT_TOKEN")
    if not token:
        raise SystemExit("cafe_report: set CAFE_REPORT_TOKEN (see .env.example)")
    return token
```

In `cli.py`, import `get_token` with `load_config`, and add the option `parser.add_argument("--send", action="store_true", help="check the key of the mailing service")` after `--log-level`. Add `if args.send: get_token()` as the first lines after `args = parser.parse_args(argv)`, and, as the last lines of `main`:

```python
    if args.send:
        log.info("the report would be sent now")
```

### 4. Search the whole history for a key

**Idea.** Git keeps every commit, and everyone who clones the repository gets the history. `git log -S"text"` lists the commits that add or remove that text, in a file anywhere, so it answers one question before you share a repository: did this key ever go in?

**Try it.** Work in a throwaway folder outside your project. Commit a settings file with the made-up key, take the key out in the next commit, add one more file, and search; then search the history of your own project for the same text:

```bash
cd ~
mkdir leak-demo
cd leak-demo
git init -b main
echo 'token = "demo-key-not-real"' > settings.toml
git add settings.toml
git commit -m "Add settings"
echo 'month = "2026-04"' > settings.toml
git commit -am "Take the key out of the settings"
echo notes > notes.txt
git add notes.txt
git commit -m "Add notes"
git log --oneline
git log --oneline -S"demo-key-not-real"
cd ~/cafe-report
git log --all --oneline -S"demo-key-not-real"
```

</details>

*Why:* the git-log page describes `-S` as a search for differences that change the number of occurrences of the string, an addition or a deletion, so the commit that added the key and the commit that removed it both show, and the commit that did neither does not. `--all` searches every branch as well. Your project prints nothing: no commit ever changed that text. If a search in a real repository lists a commit, treat the key as exposed: GitHub says the first step is to revoke or rotate it, and that removing the data from the history takes four steps, rewriting the repository locally with `git filter-repo`, updating the repository on GitHub, coordinating with colleagues to clean their clones, and preventing repeats. It also warns that commits with the data may still be accessible in forks, clones and cached views. GitHub's push protection blocks pushes that contain supported secrets, and the page says it is enabled by default for users pushing to public repositories; it is a net, not a replacement for the search. Delete the throwaway folder when you are done.

<Aside type="tip" title="Remember">

- Use `logging` with levels, a logger for each module, and configure it once in the entry point.
- The default level is `WARNING`: lower it for the run you want to see.
- Settings go in a file with defaults in code, and an argument beats the file.
- A secret comes from the environment, loaded from a `.env` that Git ignores; commit only `.env.example`.
- `git log -S"text"` searches the whole history; a key that shows up there is rotated first.

**Common trap:** a real key in the file you commit as the example.

</Aside>
