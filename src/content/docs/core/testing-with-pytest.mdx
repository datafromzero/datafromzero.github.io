## The question

The owner wants to change the order counts again, and writes:

> Last time I changed the first day of the count, nobody noticed a day was missing. Can the program check itself every time, also on the first day and the last second of a month?

A tiny list shows where such a mistake hides. These five orders have a known answer for a count from April 1: the last second of March, the first moment of April, a walk-in with no customer, a canceled order, and the first moment of May.

| order_id | customer_id | store_id | ordered_at | status |
|---:|---:|---:|---|---|
| 1 | 7 | 1 | 2026-03-31 23:59:59 | completed |
| 2 | 8 | 1 | 2026-04-01 00:00:00 | completed |
| 3 | | 2 | 2026-04-15 12:30:00 | completed |
| 4 | 9 | 2 | 2026-04-30 23:59:59 | canceled |
| 5 | 9 | 3 | 2026-05-01 00:00:00 | completed |

By the end you can write tests on lists like this one, read a failed test, and trust an answer from elsewhere.

## Learn by doing

About 30 minutes, 4 new ideas: a test and where pytest looks for your code, edge rows and a fixture, a count that doubles a repeated row, and an answer from another route. Work in `cafe-report` after C26, in the terminal, with the changes of C26 committed.

### 1. A test is a function with an assert

**Idea.** A test is a function that builds a small input, calls your code and asserts the answer you know. pytest runs the files named `test_*.py` or `*_test.py` and the functions whose names start with `test_`, and prints a dot for each test that holds.

**Try it.** Add pytest, then save the first test as `tests/test_summary.py` (make the folder `tests`):

```bash
uv add --dev pytest
```

```python
from datetime import date

from cafe_report.summary import orders_per_store


def test_orders_per_store_counts_the_completed_orders_from_the_day():
    orders = [
        {"order_id": "1", "store_id": "1", "ordered_at": "2026-04-02 08:00:00", "status": "completed"},
        {"order_id": "2", "store_id": "1", "ordered_at": "2026-04-03 09:30:00", "status": "completed"},
        {"order_id": "3", "store_id": "2", "ordered_at": "2026-04-03 10:00:00", "status": "canceled"},
    ]
    assert orders_per_store(orders, date(2026, 4, 1)) == {"1": 2}
```

Run `uv run pytest -q`.

**Predict:** The answer is right: store 1 has two completed orders, and the canceled one does not count. Does the run print a dot?

<details>
<summary>Reveal the result</summary>

```text
$ uv run pytest -q
==================================== ERRORS ====================================
____________________ ERROR collecting tests/test_summary.py ____________________
...
tests/test_summary.py:3: in <module>
    from cafe_report.summary import orders_per_store
E   ModuleNotFoundError: No module named 'cafe_report'
=========================== short test summary info ============================
ERROR tests/test_summary.py
1 error in 0.07s
```

</details>

*Why:* the test never ran: pytest could not import the package. For a test file with no `__init__.py` beside it, the pytest page says it inserts the folder of the test file into the search path, here `tests/`, not the project folder (C24's Exercise 3 again); `python -m pytest` adds the current directory instead. The lasting fix is a setting: a `[tool.pytest.ini_options]` table in `pyproject.toml` configures pytest, and the reference says `pythonpath` lists directories added to the search path, relative to the rootdir. Add this to the end of `pyproject.toml` and run again:

```toml
[tool.pytest.ini_options]
pythonpath = ["."]
```

```text
$ uv run pytest -q
.                                                                        [100%]
1 passed in 0.01s
```

`pyproject.toml` also has a `dev` list with `pytest>=9.2.0`; the uv page says a development dependency is not part of the requirements when the project is published.

### 2. Edge rows, a fixture, and a failure report

**Idea.** The mistakes that survive a first look sit at the edges of a rule: the first moment of a day, the last second before it, a canceled order, a missing customer. Put those rows in the list. A fixture is a function marked `@pytest.fixture` that builds the list for each test; a test asks for it by writing its name as an argument.

**Try it.** Add the five orders as a fixture, with `import pytest` at the top, above the first test, and a test at the end:

```python
@pytest.fixture
def orders():
    return [
        {"order_id": "1", "customer_id": "7", "store_id": "1", "ordered_at": "2026-03-31 23:59:59", "status": "completed"},
        {"order_id": "2", "customer_id": "8", "store_id": "1", "ordered_at": "2026-04-01 00:00:00", "status": "completed"},
        {"order_id": "3", "customer_id": "", "store_id": "2", "ordered_at": "2026-04-15 12:30:00", "status": "completed"},
        {"order_id": "4", "customer_id": "9", "store_id": "2", "ordered_at": "2026-04-30 23:59:59", "status": "canceled"},
        {"order_id": "5", "customer_id": "9", "store_id": "3", "ordered_at": "2026-05-01 00:00:00", "status": "completed"},
    ]


def test_the_first_moment_of_the_day_counts_and_the_last_second_before_it_does_not(orders):
    assert orders_per_store(orders, date(2026, 4, 1)) == {"1": 1, "2": 1, "3": 1}
```

It passes. Now break the rule in `cafe_report/summary.py`: change `day >= since` to `day > since`, and run `uv run pytest -q`.

**Predict:** Which test fails, and which store does the report say is missing?

### 3. A count that doubles a repeated row

**Idea.** A count can change the number of rows without an error. When an export is written twice, an order appears on two rows, and a loop that adds one for each row counts it twice. A test finds this only when the list holds a repeated row on purpose.

**Try it.** Add a test that repeats order 2, and run `uv run pytest -q`:

```python
def test_a_repeated_order_row_counts_once(orders):
    again = orders + [orders[1]]  # the export wrote order 2 twice
    assert orders_per_store(again, date(2026, 4, 1)) == {"1": 1, "2": 1, "3": 1}
```

**Predict:** The answer is the same as in unit 2, since the orders are the same. Does the test pass? If not, what do the `E` lines say?

<details>
<summary>Reveal the result</summary>

```text
..F                                                                      [100%]
___________________ test_a_repeated_order_row_counts_once ____________________
...
E       AssertionError: assert {'1': 2, '2': 1, '3': 1} == {'1': 1, '2': 1, '3': 1}
E         Differing items:
E         {'1': 2} != {'1': 1}
tests/test_summary.py:34: AssertionError
FAILED tests/test_summary.py::test_a_repeated_order_row_counts_once - Asserti...
1 failed, 2 passed in 0.02s
```

</details>

*Why:* the code of C24 adds one for each row, so order 2 counted twice. Nothing raised an error; only a test that knew the answer could see it. The fix is to skip an order id already seen. In `cafe_report/summary.py`, add `seen = set()` after `counts = {}`, and these lines at the top of the loop:

```python
        if order["order_id"] in seen:
            continue
        seen.add(order["order_id"])
```

Now `uv run pytest -q` prints `...` and `3 passed`. Commit: `git add pyproject.toml uv.lock tests cafe_report`, then `git commit -m "Test the order counts and skip a repeated order row"`.

### 4. The answer comes from another route

**Idea.** A test on the real file needs an answer from a second route on the same data: a SQL query, a PivotTable, a `uniq -c` pipeline. The numbers C24 printed for the count from April 1 came out of this function, so they cannot check it.

**Try it.** Run this query in the SQL playground of this site, at `/sql/playground/`, which has the five tables loaded:

```sql
SELECT store_id, COUNT(*) AS orders
FROM orders
WHERE status = 'completed' AND ordered_at >= '2026-04-01'
GROUP BY store_id
ORDER BY store_id;
```

Expected: 3 rows, 2 columns: stores 1, 2 and 3 with 365, 362 and 355 orders. Add the same numbers as a test on the real file, with `from pathlib import Path` and `from cafe_report.load import read_orders` in the imports and this line below them:

```python
DATA = Path(__file__).resolve().parent.parent / "data"
```

```python
def test_april_matches_the_answer_from_sql():
    orders = read_orders(DATA / "orders.csv")
    assert orders_per_store(orders, date(2026, 4, 1)) == {"1": 365, "2": 362, "3": 355}
```

**Predict:** With the four tests of this lesson in the file, how many does `uv run pytest -q` report, and do they pass?

<details>
<summary>Reveal the result</summary>

```text
....                                                                     [100%]
4 passed in 0.02s
```

</details>

*Why:* one dot for each test. The last test's numbers were not produced by `orders_per_store`, so a mistake in it cannot hide in them (the store numbers are text in the dictionary, hence the quotes). `data/` is ignored by Git, so a clean clone needs `uv run download_data.py` first, as in C25. Commit: `git add tests`, then `git commit -m "Test April against the answer from SQL"`. GitHub describes continuous integration as frequently committing code to a shared repository and building and testing it each time, and its workflows can start when code is pushed. You build none here: `uv run pytest` needs only the repository and the data script.

<Aside type="tip" title="Remember">

- A test builds a small input, calls the code and asserts an answer you know.
- The tests folder is not the project folder: tell pytest where the package is with `pythonpath`.
- Put the edge rows in the list: the first moment, the last second, a canceled order, a missing value, a repeated row.
- Read a failure from the `E` lines: the result, the known answer and what differs.

**Common trap:** a test that cannot fail for the bug you fear. Make it fail once, on purpose, before you trust it.

</Aside>

```python
def test_monthly_table_has_a_row_for_each_store_and_a_column_for_each_month(tmp_path):
    path = tmp_path / "orders.csv"
    path.write_text(
        "order_id,customer_id,store_id,ordered_at,status,payment_method\n"
        "1,7,1,2026-03-31 23:59:59,completed,card\n"
        "2,8,1,2026-04-01 00:00:00,completed,mobile\n"
        "3,,2,2026-04-15 12:30:00,completed,cash\n"
        "4,9,2,2026-04-30 23:59:59,canceled,cash\n"
    )
    table = orders_by_store_month(path)
    assert list(table.columns) == ["2026-03", "2026-04"]
    assert table.to_numpy().tolist() == [[1, 1], [0, 1]]
```
