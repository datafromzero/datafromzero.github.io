## The big idea

Build to the brief, check every card against a number you computed another way, publish, and write the README that says what the screen is and where it stops.

## Learn by doing

About 35 minutes, 5 steps: the file, the cards, the charts, the screen, publish and README. Tableau Public is free; the Help page says its data and workbooks are public, so the cafe data is fine and private data is not.

### 1. The file, and the numbers it must give

**Idea.** The numbers come first, so every later step has a test. Run the block: it rebuilds the chapter 1 table and prints what the dashboard must show.

<RunSQL query={`CREATE OR REPLACE VIEW sales_clean AS
SELECT oi.order_item_id AS line_id, o.order_id, o.ordered_at, CAST(o.ordered_at AS DATE) AS order_date,
       s.store_name AS store, p.product_name AS product, p.category,
       CASE WHEN oi.order_item_id = 6952 THEN 2 ELSE oi.quantity END AS quantity,
       p.unit_price_usd AS unit_price, oi.discount_usd AS discount,
       (CASE WHEN oi.order_item_id = 6952 THEN 2 ELSE oi.quantity END) * p.unit_price_usd - oi.discount_usd AS amount,
       o.payment_method, COALESCE(c.loyalty_tier, 'walk-in') AS loyalty_tier
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
JOIN products p ON p.product_id = oi.product_id
JOIN stores s ON s.store_id = o.store_id
LEFT JOIN customers c ON c.customer_id = o.customer_id
WHERE o.status = 'completed';

SELECT 'Revenue' AS card, CAST(ROUND(SUM(amount), 2) AS VARCHAR) AS value FROM sales_clean
UNION ALL SELECT 'Orders', CAST(COUNT(DISTINCT order_id) AS VARCHAR) FROM sales_clean
UNION ALL SELECT 'Revenue per order', CAST(ROUND(SUM(amount) / COUNT(DISTINCT order_id), 2) AS VARCHAR) FROM sales_clean
UNION ALL SELECT 'Revenue, ' || store, CAST(ROUND(SUM(amount), 2) AS VARCHAR) FROM sales_clean GROUP BY store
UNION ALL SELECT 'Revenue, ' || category, CAST(ROUND(SUM(amount), 2) AS VARCHAR) FROM sales_clean GROUP BY category
UNION ALL SELECT 'Orders at 07h, ' || store, CAST(COUNT(DISTINCT order_id) AS VARCHAR)
FROM sales_clean WHERE EXTRACT(hour FROM ordered_at) = 7 GROUP BY store;`} />

Expected: 13 rows, 2 columns, in any order: Revenue 22582.75, Orders 1799, Revenue per order 12.55; by store Campus 8998.75, Harbor 4606.25, Old Town 8977.75; by category coffee 10802.00, food 4724.00, bakery 3824.25, tea 3232.50; orders at 07h 79 at Campus, 20 at Harbor, 73 at Old Town.

To get the file, download [`sales_clean.csv`](https://raw.githubusercontent.com/datafromzero/datafromzero.github.io/v0.3.0/datasets/cafe-sales/v1/extras/sales_clean.csv): the table of chapter 1 with one more column, `hour`, the hour as text with a leading zero (`07h`) so that a chart can use it as a label. It has 3,286 rows and 14 columns. In Tableau Public, the Connect pane has Text File: choose `sales_clean.csv` and Open. The data grid shows the first 1,000 rows; a field's type can be changed with its data type icon. Check `amount` is a number and `store`, `category` and `hour` are text. Use the field names the Data pane shows.

<details>
<summary>Optional: make the file yourself</summary>

In DuckDB on your computer, run `cafe-sales.sql` (from the release `v0.1.0` of the project's repository) and the view above, then export it with the added column:

```sql
COPY (
  SELECT *, LPAD(CAST(EXTRACT(hour FROM ordered_at) AS VARCHAR), 2, '0') || 'h' AS hour
  FROM sales_clean
) TO 'sales_clean.csv' (HEADER);
```

</details>

### 2. The three cards

**Idea.** A card is a measure with the right grain. Create each with Analysis, then Create Calculated Field: name it, type the expression, click OK. Tableau's page defines `SUM` as the sum of all values and `COUNTD` as "the number of distinct items in a group", with nulls not counted; and an aggregate calculation is always a measure.

| name | expression | must read |
|---|---|---|
| Revenue | `SUM([amount])` | \$22,582.75 |
| Orders | `COUNTD([order_id])` | 1,799 |
| Revenue per order | `SUM([amount]) / COUNTD([order_id])` | \$12.55 |

Put each on its own sheet as a single number (the measure on Text). **Check:** the three numbers equal the first rows of the list above. A card that reads 3,286 counted rows, not orders.

### 3. The three charts

**Idea.** Each chart answers one question of the brief, and its sheet is named by its finding. Tableau's bar-chart page: drag a dimension to Columns and a measure to Rows; if Tableau draws a line, choose Bar on the Marks card.

| sheet name | Columns | Rows | must show |
|---|---|---|---|
| Harbor sold about half of what each older cafe sold, in half the time | `store` | Revenue | 8,977.75, 8,998.75 and 4,606.25 |
| Coffee brings in 48 percent of revenue | `category` | Revenue | coffee 10,802.00 of 22,582.75 |
| Harbor's 7 a.m. hour is its quietest: 20 orders | `hour` | Orders, then `store` | 07h: 79, 20 and 73 |

For the third, drag `store` to Rows, to the left of Orders, so that each store gets its own bars. **Check:** hover the first bar of each chart and compare it with the list.

### 4. One screen, with a phone layout

**Idea.** Build the dashboard in the order of the brief. Choose the New Dashboard icon at the bottom of the workbook; drag sheets from the Sheets list; drag objects (a Horizontal layout container for the cards, a Text object for notes) from the Objects section. Put the three cards in the container on top, the charts below in the order of the questions, and a Text object last: the freshness line, "Data through June 30, 2026, last order 16:30", and the definitions of chapter 2. Turn on Use as Filter in a chart's corner so that a click on Harbor filters the others.

For the phone, click Device Preview on the Dashboard tab, select Phone and click Add Layout. The page recommends Fit width for phones, and says every view you want on the phone must first exist in the default dashboard. **Check:** click a bar in a chart: each card should change to the figures of the rows that bar selects, which you can compute with a `WHERE` on the table of step 1 (Exercise 1).

### 5. Publish, then the README

**Idea.** Publishing is public, and it runs from the menu the Help page names: with the workbook open, Server, then Tableau Public, then Save to Tableau Public; sign in, name the workbook (a title others can find) and Save. The page says the process creates an extract, that published workbooks and data are not private, and the FAQ says you can toggle off the download of the workbook and its data in the viz settings (downloads are on by default). Tableau Public limits a workbook to 15 million rows; yours has 3,286.

Open the link on a phone, then write the README (a text file beside the data, and a Text object on the screen):

```text
Question: the decision the screen supports, in one line.
Data: the source, which rows count, the date range, and any correction made.
Findings: one line for each chart, with its number.
Limits: what was left out, what the data cannot say, and how each figure is defined.
```

Here is one finished version, built in Tableau Public from the same file and published as [Dana's cafes: sales to June 30, 2026](https://public.tableau.com/views/DanascafessalestoJune302026/DanascafessalestoJune302026). Compare its cards and bars with your own: every number should match.

<Aside type="tip" title="Remember">

- Compute the numbers first; every build step has a check.
- Cards are measures at the right grain: `COUNTD` for orders.
- One sheet per question, named by its finding.
- Publishing is public; name the workbook, check the link on a phone.
- The README says what the screen is and where it stops.

**Common trap:** publishing before comparing each card with a number you computed another way.

</Aside>

## Finish it

<Exercise id="data-analyst-first-bi-dashboard-1">

**What should the cards read after one click?** A click on a bar of the hour chart selects its store and its hour. The editor gives the revenue of the Campus 9 a.m. bar. Add the orders and the revenue per order the cards must show. Run unit 1 first. Expected: 1 row, 3 columns.

<RunSQL query={`SELECT ROUND(SUM(amount), 2) AS revenue
FROM sales_clean
WHERE store = 'Campus' AND EXTRACT(hour FROM ordered_at) = 9;`} />

<details>
<summary>Hint</summary>

Orders are a distinct count of `order_id`, and revenue per order is the sum over that count.

</details>

<details>
<summary>Half-solution</summary>

```sql
SELECT ROUND(SUM(amount), 2) AS revenue,
       COUNT(DISTINCT order_id) AS orders,
       ...
```

</details>

<Solution>

```sql
SELECT ROUND(SUM(amount), 2) AS revenue,
       COUNT(DISTINCT order_id) AS orders,
       ROUND(SUM(amount) / COUNT(DISTINCT order_id), 2) AS revenue_per_order
FROM sales_clean
WHERE store = 'Campus' AND EXTRACT(hour FROM ordered_at) = 9;
```

\$902.75, 71 orders and \$12.71 per order. If your dashboard shows another number after the click, the filter does not reach that card: look at the sheet's Use as Filter setting and at how the card is calculated.

</Solution>

</Exercise>


```sql
SELECT store,
       ROUND(SUM(amount) FILTER (WHERE EXTRACT(hour FROM ordered_at) < 10), 2) AS before_10,
       ROUND(SUM(amount), 2) AS store_total,
       ROUND(100 * SUM(amount) FILTER (WHERE EXTRACT(hour FROM ordered_at) < 10) / SUM(amount), 1) AS share_percent
FROM sales_clean
GROUP BY store
ORDER BY store;

SELECT ROUND(SUM(amount), 2) AS before_10_all_stores
FROM sales_clean
WHERE EXTRACT(hour FROM ordered_at) < 10;
```
